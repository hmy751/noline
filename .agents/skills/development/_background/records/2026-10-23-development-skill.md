# 2026-10-23 — Development 스킬로 공통 수행 계약을 이전

사용자는 구현·검토의 판단과 책임을 정리한 뒤 이를 실제 prototype의 전용 스킬에 반영하고 관련 상세가 쌓이는 구성을 원했다. DEVELOPMENT의 진입점 이전도 제안했다. Main은 한 SKILL.md와 구현·검토·검증 상세, 형성 자료를 제안했으며 정확한 분할은 추천으로 구별했다.

이후 사용자는 Personal을 코드 기준으로만 설명한 범위를 바로잡고 개선 리뷰를 요청했다. 독립 리뷰는 구조 자체를 유지하되 Main의 전체 결과 책임, 역할별 독자, 일반 절차와 데모 적용의 구별을 보완하도록 권했다. Main이 그 네 보완을 종합해 설명한 뒤 사용자가 적용을 요청했다. [원문과 판본 근거](../evidence.md)에 직접 발췌와 리뷰의 지위를 남겼다.

## 적용한 내용

- [SKILL.md](../../SKILL.md)에 요청 파악·context 소유·작업 중 맥락 재선택·역할 연결·확인·결과 전달·Owner별 갱신을 구성했다.
- [review.md](../../references/review.md)에 공유 목적·판단 범위, 검토자의 재판단·근거·강도와 Main의 종합·사용자 연결을 구별했다.
- Personal 상위 설명은 개인의 판단 기준으로 보완하고, 현재 세부 본문이 개발 판단 중심이라는 사실은 유지했다. 기존 개발 원칙의 세부 내용은 이번에 확장하지 않았다.
- 일반 개발 절차의 현재 진입은 새 스킬로 옮기고 기존 DEVELOPMENT는 원문 보존판을 남긴 뒤 제거한다. 로그인 데모의 선택·계약·실제 기록은 기존 위치를 유지한다.

구현·검증의 빈 상세 파일, 새로운 agent·설정·hook은 만들지 않았다. 스킬 발견·설치의 운영 효과나 여러 실제 작업에서의 수행 효과를 이 적용만으로 확인한 것은 아니다.

## 이후 이어갈 판단

구현자가 검토 전에 어디까지 완성하고 무엇을 넘길지부터, 검토 입력·추가 맥락·권한·반환·호출·수정·재검토·종료를 구체화한다. 이후 모델·실행 배치·기존 맥락 스킬·지속 기록의 연결을 맞춘다. 미정값을 현재 본문에서 조용히 기본값으로 채우지 않는다. 선택 이유와 소유 관계는 [형성 맥락](../context.md)을 기준으로 다시 살핀다.

# 실행 지침과 그 지침을 고칠 근거를 함께 유지하는 이유

[스킬 본문 관리 정책](../../SKILLS-CONTENT-POLICY.md)의 현재 선택을 설명한다. 사용자는 context에 적용한 본문·형성 자료 구성을 스킬에도 적용할 수 있는지 검토한 뒤, 작성·수정 과정에서 놓치지 않도록 먼저 skills 안에 정책 지침을 만들도록 요청했다.

기존 [CONTENT-POLICY](../../../../context/CONTENT-POLICY.md)의 목적은 현재 내용을 충분히 적용하면서 그 내용을 만든 이유를 가까이 보존하는 것이다. 스킬도 반복해 사용하고 수정하는 지침이므로 이 목적을 이어받았다. 실행에 필요한 상세와 형성 근거의 구별, 맥락·기록·근거의 서로 다른 갱신 책임, 최소 발췌와 원자료의 연결을 유지한다.

스킬에서는 `SKILL.md`가 실행 진입 본문이고 보조 문서도 현재 판단을 맡을 수 있다. 따라서 일반 문서의 `INDEX` 배치를 그대로 옮기지 않고 기존 진입과 조건부 상세를 유지했다. 공통 실행 기준은 공유 책임으로, 실행 도구·산출물 재료는 실제 사용 역할로 구별했다. 형성 자료는 지침을 이해·수정할 때 읽으며 매 실행의 추가 필독 자료로 만들지 않는다.

예를 들어 기존 정의와 보완 후보를 대조하라는 요구가 왜 생겼는지 남기면, 이후 수정자가 같은 기준을 계속 추가하거나 필요한 구체화까지 줄이는 안을 재검토할 근거가 된다. 이는 형성 자료의 예상 효용이며 이번 정책으로 후속 수정자의 판단이 개선됐다고 검증한 결과는 아니다.

정책은 사용자가 지정한 skills 안에서 해당 구성·갱신 책임을 소유한다. 기존 context 정책의 적용 범위를 전역으로 올리거나 Work의 기존 기록 체계를 바꾸지는 않았다. 두 정책의 공통 원칙을 나중에 한 위치로 합칠지는 열려 있으며, 현재 경로의 존재를 외부 설치 계약으로 취급하지 않는다.

파일명은 [SYSTEM-GUIDANCE](../../../../context/SYSTEM-GUIDANCE.md)의 대표 진입 지침 표기와 사용자의 정정을 따라 대문자로 정했다. 이름 자체가 권한이나 모든 요청의 필독 순서를 결정하지는 않는다. 당시 선택과 발화는 [작성 기록](records/2026-10-21-initial-policy.md)과 [근거](evidence.md)에 있다.

## 내용 분할과 판본 보존을 구별한 이유

브리핑 수정안을 채택한 뒤 Main은 같은 폴더의 `SKILL.candidate.md`를 시험 판본 보존용으로 남겼다. 그러나 동일한 본문은 이미 실험 입력에 있었고, 사용자는 후보를 남긴 이유와 점을 붙인 이름의 사용을 지적했다. 기존 context 정책의 `INDEX.<내용 이름>.md`는 함께 사용하는 본문의 내용 분할을 나타낸다. 이를 수정 상태나 판본 표시로 확장할 근거는 없었다.

현재 정책은 실행 본문·형성 자료 구별을 유지하면서 수정안 준비와 채택 후 정리까지 연결한다. 임시 후보가 필요한 동안 존재하는 것은 허용하되 작업의 기록·실험 영역에서 현재 본문과 구별한다. 채택 후에는 남은 역할과 기존 보존 사본을 확인해 중복을 정리한다. 모든 후보 파일 금지, 점이 든 파일명 금지, 고정 후보 폴더 신설의 규칙은 아니다. 원문과 시험 입력의 보존은 유지한다.

이 보완은 실제 중복 사례에 대응한 관리 기준이며 반복 방지 효과를 시험한 결과는 아니다. [당시 선택·정정과 확인 범위](records/2026-10-22-revision-lifecycle.md), [사용자 발화](evidence.md#수정안-채택-뒤-중복-판본에-대한-정정)에서 근거를 확인한다.

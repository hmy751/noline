# 대화와 현재 문서를 대조해 직접 기록한다

[record-work](../SKILL.md)로 배정된 기록 담당자가 사용한다. Main의 요약을 대신 옮기는 역할이 아니라 원문·관련 결과와 기존 문서에서 보존할 의미를 판단하고 직접 반영한다. Main의 작업 조율·설계 선택·제품 검증을 대신하지 않는다.

## 대상 기준과 현재 문서를 읽는다

지정된 Project·Workspace와 쓰기 범위를 확인한다. 대상 Work 입구에서 Workspace의 역할·읽기 경로, 문서 작성 기준, Spec·Ticket의 갱신·보존 계약을 찾는다. Noline에서는 [문서 작성과 갱신](../../../../context/work/workspaces/DOCUMENT-WRITING.md)과 [갱신 기준](../../../../context/work/workspaces/spec-and-tickets/MAINTENANCE.md)을 적용한다. 실제 대상에 없는 prototype 경로를 지어내지 않는다.

이미 유효하게 읽은 기준과 맥락은 재사용한다. 수정 대상의 현재 내용은 다시 확인하며 이전 호출에서 알던 문장으로 다른 작업자의 변경을 덮지 않는다. [대화 입력](conversation.md)의 기본 구간을 읽고 이해가 필요한 앞선 발화·기록·관련 산출물로 확장한다. 관련 없는 전체 Project 조사나 모든 Work의 인수를 기본으로 삼지 않는다.

## 현재 의미와 보존할 과정을 판단한다

문서 내용·분량·중복·원문 발췌의 기준은 대상 작성 지침을 적용한다. 목표·범위·현재 선택·결과·미확인·다음 행동에 변화가 있는지 보고, 현재 요약이 바뀐 뒤에도 다시 볼 가치가 있는 분석·대안·선택과 철회 이유·실험 과정도 살핀다. 바로 다음 행동에 쓰이지 않는다는 이유만으로 버리지 않는다.

| 확인한 변화 | 반영 판단 |
| --- | --- |
| 사용자 선택·정정 | 실제로 선택한 범위와 강도를 현재 문서에 반영한다. 질문·예시·AI 추천을 채택으로 올리지 않는다. |
| 현재 판단을 바꾸는 결과 | 실제 근거와 보고의 출처·확인 범위를 구별하고 해당 Ticket·state·Spec을 맞춘다. |
| 다시 볼 선택 과정 | 필요한 이유·조건·최소 원문을 새 record에 보존하고 현재 의미에서 상세로 연결한다. |
| 다른 영역의 반영 누락 | Work에 필요한 남은 책임을 남기고 Main에게 대상·근거를 반환한다. |
| 지속할 변화 없음 | 기록을 만들기 위한 수정 없이 결과를 반환한다. |

대화의 완료 보고와 실제 산출물이 다르면 필요한 파일·관련 diff·기존 검사 근거를 좁게 확인한다. 관찰 가능한 사실을 확인하되 제품 검사 재실행을 기록의 선행 조건으로 만들지 않는다. 다른 담당자가 확인한 근거는 출처와 한계를 유지하고, 직접 실행한 것처럼 쓰지 않는다. 새로운 완료 판단이나 상충하는 의도는 임의 확정하지 않고 필요한 질문을 Main에게 돌린다.

## 관련 Owner를 직접 고치고 연결을 확인한다

현재 문서에서는 낡은 상태를 새 의미로 교체·통합하고, 기록에서는 당시 판단과 후속 변화를 구별한다. 같은 상세를 여러 곳에 복제하지 않되 각 문서가 맡은 설명을 링크만으로 대신하지 않는다. 상태나 전제가 바뀌면 그 뜻을 실제로 서술한 관련 current를 확인한다. 관련 없는 전면 정리로 넓히지 않는다.

새 본문·기록을 만들면 해당 색인에서 찾게 한다. 기존 본문만 바뀌고 안내 의미가 같으면 색인을 기계적으로 갱신하지 않는다. Source의 원문과 기존 날짜별 기록은 보존하고 보완은 대상의 새 기록·색인으로 연결한다.

현재 작업의 읽을 자료·이유·조건이 바뀌면 Workspace의 `recover.md`를 [Work 재개 기준](../../../../context/work/AGENTS.md)에 맞춘다. 현재 선택·조건·미정의 상세는 해당 current에 남기고 안내에는 자료 선택에 필요한 짧은 뜻과 읽을 범위를 연결한다. 새 자료가 생겼다는 이유만으로 기본 읽기에 추가하거나 전체 Workspace 목록을 복제하지 않는다.

수정 뒤 요청·원문·실제 결과와 작성 지침으로 내용 충분성을 확인한다. 필요한 현재 상태와 이유가 복원되는지, 제안·채택·실제 반영·확인이 섞이지 않는지, 수정한 링크가 맞는지 본다. 재개 안내를 바꿨다면 그 안내에서 필요한 의미와 근거를 찾을 수 있는지 대조하되 링크 확인을 새 세션의 재개 성공으로 보고하지 않는다. 부분 실패는 이미 바뀐 곳과 남은 작업을 분리해 알린다. 전체를 원복하거나 완료로 숨기지 않는다.

다음 행동이 바뀌었거나 사용자가 우선순위를 바로잡았다면, 작성한 현재 문서에서 다음 담당자가 가장 먼저 무엇을 살피게 될지 짚어 본다. 그 출발점과 이유를 사용자가 이어가려던 문제에 대조하고, 남은 검증이나 앞선 제안의 위치가 다르게 읽히면 해당 문장을 고친다.

## 다음 호출에서 이어갈 수 있게 반환한다

- 이번에 읽은 원문 구간과 앞선 맥락을 추가 확인한 범위.
- 실제 반영한 의미와 문서, 무수정인 경우 그 판단.
- 미반영 내용·이유·관련 원문 위치와 다음에 필요한 판단 또는 수행.

별도 고정 출력 양식은 요구하지 않는다. 한 구간 안에 미반영 내용이 남으면 해당 위치를 유지하며 읽은 끝만 다음 시작점으로 넘기지 않는다. 반환 뒤 같은 대화에서 다시 호출될 수 있도록 담당자를 유지하되, 자동 대화 추적을 시작하지 않는다.

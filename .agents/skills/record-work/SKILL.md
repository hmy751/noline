# Record Work — 작업의 현재 의미와 과정을 남긴다

Main은 작업 판단을 이어가고 기록 담당자는 대화 원문과 관련 결과를 읽어 무엇을 어디에 남길지 판단한 뒤 직접 수정한다. 현재 재개에 필요한 의미와 나중에 다시 살필 분석·선택 과정을 함께 보존한다. 기록 기준은 대상 Work가 소유하며 이 스킬은 호출·배정·수행·반환을 연결한다.

## 기록할 시점에 같은 담당자를 호출한다

사용자가 기록을 요청하거나 작업·논의를 정리할 때 사용한다. Main은 중요한 방향 변경·전환에서 기록이 필요하면 호출할 수 있다. 매 응답·정해진 횟수마다 호출하지 않으며, 호출 사이에는 서브가 대화를 계속 감시하거나 처리하지 않는다. 작업 전체 완료와 이번 대화의 마무리는 구별한다.

| 상황 | Main이 할 일 |
| --- | --- |
| 처음 호출 | 대상 Project·Workspace, 현재 Main 대화의 식별자와 원문 접근점, 이번 입력의 끝 지점, 알려진 기존 기록 범위를 연결하고 Work 기록의 직접 수정 권한을 배정한다. |
| 같은 대화에서 다시 호출 | 기존 기록 담당자 식별자로 후속 과업을 보낸다. 직전 반환의 미반영 사항·범위와 이번 원문 끝 지점을 연결한다. 이전 읽기·판단은 재사용하되 현재 파일을 대조한다. |
| 담당자가 진행 중 | 같은 대상의 두 번째 기록 담당자를 만들지 않는다. 현재 호출이 읽는 끝 지점을 유지하고 새 대화는 후속 호출로 잇는다. |
| 담당자가 사라졌거나 재사용 불가 | 새 담당자에게 실제 문서·원문과 마지막 확인 범위·미반영 사항을 연결한다. 반영 경계가 불분명하면 관련 이전 구간까지 대조하며 이전 이해가 남아 있다고 주장하지 않는다. |
| 작업 대상이 바뀜 | 진행 중 수정과 반환을 원래 Work에 귀속한다. 새 Work는 명시적으로 다시 배정하고 원래 기록 범위·미반영 사항과 섞지 않는다. 전환 자체는 대상 Work의 생성·전환 계약이 맡는다. |

실제 host가 제공하는 서브 생성·후속 호출 기능을 사용한다. 한 번 반환했다는 이유로 담당자를 종료하지 않는다. 대화가 끝나거나 host가 유지하지 못하면 세션 밖 생존을 보장하지 않는다. 별도 상시 실행기·전역 agent 등록·hook을 이 스킬의 필수 조건으로 만들지 않는다.

## 원문과 실제 결과를 판단할 입력으로 연결한다

Main은 기록 내용을 미리 선별한 요약만 전달하지 않는다. [대화 입력](references/conversation.md)에 따라 기본 범위는 직전 반영 이후의 원문으로 하며, 담당자가 필요한 이전 대화·기존 기록·관련 실물을 직접 읽을 수 있게 한다. 최초 호출의 기존 반영 경계를 모르면 현재 기록과 대조해 범위를 정한다.

다른 담당자의 반환이나 실제 검사 결과가 Main 대화 원문에 없으면 필요한 정확한 결과·출처를 추가로 연결한다. 원문·파일을 읽지 못하면 접근 가능한 입력을 확보하거나 제한을 반환한다. 요약만 보고 원문을 확인한 것으로 표시하지 않는다.

Main은 기존 담당자 식별자, 대상 Work, 원문 접근점, 마지막 반환의 반영 범위·미반영 사항을 후속 호출에서 찾을 수 있게 유지한다. 현재 대화의 배정·반환 정보로 충분하면 별도 상태 파일이나 영구 열람 장부를 만들지 않는다. 이어받기 위해 보존이 필요하면 기존 인계 경로에 최소한으로 남기고 제품의 현재 상태 본문에 호출 이력을 쌓지 않는다.

## 기록 담당자에게 판단과 직접 수정을 맡긴다

담당자에게 이 본문과 [기록 수행](references/maintainer.md), 대상 Work의 진입·작성·갱신 기준을 연결한다. Noline에서는 [Work 지침](../../../context/work/AGENTS.md)이 입구다. 실제 대상에서는 스킬 위치가 아니라 지정된 Project의 Work 입구를 사용한다.

기본 수정 범위는 지정 Workspace의 사람용 README·`recover.md`·current·source/output 색인·새 records와 records 색인이다. 해당 대상의 보존 계약을 따르며 raw source·과거 기록·제품 코드·검사·기계 status/receipt·다른 Work·active 선택은 기록 과업으로 바꾸지 않는다. 새 Workspace 생성, stage·commit·push는 이 스킬의 수행에 포함하지 않는다. 이 경계는 지침과 host 권한으로 지키며 기존 guarded apply와 같은 기계적 거부 보장을 주장하지 않는다.

방향·단계·중심 과제나 자료 위치가 달라져 재개 안내가 현재 판단을 잘못 이끌면 `recover.md`도 갱신한다. 읽을 대상·이유·조건의 구성과 current·과거 근거의 관계는 [Work의 재개 기준](../../../context/work/AGENTS.md)을 적용한다. 같은 안내가 유효하면 호출마다 다시 쓰지 않는다.

Main과 다른 담당자는 배정된 같은 문서를 중복 수정하지 않는다. 수정 대상의 현재판을 확인하고, 병행 변경이나 결정 충돌은 해당 부분을 연결해 해결한다. 작업 중 새 제품 약속·개인 기준을 선택하거나 완료 기준을 낮추는 판단은 Main과 해당 결정권자에게 돌려준다. 기록 담당자의 자율성은 기록할 의미의 선별·구성·직접 반영에 있다.

## 관련 컨텍스트의 반영 책임을 유지한다

[development](../development/SKILL.md)는 개발 결과의 전체 판단·관련 컨텍스트 영향과 반영을, 사용자 요청의 [improvement-loop](../improvement-loop/SKILL.md)는 경험 검토·개선 선택과 실제 적용을 맡는다. Project·Personal 반영은 해당 흐름과 [context-update](../context-update/SKILL.md)를 따른다. 기록 담당자는 관련 본문을 읽고 미반영 필요를 알릴 수 있지만 Work 기록을 맡았다는 이유로 직접 수정하지 않는다.

같은 서브에게 별도의 컨텍스트 반영을 맡길 수는 있다. 그때는 대상·의미·권한과 수행 계약을 명시하며 record-work의 기본 권한을 넓힌 것으로 취급하지 않는다. Work 없이 가능한 개선 작업에 이 스킬을 위해 Work 생성을 요구하지 않는다.

## 실제 반영 결과를 회수하고 이어간다

담당자는 실제 수정한 의미·문서, 사용한 원문 범위, 미반영·해석이 필요한 내용과 이유를 짧게 반환한다. 읽은 끝과 실제 반영 범위를 구별하며 부분 실패나 열린 판단을 끝 지점 하나로 숨기지 않는다. 새 의미가 없으면 무수정으로 끝날 수 있다. 별도 종합 보고서·기계 receipt를 만들지 않는다.

Main은 방향·다음 행동에 영향을 주는 반환과 미반영 사항을 확인한다. 모든 문서를 매번 전부 다시 읽는 검토를 강제하지 않는다. 커밋·인계나 갱신된 문서를 다음 실행에 넘길 때는 필요한 실제 반영을 기다려 확인한다. 무관한 작업은 이어갈 수 있지만 호출·진행 중 상태를 기록 완료로 말하지 않는다. 파일 반영과 다음 세션 재개의 성공·사용 효과는 별도다.

목적·책임·호출 방식을 다시 판단할 때는 [형성 자료](_background/README.md)를 읽는다.

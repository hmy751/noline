# 생성·전환 구성의 근거

이 자료는 [실행 본문](../SKILL.md)과 [형성 맥락](context.md)의 주요 판단을 확인할 최소 근거다. 아래 발화는 2026-10-25~26 설계 대화에서 선별한 사용자 원문이며 전체 전사본이 아니다. 같은 날짜의 후속 선택과 실제 실행 결과를 구별한다.

## 사용자 요청과 선택

기존 이름 보존이나 새 스킬 수가 목적이 아니라는 요청:

> 너무 기존 스킬을 유지한다고 굳이 얽매이지 않아도 되니까 새로운 스킬 구성도 생각해봐 그러니까 또 억지로 만들란건 아니고 적합한거 지금 기존 시스템 새 워크플로 등등 그리고 우리가 추후 할 작업들 다 종합적으로 분석해서

기존 책임과 전체 연결을 함께 검토하라는 요청:

> 그럼 1번만 그렇게 설명해서 끝내지 말고 4가지 전체에서 기존 스킬이랑 워크플로 책임이 겹치는 부분 다시 봐봐. 기존 걸 무조건 유지하라는 건 아니고 어디는 그대로 쓰고 어디는 보완하거나 합칠지 종합해서 보여줘

네 항목의 설계·개선 리뷰와 통합 계획을 논의한 뒤 실제 prototype 적용을 요청했다:

> 먼저 커밋할거 부터 하고 그럼 프로토 타입 적용해봐

이 요청은 prototype 실행 본문과 연결의 적용이다. 새로운 실제 Work 생성이나 운영 Harness 설치·자동 activation을 요청한 것으로 확대하지 않았다. 늦은 결과의 귀속과 최신 쓰기 권한을 구별하는 보완은 독립 개선 리뷰 뒤 반영한 설계 판단이며 실제 병행 작업의 성공 관찰은 아니다.

## 기존 원형에서 유지·변경한 것

비교에 사용한 기존 create 원형과 Work 생성 계약은 새 목표의 의미 선별·원본 보호·current 직접 서술·이전 상세의 단방향 참조·생성과 활성화 구별을 갖고 있었다. 반면 설치된 Harness의 identity·Recover·Verify와 자동 Maintain activation 명령에 의존했다. 수동 demo에서는 그 동작을 실행할 기반이 없고 자동 Maintain을 재개하지 않는 방향이므로, 의미 계약을 유지하면서 수동 인수·목록 선택과 실제 host 전환을 구별했다.

이 판단은 이름이 같은 기존 스킬을 그대로 복사하면 된다는 뜻이 아니다. 현재 실행 계약은 [Work 생성과 전환](../../../../context/work/workspaces/CREATE-AND-TRANSITION.md)이며, 기계 상태·명령을 사후에 꾸며 넣어 호환 성공을 주장하지 않는다.

OS 임시 파일을 Work current의 정본으로 옮기지 않는다.
- Lauren Tan pstack 0.15.29, commit `190d28736eff128ec94f502a22c7fe0c4b56cd37`의 [session-pickup](https://github.com/cursor/plugins/blob/190d28736eff128ec94f502a22c7fe0c4b56cd37/pstack/skills/poteto-mode/playbooks/session-pickup.md)은 이전 결정·완료·남은 일을 복원하고, 이어받은 주장을 원래 목표와 실제 산출물에 대조하도록 한다. 유효한 근거를 재사용하고 남은 일을 잇는 참고다. 전체 이력 재수집이나 모든 과거 확인의 재실행으로 확대하지 않는다.

두 원문은 당시 보존판을 직접 읽은 근거다. 외부의 실제 운영 효과를 시험한 결과가 아니며 우리 새 Work의 생성·기본 선택·host 연결 전체를 정의하지 않는다. 그 경계는 [현재 계약](../../../../context/work/workspaces/CREATE-AND-TRANSITION.md)과 이번 대상의 실제 상태에서 정했다.

# Improvement Loop의 형성 자료

이 자료는 prototype의 형성 맥락·당시 선택을 보존한다. 설치 대상의 현재 Work 갱신·생성·전환은 기존 계약을 유지하도록 적응했다. [이번 적응과 남은 연결](records/2026-10-30-existing-work-contract-adaptation.md)을 먼저 구별하며, 아래 당시 Main 직접 기록·수동 demo 설명으로 현재 운영 계약을 바꾸지 않는다.

[실행 본문](../SKILL.md)은 현재 세션에서 경험·현재 내용을 개선으로 연결하는 수행을 소유한다. 이 층은 왜 그 범위와 배치를 택했는지 보존한다.

- 루프를 현재 Main과 별도 호출 본문으로 둔 이유, Personal·반영 책임·미확인의 관계: [형성 맥락](context.md).
- 직접 사용자 발화와 외부 자료에서 가져온 관점·가져오지 않은 절차: [근거](evidence.md).
- 네 묶음 합의를 실제 파일로 만든 선택과 남은 확인: [구체화 기록](records/2026-10-28-prototype.md).

원래 전체안의 독립 개선 리뷰 뒤 사용자와 합의했고 실행 파일은 Main이 작성했다. 이후 독립 검토와 사용자 재검토를 거쳐 스킬 관리 단위로 적용 설명을 통합하고 Personal 근거를 분리했다. 이 문서 검토를 실제 운영 효과 확인으로 보지 않는다.

명칭과 전체 목적을 다시 볼 때는 [이름 변경 기록](records/2026-10-28-naming.md)을 읽는다.

전체 안내·실행 상세·Personal 근거의 배치와 원문 접근 예의 당시 확인 범위는 [구조 반영 기록](records/2026-10-28-structure.md)을 읽는다.

루트 유지 판단을 바꾼 이유와 현재 관리 단위는 [통합·책임 정정 기록](records/2026-10-29-integration.md)에서 읽는다. 앞선 구조 기록의 루트 유지·context 내 근거 통합은 당시 선택이며 현재 구성은 이 정정을 따른다.

선택한 한정 시도를 기존 작업에서 실행하고 끝내는 이유와 적용 경계는 [한정 시도 연결 기록](records/2026-10-29-limited-trial.md)을 읽는다.

같은 목적에서 현행·설명·수행 수단을 비교하는 사례를 보완한 이유는 [비교 사례 선택 기록](records/2026-10-29-means-comparison.md)을 읽는다.

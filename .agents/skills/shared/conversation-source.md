# 같은 대화의 원문에 접근한다

대화를 근거로 사용하는 스킬이 원문을 찾을 때 적용한다. 읽을 범위와 보존할 내용은 호출한 스킬이 정한다. 이 문서는 세션 식별·실제 발화 구별·재접근 방법을 공유한다.

현재 host의 대화 식별자와 원문 접근점을 대조한다. 가장 최근 파일이나 제목이 비슷한 대화를 대신 선택하지 않는다. 현재 문맥의 압축 요약은 위치를 찾는 단서이며 원문을 확인한 증거가 아니다. 대상 구간은 원래 순서로 읽고 잘린 출력은 이어 읽는다. 검색은 위치 탐색에 쓰며 요청된 구간의 열람을 대체하지 않는다.

사용자·Main 발화와 주입 지침·도구 결과·다른 담당자의 보고를 구별한다. 주장 확인에 필요한 도구 입출력과 산출물은 해당 위치에서 추가 확인한다. 같은 세션의 확인된 경로를 재사용하며 무관한 로그나 다른 프로젝트의 대화를 수집하지 않는다.

## 로컬 Codex의 세션 파일을 사용하는 경우

현재 host가 `CODEX_THREAD_ID`와 로컬 세션 파일을 제공하면 `~/.codex/sessions/` 아래 그 식별자가 들어간 `rollout-*.jsonl` 파일을 대조한다. `session_meta`의 `payload.id` 또는 `session_id`와 `cwd`를 확인해 대상을 확정한다. 경로 패턴은 확인한 환경의 접근 예이며 모든 host에 대한 계약이 아니다.

실제 파일이 다음 메시지 구조를 사용하는지 먼저 확인한다. 확인한 판본에서는 `response_item` 중 `payload.type = message`의 `role = user | assistant`, `content`의 `input_text | output_text`가 발화를 담았다. 원본 줄 번호·순서를 유지하며 읽고, `event_msg`에 중복된 같은 발화를 다시 세지 않는다. system/developer 지침·tool 결과·reasoning을 사용자의 발화로 합치지 않는다. 사용자 메시지 안에 주입된 설정·이전 대화가 있으면 실제 사용자 발화와 구별한다. 도구 호출·출력은 필요한 사건에서 원래 줄로 돌아가 확인한다.

`compacted`의 replacement history는 요약·재구성일 수 있다. 같은 파일에 압축 전 원문이 남았는지 확인하고 원문을 우선한다. 파일이 있다는 사실이나 첫·끝 발화만 맞는다는 사실은 중간 원문과 이전 이관 구간의 완전성을 보장하지 않는다. fork·재개로 이전 세션을 참조하면 그 연결과 필요한 이전 원문을 확인한다. 다른 host에서는 해당 환경이 제공하는 실제 원문 접근 방법으로 같은 의미를 충족한다.

이 접근 예의 확인판과 당시 확인 범위는 [improvement-loop 형성 기록](../improvement-loop/_background/records/2026-10-28-structure.md#원문-접근-예의-확인판)에 있다. 환경별 예가 있다는 사실로 현재 세션 원문의 완전성이나 전체 열람을 확인했다고 보지 않는다.


## 접근할 수 있는 범위와 공백을 구별한다

원문 접근점·구간 경계와 확인한 내용의 지위를 반환한다. 누락 구간이 있으면 필요한 복구를 시도하고 해당 결론의 한계를 밝힌다. 읽은 범위와 기록 반영·전체 검토 완료는 각 스킬의 완료 기준으로 구별한다. 공통 접근 방법을 바꿀 때는 improvement-loop와 record-work의 입력·범위가 유지되는지 함께 확인한다.

# 선별한 설명 개선안의 실행 반영

2026-10-24. 목적·Noline 사용 장면·현재 논의·외부 자료를 선별한 안과 독립 개선 리뷰를 거쳐, 사용자가 스킬 구체화·반영을 요청했다. 실행 본문을 수정했으며 실제 설명 효과는 아직 확인하지 않았다. 요청·리뷰·자료 판본은 [근거](../evidence.md#목적레퍼런스리뷰를-선별한-뒤의-적용--2026-10-24)에 보존한다.

## 이번 선택의 이유

이전 수정에도 실제 구현 대응·전후 비교·목적별 충분성이 있었지만, 비교 응답은 요약에 머물렀다. 같은 요구를 더 강하게 쓰거나 모델을 바꾸며 반복하는 것으로 충분한 해결을 만들지 못했다. 이번에는 질문의 범위를 지키고 핵심 문장에서 생략한 처리·조건·이유를 실제 대상으로 잇는 수행을 중심에 둔다. 통합 구조나 문구 재배치만으로 효과가 입증됐다고 보지 않는다.

| 대상 | 실제 반영과 이유 |
| --- | --- |
| 본체 | 자료 선정·구현 대응·형태·첫 결과 전달에 흩어진 요구를 질문 범위, 핵심 주장 작성, 근거 대조, 충분성과 권한으로 정리했다. 첫 결과의 코드 주장도 별도 코드 설명 요청을 기다리지 않게 했다. |
| 작성 상세 | 일반 요구의 반복과 저장·조회 긴 예시를 교체했다. 전체 인증 코드와 좁은 후속 질문, 실제 동기화 요약의 빠진 연결, 여행 역할과 선택 판단에 맞는 근거를 구별한다. 예시를 모두 답에 채우는 목록으로 쓰지 않는다. |

## 가져온 것과 가져오지 않은 것

Matt의 공통 수행과 조건부 상세·완료 조건, pstack의 작업 단계와 설명 기능 연결·동작과 이유의 구별, Vercel의 요청 범위에서 자료·확인으로 이어지는 관점은 우리 목적에 맞춰 사용했다. 외부 호출 문법·숙련 개발자 전제·고정 모드 수·상시 설명 agent는 채택하지 않았다. 기계 검사는 형식·링크·발췌를 확인하고, 설명의 충분성과 근거 적합성은 실제 문단을 읽어 판단한다.

기존 두 스킬의 모든 조항, 모든 Noline 장면, 모든 리뷰 의견을 상시 요구로 누적하지 않았다. 배경은 선택을 재검토할 근거이며 실행 규칙의 상위 정답이 아니다. 단일 입구와 두 상세는 현재 책임 구분에 따라 유지하며 효과를 확인한 뒤 교체·제거할 가능성도 열려 있다. 작업 결과의 지속 책임과 공통 근거 기준은 이 설명 방법 밖에 남는다.

## 확인 범위

변경 본문에서 단순 뜻 질문, 전체 코드 요청, 특정 대목의 후속, 역할 설명, 선택 검토, 첫 결과 보고의 읽기·수행 경로를 Main이 대조했다. 원문과 코드 발췌·링크·형식 검사는 Workspace 적용 기록에 남긴다. 이 확인은 독립 응답 생성·실제 사용자 이해·자연 호출 효과의 시험이 아니다. 새 A/B·운영 설치·제품 실행은 하지 않았다.

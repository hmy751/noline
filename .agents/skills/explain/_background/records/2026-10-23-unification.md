# 2026-10-23 — 두 설명 진입점을 explain으로 통합

사용자는 리뷰 반영 구성으로 본체·상세·형성 자료를 만들고 기존 두 스킬의 연결도 정리하도록 요청했다. 생성 중에는 기존 두 스킬 제거를 감안했는지 확인했으며, 모든 옛 조항을 무조건 채우라는 요구가 아니라고 정정했다. [직접 발화와 근거](../evidence.md)를 보존했다.

## 채택한 구성

- [본체](../../SKILL.md)가 질문의 중심, 자료 선택과 실제 설명, 깊이와 종료·권한을 소유한다.
- [작성 상세](../../references/constructing-explanations.md)는 관계·조건·이유·관찰을 설명으로 만드는 방법과 짧은 작성 과정 예시를 함께 둔다.
- [앞선 발화 상세](../../references/prior-explanation.md)는 실제 발화의 뜻과 현재 타당성을 대조해 보완·정정하는 특수 수행을 맡는다.
- 형성 맥락·근거·이 기록은 선택 이유와 적용 지위를 보존하며 일상 설명의 필독 자료가 아니다.

처음에는 관계·동작과 이유·근거를 별도 상세로 제안했으나, 한 번의 독립 개선 리뷰 뒤 함께 수행하는 내용을 한 작성 상세에 묶었다. development의 본체·검토 상세에서 가져온 것은 책임과 읽을 조건을 나누는 방식이며 개발 역할·단계 자체는 이식하지 않았다.

## 이전 두 스킬과 현재 연결

이전 `work-artifact-briefing/SKILL.md`와 `explanation-recovery/SKILL.md`는 현재 실행 지침을 갖지 않는 이전 경로 안내로 전환한다. 활성 스킬 frontmatter를 남겨 새 스킬과 경쟁시키지 않는다. 기존 링크는 이 안내에서 새 explain과 당시 본문 사본을 찾을 수 있다. 해당 폴더들은 과거 근거를 위한 보존 영역이며 독립 설치할 스킬이 아니다.

전환 직전 본문은 각 폴더의 `_background/records/2026-10-23-before-explain.txt`에 바이트 그대로 보존한다. 원래 형성 기록·원자료·실험 입력·응답은 유지한다. 이전 배경의 진입에는 현재 전환 관계를 알리고, 당시 판단을 현재 결론으로 덮어쓰지 않는다.

현재 스킬 안내와 공통 기준의 consumer는 `work-discussion`과 `explain`으로 맞춘다. development의 결과 전달 부분은 새 설명 본문을 가리키고, 답을 만들 사실이 부족하면 작업 담당자가 기존 권한 안에서 추가 확인 여부를 판단하도록 연결한다. 다른 개발·검토 역할이나 실행 절차를 재작성하지 않는다.

## 이번에 옮기지 않은 것

작업물이라는 대상 제한, 두 스킬의 고정 구분, 직접 호출 때의 브리핑 제목, 고정 Main·Maintain 기록 배치는 새 실행 계약으로 두지 않는다. 이전의 조사·검증 구별은 현재 질문에 필요한 자료와 공통 기준으로 사용하고, 옛 목차를 모두 재현하지 않는다. 글로벌 스킬·실제 제품·hook·자동 설치 설정은 수정하지 않는다.

공통 설명·근거 기준은 여러 consumer의 책임이므로 explain 안에 복제하지 않는다. explain을 나중에 교체하더라도 작업 결과·제품 계약·Work 갱신 책임은 각 Owner에 남고 호출 지점과 방법만 교체할 수 있어야 한다.

## 작성 기준과 확인 지위

`skill-creator`의 실질적 본체·조건부 상세·불필요한 제약 최소화와 prototype의 `SKILLS-CONTENT-POLICY`를 적용했다. `recall-document-guidance`를 통해 목적·조건·행동의 연결, 책임별 구성, 사람이 판단할 진입, 제거 가능성을 확인했다. 이 기준을 설명 실행마다 전부 읽는 절차로 추가하지 않았다.

이번 반영은 사용자가 요청한 prototype 생성·연결 정리다. 정적 구성 확인과 예시 출처 대조는 실제 사용자 이해·일반 효과·운영 설치를 증명하지 않는다. 새 응답 비교를 자동 실행하거나 이번 생성만으로04-02 전체 완료를 선언하지 않는다. 자세한 변경·검사 결과는 Workspace014 `records/2026-10-23-ticket04-02-explain-prototype-adoption.md`가 소유한다.

## 후속: 기존 폴더 삭제와 커밋 요청

사용자는 “그럼 기록할거 하고 기존 스킬은 삭제 하자 prototyped에서 그리고 커밋 하자”라고 요청했다. 기존 두 스킬 폴더와 임시 이전 안내를 삭제하고, 형성 자료와 직전 본문 사본을 `explain/_background/legacy/` 아래로 옮겼다. 역사적 선택을 재검토할 자료는 보존하되 독립 스킬 경로는 남기지 않는다. 관련 링크와 현재 안내를 새 보존 위치로 정리했다. 위 이전 안내를 남겼다는 설명은 삭제 요청 전의 경과다.

이번 커밋은04-02 설명 구성·검토·생성·삭제 및 이에 필요한 연결 변경을 대상으로 한다. 다른 대화의 개발 검토 설계 변경은 제외한다. 실제 응답 효과·운영 설치의 확인 범위는 늘리지 않았다.

# 체계 지침을 구별하게 된 맥락

이 자료는 [체계 지침의 역할과 구성](../../SYSTEM-GUIDANCE.md)을 만든 의도·배경·선택과 근거를 보존한다. 현재 체계 지침을 구성할 때는 그 본문을 읽고, 개념·진입 책임·표기나 적용 범위를 바꾸거나 왜 이렇게 정했는지 확인할 때 여기에서 필요한 자료를 고른다.

| 확인할 질문 | 읽을 범위 |
| --- | --- |
| 왜 일반 본문 구성과 별도로 체계 지침의 역할을 설명하나 | [현재 형성 맥락](context.md#지키려는-설명과-사용-관계) |
| 왜 개발 작업이나 운영 지침으로 범위를 고정하지 않았나 | [명칭과 범위의 선택 이유](context.md#이름보다-대상과-책임을-함께-설명한다), [정정 발화](evidence.md#명칭과-범위의-정정) |
| 진입 본문 유지와 상세 분할은 어떻게 함께 성립하나 | [구성과 진입의 맥락](context.md#내용의-성격과-진입-역할을-구별한다), [직접 요청](evidence.md#진입-본체와-분할에-관한-요청) |
| 어느 선택이 채택됐고 무엇은 미정인가 | [형성과 선택 기록](records/2026-10-20-role-and-entry.md) |
| DOCUMENT-WRITING을 어떤 근거로 사용했나 | [참고 예시와 확인 범위](evidence.md#문서-작성-지침의-참고-예시) |

여기에는 데모를 설계한 대화와 작성 판단이 담겨 있다. 제품의 사건이나 팀 운영 합의가 아니며, 이전 명명 후보를 현재 분류로 적용하지 않는다. 본문·형성 자료의 공통 관리는 [CONTENT-POLICY](../../CONTENT-POLICY.md)를 따른다.

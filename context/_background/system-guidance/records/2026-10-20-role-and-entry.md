# 체계 지침의 명칭과 독립 본문 선택

[현재 본문](../../../SYSTEM-GUIDANCE.md)이 어떤 구별을 이어받았는지 보존한다. 현재 적용 설명은 [형성 맥락](../context.md), 발화와 참고 예시는 [근거](../evidence.md)에 있다.

본문·형성 자료 구성을 넓히는 과정에서 기존 관리·절차 진입까지 새 폴더 안으로 이동했다. 사용자는 진입점이자 본체인 역할을 설명하며 먼저 구별할 개념을 논의하자고 했다. Work는 기존 체계와 혼합되지 않도록 원복한 상태에서 유지했다.

| 검토한 방향 | 남긴 의미와 채택하지 않은 한정 |
| --- | --- |
| 운영 지침 | 작성·사용·관리의 성격을 함께 부르려 했으나 새 세션이 같은 구별을 할지에 대한 우려가 남았다. 현재 공식 명칭으로 병행하지 않는다. |
| 컨텍스트 사용·관리 지침, 작업 체계 기준 | 예시의 공통점을 설명하려 했으나 컨텍스트나 개발 작업으로 범위를 좁혔다. 문서 체계도 다룰 수 있다는 정정을 반영한다. |
| 대표 기준문서 | 지정된 이름에서 기준을 직접 읽는 책임은 유용하다. 다만 일반 이름 기준도 대표 본문이 될 수 있어 내용의 성격을 대신하는 범주로 삼지 않는다. |
| 체계 진입 지침 | 진입 역할은 유지하되 모든 지침이 입구일 필요는 없다. 상세로 나눈 체계 지침도 실질 기준을 소유한다. |
| 체계 지침 | 사용자가 명칭을 선택하고 독립 문서 작성을 요청했다. 개발에 한정하지 않은 정의와 실제 담당 역할을 함께 설명한다. |

새 본문은 CONTENT-POLICY와 나란히 두어 체계 지침의 구별·진입·분할·표기를 소유하고, CONTENT-POLICY는 본문과 형성 자료의 구성·보존·갱신을 계속 소유한다. 파일명과 형성 자료의 구체 배치는 작성자의 구현 선택이다.

대문자는 대표 문서를 발견하기 위한 기본 표기로 반영했다. 소문자 상세를 제외하거나 기존 파일을 일괄 개명하지 않는다. 진입 본문의 실질 내용을 유지하는 것과 세부 내용을 나누는 것은 함께 가능하다.

이번 반영은 현재 문서를 추가·연결하는 범위다. Work의 기존 구성, 참고한 Reference 원본, 실제 제품 코드와 스킬은 바꾸지 않는다. DEVELOPMENT의 최종 위치·운영 책임, 기존 Project 진입의 재편과 장기 유지 효과는 확정하지 않았다.

# 독립 책임과 로컬 위치의 근거

[context 본문](../README.md)을 형성한 대화에서 필요한 발화를 선별했다. 아래는 설계 작성 기록이 보존한 사용자 원문이며 실제 제품 사건이나 팀 합의가 아니다. 바깥 기록을 읽지 않아도 핵심 정정을 이해할 수 있게 발췌를 함께 보존한다. 출처 식별은 추가 원문 확인을 위한 정보다.

## 독립 책임

시점: 2026-10-19. 출처: 설계 기록 `2026-10-19-84-personal-project-ownership-and-format-correction.md`, 「사용자 요청」. 당시 시안은 Project가 Personal 원문을 직접 참조하고 적용·갱신 관계까지 소유했다.

> 음 개인 내용을 굳이 저 noline project context에서 알아야할까? 개는 담당 문서를 독립적으로 담당해야한다고 생각하거든?그걸 연결하는건 워크플로든 아니면 스킬이든 더 구체화 해야겠지만 어쨋든 애매하게 링크되어 있어 마치 너무 대강 데모를 가정하고 만드니까

이는 독립 내용 책임과 별도 실행 연결의 직접 근거다. 어떤 스킬·최종 운영 배치를 채택했다는 발화는 아니다. 당시 기록의 설명은 앞선 중앙 위치·직접 참조 전제를 대체한다고 명시하며, 그 전제가 처음부터 없었던 것으로 고치지 않았다.

## 로컬 context 위치

시점: 2026-10-19. 출처: 설계 기록 `2026-10-19-89-local-context-structure-correction.md`, 「직접 확인한 사용자 의도」. Main이 Personal까지 demo context 안에 둘지 확인한 뒤의 답이다.

> 당연히 context안에 둬야지 아까 로컬은 니가 글로벌로 personal로 두려고 하니까 ai-workspace 쪽에 두라고 한거고 정확히는 context안에 둬야 할꺼아냐

위치는 로컬 context 층으로 정정됐다. 기록은 Noline 당시 구조를 직접 대조했다고 보고하지만 이번 형성 자료 작성은 그 보존 기록·원자료를 읽은 것이며 실제 Noline을 다시 조사하지 않았다. Personal은 사용자 정정에 따른 데모 추가 층이다.

## 후속 갱신 책임

같은 날 개인 코드 기준 보완이 Project 가이드까지 바꾼 이유를 사용자가 재확인했다. 이 근거는 이미 [개인 기준의 소유 발췌](../personal/development/naming-and-completion/_background/evidence.md#개인-기준의-소유)에 보존돼 있어 다시 복제하지 않는다. 그 발췌는 직접 발화와 Main 정리, 이전 답변·변경 전체를 회수하지 못한 한계를 구별한다.

## 확인 범위

위 출처는 이 저장소 `context/workspaces/014-ai-development-workflow-design/records/`에 보존된 작성 기록이다. 2026-10-20 구성 작업에서 해당 원문을 대조해 발췌했다. 기록이 보존하지 않은 이전 전체 제안·정확한 수락 범위를 새로 확정하지 않는다. 본 자료와 이를 재구성한 맥락·기록은 독립된 세 증거가 아니다.

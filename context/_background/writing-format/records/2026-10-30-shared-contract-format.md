## 대표 조건을 대입한 확인

Main이 원본과 보완본을 직접 대조했다. 다음 다섯 경우에서 같은 판단을 찾았다.

- 기본 표시 형식은 공통으로 필요하지만 일부 화면만 다르다: 기본 구성을 제공하면서 직접 조합 경로를 함께 둘 수 있다.
- 재사용은 적지만 공통 형식의 필요는 남아 있다: 재사용 횟수만으로 제거를 결정하지 않는다.
- HTTP 실패 상태를 받은 뒤 본문 읽기가 실패한다: 이미 받은 상태를 잃지 않아야 한다.
- 비동기 결과를 기다리도록 바꿨지만 catch가 모든 오류를 연결 실패로 바꾼다: 대기 추가만으로 오류 의미가 보존된 것은 아니다.
- 호출자가 공통 오류를 받아야 하지만 화면별 후처리는 다르다: 오류 전달의 일관성과 UI 정책 통일을 별도 선택으로 판단한다.

독립 AI 세션의 판단 동등성·새 형식의 일반 효과·실제 제품 동작 시험은 아니다. 표시 사본과 링크 검사 결과는 적용 작업 기록에서 구별하며, Work·Maintain 통합 확인을 대신하지 않는다.

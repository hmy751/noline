# 독립 책임을 유지하고 로컬 위치를 바로잡은 과정

[context 본문](../../README.md)의 책임·위치가 형성된 2026-10-19의 정정을 2026-10-20에 선별 재구성한 기록이다. 데모 구성 논의이며 제품에서 발생한 인증 사건이 아니다. [원문 발췌](../evidence.md)가 출처와 확인 한계를 소유한다.

초기 제안은 개인 기준을 별도 작업대의 중앙 정본으로 두고 Project가 그것을 참조하는 방식이었다. 앞선 기록에는 그 방향을 설계 전제로 삼았다고 실제로 적혀 있었다. 따라서 최신 정정을 반영하면서 이전 전제를 처음부터 미정이었던 것으로 바꾸지 않았다. 다만 앞선 Main 제안 전체가 회수되지 않아 당시 사용자가 무엇까지 수락했는지는 독립적으로 확정하지 않았다.

사용자는 Project가 개인 내용을 알아야 하는지 물으며 독립적으로 담당 문서를 소유하고 연결은 워크플로·스킬에서 더 구체화하자고 했다. 현재 데모는 개인 판단과 제품 계약을 각각 설명하고 Main이 이번 Work의 입력으로 선택하는 구조로 바뀌었다. 필요 설명까지 모두 제거하거나 제품 가이드가 의미를 독자에게 조립시키도록 만드는 선택은 아니었다.

이후 Personal의 위치를 다시 확인하면서 사용자는 글로벌 분리보다 로컬 context 안의 관리 층을 의도했다고 밝혔다. 같은 demo의 context 아래 personal·project·work를 두고, 실제 Noline의 Project·Work 계층과 대조해 빠진 관리 문서와 Workspace 관계를 보완했다. 기존 prototype이 파일·동작 검사를 통과했다는 사실로 구조의 적절성을 대신했던 판단도 정정됐다.

같은 로컬 위치와 독립 책임은 함께 유지한다. 배포·동기화·스킬 연결과 최종 운영 위치를 새로 결정하거나, 예제 구성의 수정을 실제 Noline 설치·전체 기준 수락으로 처리하지 않는다. 책임 변경을 재검토할 때에는 어떤 내용이 왜 함께 갱신돼야 하는지부터 대조하며, 개인 변경에 따른 자동 Project 갱신 문제는 [후속 소유 기록](../../personal/development/naming-and-completion/_background/records/2026-10-19-personal-ownership.md)에서 이어 읽는다.

# 책임 분리를 길이·파일 수와 구별한 논의

[공통 관점](../../INDEX.md)의 책임·기존 도구 설명을 형성한 논의를 보존한다. 2026-10-13 작성 기록을 2026-10-20에 직접 읽어 재구성했다. 정확한 발화는 [책임 근거](../evidence.md#책임과-함께-읽을-맥락)와 [도구 근거](../evidence.md#기존-도구에-맡긴-책임)에 둔다.

초대의 출발 비교는 토스 예제와 Main의 변형이었다. 토스 예제는 동의창·전송을 버튼에 모았고, Main의 변형은 동의창 상세를 나누되 전송 순서를 페이지에 남겼다. 사용자는 페이지의 다른 책임과 초대 기능의 비중에 따라 다를 수 있다고 설명했다. [비교 입력과 발화](../evidence.md#초대-예제에서-비교한-책임-배치)는 외부 배치의 일괄 채택과 이 조건부 판단을 구별한다. 이 문단은 2026-10-20 누락 점검 뒤 당시 보존 기록을 다시 대조해 복원했다.

초대 기능과 Dialog를 비교하던 중 사용자는 책임 분리와 같은 책임의 맥락을 모으는 방향을 좋게 보았다. 페이지가 성장할 것으로 예상되면 별도 기능을 나눌 수 있고, 합성형 Dialog의 짧은 부품은 함께 파악하기 좋다고 답했다.

Main은 이를 길이·성장 중심으로 정리했다. 사용자는 역할·패턴상 나눌 페이지와 컴포넌트까지 짧다는 이유로 합칠까 우려하며, Dialog를 함께 보는 이유가 합성형의 구성과 부품을 파악하는 편의라고 정정했다. 이후 기록은 외부에 제공할 기능 단위, 내부 함수의 책임, 파일 배치를 서로 다른 결정으로 구별했다.

요청·진행 상태를 새 Hook으로 묶는 비교에서도 기존 React Query 등 도구가 맡은 책임이 빠졌다는 정정이 있었다. 복잡한 업무 흐름이 그 Hook을 포함할 가능성은 유지하면서, 새 단위의 책임을 이미 맡긴 일에서 출발해 판단하도록 보완했다.

당시에는 기준을 탐색하는 단계였다. 특정 파일 크기, 실제 재사용 횟수의 문턱, 모든 기능의 Hook 분리, 도구 일괄 도입은 선택하지 않았다. 실제 프로젝트의 주변 책임·도구 계약·사용 방식이 달라지면 그 조건으로 다시 판단한다. 이 기록은 실제 템플릿의 리팩터링이나 성능 개선 결과가 아니다.

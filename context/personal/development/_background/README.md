# 개발 공통 관점의 형성 자료

이 폴더는 [개발 판단의 공통 관점](../INDEX.md)을 만든 목적과 배경, 책임·조건·표현을 함께 보게 된 논의와 선택을 보존한다. 지금의 관점이 왜 남았는지 이해하고 의미를 바꾸거나 과거 선택을 다시 판단할 때 사용한다. 현재 적용할 관점과 주제 선택은 [개발 판단 안내](../README.md)에서 찾는다.

현재 이유를 설명하는 맥락, 당시 전환을 보존한 기록, 정확한 발화·관찰을 확인할 근거는 역할이 다르다. 아래 질문에 필요한 범위만 읽는다.

| 확인하려는 것 | 읽을 범위 |
| --- | --- |
| 토스 예제와 작성자 변형에서 각각 무엇을 참고했는가 | [비교 입력과 사용자 조건](evidence.md#초대-예제에서-비교한-책임-배치), [현재 책임 설명](context.md#책임을-파악하는-기준이-필요했던-이유) |
| 일반 기준·질문·사례 구성은 어떤 외부 참고를 조정했는가 | [구성의 이유](context.md#서로-다른-코드에서-같은-판단을-찾는다), [자료별 기여와 한계](evidence.md#일반-기준과-사례의-구성에-사용한-외부-비교) |
| 왜 파일 수나 코드 길이보다 책임과 사용처 지식을 먼저 보는가 | [형성 맥락](context.md#책임을-파악하는-기준이-필요했던-이유), [책임·도구 논의 기록](records/2026-10-13-responsibility-and-tools.md), 정확한 표현은 [근거](evidence.md#책임과-함께-읽을-맥락) |
| 기존 도구의 책임을 출발점에 넣은 이유는 무엇인가 | [현재 설명](context.md#이미-맡긴-책임에서-출발한다), [정정 근거](evidence.md#기존-도구에-맡긴-책임) |
| 왜 사례와 일반 기준을 함께 두며 주제별로 고르는가 | [구성 이유](context.md#서로-다른-코드에서-같은-판단을-찾는다), [주제 복원 기록](records/2026-10-19-topic-restoration.md), [일반 기준·질문 근거](evidence.md#일반-기준과-판단-질문) |
| 기준을 채택한 뒤에도 적용 조건을 판단하는가 | [공통 맥락의 연결](context.md#조건별-적용과-코드-명료함의-범위), 이미 보존한 [조건별 적용 기록](../naming-and-completion/_background/records/2026-10-18-conditional-application.md) |
| 코드 자체의 명료함과 설명의 관계는 무엇인가 | [현재 연결 설명](context.md#조건별-적용과-코드-명료함의-범위), 기존 [명료함 기록](../naming-and-completion/_background/records/2026-10-19-clarity-and-renaming.md#사용할-수-있는-코드와-지향하는-코드를-구별함) |
| 이번 자료로 확인하지 못한 것은 무엇인가 | [확인 범위와 열린 판단](context.md#확인-범위와-열린-판단) |

과거 발화에는 탐색 중 선호와 미선택 대안이 포함된다. 당시 문장을 모든 코드의 의무로 적용하지 않으며 현재 판단은 본문이 소유한다. 이미 이름 기준의 형성 자료에 보존한 공통 논의는 해당 자료를 연결하고 발췌를 다시 복제하지 않았다. 각 주제만의 선택과 원문은 해당 주제의 형성 자료가 맡는다.

이번 자료는 2026-10-20에 접근 가능한 작성 기록을 직접 읽어 구성했다. 실제 제품 사건의 회고나 장기 운영 효과 보고가 아니다. 구성·보존·갱신은 [공통 관리 원칙](../../../CONTENT-POLICY.md)을 따른다.

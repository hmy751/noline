# 디자인 시스템 판단의 형성 자료

이 폴더는 [UI 결정을 맡을 책임에 두고 쌓는다](../INDEX.md)와 영역별 본문을 만들게 된 목적·배경, 문제 정의와 구성을 바꾼 논의·선택, 필요한 원문을 보존한다. 현재 내용이 왜 남았는지 이해하고 수정·재검토할 때 사용한다. 현재 적용할 기준과 사례는 [주제 안내](../README.md)에서 찾는다.

| 확인하려는 것 | 읽을 범위 |
| --- | --- |
| 왜 absolute 금지가 아니라 결정의 자리를 묻는가 | [형성 맥락](context.md#덧대기를-줄이는-쌓는-방법이-필요했다), [정정 기록](records/2026-11-04-problem-and-evidence.md#수집-뒤-증상-판정을-철회함), 정확한 표현은 [발화](evidence.md#문제-정의의-정정) |
| 왜 계속 가져간 구조를 근거로 우선하는가 | [근거 선택 이유](context.md#계속-가져간-구조를-가장-강한-근거로-삼았다), [정정 발화](evidence.md#근거-기준의-정정) |
| 책임 지도는 왜 계단이 아니며 template은 어떤 근거인가 | [현재 설명](context.md#책임-지도는-template을-읽고-계단에서-바꿨다), [template 발화](evidence.md#template-활용), [코드 관찰](evidence.md#코드-관찰) |

| 왜 파일을 나눴고 폴더로 나누지 않았는가 | [현재 설명](context.md#영역별-본문으로-나눈-이유), [검토한 대안](records/2026-11-05-baseline-and-structure.md#1차-초안에서-영역별-본문으로) |

현재 이유는 context, 당시 대안·정정·유보는 records, 발화·관찰은 evidence에서 확인한다. 기록에는 철회한 판단과 미채택 제안도 포함되며, 현재 적용할 내용은 본문에서 찾는다. 책임·조건별 적용의 공통 배경은 [개발 공통 형성 자료](../../_background/README.md)에 있다.

자료는 2026-11-05~06에 접근 가능한 작성 대화와 수집 기록, 세션 로그를 대조해 구성했다. 이전 팀 프로젝트의 코드와 비공개 개인 자료는 공개 저장소에 옮기지 않아 이 폴더만으로 다시 대조할 수 없다. 실제 제품 효과를 확인한 자료가 아니다. [공통 관리 원칙](../../../../CONTENT-POLICY.md)에 따라 필요한 관계를 함께 갱신한다.

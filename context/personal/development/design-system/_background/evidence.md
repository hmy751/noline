## 합성과 과한 구조

합성을 선호하는 발화는 [개발 공통 근거](../../_background/evidence.md)에 있어 다시 옮기지 않는다.

개인 웹 프로젝트의 AI 대화에서 Context 기반 Root·Boundary 합성을 제안받은 뒤의 **사용자 원문**이다. 파일 안의 오타도 보존했다.

| 1차 (작업당 1회) | 초안, 선택 표 한 줄 | 목록 없음, 폼 일부, 메뉴 읽음 | 목록은 초안을 읽지 않고도 나아졌다. 같은 Field 지침을 읽은 두 목록 세션 중 한쪽만 부품을 썼다. 메뉴는 공통을 고쳤고 사례가 같은 앱의 코드를 담는다. |
| 2차 (목록·폼 2회, 메뉴 1회) | 초안, 선택 표 한 줄, 구현 상세의 두 문장 | 문장이 보인 3개는 읽음, 출력이 잘린 2개는 안 읽음 | 5개 모두 앱 토큰과 공통 입력을 썼다. 읽은 목록만 Field와 헤더를 썼고 hex가 없었다. 폼은 읽은 쪽과 안 읽은 쪽이 거의 같았다. 읽고도 공통 헤더에 미리보기용 옵션을 더한 세션과 공통 메뉴의 결함을 우회하고 말하지 않은 세션이 있었다. |

본문의 효과를 입증한 자료가 아니다.

## 본문 판단별 근거

본문의 "표시 없는 규칙"을 채택 검토하기 위한 지도다. 근거 종류의 **구조**는 프로젝트를 건너 이어진 구조, **고침**은 사용자 계정의 수정 이력, **발화**는 사용자 말, **비공개**는 공개 저장소에 옮기지 않은 자료, **설명**은 작성 주체가 불명확한 코드, **해석**은 작성자의 일반화다.

| 본문 | 판단 | 근거 종류 | 채택 검토에서 볼 점 |
| --- | --- | --- | --- |
| 시작 | 기존 체계를 먼저 찾는다 | 기준선, 해석 | 시험 결과에서 올린 규칙이다. 재측정으로 효과를 입증하지는 못했다. |
| 시작 | 옆 화면을 선례로 단정하지 않는다 | 발화, 고침(비공개 포함), 해석 | "그냥 놓친거지 개발하다가"는 한 앱의 입력칸 장면이다. 세 상황의 표는 작성자의 정리이고 사용자가 넣기로 했다. |
| 시작 | 공통 부품 변경의 이유와 순서 | 발화, 고침(비공개 포함), 기준선, 해석 | 답을 고정하지 않는 것, 이유 없는 공통화가 문제인 것, 작업량이 이유가 아닌 것은 발화다. 표의 항목과 묻는 기준의 문장은 작성자의 정리다. |
| 배치 | 부모가 간격을 정한다 | 구조, 고침(비공개 포함), 외부, 발화 | 사용자가 "맞아 레이아웃 관리 관점으로"라고 확인했다. |
| 배치 | 보장을 담은 단위는 쓰고 편의 단위는 미정 | 해석, 발화 | 나눔은 작성자의 정리다. 사용자는 모바일 경험이 적어 편의 단위의 필수 여부를 정하지 않았다. |
| 배치 | 관계별 수단표 | 해석, 외부 | 작성자가 수집 전 만들고 RN을 더했다. |
| 배치 | 자리는 관련 요소를 모두 아는 쪽이 나눈다 | 발화, 고침(비공개 포함), 해석 | 부모 간격의 연장으로 작성자가 정리했고 사용자가 넣기로 했다. |
| 배치 | 위치 숫자의 원천을 모은다 | 설명, 해석 | 사용자가 위 판단과 함께 넣기로 했다. 구체 수단은 코드 관찰 위주다. |
| 배치 | 슬롯 | 고침(비공개), 설명, 해석 | 근거가 많지 않다. |
| 배치 | 화면 틀의 신호와 할 일 | 발화, 고침(비공개), 해석 | 해법은 미정이다. |
| 배치 | 화면 폭 대응 | 고침(비공개), 구조, 해석 | 기준값 하나와 CSS 우선은 작성자의 일반화다. |
| 값 | 값의 종류와 역할 | 구조, 해석 | 구조는 강하고 세 종류 구분은 작성자의 정리다. |
| 값 | 틀린 토큰을 쓴 사람이 확인 | 구조, 기준선 | 공백은 반복됐고, 처방은 작성자의 일반화다. |
| 부품 | 독립 축으로 나눈다 | 구조, 고침(비공개) | 강한 편이다. |
| 부품 | 스타일 확장 표 | 구조, 해석 | 혼재는 사실이고, 맞는 경우의 표는 작성자의 정리다. |
| 부품 | 값과 열림의 소유 | 고침(비공개), 설명, 해석, 발화 | "알아야 하는 쪽"은 작성자의 정리다. 둘 다 지원하는 이유와 레퍼런스를 보는 것은 발화다. |
| 부품 | 합성의 조건 표 | 발화, 구조, 해석 | 선호는 발화, 조건 표는 작성자의 정리다. |
| 부품 | 공통으로 올리기 | 고침(비공개), 해석 | 일반 판단은 `shared-boundaries`와 경계를 본다. |
| 폼 | 세 책임 | 구조, 고침(비공개) | 강한 편이다. |
| 폼 | 오류 자리, 제출 표시 | 고침(비공개), 해석 | 고른 조건은 작성자의 정리다. 비활성 표시의 의도는 추정이다. |
| 폼 | 임시 값과 확정 값 | 설명, 기준선 | 사용자 판단으로 확인되지 않았다. |
| 표면 | z-index 전에 쌓임 구조 | 고침(비공개), 구조 | 복사 경로는 미확인이다. |
| 표면 | 보장을 적는다 | 고침, 해석 | 교체의 이유 기록이 없어 처방은 작성자의 일반화다. |
| 표면 | 선언형과 명령형 표 | 구조, 해석 | 경계 차이가 의도인지는 미확인이다. |
| 표면 | 겹친 상호작용 | 고침(비공개), 설명, 해석 | 근거 구현은 AI로 추정되는 것을 포함한다. |
| 상태 | `X.Loading`, 복구 범위 | 발화, 구조 | 강한 편이다. |
| 상태 | 새 안내 장치 | 발화, 해석 | 발화는 한 앱의 장면이며 조건은 작성자의 일반화다. |
| 검증 | 실제 화면 판단 | 발화 | 강한 편이다. |
| 검증 | 확인 조건 표 | 해석, 외부 | 작성자의 정리다. |
| 검증 | 테스트 범위 | 구조, 비공개 | 일부 말한 근거는 공개하지 않았다. |
| 경험 | 재작성과 도구 전환 | 고침(비공개), 발화 | 공통 재작성의 병행 이유는 사용자가 답했고 지금 신경 쓸 요소는 아니라고 했다. 나머지 전환은 이유 기록이 없어 사실만 적었다. |
| 표면 | 공통 부품과 store의 경계 | 고침(비공개), 해석 | 사용자가 정하지 않아 작성자가 기본값을 두었다. |
| 값 | 앱의 값을 지키고 새 값은 테마에 더한다 | 발화 | 사용자가 직접 말했다. |

# 해 본 범위와 정하지 않은 것을 구별해 말한다

**언제 쓰나:** 이 사용자의 UI 경험을 근거로 판단이나 설명을 할 때, 없는 기준을 말하려 할 때, 재작성이나 도구 전환을 검토할 때.

**핵심 규칙:** 표에 없는 기준을 사용자 기준처럼 말하지 않는다. 외부 권고를 쓸 때는 외부 권고라고 밝힌다. 해 본 범위는 정리에 사용한 자료에서 확인한 내용이며, 확인하지 못한 것이 곧 경험이 없다는 뜻은 아니다.

시작 본문은 [UI 결정을 맡을 책임에 두고 쌓는다](INDEX.md)다. 프로젝트 안에 AI가 쓴 코드와 동료 코드가 섞여 있어, 구현 전체를 사용자 단독 설계로 읽지 않는다.

## 계속 가져간 구조와 끊긴 구조

프로젝트를 건너 유지된 구조가 가장 강한 근거다. 복사 경로가 아니라 구조의 연속을 확인한 결과다.

| 구조 | 이어진 범위 | 달라지거나 끊긴 것 |
| --- | --- | --- |
| 토큰 | 개인 웹 프로젝트와 UI 템플릿의 변수 이름 집합이 같다. 모바일 앱은 역할 theme로 변형했다. | 값과 정의 형식은 일부 다르다 |
| Button의 축 | variant 4개, size 3개, `fullWidth`, `isLoading`이 이어졌다. 모바일 앱은 variant와 size를 유지했다. | 모바일 앱에서 `isLoading`과 `fullWidth`가 끊겼다 |
| Field 합성 | 이전 팀 프로젝트, UI 템플릿, 모바일 앱으로 합성 구조가 이어졌다. | 한 프로젝트는 단일 래퍼로 단순화했다 |
| Text, Toast | 개인 웹 프로젝트와 UI 템플릿의 구조가 같다. | 모바일 앱에서 끊겼다 |
| 위치 계산 분리 | 이전 팀 프로젝트와 UI 템플릿의 구조가 유사하다. | 모바일 앱은 호출부와 메뉴에 분산돼 있다 |

## 주제별 지위와 해 본 범위

| 주제 | 지위 | 해 본 범위 |
| --- | --- | --- |
| Headless 위임과 직접 구현 | 기준(보장을 적는다), 기본값 미정 | 라이브러리를 감싸 쓴 경우, 도입 후 직접 구현으로 바꾼 경우, 모바일에서 프리미티브로 바꾼 경우가 있다. Headless 라이브러리를 만들었다고 말할 수 없다. 교체 이유는 대부분 기록이 없다. |
| 접근성 | 목표 | UI 템플릿의 Dropdown·MultiSelect에 ARIA 일부와 Enter·Space가 있고 화살표 이동·포커스 복원은 코드에 없다. Dialog는 ESC와 바깥 클릭으로 닫으며 역할·포커스 관리는 코드에 없다. 모바일 앱에는 일부 항목에 역할과 이름이 있다. 지원 기술로 통과했는지는 확인하지 못했다. |
| Storybook | 역할 미정 | 웹에서 부품과 조합을 story로 작성했고 환경을 앱에 맞췄다. play 테스트, 시각 회귀, React Native 사용은 확인하지 못했다. |
| 배치 프리미티브 | 배치 책임을 단위로 빼는 것은 기준, 구체적 세트는 미정 | Grid는 story로 작성했고 제품 사용은 확인하지 못했다. 모바일 앱의 Stack·Container는 실제 화면에 쓰였다. |
| 화면 틀 | 문제는 기준, 해법 미정 | 여러 프로젝트에서 문제가 있었고 틀 컴포넌트로 해결한 적은 확인하지 못했다. 공용 Layout을 줄인 경험이 있다. |
| 합성과 데이터 배열 | 합성은 기준, 배열과의 경계 미정 | 반대 방향의 선택이 모두 있다. |
| 토큰 이름 체계와 기계 점검 | Project 결정 | 웹 CSS 변수와 모바일 theme의 역할 토큰을 썼다. 토큰 lint는 확인하지 못했다. |
| 빈 상태와 공통 오류 부품 | 미정 | 화면별로 만들어 왔다. |
| 재작성과 이전 | 미정 | 아래 절의 사실만 있다. |
| 다크 모드, 시각 회귀, 패키지 버저닝, 아토믹 디자인, 디자인 도구 연동 | 다루지 않음 | 이 문서의 판단으로 세울 근거를 찾지 못했다. |

## 재작성과 도구 전환은 사실만 적고 기준은 열어 둔다

왜 그렇게 했는지 기록이 대부분 없어 일반 기준으로 올리지 않는다. 이 영역을 다룰 때는 사용자에게 묻는다.

- **끝까지 옮기지 못한 경우:** 팀 프로젝트에서 공통 부품을 다시 만들었을 때 새것과 옛것이 함께 남았다. 서비스가 바쁜 상황에서 기존 공통이 이미 쓰이고 있어 한 번에 다 작업하기 어려웠기 때문이다. 옛 경로를 막는 장치가 없었고 `New`, `2` 같은 세대 이름이 쌓였다. 입력과 오버레이는 재작성 범위에 들어가지 못했다.
- **끝까지 간 경우:** 개인 프로젝트에서 스타일 라이브러리를 CSS Modules와 토큰으로 옮기는 일을 완료했다. 모바일 앱에서 Button을 Pressable로 바꾸는 일도 전체에 적용했다.
- **남은 것:** 재작성 뒤에 쓰지 않는 CSS와 의존성이 남은 적이 있다. 그 기간에는 옛 값도 함께 남아 혼동을 준다.
- **스타일 도구:** styled 계열, CSS Modules, 유틸리티 class를 프로젝트별로 써 왔다. 선택 이유를 일반화하지 않는다.
- **UI 패키지 분리:** 모노레포에 공통 UI 패키지를 두었고, 단독 빌드는 시도 후 같은 날 되돌렸다. 패키지 추상화는 실제 필요한 범위로 줄인 적이 있다.
- **토큰 시각화:** 토큰을 Storybook에 보여 주려는 시도 흔적이 있으나 정착하지 않았다.

새 재작성을 제안할 때는 무엇을 언제 끝낼지와 옛 경로를 어떻게 다룰지를 함께 묻는다. 이것을 기준으로 채택할지는 **미정**이다.

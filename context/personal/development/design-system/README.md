# 디자인 시스템 판단

프론트 구현에서 값·배치·부품·상호작용·조합·앱 연결을 쌓는 개인 판단을 다루는 주제다. 다른 주제보다 영역이 넓어 시작 본문과 영역별 본문으로 나눴다. 현재 적용할 기준과 조건별 사례는 모두 본문 층이다. 형성 자료는 본문을 만든 목적·배경·논의·선택과 필요한 원문을 보존하며, 현재 내용이 왜 남았는지 이해하거나 수정·재검토하는 데 사용한다.

현재 내용을 적용할 때는 [시작 본문](INDEX.md)에서 작업에 맞는 본문을 고른다. 전체를 읽을 필요는 없다. 의미·조건을 바꾸거나 규칙이 사용자 판단인지 일반화인지 확인할 때는 [형성 자료 안내](_background/README.md)에서 질문에 맞는 범위를 고른다.

| 본문 | 다루는 판단 |
| --- | --- |
| [시작 본문](INDEX.md) | 범위, 책임 지도, 기존 체계와 옆 화면, 공통 부품 변경, AI 작업의 어긋남 |
| [배치와 화면 틀](INDEX.layout.md) | 관계별 수단, 간격 소유, 자리와 위치 지식, 슬롯, 화면 틀, 긴 내용, 화면 폭 |
| [값과 토큰](INDEX.tokens.md) | 값의 종류, 역할의 뜻, 값의 원천, 틀린 토큰 |
| [부품 설계와 시스템 확장](INDEX.components.md) | 변형 축, 글자, 스타일 확장, 제어, 합성, 승격, 위치, 외부 UI |
| [폼과 입력](INDEX.forms.md) | 세 책임, 복합 입력행, 오류 자리, 임시 값, 제출 |
| [떠 있는 표면과 상호작용](INDEX.overlays.md) | 표면의 뜻, 겹침, 위치, 보장, 호출 방식, 터치와 입력 장치 |
| [상태 표현](INDEX.states.md) | 자리, `X.Loading`, 복구 범위, 조회 구별, 안내 장치 |
| [확인과 검증](INDEX.verification.md) | 화면 확인, 확인 조건, Storybook, 테스트, 시안 |
| [플랫폼 대입](INDEX.platforms.md) | 웹과 React Native의 수단 |
| [경험과 지위](INDEX.experience.md) | 이 주제에서 계속 가져간 구조, 주제별 지위, 재작성과 도구 전환. Personal의 협업 경험 모음과는 다르다 |
| [코드 사례](INDEX.cases.md) | 메뉴 위치, 제목과 액션, 위치 지식, 값 이중 소유, Button, Field |

공통화 범위와 폼 연결의 일반 판단은 [공통 제공과 사용처 선택](../shared-boundaries/INDEX.md)이 소유한다. 다른 판단이 필요하면 [개발 판단](../README.md)에서 관련 주제를 고른다. 주제의 구성·보존·갱신은 [공통 관리 원칙](../../../CONTENT-POLICY.md)을 따른다.

# 공통 제공과 사용처 선택

컴포넌트·Hook·업무 흐름에서 함께 보장할 동작과 사용처마다 남길 선택을 판단하는 주제다. 현재 적용할 기준과 조건별 사례를 같은 본문 층에 둔다. 형성 자료는 기준을 만든 목적·배경·논의·선택과 필요한 원문을 보존하며, 현재 내용이 왜 남았는지 이해하거나 수정·재검토하는 데 사용한다.

- 공통으로 맡길 범위, 부품 교체, 같은 업무 흐름의 관련 개선을 판단할 때는 [시작 본문](INDEX.md)을 읽는다.
- 기준만으로 선택 차이가 불분명하면 [사례 본문](INDEX.cases.md)에서 Field의 배치·입력 교체, Container의 오류 표시, 주문 후처리 중 관련 장면을 고른다. 사례는 현재 기준을 적용하기 위한 설명이며 과거 결정 기록이 아니다.

- Field의 분리 의도·입력 교체 질문, Container의 공통 형식, 업무 흐름과 관련 개선의 조건을 재검토할 때는 [형성 자료 안내](_background/README.md)에서 현재 이유·당시 선택·정확한 발췌 중 필요한 내용을 고른다.

형성 자료는 접근 가능한 작성 기록을 직접 대조해 보완했다. 실제 템플릿 원본이나 제품을 이번에 다시 실행한 것은 아니며, 사례의 가정과 기록에 보존된 의도·선택을 구별한다. 특정 연결 API·주문 Hook·Container 변경은 여전히 미선택이다.

다른 판단이 필요하면 [개발 판단](../README.md)에서 관련 주제를 고른다. 주제의 구성·보존·갱신은 [공통 관리 원칙](../../../CONTENT-POLICY.md)을 따른다.

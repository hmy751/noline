# 공통 제공과 사용처 선택의 형성 자료

이 폴더는 [공통 제공과 사용처 선택](../INDEX.md)을 만들게 된 목적·배경, 공통화의 이득과 자유도를 비교한 논의·선택, 필요한 원문을 보존한다. 현재 기준이 왜 남았는지 이해하고 수정·재검토할 때 사용한다. 현재 적용할 기준과 조건별 사례는 [주제 안내](../README.md)에서 찾는다.

| 확인하려는 것 | 읽을 범위 |
| --- | --- |
| Field의 연결 코드를 왜 미완성 공통화로 보지 않는가 | [형성 맥락](context.md#field와-container의-서로-다른-목적), [배치·교체 논의 기록](records/2026-10-14-composition-and-common-form.md), 직접 의도와 질문은 [Field 근거](evidence.md#field의-분리와-교체-질문) |
| 자유도가 더 큰 Hook이 있는데 Container를 유지할 이유는 무엇인가 | [목적의 차이](context.md#field와-container의-서로-다른-목적), [Container의 사용자 설명](evidence.md#container를-제공한-이유) |
| 같은 요청인데 공통 후처리를 다르게 묶는 이유는 무엇인가 | [업무 흐름 설명](context.md#요청이-같은지에서-업무가-같은지로), [주문·관련 개선 기록](records/2026-10-16-workflow-and-related-improvement.md), [주문 근거](evidence.md#같은-api와-같은-업무-흐름) |
| 이번 수정에 구조 개선을 함께 넣을 수 있는가 | [보완한 판단](context.md#유지-판단에-관련-개선의-조건을-보완함), [당시 가정과 선택](records/2026-10-16-workflow-and-related-improvement.md#관련-공통화를-함께-할-조건), [사용자 응답](evidence.md#관련-개선과-제품-범위) |
| 특정 API나 패턴까지 선택한 것인가 | [열린 선택과 확인 한계](context.md#열린-선택과-확인-한계) |

현재 이유는 context, 당시 대안·정정·유보는 records, 발화·관찰은 evidence에서 확인한다. 기록에는 미선택 대안도 포함되며 현재 요구로 자동 적용하지 않는다. 책임·조건별 적용·주제 구성의 공통 배경은 [개발 공통 형성 자료](../../_background/README.md)에 연결한다.

자료는 2026-10-20에 접근 가능한 작성 기록을 직접 읽어 구성했다. 외부 템플릿의 현재 코드나 제품 효과를 새로 확인한 것은 아니다. [공통 관리 원칙](../../../../CONTENT-POLICY.md)에 따라 필요한 관계를 함께 갱신한다.

# 계약과 수명

공통 입력·반환·오류의 의미, 상태·타이머·이벤트의 수명, 지원 범위 안의 정확성을 판단하는 주제다. 현재 적용할 기준과 조건별 사례가 본문을 이룬다. 형성 자료는 기준을 만든 목적·배경·논의·선택과 필요한 원문을 보존하며, 현재 내용이 왜 남았는지 이해하거나 수정·재검토하는 데 사용한다.

- 공개한 계약을 믿고 호출할 수 있는지, 책임을 옮기면 시간·실패·종료 의미가 달라지는지 판단할 때는 [시작 본문](INDEX.md)을 읽는다.
- 같은 타입이나 호출 모양인데 선택이 달라지는 이유가 필요하면 [사례 본문](INDEX.cases.md)에서 fetcher·silent·Toast·이벤트 Hook 중 관련 장면을 고른다. 현재 판단을 위한 조건별 비교이며 실행 완료 기록이 아니다.

- 오류의 형태·의미를 믿어야 하는 이유, 타이머 위치를 고르는 조건, 지원 범위와 정확성의 구별을 재검토할 때는 [형성 자료 안내](_background/README.md)에서 현재 이유·당시 선택·정확한 발췌 중 필요한 내용을 고른다.

형성 자료는 접근 가능한 작성 기록을 직접 읽어 보완했다. 당시 코드 분석과 가정한 리뷰, 사용자의 직접 동의와 불확실한 회고를 구별한다. 원래 구현을 이번에 실행하거나 현재 상태를 확인한 것은 아니며, 타이머 이전·null 정책·새 지원 범위는 여전히 미선택이다.

표현과 동작 중 무엇을 고칠지 함께 판단해야 하면 [이름·책임·완료](../naming-and-completion/INDEX.md)를 읽는다. 주제의 구성·보존·갱신은 [공통 관리 원칙](../../../CONTENT-POLICY.md)을 따른다.

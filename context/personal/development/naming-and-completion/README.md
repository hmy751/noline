# 이름·책임·완료 범위

함수·Hook·상태·반환·완료 알림이 맡은 일과 끝난 일을 드러내게 하는 개인 기준이다. **본문은 현재 적용할 판단과 조건을 설명하고, 형성 자료는 그 판단을 만들게 된 의도·배경·논의·선택과 근거를 보존한다.** 형성 자료는 현재 방향을 더 정확히 이해하거나 고칠 때 사용한다.

현재 코드에 적용할 때는 [시작 본문](INDEX.md)을 읽는다. 유지·설명 보완·개명·동작 수정이 갈리는 이유가 더 필요하면 [사례 본문](INDEX.cases.md)에서 같은 인증 코드의 이름 비교, 저장 완료 요구, 문자열 `isError` 중 관련 장면을 고른다. 사례도 본문이며 형성 이력으로 읽지 않는다.

기준을 만든 의도를 확인하거나 의미·우선순위·적용 조건을 바꿀 때, 또는 과거 선택을 다시 검토할 때는 [형성 자료 안내](_background/README.md)에서 질문에 맞는 현재 맥락·당시 기록·근거를 고른다. 이 자료는 개인 개발 기준을 작성한 논의이며 Noline 제품 사건이나 팀의 합의가 아니다.

현재 표현은 확인한 사용자 방향을 구체화한 시안이다. 모든 문장·사례의 충분성이나 특정 이름의 최종 채택까지 확인된 것으로 보지 않는다. 구성·보존·갱신의 공통 원칙은 [CONTENT-POLICY](../../../CONTENT-POLICY.md)가, 다른 개발 판단의 선택은 [상위 안내](../README.md)가 맡는다.

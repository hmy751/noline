# 이름·완료 기준의 형성 자료

이 폴더는 [이름·책임·완료 본문](../INDEX.md)을 만들게 된 의도·배경·목적, 중요한 논의와 선택, 필요한 원문을 보존한다. 현재 내용이 왜 이렇게 구성됐는지 복원하고 더 정확히 이해하거나 수정·재검토할 때 사용한다. 현재 적용할 기준과 조건별 사례는 [주제 안내](../README.md)에서 찾는다.

현재 이유를 설명하는 맥락, 당시 선택을 보존한 기록, 그 설명을 확인할 근거는 서로 다른 자료다. 필요한 질문에서 시작해 아래 범위만 읽는다.

| 확인하려는 것 | 읽을 범위 |
| --- | --- |
| 이름 규칙보다 코드의 역할·완료 이해를 먼저 다루는 이유 | [현재 형성 맥락의 목적](context.md#무엇을-이루려는가), 출발 발화가 필요하면 [목적 근거](evidence.md#목적) |
| 설명으로 쓸 수 있는 코드를 왜 더 명료하게 만들려 하는가 | [현재 방향](context.md#코드가-의미를-드러내는-방향), 당시 해설의 보완은 [명료함 기록](records/2026-10-19-clarity-and-renaming.md#사용할-수-있는-코드와-지향하는-코드를-구별함), 직접 발화는 [해당 근거](evidence.md#코드가-드러내는-의미) |
| 코드 명료함을 지향하면서 문자열 isError를 유지한 판단도 남는가 | [이득·비용과 두 판단의 관계](context.md#이득과-비용을-나누어-판단하는-이유), [유지 기록](records/2026-10-16-iserror-retention.md), [직접 근거](evidence.md#문자열-iserror의-유지-판단) |
| 내부 두 사용처를 바꿀 수 있다는 사실만으로 개명해도 되는가 | [이득과 비용의 현재 설명](context.md#이득과-비용을-나누어-판단하는-이유), 이전 문장의 정정은 [비용 판단 기록](records/2026-10-19-clarity-and-renaming.md#개명-가능성과-개선-이득을-나눔), 실제 문구는 [비교표 근거](evidence.md#개선의-이득과-비용) |
| 기준을 채택한 뒤에도 유지·수정·보류를 판단하는가 | [조건별 적용의 현재 설명](context.md#조건별-적용과-내용의-소유), 혼동과 확인 과정은 [적용 방식 기록](records/2026-10-18-conditional-application.md), 확인한 발화 범위는 [조건별 적용 근거](evidence.md#조건별-적용) |
| 개인 기준이 바뀌면 Project도 함께 바꿔야 하는가 | [현재 책임 관계](context.md#조건별-적용과-내용의-소유), 이전 반영을 다시 본 이유는 [소유 관계 기록](records/2026-10-19-personal-ownership.md), 사용자 정정과 Main의 해석은 [소유 근거](evidence.md#개인-기준의-소유) |
| 지금까지 확인한 방향과 아직 확정하지 않은 것은 무엇인가 | [열린 판단과 확인 한계](context.md#확인한-방향과-열린-판단) |

과거 기록과 발췌에는 현재와 다른 설명이나 채택하지 않은 확대 해석도 포함된다. 당시 표현을 현재 요구로 적용하지 않으며, 현재 기준은 본문에서 읽는다. 자료를 이미 찾았다면 이 안내를 다시 거칠 필요는 없다.

이 묶음은 기존 데모의 형성 맥락과 근거 발췌에서 재구성했다. 최초 재구성에서는 바깥 작업의 전체 대화나 원기록을 새로 열람하지 않았다. 이후 누락 보완에서 문자열 `isError`의 작성 기록을 직접 대조했으며 근거 항목에 그 범위를 밝혔다. 각 기록은 재구성 시점과 확인 범위를 밝히며 발췌의 원문은 [evidence](evidence.md)에 한 번만 보존한다. 자료의 구성·보존·갱신은 [공통 관리 원칙](../../../../CONTENT-POLICY.md)을 따른다.

# 코드 표현과 진단

**코드에서 흐름을 읽고, 주석에서 이유를 찾고, 로그에서 실패 맥락을 찾을 수 있게 한다.** 새 코드를 쓰거나 맡은 범위의 코드를 고칠 때 적용한다.

## 처리 목적이 보이게 문장을 묶는다

- **중괄호:** JS/TS의 블록 생략 가능한 조건문·반복문에도 쓴다. 짧은 guard도 같다.
- **빈 줄:** 관련 변수나 짧은 연속 처리는 묶되, 같은 목적이어도 선언·조건 검사·실행의 경계는 빈 줄로 구별한다.
- **기계적 형식:** 들여쓰기·따옴표 등은 Project의 formatter를 따른다.

아래는 입력 준비·조건 검사·요청·결과 반영을 구별한 예다. 관련 입력 변수는 붙여 쓴다.

```ts
const email = values.email.trim();
const password = values.password;

if (!email || !password) {
  return;
}

const result = await signIn(email, password);

applySession(result);
```

전체가 하나의 로그인 흐름이어도 각 구간을 띄울 수 있다. 같은 목적이라는 이유로 모두 붙이거나 모든 `await`·`return` 앞뒤를 자동으로 띄우지는 않는다. **없던 조기 반환을 추가하거나 실행 순서를 바꾸면 동작 변경**이므로, 해당 요구와 보존 조건을 따로 확인한다.

## 전체 동작과 필요한 상세를 연결한다

**맡긴 동작의 흐름을 먼저 읽고, 필요한 helper의 상세로 내려갈 수 있게 배치한다.**

| 읽다가 겪는 문제 | 살펴볼 것 |
| --- | --- |
| 세부 확인 때문에 같은 파일들을 반복해서 오간다. | 관련 코드의 배치와 이름을 함께 본다. |
| 전체 동작을 이해하려고 호출 순서를 다시 조립한다. | 흐름을 조율하는 책임과 helper의 관계가 드러나는지 본다. |
| 순서만 바꿔도 여전히 여러 역할이 뒤섞인다. | 배치뿐 아니라 책임 구분을 검토한다. |

고정 public/private 순서나 보기 좋은 배치를 위한 새 함수·파일 분리는 요구하지 않는다. 위치를 옮길 때도 언어·프레임워크의 선언·초기화 조건을 보존한다.

## 주석은 이유와 필요한 탐색을 돕는다

**이름·타입·책임·제어 흐름으로 드러낼 수 있는 의미는 코드에서 먼저 표현한다.** 그 뒤에도 필요한 설명을 남긴다.

| 주석이 하는 일 | 판단 |
| --- | --- |
| 인접 코드를 그대로 다시 읽어 준다. | **줄인다.** |
| 선택 이유·외부 제약·비자명한 계약을 설명한다. | **남긴다.** |
| 관련 처리 구간을 빠르게 찾게 한다. | **탐색에 필요하면 둔다.** |
| 불명확한 역할을 매번 장황하게 해설한다. | **코드의 이름·구성·흐름부터 개선할 여지를 본다.** |
| “항상 최신”, “모두 완료”처럼 실제보다 큰 보장을 약속한다. | **실제 계약과 맞춘다.** |

긴 장식 구분선은 간소화한다. 요약·예시·단계 번호라는 형식만으로 삭제하지 않으며, 모든 줄에 단계별 해설을 붙이지 않는다.

## 실패 처리와 진단 정보를 따로 판단한다

**실패를 어떻게 처리할지 정한 뒤, 그 처리로 남지 않는 진단 정보가 필요한지 본다.**

| 판단할 것 | 확인할 내용 |
| --- | --- |
| **실패 처리** | 복구·호출자 전파·사용자 안내 중 무엇이 필요한가? |
| **추가 진단** | 처리만으로 남지 않는 사건·실패 단계·작업 맥락이 있는가? |
| **중복 출력** | 한곳에 모아도 필요한 맥락과 작업 간 연결이 남는가? |
| **기록 표현** | 실제로 관찰한 사건·값·완료 범위만 말하는가? |

- **복구에 성공해도** 반복 원인을 조사하려면 로그가 필요할 수 있다.
- **예외를 전파해도** 모든 층에 로그를 남길 필요는 없다.
- **로그를 남겨도** 필요한 반환·예외 전달·사용자 안내를 대신하지 못한다.

진단에 쓰이지 않는 정상 진행 출력과 같은 오류의 중복 출력을 줄인다. console 전면 금지·새 logger 도입·매 catch의 로그 추가를 이 기준만으로 요구하지 않는다. 수집 방법·필수 정보·민감 정보 보호는 Project 계약을 따른다.

## 함께 적용할 기준

현재 Project의 언어·표현 규약과 도구 설정을 함께 적용한다. 개인 기준과 충돌하면 [적용 책임](../../README.md#이번-제품에-적용할-때)에 따라 차이와 영향을 드러내고 이번 작업의 권한 안에서 선택한다.

- 이름·타입·상수의 의미·완료 범위: [이름과 완료](../naming-and-completion/INDEX.md)
- 오류의 뜻·자원 수명·catch와 비대기 실패 책임: [계약과 수명](../contracts-and-lifetime/INDEX.md)
- 이 기준의 구성·형성 이유·근거: [주제 안내](README.md)

변경 수행과 동작 확인은 기존 개발 흐름이 맡는다. 이 본문을 읽었다는 이유로 관련 없는 기존 코드 전체를 정리하지 않는다.

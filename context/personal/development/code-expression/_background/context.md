# 표현과 진단을 개인 기준으로 이어받은 이유

[코드 표현 본문](../INDEX.md)의 목적과 구성 선택을 설명한다. 기존 제품 가이드의 일반 판단을 이어받되, 제품 사실이나 도구 설정까지 개인 기준으로 만들지 않으려는 구체화다.

## 출처가 있던 곳과 적용할 범위를 나눔

기존 Noline 코드 표현 가이드에는 중괄호·개행·주석·진단처럼 다른 제품에도 가져갈 판단과 인증·네트워크·지도 삭제처럼 제품 계약을 알아야 판단할 내용이 함께 있었다. 사용자는 중괄호와 통화를 예로 들어 개인 기준과 프로젝트 기준을 구별하자고 제안했다. [당시 발화와 보존 가이드](evidence.md#개인-기준과-제품-기준의-구별)를 대조해, 어디에서 나온 규칙인지와 어디에 적용할 판단인지를 구별했다.

이 본문은 읽는 흐름·설명·진단의 일반 판단을 개인 기준으로 구성한다. 실제 제품의 실패 의미·완료 약속·logger 설정·민감 정보 정책은 Project에서 확인한다. 기존 제품 문서를 자동으로 삭제하거나 모든 저장소에 이 기준을 배포하는 결정은 아니다.

## 이름과 계약의 질문을 유지하며 표현을 보완함

이름·완료 본문에 전부 합치는 대안도 검토했다. 그러나 완료 시점이나 역할을 판단하려는 독자에게 개행·주석·로그 상세까지 함께 읽게 하기보다, 읽기 흐름과 보조 정보의 질문을 별도 주제로 두었다. 기존 구현·검토 흐름에서 필요한 Personal을 고를 수 있으므로 별도 스킬이나 검토 관문은 만들지 않았다. 이 배치는 작성자가 구체화한 제안이며 [prototype 적용 요청](evidence.md#프로토타입-적용-요청)에 따라 반영했다.

값이 같은 상수의 의미·변경 이유는 이름·완료가, catch의 실패 분류 범위와 비대기 작업의 실패 책임은 계약·수명이 맡는다. 주석 상세와 진단 필요성은 이 주제가 맡는다. 같은 비동기 규칙을 여러 본문에 복제하지 않고 각 판단의 위치에서 연결했다.

코드 자체의 명료함을 지향한다는 [기존 발화](../../naming-and-completion/_background/evidence.md#코드가-드러내는-의미)는 유지한다. 이유·외부 제약·탐색 안내까지 모두 없애라는 뜻으로 해석하지 않았다. 중괄호는 보존 가이드의 언어 맥락에 맞게 JS/TS의 블록 생략 가능한 제어문으로 한정했고, 로그는 실패 처리와 추가 진단의 질문을 구별했다. 구체화에 사용한 [원문과 해석의 범위](evidence.md#보존-가이드에서-이어받은-판단)를 확인할 수 있다.

## 적용과 효과 확인의 경계

이번 반영은 prototype의 현재 본문·형성 자료·진입을 갖추는 작업이다. 형식만 통일하려고 await·조기 반환을 바꾸면 동작이 달라질 수 있으므로 표현 판단과 실제 계약을 함께 보도록 했다. 기존 코드의 일괄 정리나 도구 변경은 포함하지 않는다.

새 독자가 이 구성을 더 쉽게 사용했는지, 실제 코드의 읽기·변경 비용이 줄었는지는 아직 확인하지 않았다. 여러 작업에서 이름·완료와 이 주제를 항상 함께 읽어야 하거나 같은 내용을 중복 관리한다면 구성을 다시 비교할 수 있다. 상수·catch·void의 보완도 실제 제품의 특정 결함을 확인했다는 뜻은 아니다.

## 핵심 판단을 먼저 찾도록 본문을 재구성함

첫 반영 뒤 사용자가 서술적인 본문이 눈에 잘 들어오지 않는다고 지적했다. 이에 현재 본문은 각 절의 핵심을 먼저 드러내고, 주석 역할·실패 진단처럼 선택을 비교할 부분은 표로, 중괄호·개행은 같은 동작의 전후 코드로 구성했다. 조건과 제약을 삭제해 단정적인 규칙으로 바꾸지는 않았다. [직접 피드백](evidence.md#본문-읽기에-대한-피드백)이 이번 구성 변경의 근거이며 사용자는 이후 더 보기 좋다고 평가했다. 실제 개발에서 반복해서 사용하는 효과는 아직 확인하지 않았다.

## 같은 목적과 붙여 읽을 단위를 구별함

첫 빈 줄 문안은 같은 조건·결과를 만드는 코드를 붙이도록 설명했다. 사용자는 유사한 변수 선언을 묶는 것은 자연스럽지만 같은 목적의 코드도 띄우는 편이 낫다고 짚었다. 이에 붙여 읽을 작은 묶음과 선언·조건 검사·실행의 구간을 구별하도록 문안과 예시를 바꿨다. Airbnb의 블록 뒤 간격과 변수 묶음 기준을 비교했으며, 현재 개인 기준과 외부 가이드의 명시 규칙은 [발화·비교 근거](evidence.md#빈-줄-기준을-구체화한-선택)에 구별했다. 이전의 같은 목적이라는 조건만으로 넓은 구간을 붙이라는 뜻으로 적용하지 않는다.

# 012 — SDK 업그레이드를 이어갈 때

2026-11-17 버전 설정을 전수 조사했고, 서버 Node를 범위에 넣었다. 대상 SDK 58, 핫픽스는 `release/1.1`, 최소 iOS 16.4는 정했다. 출시는 2번(1.2.0 = SDK 54 + New Architecture, 1.3.0 = SDK 58·iOS 27)이고, Ticket 5개로 확정해 문서를 만들었다. 구현 전에 기기 DB와 오프라인 지도가 남는지 먼저 판정하고(02, DB가 남지 않으면 멈춤), SDK는 한 버전씩 올린다. 2026-11-18 Ticket 01을 시작해 기준선·`release/1.1`(원격, 빌드·OTA 확인)·Node 24 설정 변경(main 병합·push, Render가 Node 24.16.0으로 배포)·설치 절차(`pnpm exec expo install`)까지 했고, 운영 앱 확인까지 마쳤다. 1.1.4는 2026-11-17 출시됐고(2026-11-20 App Store 조회), 01의 남은 일은 실기기 점검표다. 운영 서버는 `render.yaml`이 아니라 Render 대시보드 설정과 `.nvmrc`로 배포된다. 02 판정도 마쳤다. 기기 DB와 오프라인 지도가 SDK 54·New Architecture·Mapbox v11 앱으로 덮어 설치한 뒤에도 남아, 03을 시작할 수 있고 04의 지도 대응은 빠졌다. 2026-11-18 03을 시작해 SDK 52·53·54를 작업 브랜치 `feat/012-sdk54`(worktree `.claude/worktrees/012-sdk54`)에 커밋했다. 2026-11-19까지 검사 장치·EAS preview·iPad 실기기 확인을 마치고 main에 병합해(`ae97809e`, 2026-11-19 push, Render 재배포 health 200) 03을 끝냈다. 2026-11-19 04(New Architecture와 1.2.0)의 코드 작업을 앞당겨 시작해 작업 브랜치 `feat/012-newarch`(worktree `.claude/worktrees/012-newarch`)에 커밋했다. 같은 날 iPad 실기기에서 1.1.4 위 덮어 설치와 비행기 모드를 확인했고, 거기서 찾은 일정 지도 차이(마커 번호·처음 위치)를 고쳐 `c5fdbbdc`로 커밋했다(함께 찾은 `createPack` 완료 시점 문제는 Work 008로 넘겨 012에서 고치지 않기로 했다). 2026-11-20 사용자의 "병합하고 push"로 `feat/012-newarch`를 main에 병합해(`6d34c44b`) push했다. 같은 날 사용자의 "쭉 다해줘"로 iPad에서 `OfflineMapView` 오프라인 화면과 첫 일정에 좌표가 없는 날을 확인했고, 병합된 012 worktree 2개(`012-sdk54`, `012-newarch`)와 브랜치 4개를 지웠다. 직전에 Project 출시 기준에 release 브랜치 OTA 절을 넣었다(`69bfa8eb`, push 안 함). 지금 남은 것은 Render에서 `6d34c44b` Live 확인(사용자), Ticket 01 점검표(iPad 1.1.4 preview 근거를 인정할지 사용자 결정, 남는 것은 운영 앱 Google·Apple 로그인과 iPhone의 1.1.4), Ticket 04의 iPhone·Android·Apple 로그인이며, main preview 빌드(EAS 11월 횟수 초과로 미룸)와 1.2.0 스토어 빌드·OTA는 멤버십(2026-12-18)·인증서(2026-12-30) 갱신 뒤다. main은 이제 SDK 54·New Architecture라 1.1.4 사용자에게 보낼 OTA·핫픽스는 `release/1.1`에서만 낸다(main push는 OTA 발행이 아니다). 03에서 넣은 fmt consteval 우회는 New Architecture에서 필요 없어져 지웠다. 버전이 어긋나면 앱이 깨지는 일이라 단계마다 원인을 가르고 확인할 수 있는 순서가 핵심이다. 마감이 있다는 점을 놓치지 않는다.

**먼저 읽는다.** 이 둘이 빠지면 마감·순서를 잘못 잡거나, 이미 고정한 버전을 실수로 되돌린다.

- [Ticket 색인](current/memory/tickets/index.md): 확정한 Ticket 5개와 선행·일정, 공통 규칙(설치 절차·검사 명령 포함), Spec 완료 기준을 맡는 Ticket. 진행 중인 [01](current/memory/tickets/01-preparation-baseline-and-node24.md)과 [04](current/memory/tickets/04-new-architecture-and-1-2-0.md)의 "현재 상태와 실제 결과"로 이어서 읽는다
- [제약·현재 설계·가정](current/memory/spec/05-constraints-design-assumptions.md): Apple 마감·핫픽스 빌드 보호·서버 배포·인증서 같은 제약과 일정, 버전의 현재와 이후 표, 진행 순서, 일부러 벗어난 버전과 실수로 섞인 버전의 구별

**첫 행동:** 작업 트리의 현재 브랜치와 main이 origin과 어떤지 먼저 확인한다(2026-11-20 기준 main이 문서 커밋 `a44f1993`·`69bfa8eb`와 그 뒤 기록 커밋만큼 앞서 있고 push하지 않았다. main push는 문서만이어도 Render 재배포다. 이 Work와 무관한 미커밋 수정도 같은 트리에 있다). 그다음 [현재 상태](current/state/index.md)의 다음 행동을 따른다. 남은 것은 대부분 사용자가 움직여야 한다. Render 대시보드에서 `6d34c44b` 배포가 Live인지(Main은 로그인 화면이라 못 봤다), [Ticket 01](current/memory/tickets/01-preparation-baseline-and-node24.md#현재-상태와-실제-결과) 점검표에서 iPad 1.1.4 preview 근거를 인정할지, iPhone을 연결해 운영 앱 로그인과 iPhone의 1.1.4·[Ticket 04](current/memory/tickets/04-new-architecture-and-1-2-0.md#현재-상태와-실제-결과)의 Apple 로그인을 볼지다. iPhone의 Noline Dev 자리에는 판정용 앱(빌드 91)이 그대로 있다. 1.1.4 OTA나 핫픽스가 필요하면 worktree `.claude/worktrees/012-release-1.1`(`release/1.1`)에서 낸다(방법은 Project 출시 기준의 release 브랜치 절). iPad를 다시 조작하려면 USB를 연결하고 DeviceKit 제어 서버를 다시 띄운다(명령은 현재 상태 끝). 12월 갱신 뒤 main preview 빌드와 1.2.0 빌드로 가기 전에는 Expo 최신 SDK와 Apple 요건도 다시 본다.

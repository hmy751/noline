- 구성: Expo SDK 54(expo 54.0.36 템플릿), RN 0.81.5, React 19.1.0, `newArchEnabled: true`, expo-sqlite ~16.0.10, @rnmapbox/maps 10.3.18(native Mapbox v11), expo-file-system(legacy). 번들 ID `com.noline.dev`, 같은 EAS 프로젝트·팀, 이름 "Noline (판정)", 1.1.4 / 빌드 90 → 91.

## 시뮬레이터 시도와 중단

판정용 앱 빌드를 기다리는 사이 사용자가 "이건 시뮬레이터로 안되나? 니가? 할수 있ㅇ면 니가 해"(1865행)라고 했다. Main은 시뮬레이터로 1.1.4를 빌드했는데, Release 빌드가 `.env.production`을 읽어 운영 번들 `com.ham.noline`(운영 서버를 보는 앱)으로 설치됐다(1961행). Main은 그 앱을 열지 않고 두었고, 개발 환경값으로 다시 빌드하기 시작했다(1973행). 이 앱은 시뮬레이터 안에 남아 있다.

다시 빌드하던 중 사용자가 "근데 이렇게 빌드하고 확인하는게 빨라? 아님 실제 기기로 테스트하는게 빨라?"(1978행)라고 물었다. Main은 실기기를 권했다(1982행). 이유는 셋이다.
- 실기기에는 1.1.4 preview가 이미 설치돼 있고 판정용 앱 빌드도 끝나 있다. 시뮬레이터는 빌드가 두 번 더 필요하다.
- 판정의 핵심인 "비행기 모드에서 옛 지도가 그려지는가"는 시뮬레이터에 비행기 모드가 없어 볼 수 없다. 시뮬레이터로 해도 실기기 확인이 한 번 더 필요하다.
- 시뮬레이터가 나은 점은 덮어 설치 전후 DB 파일을 Mac에서 직접 비교할 수 있다는 것뿐이다.

사용자는 "그럼 중지하고 하던대로 하자"(1992행)라고 했고, Main은 시뮬레이터 빌드와 로컬 서버를 멈췄다.

## 기기 직접 조작

사용자가 `/device-access-setup`으로 "지금 내기기에 접근해봐 usb 연결은 했어"(2035행)라고 요청했다. Main은 2026-11-06에 만든 제어 인스턴스(`~/Documents/Codex/2026-11-06/new-chat/work/iphone-control`: DeviceKit으로 빌드한 xctestrun, mobilecli 1.0.22)를 다시 써서 `xcodebuild test-without-building`으로 iPhone 안의 제어 서버를 띄웠다("Server is ready", 2089–2121행). iPhone 14 Pro, iOS 27.2.1, USB 페어링, 개발자 모드 켜짐 상태였다. 스크린샷과 화면 요소 읽기, 로그인 뒤 프로필 탭 전환으로 터치까지 CLI 경로에서 확인했다. Mobile MCP 경로와 Wi-Fi 연결은 확인하지 않았다.

로그인은 사용자가 했다("로그인했어", 2170행). Main은 "기기 데이터 정리하고 로그아웃" 버튼을 누르지 말라고 미리 안내했다. 사용자가 비행기 모드도 켜 줄 수 있느냐고 묻자("니가 할수는 없나?", 2287행), Main은 기기 시스템 설정이라 하지 않겠다고 답했다(2291행). 비행기 모드 켜기·끄기는 모두 사용자가 했다.

**Main의 실수:** 저장 공간 표시를 다시 읽으려다 명령에 앱 종료를 끼워 1.1.4 앱을 한 번 종료했다(2250행). 오프라인 준비가 끝난 뒤였고, 다시 열었을 때 값이 정상이었다.

## 데이터 넣기와 덮어 설치

Ticket 02는 "여행을 만들어 활성화"라고 했지만, Main은 계정에 있던 여행 "도쿄, 일본"(원래 온라인 전용)을 오프라인 활성화하는 쪽을 택했다. 활성화하면 일정·경비·경로와 도시 지도를 함께 받는다. 그 뒤 비행기 모드에서 경비 하나를 추가해 미전송 변경을 남겼다(2318–2384행). 오프라인 일정 지도에서 경로는 그려졌지만 지도 이동이 잘 되지 않아 육지 배경은 1.1.4에서 확인하지 못했다(2472행).

판정용 앱은 Mac에 받은 `.ipa`를 `xcrun devicectl device install app`으로 USB 설치했다. 비행기 모드에서도 설치는 된다. 그런데 새 빌드는 첫 실행에 iOS가 인터넷으로 개발자 신뢰를 확인해야 열려("앱을 확인할 수 없음", 2464–2472행), 매번 비행기 모드를 잠시 끄고 한 번 연 뒤 다시 켰다. 판정용 앱에는 동기화 코드가 없어 그동안 미전송 경비가 서버로 가지 않는다. 빌드 91은 서명 확인 때 지도 화면을 열지 않고 첫 화면만 띄워, 온라인 상태에서 지도 타일을 새로 받지 않게 했다(2659–2687행).

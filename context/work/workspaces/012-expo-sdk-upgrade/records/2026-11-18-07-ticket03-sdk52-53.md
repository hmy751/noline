# 2026-11-18 — Ticket 03 진행: SDK 52·53 (Legacy 유지)

원문 줄 번호는 Main 대화 `6cf742c7-a162-4a57-981d-2258485e4b19`(JSONL 로그) 기준이다. 검사 로그는 세션 scratchpad의 `baseline/sdk52`·`sdk52b`·`sdk52c`·`sdk53`·`sdk53b`에 있었고, 판단에 필요한 수치는 아래와 [Ticket 03](../current/memory/tickets/03-sdk54-legacy.md#현재-상태와-실제-결과)에 옮겼다.

## 시작과 작업 위치

Ticket 02 뒤 기기 처리를 묻자 사용자가 "아니 몰라서 진행에 도움되눈쪽으로 니가 알아서 해"(2772행)라고 했다. Main은 iPhone을 판정용 앱 상태로 두고 DeviceKit 제어 서버를 끄고, Ticket 01 점검표는 운영 앱이 1.1.4로 업데이트된 뒤 그 앱으로 하기로 정해 기록했다(`6b797c75`). 사용자가 "03 시작"(2823행)이라고 했다가 바로 "그전에 기록할거랑 커밋하고 진행하자"(2830행)라고 해, Main은 판정용 앱과 RNTL 확인 소스를 Workspace의 source에 보존해 `ff51ecd9`로 커밋한 뒤 시작했다.

작업은 main `ff51ecd9`에서 분기한 worktree `.claude/worktrees/012-sdk54`, 브랜치 `feat/012-sdk54`에서 했다. main과 `release/1.1`은 바꾸지 않았고 브랜치는 push하지 않았다. 설치는 `apps/client`에서 `CI=1 pnpm exec expo install expo@~5x.0.0` 뒤 `--fix`로 했다. Ticket 01에서 정한 `pnpm exec expo install` 절차가 실제 SDK 상향에서 동작함을 처음 확인한 셈이다.

## SDK 52 (`8bfe21e1`)

expo 52.0.49, RN 0.76.9, React 18.3.1, expo-router 4.0.22, expo-sqlite 15.1.4, reanimated 3.16.x, dev-client 5.0.20.

Ticket이 54에 두었던 일 셋을 52에서 해야 했다. 각각 52에서 바로 막혔기 때문이다.
- **`expo-dev-menu@5.0.23` patch 삭제:** dev-client 5가 들어오며 patch를 적용할 패키지가 사라져 `ERR_PNPM_PATCH_NOT_APPLIED`로 `--fix`가 막혔다. root `pnpm.patchedDependencies`와 `patches/`에서 지웠다.
- **ui peer 전환과 root react 삭제:** 첫 검사에서 client test 17 suites·171 tests가 `__fbBatchedBridgeConfig is not set`으로 실패하고 typecheck가 77개였다. `packages/ui`가 react-native 0.74.5를 일반 의존성으로 가져 RN이 두 벌 설치된 탓이다. ui의 react·react-dom·react-native·reanimated를 peerDependencies(`>=18.3.1`, `>=18.3.1`, `>=0.74.5`, `>=3.10.0`)로 바꾸고 root `package.json`의 react를 지우자 RN이 한 벌이 되고 테스트 920개가 통과했다(2969–2974행).
- **drizzle-orm 0.45.4:** 남은 타입 오류 중 2개는 drizzle-orm 0.30.10의 `.d.ts`가 expo-sqlite 15에서 사라진 `expo-sqlite/next`를 import해, 타입이 worktree 바깥 main 저장소의 `node_modules`(expo-sqlite 14)로 잡힌 것이었다. 런타임은 type-only import라 영향이 없다. client만 최신 안정판 `~0.45.4`(1.0 RC는 쓰지 않음)로 올렸고 서버는 자기 0.29.5를 유지해 서버 검사가 통과했다(3006–3008행).

그 밖의 변경:
- `@sentry/react-native` 6.22는 Xcode 26 컴파일 때문에 일부러 높인 버전이라 `expo.install.exclude`에 넣었다.
- expo-build-properties 0.13이 deploymentTarget 15.1 이상을 요구해 `app.config.js`의 최소 iOS를 15.0 → 15.1로 올렸다(최종 목표는 16.4).
- expo-router 4의 Router 타입에 맞춰 `tests/app/layout.test.tsx`의 mock에 `dismissTo`·`reload`를 넣었다.

**네이티브 빌드와 fmt 우회.** 시뮬레이터 Release 빌드는 dev 환경값을 명시해야 한다. `.env.development`·`.env.development.local`을 export하고 `APP_VARIANT=development`를 줘야 하며, 그러지 않으면 Release가 `.env.production`을 읽어 운영 번들 앱이 된다(Ticket 02의 시뮬레이터 시도에서 겪은 문제). 첫 빌드는 RN 0.76의 fmt 11.0.2가 Xcode 26.5 clang에서 `call to consteval function ... is not a constant expression` 오류 10개로 실패했다(3070행). fmt 11.0.2는 바깥에서 정한 `FMT_USE_CONSTEVAL`을 받지 않으므로, pod 설치 뒤 `fmt/base.h`의 감지 줄 두 곳을 0으로 바꾸는 임시 config plugin `apps/client/plugins/with-fmt-consteval-off.js`를 `app.config.js`에 등록했다. 제거 기준은 "SDK 54 이상에서 이 처리 없이 빌드되면 삭제"이고 파일 주석에도 적었다. 재빌드는 0 errors였고, 시뮬레이터의 기존 데이터(1.0.0 빌드 6 위에 덮어 설치, 여행 "파리, 프랑스" 일정 6·EUR 219, 준비 완료)가 앱에 보였다(3126–3136행).

**Main의 실수.** 첫 커밋 때 `git add`가 `patches` 경로 오류로 멈춰 patch 삭제만 커밋됐다. push 전이라 amend로 나머지를 넣어 바로잡았다(3158–3169행).

## SDK 53 (`668d4e73`)

expo 53.0.27, RN 0.79.6, React 19.0.0, react-dom ^19, expo-router 5.1.11, expo-sqlite 15.2.14, reanimated 3.17.5, jest-expo 53.0.14, react-test-renderer 19.0.0, `@types/react` ~19.0.10, TypeScript ~5.8.3(client·ui). **React 19가 Ticket 예상(54)보다 한 단계 이른 53에서 들어왔다.**

- **테스트 2개 실패:** `tests/app/layout.test.tsx`와 `tests/shared/services/sync/provider-network.test.tsx`의 타이머 수 검사가 실패했다. 임시 추적으로 보니 fake clock에 남은 job 하나가 React 19 `react.development.js`의 `queueSeveralMicrotasks`가 `act` 안에서 부른 `queueMicrotask`였고 앱 타이머가 아니었다. 앱 코드는 `queueMicrotask`를 쓰지 않음을 확인하고(3278행) `apps/client/jest.config.cjs`에 `fakeTimers: { doNotFake: ['queueMicrotask'] }`를 넣었다. 테스트 자체는 고치지 않았고 임시 추적 파일은 지웠다.
- **타입:** React 19의 `useRef`가 `RefObject<MapView | null>`을 돌려줘 `src/shared/hooks/map/useMyLocation.ts`의 prop 타입을 바꿨다. expo-router 5 Router에 생긴 `prefetch`를 mock에 넣었다.
- **결과:** client test 920 통과, typecheck 5개(기준선 6에서 TimeField 오류가 사라짐), lint 같음, schema·server 통과. react·react-native가 한 벌씩이다(`@expo/cli`의 정적 canary 사본과 `packages/eslint-config`의 react 18.2.0 dev 사본은 앱 런타임과 별개).
- **네이티브:** 시뮬레이터 Release 빌드 0 errors, 설치·실행까지 됐다. 사용자가 "결과 나오면 일단 작업 중지해봐"(3321행)라고 해 앱 화면은 보지 않았다. fmt 우회가 53에서도 필요한지는 따로 보지 않았다(plugin이 적용된 채 빌드).

사용자가 "그래 기록할거나 커밋 하고 계속 진행해보자"(3354행)라고 해 SDK 53을 커밋하고 이 기록을 남겼다. 다음은 SDK 54다.

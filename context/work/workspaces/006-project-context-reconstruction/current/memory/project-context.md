# 선택한 Project 맥락과 적용 범위

이 작업에서는 [Project README](../../../../../project/README.md), [제품 의미](../../../../../project/common/product.md), [현재 구조와 검증 경계](../../../../../project/current/architecture.md)를 선택한다. 제품이 지키려는 데이터 관계와 현재 책임·검증 한계를 첫 조사에서 구분하기 위한 실제 본문이다. 기존 설명의 충분성·분할·최신성도 검토 대상이므로 이 선택을 보완 범위의 한계나 현행 문구 보존 명령으로 읽지 않는다.

첫 조사에서는 [Project 읽기 기준](../../../../../project/REFERENCE/reading.md)으로 주제별 본문을 추가 선택한다. 전체 내용을 기본 읽기에 싣지 않고 자료와 보완 후보 지도에서 필요한 검토 범위를 확장한다. 주제별 guidance·Decision은 실제 질문과 후보에 맞춰 선택한다.

08에서 Recover가 고른 Project 본문과 그 하위 현재 읽기 경로의 옛 제품 문서 의존을 제거하고 확인했다. 앞으로 Owner를 바꿀 때도 현재 읽기와 원본 보존을 함께 대조한다. 조사 목적으로 원자료를 읽는 것과 이후 개발의 일반 진입 경로를 구별한다.

본문 작성·이관에 들어가기 전에는 [관리 계약](../../../../../project/MAINTENANCE.md), [내용 정책](../../../../../CONTENT-POLICY.md), [작성 형식](../../../../../WRITING-FORMAT.md)과 해당 주제 Owner를 읽는다. 기존 규칙을 이유로 사용자가 요청한 적극적인 재구성을 국소 수정으로 줄이지 않는다. 반대로 문서 재구성 권한으로 미결 제품 계약이나 실행층 개편을 대신 결정하지 않는다.

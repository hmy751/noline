# 요구 결과와 대표 장면

## 수집에서 다음 작업을 고를 수 있다

첫 결과는 파일명 목록을 넘어, 어떤 내용이 어디에 있고 왜 다음 작업에 필요한지 보여 주어야 한다. 자료별로 읽은 범위와 미확인 부분을 구분하고, 제품 질문이나 설명 주제로 묶어 현재 Project의 대응 내용과 비교한다. 빠진 내용뿐 아니라 기존 내용을 더 잘 설명할 기회도 후보에 넣는다.

각 주요 후보에는 현재 설명의 부족함, 보완했을 때 달라질 이해·판단, 근거 접근점과 필요한 검증, 권장 처리 및 열린 선택을 제시한다. 이를 바탕으로 사용자가 우선순위와 후속 Ticket 묶음을 판단할 수 있어야 한다. 조사 전에 최종 주제 수·Ticket 수를 고정하지 않는다.

## 오래된 설명을 현재 사실로 바꾸어 읽을 수 있다

과거 문서에 있던 문제나 제안이 지금도 남아 있는지 코드·후속 기록으로 확인한다. 예를 들어 004 당시의 날짜 관련 질문은 이후 002에서 바뀐 입력·전송 표현과 구분해 대조해야 한다. 과거 문제가 있었다는 기록만으로 현재 결함이나 미결 제품 선택을 확정하지 않는다.

구현 사실을 설명하는 문장이 낡았으면 사실에 맞춰 보완한다. 채택된 제품 계약과 코드가 충돌한다면 둘을 구분해 드러내고, 코드를 그대로 새 제품 약속으로 올리지 않는다. 새로운 제품 선택이 필요할 때에는 구체적인 선택지·차이·영향을 논의한다.

## Project만으로 의미와 이유를 이해한다

다음 작업자는 Project 진입점에서 주제의 본문을 찾아 그 기능이 필요한 이유, 관련 책임 사이의 관계, 적용 조건과 예외, 현재 구현의 차이를 이해한다. 이관한 주제의 기본 뜻과 선택 이유를 조립하기 위해 `.claude/context`, `.claude/decisions` 등의 옛 제품 문서나 여러 과거 Workspace를 읽게 하지 않는다. 상세 코드와 현재 근거는 필요한 추가 확인 경로로 연결한다.

예를 들어 활성 여행과 네트워크 제한을 설명한다면 각각의 이름만 나열하지 않고, 데이터 보존과 온라인 서비스 제한이 사용자 장면에서 어떻게 함께 작동하는지 필요한 깊이로 풀어 쓴다. 이 장면은 Ticket 02의 읽기 확인에도 사용한다.

## 옛 문서를 현재 읽기에서 분리한다

이관한 주제는 Project 본문에서 현재 기준과 필요한 선택 이유를 찾을 수 있어야 한다. 현재 가이드·본문·형성 자료가 옛 `.claude` 제품 문서나 그 아카이브로 읽기를 안내하지 않는다.

옛 자료는 일반 읽기 경로에서 제외되는 아카이브로 격리하거나 제거한다. 아카이브의 물리 위치나 삭제 여부가 완료를 가르는 것이 아니라, 현재 설명의 충분성과 옛 문서 의존 제거가 기준이다. 경로 검사의 성공, 본문 이해의 성공과 실제 읽기 경로의 분리를 각각 확인한다.

# 문제·목표·범위

## 왜 다시 시작하는가

사용자는 002에서 쌓인 작업을 바탕으로 다양한 자료를 수집하고 고민하여 Project Context를 보완하기를 기대했다. 005에서 수행한 개별 주제 보완은 이 기대에 비해 지엽적이었고, 이관하려던 `.claude` 제품 본문을 계속 현재 Owner처럼 갱신한 방향도 맞지 않았다. 기존 `context/project` 본문을 적극적으로 다듬는 일도 부족했다. 005는 목표 달성으로 수락된 것이 아니라 사용자 요청으로 종료되었다.

006은 이 평가를 현재 범위의 출발점으로 삼는다. 기존 결과를 폐기하거나 되돌리지는 않되, 005의 티켓 분류·우선순위·국소 수정 접근을 이어받지 않는다. 당시 결과는 다시 살펴볼 근거 중 하나다. [사용자 방향 원문](../../../source/user-direction.md)에 이 판단의 발화를 보존한다.

## 이루려는 결과

흩어진 설명·선택 이유·구현 경험을 현재 사실과 대조하여 `context/project`에서 제품의 의미, 설계 이유, 현재 구현의 차이와 관련 작업의 판단 기준을 충분히 이해할 수 있게 한다. 유효한 내용을 옮기는 것과 기존 본문의 설명·구조를 개선하는 것을 함께 수행한다.

이관한 주제의 최종 상태에서는 현재 가이드와 Project 본문만으로 현재 의미와 필요한 선택 이유를 이해할 수 있어야 한다. `.claude/context`, `.claude/decisions` 등 옛 제품 문서를 현재 판단을 위한 일반 읽기 경로에 남기지 않는다. 옛 자료는 일반 읽기에서 제외되는 아카이브로 격리하거나 제거할 수 있으며, 보존 위치나 물리적 삭제 자체가 목표는 아니다.

본문의 재작성, 병합·분리, 설명 순서 변경, 빠진 이유·조건·사례 복원도 범위에 포함한다. 현재 파일 구성이나 문장 수를 유지하는 것이 목표는 아니다. 보존할 대상은 유효한 의미와 판단에 필요한 이유이며, 새 구성은 독자의 이해와 관리 책임에 맞춰 선택한다.

## 포함할 범위

- `.claude`의 제품 설명·결정·기록과 저장소 안의 다른 흩어진 문서를 찾아 수집하고 현재 역할을 판별한다. 루트와 앱·패키지의 `CLAUDE.md`, `AGENTS.md`, README 등 프로젝트 컨텍스트를 담거나 연결하는 문서도 명시적으로 포함한다.
- 이 분산 문서는 조사 입력이자 실제 정리 대상이다. Project로 이관할 현재 의미와 선택 이유, 현재 읽기 경로에서 제외할 옛 제품 문서, 계속 남아야 하는 실행 지침을 구별한다. 파일명이나 `.claude` 안팎의 물리 위치만으로 일괄 처리하지 않는다. `AGENTS.md`가 원본을 가리키는 연결이면 별도 본문으로 중복 집계하지 않고 원본과 읽기 경로를 함께 확인한다.
- 002의 전체 작업 흐름과 자료를 펼쳐 구현 변화뿐 아니라 제품 계약·설계 선택·검증 한계·이후 작업에 유효한 경험을 추출한다.
- 004의 이관 결과와 제품 질문·선택지, 005의 결과를 현재 코드와 후속 기록에 대조한다.
- 기존 Project 본문 자체의 내용 부족, 단편화, 중복, 설명·구조 문제를 검토하고 개선한다.
- 검증된 주제의 현재 의미와 필요한 선택 이유를 Project 체계에 충분히 담고 관련 진입점·Owner 설명을 새 위치로 맞춘다. 옛 제품 문서는 현재 경로에서 참조하지 않도록 아카이브로 격리하거나 제거한다.

스킬·에이전트·설정·실행 연결 개편은 기본 범위에 포함하지 않는다. 제품 지식과 실행 지침이 섞인 rule·runbook 등은 실제 내용을 보고 제품 설명의 이관 범위와 계속 남을 실행 책임을 구별한다. 이 기준은 이관한 제품 주제의 현재 읽기 경로를 정하는 것이며 `.claude` 전체를 일괄 삭제하는 권한은 아니다. 제품 버그 수정이나 기능 추가, 개인 협업 기준 개선은 별도 작업 후보로 구분한다.

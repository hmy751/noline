# 작업 구성·제약·열린 판단

## 하나의 Spec과 단계별 Ticket

하나의 Spec이 수집·검증·본문 재구성·이관·읽기 경로 정리의 전체 결과를 맡는다. 세션 수나 문서 수가 많다는 이유로 Workspace를 먼저 나누지 않는다. 후속 Ticket은 독립적으로 설명하고 확인할 수 있는 주제나 결과 단위로 나누며, 실행하면서 범위·의존성에 맞춰 조정한다.

첫 Ticket은 자료와 보완 후보를 넓게 펼쳐 다음 논의를 구체화한다. 이후 Ticket은 주제의 근거 검증에서 최종 본문 반영과 읽기 확인까지 이어지도록 구성한다. 수집 담당·이관 담당처럼 단계만 나눠 실제 내용을 아무도 끝내지 않는 구성을 피한다.

## 조사와 재구성의 접근

먼저 `.claude` 문서와 루트·앱·패키지의 `CLAUDE.md`·`AGENTS.md`·README 등 분산된 컨텍스트를 현재 Project 본문과 대조해 대응 관계를 정리한다. 어떤 유효한 내용이 기존 문서에만 있는지, 이미 옮긴 내용과 중복·충돌하는지, 기존 Project 본문에서 무엇을 더 설명하거나 재구성해야 하는지 살펴 이관할 의미와 보존할 근거를 드러낸다. 아카이브를 준비할 `.claude` 문서의 역할과 저장소 전반에서 현재 기준을 읽는 경로를 함께 파악하려는 순서다. 루트·앱·패키지 가이드는 최초 대응 조사부터 포함하며, 실제로 필요한 진입 안내와 경로별 기준을 어디에 남길지도 판단한다.

이 대응 관계에 002의 작업 축적과 004의 계약 논의·이관 결과를 연결하고, 005의 결과와 다른 흩어진 자료로 범위를 넓힌다. `.claude`에 대응 항목이 없는 중요한 내용도 독립된 보완 후보로 추가한다. 이 우선순위는 조사 시작과 결과 제시의 순서이며, `.claude` 전체 검증·이관을 마쳐야 다른 자료를 볼 수 있다는 선행 조건은 아니다.

전체 자료의 지도를 넓게 보고 중요한 본문을 실제로 읽으며, 미확인 범위를 명시한다. 모든 원문을 완독해야만 판단을 시작하는 조건도, 이미 알려진 주제만 읽는 제한도 두지 않는다. 후보별 중요도와 근거 상태에 따라 추가 대조를 깊게 한다.

조사 중 낡은 문장 하나를 찾았다고 코드나 `.claude` 본문부터 수정하지 않는다. 그 내용이 어느 제품 주제에 속하고 Project에서 어떻게 이해되어야 하는지 판단한다. 현재 Project의 구조와 선택 문서는 검토 출발점이며 재구성의 상한이 아니다.

## 아직 확정하지 않은 것

조사 시작은 `.claude`와 루트·앱·패키지의 분산된 컨텍스트를 현재 Project에 대조하는 것으로 정했다. 그 이후 실행할 주제 묶음·Ticket 수·주제별 우선순위, 아카이브의 실제 위치와 호환 문서 형태는 첫 조사와 주제별 영향 확인으로 구체화한다. 제품 지식과 실행 지침이 섞인 문서의 분리·이관 범위는 해당 문서의 내용과 소비자를 보고 논의한다. 이 미정 사항이 자료 수집을 막지는 않는다.

현재 `.claude` 실행층은 계속 사용되고 있으므로 문서 아카이브 방향을 전체 폴더의 폐기로 확대하지 않는다. 스킬 변경은 사용자가 별도 논의를 원했다. 기존 작업 결과를 되돌리거나 과거 기록을 현재 정책처럼 고쳐 쓰지 않는다.

# Ticket 04 — 오프라인 지도·경로 재구성

상태: 완료. 2026-10-31, 오프라인 지도 pack과 저장 경로의 준비·재사용·표시·정리 의미를 현재 코드와 SDK에 대조해 Project로 이관하고 독립 검토·검증을 마쳤다. 이 완료는 문서 이관 범위이며 발견한 제품 결함의 해결이나 실기기 검증, 006 전체 이관 완료를 뜻하지 않는다.

## 맡은 결과와 범위

데이터 활성화, native 지도 pack, SQLite metadata, 저장 geometry와 화면 표시가 어떤 조건에서 준비·재사용·정리되는지 현재 Project context에서 이해할 수 있게 한다. 유효한 선택 이유와 비용을 보존하면서 과거의 준비 완료·500ms 대기·경로 최신성·만료 정리 보장을 현재 구현과 SDK에 맞게 교정한다.

완료 상태에서는 현재 Project 본문과 형성 자료만으로 대표 개발 질문에 답할 수 있어야 한다. 옛 지도·경로 가이드와 결정 또는 그 아카이브로 일반 읽기를 안내하지 않는다. 문서 정정, 확인된 구현 공백, 실기기 검증이 필요한 주장과 새 제품 선택을 구별한다.

## 실행 맥락과 접근

Ticket 03의 데이터 수명 설명에 이어 지도·경로의 준비·재사용·표시·정리를 맡았다. 기존 오프라인 지도·경로 설명과 도입 결정 4개를 실제 생성·수정·삭제·활성화·renderer 소비자 및 설치된 Mapbox SDK 구현에 대조했다.

[공통 내용·구성 판단 기준](../spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)에 따라 기존 내용의 현재 적합성과 형식의 역할을 함께 판단했다. 상태와 경로 차이를 보여 주는 비교표, 공급자 선택 이유, 도시별 공유와 사전 계산의 비용은 유지했다. 일반 구현 체크리스트와 긴 코드 복사는 실제 작업 조건·행동·예외 가까이에 통합하고, 활성화 구현·Policy·용량 집계는 기존 Owner로 연결해 복제를 줄였다.

## 완료 조건과 확인 방법

- 데이터 입수, 지도 pack, 저장 경로와 화면 표시의 완료 의미를 자원별로 구별해 설명할 수 있다.
- pack metadata와 native 파일, 저장 경로 입력과 현재 장소·인접 관계, 화면 표시 결과의 차이를 현재 코드에 대조한다.
- 유효한 선택 이유·비용과 현재 구현 공백, 실기기 확인이 필요한 주장을 구별한다.
- 현재 Project 읽기 경로가 옛 가이드·결정이나 아카이브를 제품 정본으로 안내하지 않는다.
- 기존 검사와 링크·정적 검사의 통과 범위 및 전체 Harness 실패를 실제 결과에 남긴다.

제품 버그 수정이나 새 제품 계약은 문서 이관 완료로 대신하지 않는다.

## 현재 상태와 실제 결과

[Project 지도·경로 본문](../../../../../../project/guidance/offline-maps-and-routes/INDEX.md)은 데이터 입수, native 지도 pack, 저장 geometry와 화면 표시의 관계를 설명한다. 지도 파일과 저장 경로의 조건부 상세 및 형성 자료에는 도시별 공유, 두 저장소 운영, 사전 계산·fallback·전체/증분 계산의 선택 이유와 비용을 보존했다. 옛 가이드·결정 4개는 원문을 보존한 아카이브로 옮겼고 현재 소비 경로는 새 Owner로 전환했다. 상세 판단과 원본 대응은 [이관 결과](../../../output/ticket-04-result.md)가 맡는다.

현재 코드와 SDK 대조에서는 pack 등록과 실제 tile 다운로드 완료가 다르고, metadata 삭제가 native 파일 회수를 보장하지 않음을 확인했다. 공유 count·flag와 native pack의 정합성도 일반적으로 보장되지 않는다. 생성·수정·활성화의 경로 준비는 서로 다른 입력과 재사용 조건을 사용해 저장 row만으로 최신 geometry를 보장할 수 없다. 500ms 대기는 최신성 보장이 아니며, 좌표 변경·삭제·중복·0 좌표와 일부 구간 합계 표시에도 후속 검증이 필요하다. 이 차이는 제품 보완 과제이며 제품 코드는 변경하지 않았다.

기존 검사 4 suites·58 tests와 변경 문서의 상대 파일·앵커 검사, `git diff --check`가 통과했다. 해당 테스트는 route hook과 native 경계를 mock하므로 실제 Mapbox 다운로드 완료, 오프라인 재실행, geometry 최신성이나 실제 파일 회수를 입증하지 않는다. 실기기 검증은 수행하지 않았다. 전체 Harness 검사는 역사 링크 오류 22건 때문에 실패했으며 현재 변경 문서의 링크 결과와 구별한다.

독립 검토·검증은 유효한 비교와 선택 이유를 보존하면서 준비 완료, 시간순 입력, 500ms, 경로 최신성 및 정리 보장의 과장을 교정한 현재 문서 구성을 이관 범위에 적합하다고 판단했다. Ticket 04의 실제 문서 이관·참조 전환은 `d5867d7`으로 커밋했으며 Workspace 기록은 별도 커밋으로 분리한다. 다음 문서 이관은 Ticket 05의 구조·계층·UI·schema다.

01의 첫 조사 결과를 바탕으로 02–08 후속 범위를 순차적으로 구체화한다. 03 이후의 나머지 Ticket은 실행 범위와 의존 관계를 정할 때 본문을 만든다. 개별 진행과 실제 결과는 각 Ticket 본문에서 확인한다.

03 이후 모든 이관 Ticket의 실행·리뷰·완료 판단에는 [공통 내용 판단 기준](../spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)을 적용한다. 기존 설명 자체의 현재 적합성과 문서 역할에 맞는 구성·형식인지를 함께 확인한다. 기존 형식이 적합하면 유지할 수 있으며 새 모양으로 통일하는 것이 목표는 아니다. 새 Ticket을 만들 때도 이 기준을 연결하고 해당 주제에서 대조할 원자료·코드·소비 경로를 구체화한다.

04는 오프라인 지도·경로, 05는 구조·계층·UI·schema, 06은 작성·입력·날짜, 07은 통화·API·오류, 08은 개발 시작과 전체 읽기 점검을 권장 범위로 둔다. 모든 주제에 본문·선택 이유 보완, 현재 참조 전환, 옛 제품 문서의 격리 또는 제거를 포함한다. 08은 이 정리를 처음 수행하는 Ticket이 아니라 주제별 처리 후 빠진 진입점과 옛 결정·아카이브 연결을 최종 확인하는 범위다.

# Ticket 01 — 자료와 실질적인 보완 후보를 넓게 펼치기

상태: 완료. 첫 조사 결과를 사용자가 수락해 코드 대조를 포함한 후속 주제별 실행으로 이어졌다.

## 맡은 결과와 범위

분산된 제품 설명과 기존 Project 본문을 대조해 사용자가 다음 작업을 고를 수 있는 지도를 만든다. 파일 이동 목록이 아니라 Project에서 더 잘 설명할 의미·이유·경험, 현재 설명과의 중복·충돌·누락, 필요한 검증과 제품 판단을 드러내는 것이 결과다.

조사는 `.claude` 문서, 루트·앱·패키지의 `CLAUDE.md`·`AGENTS.md`·README, 현재 Project 본문을 시작점으로 삼고 002·004·005의 결과와 다른 발견 자료를 연결한다. 과거 설명은 현재 코드·후속 결정과 대조하며, 코드가 존재한다는 이유만으로 제품 계약을 바꾸지 않는다.

## 실제 결과

[첫 조사 — 자료 대응과 Project 보완 후보](../../../output/source-map-and-candidates.md)에 분산 자료와 현재 Project의 대응, 보완 후보, 읽은 범위와 후속 묶음을 정리했다. 주요 후보 일부를 코드와 대조하면서 실제로 존재하지 않는 `packages/db`·Prisma 설명과 현재 생성 흐름과 다른 오프라인 지도 다운로드 안내도 확인했다.

사용자는 `.claude`의 최신성도 코드와 대조하는 범위에 포함되는지 확인한 뒤, 이 기준을 포함한 후속 진행을 수락했다. 이에 따라 후보별 처리는 다음처럼 구별한다.

- 설명만 낡았다면 현재 사실에 맞게 고쳐 Project 이관 후보로 삼는다.
- 코드가 채택된 제품 계약과 다르면 계약과 구현의 차이를 드러내며, 제품 약속을 코드에 맞춰 암묵적으로 바꾸지 않는다.
- 당시 제안·예시·미구현 계획이면 현재 기능으로 옮기지 않고 필요한 선택 이유나 역사 근거만 보존한다.

첫 조사에서 제안한 02–08 후속 범위 중 02를 첫 실행으로 채택했다. 이 지도와 후속 진행 수락은 전체 자료 검토나 Workspace 완료를 뜻하지 않는다.

## 완료 근거와 남은 범위

첫 결과에서 자료 대응과 실질적인 보완 후보, 코드 대조 필요, 우선순위와 후속 실행 묶음을 제시했고 사용자가 후속 진행을 선택했다. 실제 Project 본문 재구성·Owner 이동과 주제별 검증은 각 후속 Ticket이 맡는다.

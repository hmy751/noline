# Ticket 09 — 제품 개발 기준과 위험 점검 통합

## 맡은 결과와 범위

같은 제품 규칙을 `.claude/rules`·guards·Project에서 따로 관리하던 중복과 권위 모호함을 해소한다. 관련 작업자가 적용 조건·실패 위험·확인 방법을 현재 주제 본문과 필요한 진입 안내에서 함께 찾을 수 있게 한다.

rules 전체와 Guard Map을 02–08에서 구성한 Project의 제품·여행 접근·데이터 수명·구조와 schema·날짜·API·오류 본문 및 관련 코드에 대조한다. root와 앱·패키지 guide, 이 기준을 읽는 실행자·agent·checker·Verify 선언도 변경 영향에 포함한다. runbooks·commands·skills·agents·hooks와 역사 자료 전체의 정리는 각각 Ticket 10–12가 맡는다. 제품 동작 수정은 이 Ticket의 결과가 아니다.

## 실행 맥락과 접근

[09–13 구성](../../../output/ticket-recomposition-09-13.md)과 [Spec의 내용 판단 기준](../spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)을 적용한다. 기존 rule·guard와 받을 Project 본문을 함께 읽고 현재 코드·유효한 제품 계약·실제 사용 조건으로 내용 자체를 확인한다. 현재 구현을 이유로 채택된 계약을 자동 축소하지 않는다.

중복은 문장 수가 아니라 조건·예외·규칙 강도·선택 이유와 비용을 대조해 통합한다. 필요한 위험·확인 조건이 현재 Owner에 빠졌으면 근거를 확인해 보강하고, 낡은 지시·근거 없는 보장·중복 소유는 제외한다. 유효한 compact 안내가 별도로 필요한지는 실제 진입 효과로 판단하며 현재 rule/guard 분리를 보존 조건으로 삼지 않는다.

예를 들어 Local 변경과 queue의 원자성, 삭제 행의 일반 조회와 sync 전달 차이, 날짜와 시점 구분은 규칙 문장만 합치지 않는다. 계약, 실패 위험, 변경 시 확인할 조건과 실제 구현 차이를 함께 비교해 가장 적절한 Owner에 구성한다.

한 주제마다 내용 판단, Owner 통합·보완, 직접·간접 참조 전환, 옛 경로 제거·격리와 확인까지 끝낸다. 같은 파일을 다음 Ticket도 사용한다는 이유로 이번 변경에 필요한 연결 수정을 미루지 않는다.

## 완료 조건과 확인 방법

- 모든 현재 rule·guard의 유효한 의미가 어디에 통합·보강됐고 무엇을 제외했는지 판단과 실제 위치가 있다.
- 이유·조건·예외·비용과 규칙 강도가 통합 과정에서 사라지거나 확대되지 않는다.
- 대표 변경 작업에서 현재 Owner를 따라 올바른 계약·위험·확인 조건과 현재 구현 차이를 찾을 수 있다.
- 옛 원본을 제거·격리하거나 별도 안내를 남긴 이유가 분명하고, 영향받는 guide·agent·checker·Verify 선언과 직접·간접 참조를 함께 맞춘다.
- 독립 검토는 기존 설명 자체의 현재 적합성, 새 구성의 이득·부담과 손실된 조건·이유를 확인한다.
- 내용 충분성, 링크·읽기 경로와 관련 검사는 서로 다른 근거로 보고한다. 제품 동작을 고쳤거나 전체 `.claude` 정리가 끝났다고 확대하지 않는다.

## 현재 상태와 실제 결과

Main은 제품 규칙과 위험 점검을 Project의 주제별 Owner에 통합하고 현재 소비 경로를 전환한 뒤, 문서·소비자 담당 확인과 독립 검토를 거쳐 이 Ticket을 완료로 판단했다. 세부 변경, 원본 9개의 격리, 소비자 전환과 검증 한계는 [Ticket 09 결과](../../../output/ticket-09-result.md)에 있다.

여기서 Activation Router는 여행 활성 상태에 따라 Local SQLite와 Server API를 선택하는 제품 책임이다. 개발 작업을 어떤 스킬·절차로 진행할지 정하는 수행 흐름과는 다르다. 관련 스킬은 단순 분배기가 아니라 호출 조건·판단·수행 방법과 필요한 워크플로를 소유할 수 있으며, 그 워크플로와 연결 지침의 대조는 Ticket 10·11의 남은 범위다.

제품 코드는 바꾸지 않았고 실제 앱·JWT·PostgreSQL·native SQLite 실행은 이번 확인 범위가 아니다. 전체 harness 검사는 역사 링크 52건 때문에 실패했으며, 그중 비활성 003의 옛 rule/guard 링크 5건이 이번 정리 뒤 드러났다. 002 선언에는 이번 변경과 무관한 파일 누락 6건이 남아 있다. 이를 Ticket 09의 현재 문서 통합 결과나 Workspace 전체 완료로 확대하지 않는다.

Main은 Ticket 09의 제품 기준 통합과 006 후속 작업 기록을 commit `c6bc416`(`docs(context): 제품 기준 통합과 006 후속 작업 기록`)으로 커밋했다고 보고했다. 로컬 commit 내용을 확인한 결과 Ticket 09 산출물과 current 갱신이 포함됐고, 개인 문서와 `.pnpm-store/`는 포함되지 않았다.

# Ticket 08 — 개발 시작과 전체 읽기 경로

## 맡은 결과와 범위

개발 시작 안내를 실제 환경·인증·DB·native 실행 코드와 맞추고, 남은 제품 결정의 유효한 이유를 Project에 보존해 옛 제품 문서에 의존하지 않는 현재 읽기를 완성한다. [공통 품질 기준](../spec/04-quality-and-completion.md)을 적용하며 제품 코드·실행층 전체 개편은 포함하지 않는다.

## 실행 맥락과 선택

02–07의 주제별 결과를 재사용하고 루트 README·START_GUIDE·서버/SQL 안내, 두 세션 결정과 Data/Service·Policy·용어·새 여행 결정을 대조했다. 소개·실행 절차·형성 자료의 역할이 달라 같은 형식으로 통일하지 않았다. 현재 의미와 필요한 이유는 Project에, 실제 시작 절차는 개발 안내에 유지했다.

현재 진입점과 default 001·explicit-bound 002/006의 소비 경로를 확인했다. 기록의 과거 링크를 현재 정책처럼 다시 쓰거나 전체 검사 통과를 위해 옛 정본을 되살리지 않았다.

## 완료 조건과 확인

현재 설명이 코드·유효 계약과 맞고, 이유·조건·비용을 보존하며, 옛 제품 원본 없이 대표 질문에 답할 수 있어야 한다. 원본 보존·링크·bridge·Recover는 각자 범위로 확인한다. 전체 Harness 실패와 실제 설치·기기·DB·배포 미확인을 숨기지 않는다.

## 현재 상태와 실제 결과

문서 이관과 독립 개선 검토·별도 검증을 마쳤다. [실제 결과와 원본 대응](../../../output/ticket-08-result.md)에 개발 안내 정정·세션 선택 이유·아카이브·대표 질문과 검증을 남겼다. 원문 11개 byte 일치, 상대 링크 592개, Recover 006·002·001·default 성공을 확인했다. 기존 세션 검사 10 suites·107 tests는 실제 대역과 한계를 대조해 재사용했다.

001 Verify evidence 214개는 모두 존재한다. 전체 Harness에는 [역사 참조 47건](../../../output/ticket-08-historical-references.md)이 남아 전체 통과를 주장하지 않는다. 제품 코드·실제 DB·앱·배포는 변경하거나 실행하지 않았다. 문서 이관 완료와 006 전체 수락은 별개다.

사용자의 후속 요청으로 08을 작업·기록으로 나눠 커밋하고 `.claude`의 남은 정리 후보를 조사한다. 추가 제거·이동이나 실행층 재설계는 이 Ticket 완료에 끼워 넣지 않는다.

# Ticket 03 — 데이터 저장·동기화·정리 재구성

상태: 실행 대기. 02의 교정 결과를 확인한 뒤 시작하며 최신 진행은 [state](../../state/index.md)를 따른다. 이번 문서 구성 교정에서 03의 조사·이관에 착수하지 않았다.

기존 저장·sync 문서의 표·절차·체크리스트도 [공통 내용·구성 판단 기준](../spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)에 따라 역할·적용 조건·중복을 판단한다. 적합한 형식은 유지하되 pending·완료·정리의 조건이나 예외가 재배치 중 빠지지 않게 대조한다.

## 맡은 결과와 범위

Local 변경, `sync_queue`, push/pull, 여행별 정리와 계정 종료가 데이터를 어떻게 보존하거나 제거하는지 Project context에서 함께 이해할 수 있게 한다. 활성 여행의 Local 기준과 서버 반영, 미전송 변경 보호, cleanup 조건과 종료 절차의 책임을 현재 코드와 기존 근거에 대조해 재구성한다.

완료 상태에서는 현재 Project 체계만으로 이 주제의 의미와 필요한 선택 이유를 이해할 수 있어야 한다. 현재 가이드·본문·형성 자료에서 `.claude/context`, `.claude/decisions` 등의 옛 제품 문서나 그 아카이브로 돌아가는 읽기 연결을 남기지 않는다. 옛 자료는 일반 읽기에서 제외되는 아카이브로 격리하거나 제거할 수 있으며 물리 위치나 삭제 자체를 목표로 삼지 않는다. 문서 정정과 제품 결함, 새 제품 선택을 구별하며 현재 코드 동작을 자동으로 새 제품 약속으로 채택하지 않는다.

## 실행 맥락과 접근

Ticket 02는 제품·여행 접근·목록의 설명과 옛 Policy 읽기 경로 분리를 마쳤다. 그 완료 기준을 이어 적용하며, 002의 14·15·16 결과와 003의 관련 재현을 현재 코드에 대조해 Local 변경부터 queue·push/pull·여행 정리·계정 종료까지의 관계를 구성한다.

특히 PENDING만 확인하는 여행별 정리 경로와 FAILED·IN_PROGRESS까지 포함해야 하는 보존 계약의 차이를 우선 확인한다. 과거 설명, 실제 코드, 테스트·후속 결정을 구별하고 Project의 기존 Owner와 겹치거나 충돌하는 설명을 함께 정리한다.

[공통 내용 판단 기준](../spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)에 따라 기존 설명과 새 구성 모두의 적합성을 검토한다. 이 주제에서는 ‘pending’, ‘동기화 완료’, ‘정리 가능’이 각 호출부에서 실제로 뜻하는 범위와 데이터가 남거나 지워지는 조건을 대조한다. 기존 보존 이유와 정리를 지연하는 비용은 유지하되 오래된 상태명·함수 지시·완료 보장을 그대로 옮기지 않는다. 새 구성은 Local 변경부터 계정 종료까지의 관계를 더 잘 이해하게 하는지로 판단한다.

## 완료 조건과 확인 방법

- Local mutation과 queue 기록, push/pull, 비활성화·cleanup, 로그아웃·탈퇴 사이의 책임과 순서를 Project 진입점에서 이해할 수 있다.
- 미전송·실패·진행 중 작업이 각 정리 경로에서 어떻게 보존되는지 현재 코드와 근거에 대조되어 있다.
- 채택된 제품 계약, 현재 구현, 확인하지 못한 동작과 새 판단이 필요한 차이가 구별되어 있다.
- 현재 의미와 필요한 선택 이유가 Project 체계에 충분히 담기고, 현재 경로가 옛 `.claude/context`·`.claude/decisions` 문서나 그 아카이브로 읽기를 안내하지 않는다.
- 옛 제품 문서가 아카이브로 격리되거나 제거되어 경쟁 정본이나 우회 Owner로 남지 않는다.
- 대표 질문으로 읽기 경로를 확인하고, 실행한 테스트·정적 검사와 그 입증 범위 및 남은 오류를 실제 결과에 기록한다.

제품 버그 수정이나 새로운 제품 계약이 필요하면 문서 이관 완료로 숨기지 않고 별도 판단 대상으로 남긴다.

## 현재 상태와 실제 결과

아직 실행 결과는 없다. 02가 정리한 Router·목록 계약을 입력으로 삼되 저장·sync·cleanup의 안전성을 별도로 대조한다.

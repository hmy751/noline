# Ticket 03 — 데이터 저장·동기화·정리 재구성

상태: 완료. 2026-10-31, Local 저장부터 동기화·정리·계정 종료까지의 문서 이관과 역할별 재구성, 독립 검토·검증을 마쳤다. 이 완료는 문서 이관 범위이며 확인된 제품 보호 공백의 해결이나 006 전체 이관 완료를 뜻하지 않는다.

기존 저장·sync 문서의 표·절차·체크리스트도 [공통 내용·구성 판단 기준](../spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)에 따라 역할·적용 조건·중복을 판단했다. 적합한 비교표와 절차는 유지하고, 일반 체크리스트는 실제 작업 조건 가까이에 통합했다.

## 맡은 결과와 범위

Local 변경, `sync_queue`, push/pull, 여행별 정리와 계정 종료가 데이터를 어떻게 보존하거나 제거하는지 Project context에서 함께 이해할 수 있게 한다. 활성 여행의 Local 기준과 서버 반영, 미전송 변경 보호, cleanup 조건과 종료 절차의 책임을 현재 코드와 기존 근거에 대조해 재구성한다.

완료 상태에서는 현재 Project 체계만으로 이 주제의 의미와 필요한 선택 이유를 이해할 수 있어야 한다. 현재 가이드·본문·형성 자료에서 `.claude/context`, `.claude/decisions` 등의 옛 제품 문서나 그 아카이브로 돌아가는 읽기 연결을 남기지 않는다. 옛 자료는 일반 읽기에서 제외되는 아카이브로 격리하거나 제거할 수 있으며 물리 위치나 삭제 자체를 목표로 삼지 않는다. 문서 정정과 제품 결함, 새 제품 선택을 구별하며 현재 코드 동작을 자동으로 새 제품 약속으로 채택하지 않는다.

## 실행 맥락과 접근

Ticket 02가 정리한 제품·여행 접근·목록 계약을 입력으로 삼아, 002의 14·15·16 결과와 003의 관련 재현을 현재 코드에 대조했다. Local 변경부터 queue·push/pull·여행 정리·계정 종료까지의 관계를 한 데이터 수명 흐름으로 구성했다.

특히 PENDING만 확인하는 여행별 정리 경로와 FAILED·IN_PROGRESS까지 포함해야 하는 보존 계약의 차이를 우선 확인했다. 과거 설명, 실제 코드, 테스트·후속 결정을 구별하고 Project의 기존 Owner와 겹치거나 충돌하는 설명도 함께 정리했다.

[공통 내용 판단 기준](../spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)에 따라 기존 설명과 새 구성 모두의 적합성을 검토했다. 기존 보존 이유와 정리를 지연하는 비용은 유지하되 오래된 상태명·함수 지시·완료 보장은 옮기지 않았다. 인증 상태와 종료 실패의 상세는 기존 app-runtime Owner에 유지해 중복을 줄였다.

## 완료 조건과 확인 방법

- Local mutation과 queue 기록, push/pull, 비활성화·cleanup, 로그아웃·탈퇴 사이의 책임과 순서를 Project 진입점에서 이해할 수 있다.
- 미전송·실패·진행 중 작업이 각 정리 경로에서 어떻게 보존되는지 현재 코드와 근거에 대조되어 있다.
- 채택된 제품 계약, 현재 구현, 확인하지 못한 동작과 새 판단이 필요한 차이가 구별되어 있다.
- 현재 의미와 필요한 선택 이유가 Project 체계에 충분히 담기고, 현재 경로가 옛 `.claude/context`·`.claude/decisions` 문서나 그 아카이브로 읽기를 안내하지 않는다.
- 옛 제품 문서가 아카이브로 격리되거나 제거되어 경쟁 정본이나 우회 Owner로 남지 않는다.
- 대표 질문으로 읽기 경로를 확인하고, 실행한 테스트·정적 검사와 그 입증 범위 및 남은 오류를 실제 결과에 기록한다.

제품 버그 수정이나 새로운 제품 계약이 필요하면 문서 이관 완료로 숨기지 않고 별도 판단 대상으로 남긴다.

## 현재 상태와 실제 결과

[Project 데이터 수명 본문](../../../../../../project/guidance/data-lifecycle/INDEX.md)은 Local 저장·queue·push/pull·활성화·비활성화·vacuum·계정 종료를 연결한다. 가까운 형성 자료에는 즉시 해제, 원본 보존과 공간 회수의 절충 및 후속 보완을 남겼다. 옛 제품 문서와 결정 3개는 원문을 보존한 아카이브로 옮겼고, 현재 소비 경로는 새 Owner로 전환했다. 상세 대응과 선택 이유는 [이관 결과](../../../output/ticket-03-result.md)가 맡는다.

현재 코드 대조에서는 여행별 정리가 PENDING만 확인하고 일부 child UPDATE의 여행 귀속을 놓칠 수 있어 FAILED·IN_PROGRESS 변경을 충분히 보호하지 못하는 차이를 확인했다. 재활성화가 `cleanupPending`을 해제하지 않고 pending cleanup도 활성화 상태를 다시 검사하지 않아 옛 정리 예약이 적용될 수 있다. 이는 현재 소스에서 확인한 위험 경로이며 실앱 데이터 손실을 새로 재현한 결과는 아니다. 제품 코드는 변경하지 않았고 제품 개선 우선순위로 분리했다.

Main과 별도 조사 실행을 합쳐 기존 검사 11 suites·97 tests가 통과했다. 이는 메모리 SQLite·Drizzle SQL, mock HTTP·native 경계의 제한된 근거이며 여행별 세 상태 정리 안전, 재활성화 실앱 손실, 실제 PostgreSQL 동시 cursor나 기기 저장 내구성을 입증하지 않는다. 변경 문서의 파일·앵커 링크와 `git diff --check`는 통과했다. 전체 Harness 검사는 역사 문서의 링크 오류 24건 때문에 실패했으며 현재 본문의 링크 결과와 구별한다.

최종 독립 검토는 저장부터 종료까지의 설명, 미전송 보호 차이, 유효한 이유와 비용, 대표 읽기 경로 및 옛 정본 제거에 문서 이관 완료 근거가 있다고 판단했다. 실제 문서 이관·참조 전환은 `c69b463`으로 커밋했으며, 006 조사·검토 결과와 상태는 별도 기록 커밋으로 분리한다. 다음 문서 이관은 Ticket 04의 오프라인 지도·경로다.

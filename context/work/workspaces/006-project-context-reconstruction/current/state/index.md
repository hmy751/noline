## 다음 Ticket에서도 적용할 판단

[Spec 04](../memory/spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)에 따라 기존 내용의 현재 적합성과 문서 역할에 맞는 구성을 함께 판단한다. 기존 표·목록·체크리스트가 적합하면 유지할 수 있다. 새 형식으로 통일하거나 원문을 그대로 옮겼다는 사실로 판단을 대신하지 않는다. 재배치 뒤에는 조건·예외·이유·규칙 강도·예시 범위와 주변 읽기 경로를 대조한다.

이관한 주제는 현재 가이드·Project 본문·형성 자료만으로 필요한 뜻과 선택 이유를 이해하게 한다. 옛 제품 자료는 일반 읽기에서 제외되는 archive로 격리하거나 제거하고, 역사 조사 접근점과 현재 읽기를 구별한다. 제품 약속과 코드 차이는 드러내며 문서 수정으로 제품 결함까지 해결했다고 쓰지 않는다.

## 현재 결과와 확인 한계

02의 실제 산출물·원본 대응은 [이관 결과](../../output/ticket-02-result.md), 내용·구성별 수정과 유지 이유는 [재리뷰](../../output/ticket-02-content-review.md)에 있다.

03은 [데이터 수명 결과](../../output/ticket-03-result.md)에 새 Project 본문, 옛 문서 3개의 보존·격리, 현재 참조 전환과 코드 대조 결과를 남겼다. 기존 검사 11 suites·97 tests와 변경 문서 링크 검사는 통과했지만, 여행별 FAILED·IN_PROGRESS 보호와 재활성화 뒤 정리 예약의 실앱 안전을 입증하지 않는다. 전체 Harness 검사는 현재 산출물과 구별되는 역사 링크 오류 24건 때문에 실패한다. 제품 코드는 변경하지 않았다.

다른 주제가 함께 쓰는 옛 결정·혼합 문서와 Project의 미이관 링크는 남아 있다. 역사 Work의 원문 링크를 현재 제품 안내로 되살리지 않으며, 남은 주제의 이관과 전체 읽기 분리는 04–08에서 이어간다.

## 다음 행동

04에서 데이터 활성화 완료와 오프라인 지도 pack·경로 준비·만료·재시도의 차이를 현재 코드와 채택된 계약에 대조한다. 기존 설명과 형식의 적합성을 판단하고, 현재 Project Owner 구성과 옛 문서 읽기 경로를 정리한다.

제품 수정을 별도로 진행한다면 여행별 미전송 판정과 재활성화 정리 보호를 우선 검토한다. FAILED·IN_PROGRESS·귀속 불명 작업 보존, 검사와 쓰기 사이의 경합, 재활성화 시 예약 취소를 함께 다뤄야 한다. 이 권고는 아직 제품 구현이나 새 제품 정책으로 채택된 결과가 아니다.

예정 06에서는 일정 수정의 online → offline/unknown → online 전환 중 입력 표시·편집과 내부 값 보존, 자동 제출 없음, 복귀 후 재저장을 확인한다. 현재 Drawer가 전체 입력 영역을 제한 안내로 바꾼다는 사실은 확인했지만 입력값 소실까지 확인된 것은 아니다.

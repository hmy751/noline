# Ticket 02 결과 — 제품·활성화·네트워크 접근

2026-10-31, 바로 앞서 수행한 Ticket 02 결과를 정정된 이관 기준에 맞춰 수정했다. 제품 기준·여행 접근의 현재 설명과 필요한 선택 이유를 Project에서 읽도록 구성하고, 옛 Policy 호환 진입을 제거했다. 02가 맡은 제품·접근·목록·화면 복구 범위의 이관을 마쳤으며 006 전체 완료나 저장·지도·폼 전체 이관을 뜻하지 않는다.

## 현재 결과와 달라진 읽기

[제품 기준](../../../../project/common/product.md)은 활성·비활성 여행과 연결 상태별 데이터 위치, 여행 기본 정보·읽기 내용·작성 초안의 서로 다른 보존 이유를 설명한다. 새 여행의 서버 생성, 같은 계정의 Local 이용과 데이터·날짜·통화·ID·원자성 관계를 유지했다. 이 본문이 준비·폼의 옛 문서를 다시 읽도록 하던 링크는 제거하고 제품 수준에서 필요한 조건과 한계를 직접 적었다.

[여행 접근 본문](../../../../project/guidance/travel-access/INDEX.md)은 네트워크 관측, Policy·Router 책임, 여행 목록 반영·출처·선택, 조회·캐시 표시, 화면 복구·초안 보존의 현재 Owner다. Router와 목록 계약을 코드와 대조해 추가했고, 옛 Selective Activation 본문에 있던 같은 상세는 새 Owner 안내로 정리했다. 오류 가이드의 이관된 화면 설명도 새 Owner를 안내하도록 좁혔다.

[형성 맥락](../../../../project/guidance/travel-access/_background/context.md)과 [선별 근거](../../../../project/guidance/travel-access/_background/evidence.md)에 Data/Service·Policy 책임을 나눈 이유, 기각 대안, 조회 배치·홈 표현·목록·경비 초안·네트워크 관측의 전환과 발췌를 담았다. [Selective Local-First 결정](../../../../project/decisions/0001-selective-local-first.md)도 이유와 재검토 조건을 직접 설명한다. 이 문서들은 옛 `.claude/context`·`.claude/decisions`·아카이브를 현재 읽기 경로로 연결하지 않는다.

Project 색인·Decision 색인, client/UI guide, 관련 rule·guard·현재 맥락, 문서 관리 command reference의 해당 주제 진입을 새 Owner에 맞췄다. 스킬·설정·실행 체계를 개편한 것은 아니다.

## 확인한 근거와 범위

이번 Main은 Router·TripRepository·Local 목록 반영·useGetTrips·여행 선택을 다시 읽고 추가한 목록·접근 설명과 대조했다. 앞선 실행에서는 Policy 표·hook, 공통 조회·소비자, Query 설정·취소 helper와 Network Store를 대조했다. 제품 코드는 이번에 변경하지 않았다.

독립 검증자는 기존 결정·002 기록의 발췌·기각 이유·보류 범위와 새 형성 자료를 대조하고 Router·Repository·Local datasource·조회/선택·목록 갱신·공통 조회 조합을 확인했다. 발견한 Policy UI의 옛 오류 가이드 경유, 활성화의 이전 목록 anchor, command reference의 옛 결정 경로를 수정했다. 좁은 재확인에서 그 결함이 해소됐고 새 필수 수정은 없었다. 검증 당시 남아 있던 Work 결과의 옛 상태 설명은 이 결과문서에서 재작성했다.

대표 질문을 현재 Project에서 읽어 확인한 답은 다음과 같다.

- 비활성 여행의 카드·선택은 기본 맥락으로 유지하지만 일정·경비 내용은 읽기 정책으로 제한한다. 열린 초안은 사용자의 미저장 입력이어서 보존하고 실행 불가 영역만 제한하는 것이 계약이다. 현재 일정 수정 화면은 정책 제한 때 입력 영역 전체를 대체하는 차이가 있으며, 이 구현을 계약 충족으로 설명하지 않는다.
- 표시 online·실제 offline이면 성공한 캐시는 표시할 수 있지만 재조회는 막는다. 캐시가 없으면 실제 정책의 제한을 적용한다.
- Data는 소유권·무결성·sync를, Service는 외부 호출·가용성을 맡는다. Router를 온라인마다 Server 우선으로 바꾸는 안과 사용자 모드 선택을 기각한 이유를 새 자료에서 찾을 수 있다.
- 목록 fallback은 활성 여행·세션·제한된 API 장애 조건을 지키며, 사라진 기존 선택은 성공·갱신 종료·실제 online·remote/mixed일 때만 정리한다.

앞선 2026-10-30 실행의 client 검사 4 suites·65 tests 통과는 해당 코드 판본에서 제어된 Network Store·Query·화면·목록 연결을 확인한 결과다. 이관 마무리에서는 이를 재실행하지 않았고, 이후 사용자가 요청한 [내용 적합성 재리뷰](ticket-02-content-review.md)에서 7 suites·146 tests를 직접 실행해 통과했다. 실기기 단절·native 지도·실서버 sync 성공의 근거로 확대하지 않는다.

그 재리뷰에서는 기존 내용 보존과 현재 적합성 확인을 구별했다. 옛 Policy에서 따라온 존재하지 않는 `ServiceConfig` 변경 지시를 실제 타입·정책표·소비자로 정정했고, 원결정의 기록 우선과 좌표 없는 일정의 지도 제한·수동 보완 이유를 복원했다. 새 본문의 관련 계약을 함께 읽는 장점은 유지했다. 두 수정은 별도 검증자의 원문·코드 대조를 마쳤다.

이후 context 변경분을 다시 검토해 일정 수정의 입력 표시 계약을 현재 구현으로 일반화한 문서 오류를 추가로 발견했다. 제품 기준·여행 접근·형성 맥락에서 계약과 구현 차이를 구분하고 좌표 보완 설명에도 수정 정책 허용 조건을 명시했다. 146개 테스트는 일정 수정의 연결 전환 중 입력 표시까지 입증하지 않는다. 발견 근거와 이전 검증의 한계는 [내용 적합성 재리뷰](ticket-02-content-review.md#변경분-재검토에서-추가로-확인한-차이)에 기록했고, 제품 수정·동작 검증은 후보 06에 구체적으로 남겼다.

## 문서 구성까지 다시 판단한 결과

내용 대조만으로 구성 적합성을 확인했다고 볼 수 없어 02를 다시 열고 이번 변경 문서 전체를 역할별로 검토했다. 여행 접근은 사용 조건·핵심 규칙과 작업별 진입, 책임 경계, 구체 계약, 구현 접근점 순으로 정리했다. 별도 체크리스트의 의미는 해당 조건 가까이에 통합했으며 상태 비교표·제품 장면·결정 이유·compact rule처럼 적합한 기존 구성은 유지했다. 주변 입력 설명과 오류 예시의 범위도 보완했다.

재구성 과정의 누락·앵커 지적을 수정하고 독립 재확인을 받았다. 역할별 유지·변경 이유, 대표 읽기와 확인 범위는 [내용·구성 재리뷰](ticket-02-content-review.md#문서-역할과-구성-재검토)에 있다. 이 관점은 공통 Spec과 후속 Ticket 진입에 반영했으며 기존 형식의 재사용을 금지하는 규칙으로 만들지 않았다.

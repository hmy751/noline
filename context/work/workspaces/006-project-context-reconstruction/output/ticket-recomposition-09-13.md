# 09–13 실행 Ticket 구성

2026-10-31. 사용자는 기존 이관에서 주의했던 내용·형식 판단을 다시 적용해 합칠 내용, 새로 받아들일 유효한 내용, 버릴 내용을 판단한 뒤 Ticket을 재구성하도록 요청했다. 앞선 추가 조사에서 사용 중이라는 이유로 rules·guards·runbooks 등의 현 위치를 유지했던 분류와 좁은 두 묶음 제안은 이 구성으로 대체한다.

01–08의 검증된 제품 본문과 이관 결과는 재사용한다. 그 완료를 남은 `.claude` 전체의 적합성·필요성 확인으로 확대하지 않는다. 006의 같은 Spec 안에서 아래 09–13을 이어 수행한다. 이 문서는 실행 범위·완료 근거·의존 관계를 정하는 Main의 구성 산출물이며, 현재 진행은 Ticket/state가 소유한다. 아직 실제 통합·제거에 착수하지 않았다.

## 공통 수행 기준

[Spec 04](../current/memory/spec/04-quality-and-completion.md), [내용 판단 기록](../records/2026-10-31-03-cross-ticket-content-review-criteria.md), [역할·형식 판단 기록](../records/2026-10-31-04-document-role-and-format-review.md)을 모든 후속에 적용한다.

- 기존 원문과 받을 본문을 함께 검토한다. 현재 코드·유효한 계약·실제 사용 조건으로 내용 자체를 확인한다. 현재 구현을 이유로 채택된 약속을 자동 축소하지 않는다.
- 중복은 조건·예외·규칙 강도·이유·비용을 대조해 통합한다. 필요한 내용이 빠져 있으면 근거를 확인해 보강하고, 낡은 지시·중복 절차·근거 없는 보장은 현재 기준에서 제외한다. 새로운 제품·운영 약속의 채택은 사실 복원과 구별한다.
- 표·목록·체크리스트·예시·문단은 역할에 맞게 유지하거나 바꾼다. 파일 수 감소나 새 형식 일치만으로 개선을 판단하지 않는다. 긴 새 통합 문서 하나로 모두 몰아넣지도 않는다.
- 각 Ticket이 조사·내용 구성·선택 이유·현재 참조 전환·옛 호출/읽기 경로 분리·검증까지 완성한다. 같은 파일을 다른 Ticket도 사용한다는 이유로 자신의 변경에 필요한 연결 수정을 미루지 않는다.
- 독립 검토는 원문 자체의 현재 적합성, 새 구성의 이득과 부담, 손실된 조건·이유를 확인한다. 별도 검증은 최신 산출물·실제 읽기/호출·필요한 검사의 범위로 판단한다. 링크 통과와 내용 충분성, 정적 bridge와 실제 도구 동작을 구별한다.
- 각 결과에 통합·보강·제외·잔존의 이유와 실제 위치를 남긴다. 현재 사용처가 있다는 것은 대체할 연결의 근거이며 현 구조 유지의 충분한 이유가 아니다.

## 09 — 제품 개발 기준과 위험 점검의 통합

### 맡은 결과

같은 제품 규칙을 `.claude/rules`·guards·Project에서 따로 관리하던 중복과 권위 모호함을 해소한다. 관련 작업자가 적용 조건·위험·확인 방법을 현재 주제 본문과 필요한 진입 안내에서 함께 찾을 수 있게 한다.

### 범위와 접근

rules 전체와 Guard Map을 02–08의 Project 제품·여행 접근·데이터 수명·구조/schema·날짜·API·오류 본문 및 관련 코드와 대조한다. root·앱/패키지 guide와 이 자료를 읽는 실행자도 함께 확인한다. 유효한 compact 설명을 어디에 둘지는 읽기 효과로 판단하며 현재의 rule/guard 분리를 보존 조건으로 삼지 않는다.

예를 들어 Local 변경과 queue의 원자성, 삭제 행의 일반 조회와 sync 전달 차이, 날짜/시점 구분은 규칙 문장만 합치지 않고 조건·예외·실패 위험을 함께 비교한다. Project의 기존 구성이 부족하면 그 본문을 재구성한다. 독립 점검 안내가 실제로 필요하면 적절한 Owner에 두되 정책을 중복 소유하지 않게 한다.

### 완료 근거

모든 현재 rule·guard의 유효 의미가 어디에 통합·보강됐고 무엇을 제외했는지 판단이 있다. 대표 변경 작업에서 올바른 계약과 현재 구현 차이를 찾는다. 해당 원본을 격리/제거하거나 꼭 필요한 연결만 남긴 이유가 분명하고, 변경에 영향받는 guide·agent·checker·Verify 선언을 함께 맞춘다. 제품 동작 수정은 범위 밖이다.

### 의존과 상태

02–08을 기반으로 바로 착수할 수 있다. 다음 실행은 09다. 새로운 목적지 디렉터리와 rule 파일 수를 미리 고정하지 않는다.

## 10 — 반복 개발·문서 관리 작업의 현재 실행 경로 통합

### 맡은 결과

같은 작업에 여러 절차·기록 위치·정책 원천을 제시하는 상황을 없앤다. 필요한 수행 방법은 현재 실행·관리 체계로 받아들이고, 낡은 명령과 불필요한 우회 경로를 정리한다.

### 범위와 접근

runbooks·workflows, check-docs/doc-save/doc-discuss/doc-refactor/generate-pr, deprecated noline-work를 현재 development·context-update·explain·work-discussion·start-app 및 Project/Work 관리 계약과 비교한다. 도구 실행 방법, 제품 규칙, 기록 책임, 역사 예시를 문서 안에서도 구별한다.

문서 command의 모든 정책 선행 읽기, commit 선행 강제, command 내부 정책 사전과 옛 저장 경로는 현재 필요를 다시 판단한다. 필요한 변경 영향 확인·원문 보존·작업 순서가 현재 체계에 빠져 있으면 근거와 함께 보완한다. generate-pr는 기능 가치와 현재 작성 기준을 별도로 비교하며 네 문서 command와 자동으로 함께 폐기하지 않는다.

noline-work의 원본·symlink·expectedSkills, workflows의 역방향 안내 등 자신의 정리에 필요한 발견·검사 연결을 이 Ticket에서 함께 바꾼다. 11로 미뤄 깨진 상태를 완료 처리하지 않는다.

### 완료 근거

새 Entity/API/Form 작업, 문서 갱신·논의·PR 작성의 대표 요청에서 필요한 내용과 실제 담당 경로를 찾는다. 같은 작업을 다른 저장 위치나 정책으로 보내는 옛 실행 지시가 현재 호출 경로에 남지 않는다. 통합된 절차의 조건·권한·이유를 보존하고, 제거한 기능이 여전히 필요하다면 대체 경로를 실제로 확인한다.

### 의존과 상태

09에서 정한 제품 기준 Owner를 사용한다. 사전 비교는 병행할 수 있지만 같은 Project·skill 본문을 동시에 수정하지 않는다. 09 이후 실행한다.

## 11 — 공통 실행 기준과 도구별 연결의 책임 정리

### 맡은 결과

Claude/Codex가 공유할 실행 내용과 각 도구가 요구하는 진입·설정의 책임을 분명히 하고, 필요한 의미를 `.claude` 안의 기존 배치에 묶어 두는 중복과 제약을 해소한다. 도구 연결을 유지하면서 불필요한 원본·사본·우회 경로를 줄인다.

### 범위와 접근

10 이후 남은 skills·공유 기준·agents·hooks·settings·harness 안내, `.agents`·`.codex` bridge와 검사 코드를 함께 대조한다. 현재 skills·공유 기준과 함께 관리되는 `_background`·형성 자료도 본문의 의미·출처·현재 읽기 관계와 함께 판단한다. 10에서 바꾸는 스킬의 관련 형성 자료는 10이 함께 맞추고, 12로 넘겨 본문만 먼저 완료하지 않는다. 공통 본문의 적절한 Owner와 도구별 필수 경로를 실제 소비 방식으로 판단한다. 공통 원본 이동이나 현 위치 유지 중 어느 쪽도 출발점에서 확정하지 않는다. 남기는 항목에는 구체적인 책임·필요 연결·대체 비용을 설명한다.

observer의 ‘모든 skill은 dispatcher’ 기준은 현재 스킬의 판단·수행 계약과 제품 의미 소유를 구별하도록 재검토한다. 양 도구 정의를 함께 맞춘다. hooks는 설정에서 wrapper·공통 구현까지 따라 중복과 실제 결합을 확인한다. 기존 Maintain의 binding·권한·guarded apply 의미를 이번 위치 정리로 새로 설계하지 않는다. 새 범용 framework나 새로운 자동 실행을 추가하는 작업도 아니다.

### 완료 근거

공통 기준의 실제 원천과 Claude/Codex의 읽기·호출 경로를 각각 확인한다. 변경한 연결과 영향받는 대표 호출을 확인하며 무관한 모든 skill·host lifecycle의 실행을 새 완료 조건으로 추가하지 않는다. 필요한 연결을 대체한 뒤 옛 연결을 정리하고 parity·discovery·관련 회귀 검사를 수행한다. 실제 host 동작이 바뀌는 범위는 가능한 제한된 실행으로 확인하며 핵심 실행 확인이 막히면 완료로 닫지 않는다. 제품 앱·외부 서비스의 실행을 도구 연결 증거로 대신하지 않는다.

### 의존과 상태

09–10의 내용·호출 정리를 바탕으로 실행한다. 09–10에서 이미 전환한 연결은 재사용하고 남은 배치만 판단한다. 충분히 판단한 Owner를 위치 통일만을 위해 다시 옮기지 않으며, 재변경에는 실제 중복·책임 충돌·도구 제약의 근거가 있어야 한다. 현재 개인 설정의 비밀값·무관한 전역 하네스는 범위에 넣지 않는다.

## 12 — 남은 선택 이유 복원과 역사 자료의 읽기 분리

### 맡은 결과

현재 판단에 필요한 이유가 sessions·audits·CHANGELOG·옛 하네스 결정에만 남아 있지 않게 하고, 현재 설명과 당시 근거의 권위를 구별한다. 역사 자료가 일반 읽기의 우회 정본이 되는 연결을 없앤다.

### 범위와 접근

남은 하네스 decisions·sessions·audits·CHANGELOG와 root/harness의 역사 연결을 09–11의 현재 Owner 및 기존 형성 자료와 대조한다. 제품 의미는 Project, 실행·관리 기준은 해당 책임 본문에 통합하고, 정확한 원문이 필요한 선택 이유는 가까운 형성 근거에 선별한다. 이미 충실히 보존한 내용을 다시 복제하지 않는다.

원문은 재검토·복구 가치와 중복 여부를 판단해 archive로 격리하거나 불필요한 사본을 제거한다. 모든 archive를 옮기거나 과거 문장을 현재 정책으로 고쳐 쓰는 작업이 아니다. 이미 격리된 자료는 현재 읽기 의존·중복·보존 문제가 있는 범위에서만 추가 처리한다.

### 완료 근거

현재 읽기에서 필요한 이유·비용·재검토 조건을 이해할 수 있고 옛 문서나 archive를 필수 단계로 열 필요가 없다. 보존한 원문은 이동 전후 일치와 출처를 확인한다. 현재 root·guide·형성 자료·live Workspace의 참조는 함께 전환하며 역사 Workspace의 기록을 일괄 최신화하지 않는다.

### 의존과 상태

09–11에서 이동하는 자료의 원문 보존과 해당 주제의 선택 이유는 각 Ticket이 맡는다. 12는 그때까지 미처리된 역사 묶음과 그 현재 소비를 맡으며 앞선 Ticket의 내용 복원을 대신하는 마지막 수거 단계가 아니다. 보존 위치는 실제 내용·소비를 보고 결정한다.

## 13 — 전체 판단·읽기·실행 경로 검증과 종료 판단

### 맡은 결과

01–12가 전체 목표를 충족하는지 확인하고 남은 `.claude` 항목마다 왜 필요한지, 어떤 내용을 어디로 통합·보강·제외했는지 설명할 수 있는 상태를 만든다. 개별 검사 통과와 전체 목표 수락을 구별한다.

### 범위와 접근

첫 후보 지도·추가 조사·이 구성의 대상과 실제 결과를 대조한다. root/Project/경로별 guide/직접 명령/skill/agent/hook에서 출발해 현재 경로의 직접·간접 연결을 확인한다. workflows에서 놓친 것처럼 기존 checker가 선택하지 않은 파일도 실제 진입에서 도달하면 검사 범위에 포함한다.

default 및 현재 explicit-bound Workspace를 확인해 필요한 Recover·Verify 선언을 맞추고, 유효한 원문·역사 기록을 보존한다. 기존 역사 참조47건은 현재 경로의 실패와 구별하고, 판단한 검사 계약과 실제 결과를 공개한다. 근거 없는 제외나 전체 역사 원문 재작성으로 green을 만들지 않는다. checker 자체를 바꾸면 그 경계도 검증한다.

### 완료 근거

현재 내용의 정합성과 충분성, 재구성의 이득과 비용, 옛 읽기·발견 경로 제거, 필요한 host 연결의 동작을 각각 확인한다. 이미 알려진 항목의 담당 누락이나 현재 경로 실패가 남으면 해당 Ticket을 다시 열어 해결한다. 확인되지 않은 핵심 범위를 단순 후속 목록으로 넘기고 완료하지 않는다.

현재에 영향이 없는 역사 참조나 범위 밖 제품 버그는 근거·영향·후속을 구별한다. 남은 자료와 확인 범위를 사용자에게 제시해 006 전체 수락을 받는 단계로 연결한다. 사용자의 수락을 검사나 Main 판단으로 대체하지 않는다.

### 의존과 상태

09–12의 자체 검증 후 마지막에 실행한다. 새 내용을 이때 처음 조사·통합하는 기본 계획이 아니며 전체 연결의 누락을 최종 확인한다.

## 전체 범위와 순서

기본 순서는 **09 → 10 → 11 → 12 → 13**이다. 각 Ticket 안에서 독립된 근거 조사는 병행할 수 있지만 같은 본문·연결의 수정 담당은 하나로 둔다. 규모를 확인한 뒤 더 나눌 필요가 생기면 각 하위 결과가 내용·참조·격리·검증까지 완성되는지 먼저 판단한다.

rules·guards와 관련 Project는09, runbooks·workflows·commands·deprecated noline-work는10, 남은 공통 실행 본문·agent·host 연결·harness 현재 설명은11, 미처리 역사 본문과 그 현재 의존은12, 전체 후보·남은 파일·간접 경로와 확인 상한은13이 맡는다. root·경로별 guide·checker·bridge·live consumer는 자신을 바꾸는 각 Ticket의 영향 범위이며 마지막 Ticket만의 책임이 아니다.

제품 동작 버그·신규 기능·운영 배포 수정·개인 협업 기준 개선은 이번 구성 밖이다. 이미 확인한 데이터·지도·입력·접근/공개·금액·배포 공백은 02–08 결과에 남기고, 이 문서 정리를 통해 해결됐다고 보고하지 않는다. 실제 command 호출 빈도·외부 링크·일부 host 동작은 아직 미확인이므로 해당 실행 Ticket에서 필요한 확인과 그 판단 영향을 구체화한다.

## 기존 Ticket을 재구성한 관계

자동 기록에 먼저 생성됐던 `09-claude-content-integration-and-cleanup.md`는 전체 남은 정리를 한 Ticket에 담았다. 같은 파일의 제목·범위·완료 기준을 **09 제품 개발 기준과 위험 점검 통합**으로 좁히고, 나머지 책임은 아래 10–13으로 분리해 실제 본문에 반영했다. 이전의 넓은 09는 별도 실행 범위로 남기지 않았다.

- 09: 기존 `current/memory/tickets/09-claude-content-integration-and-cleanup.md`를 구체화.
- 10: `current/memory/tickets/10-development-and-document-workflows.md`.
- 11: `current/memory/tickets/11-shared-execution-and-host-connections.md`.
- 12: `current/memory/tickets/12-historical-reasons-and-reading-separation.md`.
- 13: `current/memory/tickets/13-integrated-verification-and-acceptance.md`.

[Ticket 색인](../current/memory/tickets/index.md)은 제목·맡은 결과·본문 경로를 연결하며, [state](../current/state/index.md)는 다음 실행을 09로 안내한다. Spec의 목표·권한과 공통 품질 기준은 이어 적용한다. 이 문서는 재구성 이유와 책임 경계를 설명하며, 이후 실제 진행과 실행 정의는 state와 각 Ticket에서 확인한다.

구성에 대한 독립 검토는 알려진 범위의 담당 누락·단계만 분리한 책임 공백·현 위치 유지 전제·불필요한 전면 재설계를 찾지 못했다. 제안된 형성 자료 책임과 영향 범위에 한정한 host 검증을 반영했다. 이는 Ticket 구성의 검토이며 실제 통합·제거·호스트 동작을 검증한 결과가 아니다.

# 변경 문서의 역할과 형식을 판단한 뒤 재사용한다

2026-10-31, Ticket 02의 내용·구현 대조 뒤에도 구성 판단이 빠진 문제를 사용자가 명확히 했다. 아래는 이번 대화에서 보존한 최소 원문이다.

> 난 사실 context/project/guidance/travel-access/INDEX.md 여기에서 체크리스트랑 이런게 지금 형식과 달라서 한 번 물어본거였어 니가 정말 판단해서 내린결정인가 아니면 그냥 가져온건가 싶어서

> 그래 그럼 체크리스트만 없애지 말고 지금 변경분 문서들을 전체를 지금 기준에 맞게 판단해서 수정해줘. 이 관점도 워크스페이스에 기록해서 다른 티켓에서도 그냥 가져오는 실수 안 하게 해줘

> 그래 물로 ㄴ기존 형식이 적합하면 가져오는건 상관없는데 지금처럼 판단이 빠지거나 뭔가 놓친건 문제가 있어보여

Main은 체크리스트 다섯 항목을 옛 Policy에서 그대로 가져왔고 이전 검토가 그 구성의 적합성까지 입증하지 못했음을 인정했다. 현재 기준은 기존 형식 재사용을 금지하지 않는다. 유지·변경을 문서의 역할, 읽을 조건, 판단과 행동, 중복, 의미 보존에 따라 정해야 한다는 것이 이번 교정이다.

체크리스트만 제거하면 의미가 빠지고, 모든 문서를 기준 본문 형식으로 맞추면 구조 설명·결정 이유·원자료의 역할이 훼손된다. 따라서 현재 006의 변경 문서 전체를 역할별로 검토했다. 여행 접근의 기준과 실제 연결은 사용 조건·책임·적용 관계 순으로 정리하고 확인 항목을 관련 조건에 통합했다. 상태·비교 표, 제품 장면, 결정 이유, compact rule과 위험 지도 등 적합한 구성은 유지했다. 주변 입력 설명의 과장, 오류 예시 범위의 누락과 중간 archive의 지위도 보완했다. Work는 기존 운영 계약 안에서 상세 결과·실행 정의·다음 행동의 중복을 줄였다.

독립 리뷰에서 이번 재배치 중 빠진 사용자 안내의 내부 구현명 금지 조건을 발견해 복원했다. 이후 해당 조건과 새·역사 앵커를 좁게 재확인했다. 구성의 이득과 조건·예외·강도 보존은 함께 확인해야 한다는 실제 근거다. 제품 코드를 수정하거나 이전 테스트 통과를 새 제품 검증으로 재해석하지 않았다.

후속 적용은 [Spec 04](../current/memory/spec/04-quality-and-completion.md#후속-ticket의-내용-판단과-리뷰)가 소유한다. [Ticket 색인](../current/memory/tickets/index.md)과 03에서 같은 기준을 연결하며, 이후 Ticket도 주제별 원자료·현재 산출물·주변 설명을 함께 대조한다. 모든 문서에 같은 검토표를 만들거나 기존 형식을 바꾸라는 의무는 아니다. 역할별 실제 처리와 대표 읽기 결과는 [내용·구성 재리뷰](../output/ticket-02-content-review.md#문서-역할과-구성-재검토)에 있다.

마무리에서 Work의 별도 정적 검토도 완료했고 필수 보완은 없었다. Main의 이번 수정 문서 19개 로컬 파일·앵커 링크 검사와 `git diff --check`는 통과했다. 006 id를 명시한 Recover에서 공통 구성 기준과 02 완료·03 대기 상태를 확인했다. 제품 코드·기존 raw source·날짜별 record는 변경하지 않았으며 전체 Harness 통과나 006 전체 완료를 주장하지 않는다.

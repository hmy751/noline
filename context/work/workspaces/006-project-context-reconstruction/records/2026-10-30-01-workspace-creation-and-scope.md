# Project Context 재구성 Workspace 생성

## 선택의 배경

005의 개별 보완 결과가 사용자 기대에 못 미쳐 작업을 종료했다. 사용자는 폭넓은 수집·검증, `.claude` 문서의 이관 준비, 002의 다양한 축적 반영, 004처럼 구체적인 제품 질문 나열, 기존 Project 본문의 적극적인 정리를 원했다. 정확한 발화는 [사용자 원문](../source/user-direction.md)에 보존했다. 사용자가 말한 `project/context`는 이 저장소의 `context/project` 본문을 가리키는 것으로 해석했다.

작업량은 클 수 있지만 결과가 Project Context의 재구성으로 연결되므로 하나의 Spec으로 관리한다. 지금 모든 세부 Ticket을 확정하면 자료를 보기 전에 Main의 분류로 범위를 좁힐 수 있다. 따라서 첫 Ticket은 넓은 자료·내용 후보 조사로 정하고, 결과를 토대로 후속 주제를 나누기로 했다.

## 구성과 범위

006은 005의 후속 방향을 독립된 current에 소유한다. 002·004·005의 상세 자료는 필요한 exact 경로로 단방향 연결했다. 과거 Workspace의 진행 상태나 검증 receipt를 복제하지 않았다. 005의 수행 결과를 되돌리지 않지만 기존 Ticket 구성과 목표 달성 판단은 승계하지 않는다.

문서 이관은 검증과 현재 본문 재구성을 포함한다. `.claude` 전체의 이동·삭제나 스킬·설정 개편으로 확대하지 않는다. 제품 지식과 실행 지침이 섞인 자료는 실제 사례를 보고 처리 범위를 논의한다. 기존 Project의 구조도 검토 대상이며, 보존 대상은 유효한 의미·이유·근거다.

## 이번 실행의 경계

Main이 새 Workspace의 Spec 다섯 파일, 첫 Ticket, 상태·source·output·records와 기계 계약을 구성했다. 생성 전 Git 상태에서 `.pnpm-store/`만 untracked였고 해당 내용을 건드리지 않았다. Project 본문과 기존 Workspace는 수정하지 않았다. 생성 기준 HEAD는 `f525421`이다.

이 기록은 생성과 범위 선택의 근거다. 재진입·링크 검사 결과는 검증 후 별도 기록으로 남긴다. 자료 조사와 실제 이관, session 활성화, 커밋은 이번 생성 결과에 포함하지 않는다.

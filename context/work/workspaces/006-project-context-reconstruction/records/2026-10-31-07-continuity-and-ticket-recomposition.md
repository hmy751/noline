# 현 위치 유지 전제의 교정과 09–13 재구성

## 사용자 정정과 바뀐 판단

08 뒤 Main은 `.claude`의 rules·guards·runbooks·hooks와 역사 자료를 ‘현재 유지’로 분류했다. 실제 사용·참조와 역할의 존재는 확인했지만, 필요한 역할을 보존하는 것과 현 위치·구조를 유지하는 것을 같은 결론으로 묶었다. 사용자는 “왜 유지해”라고 물었다.

Main은 현재 참조는 정리할 때 대체해야 할 연결의 근거이며, 현 구조를 유지할 충분한 이유가 아니라고 교정했다. 사용자는 이어 다음과 같이 요청했다.

> 그래 다시 작업하면서 주의했던점 유의해서 합칠건 합치고 새로 받아들일건 받아들이고 다만 판단해서 버릴건 버리고 등등 이전 기록 확인해서 작업방식 주의점 생각해서 다시 어떻게 할지 설명해봐

이는 기존 내용을 무조건 보존하거나 `.claude`를 무조건 비우라는 지시가 아니다. 기존 설명과 받을 본문을 현재 근거에 함께 대조하고, 유효한 의미·이유·조건·비용을 통합·보강하며 낡거나 불필요한 내용은 제외하라는 판단 요구다. 도구 연결은 실제 소비와 대체 범위를 확인한 뒤 정리한다.

이 교정은 앞선 02의 체크리스트 문제와 연결된다. 당시 사용자는 기존 형식이 적합하면 재사용해도 되지만 판단 없이 가져오거나 조건을 놓치는 것은 문제라고 했다. 이번에도 형식·경로 보존 자체를 목적에 두지 않고, 기존의 장점을 잃지 않으면서 새 구성이 이해·관리에 실제로 도움이 되는지 판단한다. [내용·구성 재리뷰](../output/ticket-02-content-review.md)에 그 실제 발견과 수정이 있다.

## 한 개의 넓은 Ticket을 결과별로 나눈 이유

자동 기록은 앞선 설명을 전체 정리를 맡는 넓은09로 먼저 반영했다. 사용자가 “그래 다시 티켓 구성해봐 그럼”이라고 요청한 뒤 Main은 이 범위를 09–13으로 재구성했다. 제품 기준, 반복 수행, 공통 실행·도구 연결, 역사 이유와 전체 검증은 각각 다른 결과를 확인해야 하므로 나눴다. 수집·작성·링크 수정 같은 작업 단계별로 나누면 한 주제를 아무도 끝내지 않는 문제가 생기므로 각 Ticket이 내용부터 경로 정리와 확인까지 맡는다.

[구성 산출물](../output/ticket-recomposition-09-13.md)은 대상·완료 근거·의존 관계를 설명한다. 09는 기존 파일을 좁혀 제품 기준·위험 점검을 맡고, 10은 반복 개발·문서 관리 절차, 11은 공통 실행·도구 연결, 12는 미처리 선택 이유·역사 자료, 13은 전체 검증을 맡는다. 현재 실행 정의는 [Ticket 색인](../current/memory/tickets/index.md)의 본문에 반영했다.

독립 구성 검토자는 알려진 담당 누락·단계 분할의 책임 공백·현 위치 유지 전제·불필요한 전면 재설계를 찾지 못했다고 보고했다. 스킬과 함께 관리되는 형성 자료도 같은 담당이 보도록 하고, host 검증을 변경한 연결·영향받는 대표 호출에 한정하는 두 제안을 Main이 반영했다. 이 검토는 구성의 적합성을 다뤘으며 실제 이관·제거·도구 동작을 확인한 것은 아니다.

## 현재 수락된 범위와 이번 정리

사용자는 구성 설명 뒤 “좋아 기록 정리하고 다른 세션이 봐도 이워크스페이스 흐름 맥락을 알도록 잘 적고 구성해봐”라고 요청했다. Main은 실제09–13 파일·색인·state 반영을 확인하고, 재진입 README·현재 상태·기록 색인과 철회된 후보 권고의 지위를 맞췄다. 전체006을 완료로 수락하거나09의 실제 통합·삭제를 시작하라는 뜻으로 확대하지 않았다.

01–08의 유효한 결과는 재사용한다. 07 작업/기록은 `1a614ab`/`f466a32`, 08은 `bebf123`/`55dbe0a`로 커밋됐다. 후속 범위와 이번 기록 정리는 별도 미커밋 변경이다. 제품 공백과 전체 Harness 역사 참조47건은 계속 구별하며 원문 보존을 위해 검사를 느슨하게 만들거나 과거 기록을 현재 정책으로 덮어쓰지 않는다.

자동 Maintain의 과거 generation1 실패·미반영은 [복구 기록](2026-10-31-06-record-repair-and-cleanup-investigation.md)에 남아 있다. 이번 정리 전 generation2의 대기 event는 실제 완료되어09–13 반영을 확인했다. Main은 중복 쓰기를 피하려고 연결을 잠시 해제하고 explicit006 bootstrap과 guarded apply로 기록 정리를 수행한다. 이 기록은 자동 event의 성공을 소급 선언하거나 다른세션의 binding을 바꾸지 않는다.

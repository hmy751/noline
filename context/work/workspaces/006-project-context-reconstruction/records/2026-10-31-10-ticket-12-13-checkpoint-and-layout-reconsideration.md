# Ticket 12·13 중간 커밋과 배치 재검토

## 실제 결과와 중간 커밋

Main은 Ticket 12에서 CHANGELOG를 현재 Owner와 대조하고 원문을 보존한 뒤 현재 읽기에서 제거했다고 보고했다. 역사 링크 baseline 63건 중 live 002 output의 중복 1건을 정리해 strict 실패는 62건이 됐다. 고유 target 29개 중 27개의 Git 객체와 문서 25개의 보존판을 확인했지만, 미커밋 초기 코드 원판 2개는 보존을 확인하지 못했다.

Ticket 13에서는 최초 후보와 현재 Owner를 대조하고 client/server guide와 Project Decision의 잔여 읽기 결함을 고쳤다. 당시 live consumer로 판단한 001·002·006의 입력을 대조했으며, 001 구조 검사와 002 타입 검사는 각각 역사 링크와 현재 제품 타입 오류로 실패했다. 이 실패는 receipt에 그대로 보존했고 후속 Recover 세 건은 성공했다. Main은 독립 검토와 별도 검증의 발견을 반영하고 재확인했다고 보고했다.

사용자는 이 결과를 먼저 기록하고 커밋하라고 요청했다. 이 중간 커밋은 위 작업과 검증 근거를 보존하기 위한 것이며 006 전체 완료나 검사 통과를 뜻하지 않는다.

## 필요한 책임과 기존 배치를 다시 구별한 이유

전체 대조 결과는 `.claude/README.md`, `.claude/harness/README.md`, `.claude/_archive`에 남은 역할을 설명했지만, 역할이 필요하다는 사실과 그 역할을 기존 `.claude` 계층에서 계속 소유해야 한다는 판단을 충분히 구별하지 못했다.

2026-10-31 현재 대화에서 사용자는 다음처럼 문제를 제기했다. 아래는 해당 발화의 연속된 부분을 그대로 발췌한 것이다.

> 여기 내용이이렇게 필요한가 싶어 __archive도 루트로 옮기고 .claude에 굳이 이런 관리가 필요한가? 싶은?
> 그리고 지역 전역 CLAUDE.md 도 어떤식으로 구성하고 관리할지 좀 context 고려해서 생각해봤으면 좋겠어

Main이 실제 문서를 다시 대조한 결과, 두 README의 읽기 순서·주제 링크·Owner·보존 설명은 root guide와 Context 문서에 상당 부분 반복됐다. 정확한 옛 원문을 현재 읽기와 분리해 보존하는 책임도 필요하지만, 그 책임이 Claude host 전용 폴더를 요구하지는 않는다. 실제 Claude host 소비자는 settings·hook wrapper·공통 스킬 symlink로 더 좁게 식별할 수 있다.

따라서 이전 결과의 남아 있는 역할 판단은 유지하되, 그 역할 때문에 기존 README·harness 문서와 archive 배치를 유지한다는 결론은 변경했다. 유효한 의미를 기존 Owner에 통합하고 현재 소비 경로를 전환한 뒤 문서를 제거하며, 옛 원문은 root `_archive/`로 옮기는 방향이다. Context·스킬의 현재 형성 자료와 Work 기록까지 archive에 모으지는 않는다.

## 채택한 다음 순서와 경계

Main은 먼저 현재 결과를 기록·커밋하고 `.claude` 문서·archive 정리부터 진행하라는 요청으로 해석했다. 프로젝트 root·하위 `CLAUDE.md` 정리는 후속 단계에 두고, 전역 개편은 다른 프로젝트에 미치는 영향 때문에 별도 작업으로 구분한다.

1. 현재 Ticket 12·13 결과와 실패 receipt를 중간 커밋으로 보존한다.
2. `.claude/README.md`와 `.claude/harness/README.md`의 유효한 내용을 실제 Owner에 통합하고 제거 가능성을 확인한다.
3. `.claude/_archive`를 root 보존 경계로 옮기며 현재 참조·보존 경로표·검사를 함께 맞춘다. 보존 원문과 원래 경로·해시는 유지한다.
4. 프로젝트 root와 하위 `CLAUDE.md`를 경로별 진입 지침으로 정리한다.

전역 개편은 이번 006 종료의 선행 조건으로 삼지 않는다. 전역 지침은 공통 행동·권한·조건별 진입을, Personal은 판단 관점·경험을 맡으므로 한 저장소의 Personal로 전역 지침을 옮기는 방식도 채택하지 않는다.

역사 records/source를 현재 정책으로 소급 수정하지 않고, 제품 타입 오류나 미커밋 원판 부재를 이번 문서 배치 변경으로 해결했다고 보고하지 않는다. 006 전체 수락은 로컬 정리 결과와 한계를 제시한 뒤 별도로 받는다.

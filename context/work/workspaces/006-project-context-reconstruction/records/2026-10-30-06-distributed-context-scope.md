# 루트·앱·패키지의 분산 컨텍스트를 작업 범위에 명시

## 사용자 요청

> 아 맞다 그것도 보완해줘 보면 .claude도 범위지만 펴져있는 컨텍스트 예를 들어 루트나 프로젝트에 있는 CLAUDE.md 같은것들도 확인하고 작업 범위로 넣어줘

출처는 현재 대화의 사용자 발화다. 기존 Spec의 “다른 흩어진 문서”만으로는 루트·앱·패키지의 가이드가 뒤로 밀리거나 참고 링크로만 취급될 수 있어 실제 조사·정리 대상으로 구체화했다.

## 반영한 범위와 순서

`.claude` 문서와 현재 Project의 대응·이관 관계를 먼저 드러내는 우선순위는 유지하면서, 루트·앱·패키지의 `CLAUDE.md`, `AGENTS.md`, README 등 분산된 컨텍스트를 최초 대응 조사에 함께 포함했다. 문서에 남길 안내·기준, 보완할 본문, 통합·이관할 내용과 중복·충돌을 판단하며 후속 문서 변경까지 작업 범위로 삼는다. 이 예시 파일들만으로 전체 조사 범위를 제한하지 않는다.

Spec의 범위·조사 접근·품질 기준, Ticket 01의 입력·첫 결과·완료 기준, state의 다음 행동·다른 세션 안내, source 색인의 실제 접근점을 맞췄다. 스킬·설정 개편의 별도 논의 경계는 유지하지만 이를 문서 내용 검토에서 제외하는 근거로 사용하지 않는다. 모든 가이드를 아카이브하거나 Project로 일괄 이동한다고 정한 것은 아니다.

## 확인 범위와 다음 작업

`aae7c22` 이후 작업 트리에서 root, apps/client, apps/server, packages/schema, packages/ui의 `CLAUDE.md`와 각 위치의 `AGENTS.md -> CLAUDE.md` 연결을 확인했다. 같은 본문을 두 개의 독립 자료로 집계하지 않는다. 경로와 연결을 확인했으며 본문 최신성·제품 사실·최종 처리 방안은 아직 조사하지 않았다.

이번에는 006의 작업 정의와 기록만 보완한다. 원본 가이드나 제품 코드는 수정하지 않았고, 실제 조사는 다른 세션의 Ticket 01에서 이어간다. 앞선 인수 리허설은 그 당시 범위를 검토한 기록으로 보존하며, 새 범위는 최신 Spec·Ticket·state에서 읽는다.

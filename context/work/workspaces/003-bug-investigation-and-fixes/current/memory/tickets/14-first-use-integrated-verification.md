# 14. 개발자 첫 사용의 iOS 통합 검증

## 맡은 결과와 범위

개별 수정 이후 개발자가 앱을 처음 켜 주요 기능을 연속해서 시험할 수 있는지 실제 iOS 사용 결과로 판정한다. 카테고리별 정상 사용·실패 복구·기능 간 연결을 로컬/서버 데이터와 함께 확인해 전체 완료를 판단할 근거를 만든다.

이 티켓은 테스트와 판정 결과를 맡는다. 알려진 결함의 수정이나 각 domain의 미확인을 여기로 몰아넣지 않는다. 새 실패는 담당 티켓에 결과를 돌려보내고, 담당이 없으면 Main이 배치를 정한다.

## 실행 맥락과 접근

[카테고리 조사](../../../records/2026-09-13-02-major-feature-category-investigation.md)의 표와 미확인이 기준이다. 현재 실제 iOS 전체 실행은 미수행이다. [첫 사용 조사](../../../records/2026-09-13-01-first-use-scenario-investigation.md)의 정상·반대 조건도 유지한다.

시험 계정·격리 서버/DB·지도/OAuth 설정·iOS 실행 방법과 데이터 정리 범위를 먼저 확인한다. 개인 사용자 데이터로 삭제·계정 변경을 시험하지 않는다. fixture와 실행 절차 준비는 앞서 가능하지만, 전체 통과 판정은 01–13의 적용 결과 및 남은 blocker 검토 후에만 한다. 각 티켓의 자기 경계 검증을 이 티켓으로 대체하지 않는다.

공통 기준은 [기대 동작](../spec/02-behavior-and-cases.md)과 [품질·완료 판단](../spec/04-quality-and-completion.md)을 따른다.

## 완료 조건과 확인 방법

- 신규 설치/저장 계정 재시작, 로그인 취소·성공·갱신·재인증, 첫 여행 생성·선택·기간 수정·삭제를 수행하고 의도한 계정/여행에 남는지 확인한다.
- 비활성 온라인 일정·경비 생성/수정/삭제/상세/연결, 통화별 합계, 폼 취소/재진입과 기간 밖 항목 접근을 확인한다.
- 활성화·비활성화·재활성화·A→B 전환, 지도 다운로드 실패/재시도/삭제/재시작과 준비 표시를 실제 타일·로컬 데이터에 대조한다.
- 장소 검색·상세 지도 이동·위치 권한·marker/card·이동수단·최신 경로를 확인한다. 느린 요청·화면 전환·연속 클릭을 대표 흐름에 섞는다.
- 활성 여행 비행기 모드 입력→앱 강제 종료→재실행→재연결→서버 반영을 검증한다. 비활성 오프라인 제한, 전송 실패 후 재시도·pull 충돌·수동 sync 표시도 포함한다.
- 미전송 상태에서 로그아웃 취소, 계정 전환 중 진행 요청, 계정 삭제와 프로필 용량·개발자 reset 후 재사용을 격리 데이터에서 확인한다.
- 수행 환경·초기 데이터·행동·기대/실제 결과·관련 로그/DB 증거·담당 티켓을 남긴다. 실패·환경 때문에 못 한 항목·변경 불필요를 구분하며, unresolved blocker가 있으면 전체 완료 판정을 보류한다.
- 주석 처리된 다크 모드/언어/지도 관리 메뉴와 미지원 영수증 업로드를 새 기능 구현 요구로 추가하지 않는다.

## 현재 상태와 실제 결과

구성됨, 실행 전. 위 확인 계획을 수행하거나 제품 코드를 수정한 상태가 아니다. 기존 조사 근거는 위에 연결했으며, 실행할 때 현재 코드·환경과 수정 전 조건을 다시 대조한다.

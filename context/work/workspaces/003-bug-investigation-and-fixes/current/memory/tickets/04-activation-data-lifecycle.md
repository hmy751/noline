# 04. 활성화·비활성화·재활성화의 데이터 안전

## 맡은 결과와 범위

여행의 오프라인 데이터 소유권을 전환해도 미전송 입력을 보존하고, 다시 활성화한 여행에 과거 정리 예약이 적용되지 않게 한다. 활성화 데이터 저장, 비활성화 옵션, cleanup 예약·취소·실행, A에서 B로 전환 중 실패·중단을 함께 맡는다.

지도 타일의 다운로드 상태와 재시도 UI는 05이 맡는다. 여기서 데이터 활성화 성공을 지도·경로까지 모두 준비됐다는 뜻으로 사용하지 않는다.

## 실행 맥락과 접근

[카테고리 조사](../../../records/2026-09-13-02-major-feature-category-investigation.md)의 비활성화→재활성화→queue 소진→cleanup 실행에서 활성 여행 일정에 deletedAt이 기록됐다. A 선해제 후 B 활성화 실패 시 A 복원 부재는 소스 조건이며, 무조건 원자적 전환을 제품 정책으로 확정한 것은 아니다.

[activate](../../../../../../../apps/client/src/entities/trip/data/useActivateTrip.ts), [deactivate](../../../../../../../apps/client/src/entities/trip/data/useDeactivateTrip.ts), [cleanup](../../../../../../../apps/client/src/shared/services/sync/cleanup-job.ts), [홈 전환](../../../../../../../apps/client/src/screens/HomeScreen/TripsSection.tsx)이 연결된다. 10의 미전송 판정·원자성과 11의 실제 전송 결과가 데이터 안전 완료의 선행 결과다. 13의 활성화 응답 검증도 실제 서버 통합 전에 필요하다.

공통 기준은 [기대 동작](../spec/02-behavior-and-cases.md)과 [품질·완료 판단](../spec/04-quality-and-completion.md)을 따른다.

## 완료 조건과 확인 방법

- 정상 최초 활성화와 서버 실패 시 로컬 미활성 대조군을 보존한다. 부분 데이터 저장 실패에서는 불완전한 데이터를 활성 상태로 노출하지 않는다.
- 미전송 상태별 비활성화·데이터 보관/정리 옵션을 시험하고, 재활성화 뒤 과거 예약이 현재 활성 데이터에 적용되지 않음을 실제 저장 결과로 확인한다.
- 정리 예약 후 앱 재실행·전송 완료, 다운로드/동기화 중 반복 전환, cleanup과 재활성화가 겹치는 조건을 격리 DB에서 시험한다.
- A→B 실패 시 실제 결과를 재현하고 기존 A 보존/복원 또는 명시적 비활성·재시도 중 어떤 동작이 현재 계약에 맞는지 결정한다. 사용자 선택이 필요한 정책은 확인 전 구현하지 않는다.
- UI·activation row·로컬 일정/경비·미전송 queue가 같은 데이터 상태를 나타내고, 자동 정리로 미전송 입력이 없어지지 않는다.

## 현재 상태와 실제 결과

구성됨, 실행 전. 위 확인 계획을 수행하거나 제품 코드를 수정한 상태가 아니다. 기존 조사 근거는 위에 연결했으며, 실행할 때 현재 코드·환경과 수정 전 조건을 다시 대조한다.

# 05. 오프라인 지도 준비 상태와 재시도

## 맡은 결과와 범위

지도 다운로드 완료·실패·중단과 실제 native pack 존재가 앱의 준비 상태에 반영되게 한다. 지도만 실패한 활성 여행에서도 재시도할 수 있고, 지도 삭제·재활성화 뒤 과거 준비 flag를 재사용하지 않게 한다.

지도 다운로드/정리/재사용, activation metadata, 활성화 진행 Drawer와 개발자 지도 삭제의 상태 갱신을 맡는다. 04의 데이터 활성화 결과와 09의 경로 준비 결과를 소비하여 부분 성공을 표시한다.

## 실행 맥락과 접근

[카테고리 조사](../../../records/2026-09-13-02-major-feature-category-investigation.md)는 설치 iOS SDK의 pack 생성 promise가 타일 완료를 뜻하지 않는 계약을 확인했다. 진행률 0·10%의 ready 처리, 삭제 뒤 flag 잔존, 활성 여행 지도 재시도 누락, 실패 Drawer의 대기 문구를 분리 실행했다.

[다운로드](../../../../../../../apps/client/src/shared/services/offline-map/download.ts), [정리](../../../../../../../apps/client/src/shared/services/offline-map/cleanup.ts), [metadata](../../../../../../../apps/client/src/shared/services/offline-prep/metadata.ts), [진행 UI](../../../../../../../apps/client/src/entities/trip/ui/ActivationProgressDrawer.tsx)가 중심이다. native pack 자체 시험은 독립 착수 가능하다. 활성화 전환 통합은 04, 경로 상태를 포함한 UI 완료는 09의 성공·부분 실패 계약을 받은 뒤 확인한다.

공통 기준은 [기대 동작](../spec/02-behavior-and-cases.md)과 [품질·완료 판단](../spec/04-quality-and-completion.md)을 따른다.

## 완료 조건과 확인 방법

- pack 생성·다운로드 진행·완료·실패·취소·재시작을 구별한다. 실제 iOS에서 다운로드 후 비행기 모드로 대상 영역의 타일을 확인하고 그 결과와 준비 표시를 대조한다.
- 도시 DB row만 있고 pack이 없거나 미완료인 경우 재사용 성공으로 판정하지 않는다. 정리·개발자 지도 삭제 뒤 flag와 용량 표시가 실제 자원 상태를 반영한다.
- 이미 활성화됐지만 지도 실패/삭제 상태인 여행에서 지도 재시도가 가능하며, 중단 후 재실행도 영구 대기 상태로 남지 않는다.
- 데이터 성공·지도 실패·경로 실패 조합에서 실제 준비된 기능과 실패한 기능을 구별하고 재시도·닫기 등 다음 행동을 제공한다. 실패를 계속 준비 중 또는 모두 완료로 표시하지 않는다.
- Drawer 자체의 탈출 불가를 기존 조사로 확정하지 않는다. 실제 닫기·뒤로가기와 재진입을 포함해 검증한다.

## 현재 상태와 실제 결과

구성됨, 실행 전. 위 확인 계획을 수행하거나 제품 코드를 수정한 상태가 아니다. 기존 조사 근거는 위에 연결했으며, 실행할 때 현재 코드·환경과 수정 전 조건을 다시 대조한다.

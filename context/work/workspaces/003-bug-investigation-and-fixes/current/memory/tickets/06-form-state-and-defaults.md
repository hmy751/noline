# 06. 폼의 초기값·취소·재진입 일관성

## 맡은 결과와 범위

여행·일정·경비 작성/수정에서 늦게 도착한 기본값은 올바르게 반영하고, 사용자가 직접 바꾼 값은 비동기 조회나 재렌더로 덮어쓰지 않게 한다. 취소·재열기·다른 항목 전환·picker 닫기·화면 복귀의 입력 상태도 판별하고 필요한 결함을 고친다.

확인된 경비 통화 초기값 문제와 아직 미확정인 재진입 조건을 구분한다. 날짜 값 자체의 저장/표시 변환은 08, 저장 실패 안내는 01, 저장 대상 여행 유지와 중복 생성은 03가 맡는다.

## 실행 맥락과 접근

[첫 사용 조사](../../../records/2026-09-13-01-first-use-scenario-investigation.md)에서 USD 기본값 뒤 JPY 여행 정보가 도착해도 USD가 유지됐다. 반면 수정 Drawer 부모가 닫을 때 선택값을 null로 만드는 근거가 있어 같은 ID 재열기를 일괄 결함으로 판정하지 않았다. 전달된 일정 날짜를 폼이 사용한다는 정상 근거도 유지한다.

[경비 작성 hook](../../../../../../../apps/client/src/features/expense/create-expense/useCreateExpenseForm.ts), [일정 작성 hook](../../../../../../../apps/client/src/features/schedule/create-schedule/useCreateScheduleForm.ts), [여행 편집](../../../../../../../apps/client/src/features/trip/update-trip/EditTripDrawer.tsx)에서 시작해 실제 부모와 picker까지 연결한다. 독립 착수 가능하다. 서버 저장 전후 연결 검증은 03·07의 작업 결과를 사용한다.

공통 기준은 [기대 동작](../spec/02-behavior-and-cases.md)과 [품질·완료 판단](../spec/04-quality-and-completion.md)을 따른다.

## 완료 조건과 확인 방법

- cache 없음·늦은 여행 통화 도착·다른 여행 전환에서 기대 기본값이 반영된다. 그 사이 사용자가 통화를 직접 골랐다면 새 기본값이 덮어쓰지 않는다.
- 일정/경비 수정 취소 후 같은 항목·다른 항목 재열기, 열린 상태의 query 갱신, picker 확인/취소를 실제 렌더와 native 입력으로 대조한다. 정상인 조건은 변경 불필요 근거로 남긴다.
- cold link·일반 push 진입에서 필수 여행/날짜 정보와 뒤로가기 경로를 확인한다. back stack 없는 일정 생성의 fallback 경로 의심도 여기서 판별한다.
- 키보드·스크롤·drawer 닫기·느린 저장 중 이탈에서 선택/입력 상태를 확인하고, 실패 후 재시도는 같은 의도한 입력으로 가능해야 한다. 지원하지 않는 입력을 새 기능으로 넓히지 않는다.

## 현재 상태와 실제 결과

구성됨, 실행 전. 위 확인 계획을 수행하거나 제품 코드를 수정한 상태가 아니다. 기존 조사 근거는 위에 연결했으며, 실행할 때 현재 코드·환경과 수정 전 조건을 다시 대조한다.

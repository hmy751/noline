# Ticket 색인

번호는 개발자가 앱을 처음 켜서 장면을 확인하는 순서다. 앱 시작·로그인과 홈을 먼저 보고, 활성화·입력·지도 사용을 거쳐 오프라인/재연결과 마지막 통합 검증으로 이어진다. 실제 구현의 선행 조건은 각 티켓 본문에서 별도로 확인한다.

기존 14개 티켓의 범위와 완료 조건은 유지했다. 여러 시점에 걸친 티켓은 첫 관련 장면에 배치했으므로 02의 로그아웃·계정 전환 같은 후반 조건은 마지막 사용 흐름에서 다시 확인한다. 서버·저장 기반 티켓은 별도 화면이 아니라 해당 결과를 본격적으로 확인하는 단계에 둔다.

## 앱을 켜고 홈에서 준비하기

- [01. 앱 준비 실패와 조회·저장 오류 복구](01-startup-and-error-recovery.md): 앱 실행 직후 초기 화면·필수 준비·실패 시 재시도.
- [02. 로그인 복구와 계정 전환의 데이터 보호](02-auth-account-recovery.md): 저장된 로그인 복원 또는 로그인 화면 진입.
- [03. 여행 생성·선택·수정·삭제의 연결](03-trip-management.md): 홈에서 여행 생성·선택 후 수정·삭제.
- [04. 활성화·비활성화·재활성화의 데이터 안전](04-activation-data-lifecycle.md): 홈의 여행 활성화와 이후 비활성화·재활성화.
- [05. 오프라인 지도 준비 상태와 재시도](05-offline-map-readiness.md): 활성화 직후 지도 다운로드 진행·실패·재시도.

## 근거와 현재 상태

각 본문은 맡은 결과·근거·의존 관계·완료 조건·실제 상태를 소유한다. 전체 단계와 다음 행동은 [state](../../state/index.md), 기존 후보의 담당은 [후보 목록](../analysis-items.md)에서 찾는다.

[카테고리 조사](../../../records/2026-09-13-02-major-feature-category-investigation.md)는 정상 근거·결함·미확인의 원자료다. [초기 구성 이유](../../../records/2026-09-13-03-ticket-composition.md)의 번호는 당시 기준이며, [장면 순서 재배치와 번호 대응](../../../records/2026-09-13-04-ticket-scene-order.md)에서 현재 번호를 확인한다.

01–13의 미확인은 해당 본문에서 먼저 다룬다. 14는 알려진 결함을 처음 조사하는 대기열이 아니라 기능 간 연결을 최종 대조하는 책임이다. 비활성 여행의 오프라인 편집, 숨겨진 설정 메뉴, 영수증 업로드 같은 미지원 기능은 추가하지 않는다.

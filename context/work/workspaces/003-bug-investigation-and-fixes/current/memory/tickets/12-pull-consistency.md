# 12. Pull 누락과 미전송 수정 덮어쓰기 방지

## 맡은 결과와 범위

서버 변경을 받는 동기화에서 시간 경계 때문에 변경을 놓치거나, 아직 전송하지 않은 로컬 수정을 설명 없이 이전 값으로 덮어쓰지 않게 한다. 서버 조회 기준 시각, cursor 입력, local upsert·삭제와 pending 충돌을 함께 맡는다.

충돌 시 무조건 local 우선 또는 server 우선이라는 새 정책은 여기서 기정사실로 만들지 않는다. 현재 계약을 확인하고 필요한 정책 판단을 먼저 분리한 뒤 채택 범위를 구현한다.

## 실행 맥락과 접근

[카테고리 조사](../../../records/2026-09-13-02-major-feature-category-investigation.md)는 실패한 수정의 local 표시값이 이전 서버 값으로 바뀌고 queue payload는 남는 조건을 실행했다. 서버가 실제 cursor에서 그 row를 반환하는 조건과 조회 도중 쓰기 누락은 아직 통합 재현하지 않았다.

[client engine](../../../../../../../apps/client/src/shared/services/sync/engine.ts), [DB upsert](../../../../../../../apps/client/src/shared/db/utils.ts), [server sync](../../../../../../../apps/server/src/routes/sync.ts)가 연결된다. 10의 정확한 미전송 귀속 결과가 충돌 판정의 선행 결과다. 11의 실패/재시도 계약을 소비하지만 이 티켓이 전송 엔진을 다시 소유하지 않는다.

공통 기준은 [기대 동작](../spec/02-behavior-and-cases.md)과 [품질·완료 판단](../spec/04-quality-and-completion.md)을 따른다.

## 완료 조건과 확인 방법

- 격리 PostgreSQL에서 pull 조회 도중 생성·수정·삭제를 주입하고 다음 cursor 요청까지 대조하여 빠진 변경이 없음을 확인한다.
- 같은 entity의 미전송 CREATE/UPDATE/DELETE와 서버 수정·삭제의 조합을 재현한다. 자동 처리 가능한 기존 정책과 사람 선택이 필요한 정책을 명시하고, 미확정 정책이 결과를 막으면 구현 완료로 닫지 않는다.
- 채택한 정책에서 사용자 입력 또는 복구 가능한 변경 근거가 남고, 성공적인 재전송·후속 pull 뒤 화면·SQLite·서버가 합의된 값에 도달한다.
- 정상적인 서버 변경 수신과 삭제 전파는 보존한다. mock 응답 덮어쓰기 시험만으로 server cursor 무누락을 입증하지 않는다.

## 현재 상태와 실제 결과

구성됨, 실행 전. 위 확인 계획을 수행하거나 제품 코드를 수정한 상태가 아니다. 기존 조사 근거는 위에 연결했으며, 실행할 때 현재 코드·환경과 수정 전 조건을 다시 대조한다.

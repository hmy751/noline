# 08. 날짜 의미와 여행 기간 밖 항목 접근

## 맡은 결과와 범위

여행 날짜·경비 날짜·일정 날짜와 시간이 변환·저장·재조회 과정에서 의도한 날짜를 유지하게 한다. 여행 기간을 줄이거나 일정을 기간 밖으로 옮겨도 저장된 항목에 접근할 경로를 잃지 않게 한다.

공유 날짜 util과 생성/수정/표시 소비자, 일정·경비 날짜 그룹, 기간 변경 후 지도 선택 날짜와 활성화 만료일의 연결을 맡는다. 통화별 합계를 유지하고 자동 환산이나 새로운 여행별 시간대 기능은 추가하지 않는다.

## 실행 맥락과 접근

[카테고리 조사](../../../records/2026-09-13-02-major-feature-category-investigation.md)에서 로스앤젤레스 시간대의 날짜가 하루 앞으로 바뀌었고, 기간 밖 일정은 그룹에서 빠졌다. 서울/UTC 날짜와 기간 밖 경비 노출·통화별 합계는 정상 대조군이다.

[날짜 util](../../../../../../../apps/client/src/shared/lib/datetime.ts), [일정 화면](../../../../../../../apps/client/src/screens/ScheduleScreen.tsx), [경비 화면](../../../../../../../apps/client/src/screens/ExpensesScreen.tsx)가 중심이다. util·그룹 재현은 독립 착수 가능하다. 저장 왕복은 03·07, 활성화 만료일의 상태 연결은 04의 계약을 사용한다. 날짜만 나타내는 값과 특정 시점을 나타내는 ISO 값의 기존 의미를 먼저 확인한다.

공통 기준은 [기대 동작](../spec/02-behavior-and-cases.md)과 [품질·완료 판단](../spec/04-quality-and-completion.md)을 따른다.

## 완료 조건과 확인 방법

- 서울·UTC·로스앤젤레스에서 동일 입력 날짜의 생성→저장→편집→표시를 여행·일정·경비별로 확인한다. 자정·기간 경계·일광절약시간 전환도 포함하되 기대 시각 의미를 명시한다.
- timezone 포함 ISO 저장 계약을 유지하며, 기존 저장 데이터의 해석이 바뀌는지 검토한다. 데이터 변환이 필요하면 대상·호환성·복구 판단을 먼저 남긴다.
- 기간 축소·기간 밖 이동 뒤 일정/경비에 다시 접근해 편집·삭제할 수 있다. 기간 밖 항목 표시 또는 이동 제한 등 구체 UI는 기존 흐름과 비교해 정하고 임의 삭제로 해결하지 않는다.
- 기간 변경 뒤 선택된 지도 날짜가 유효하게 처리되고 활성화 만료 조건이 실제 여행 기간과 어긋나지 않는지 검증한다.
- 경비의 기존 기간 밖 노출과 통화별 독립 합계, 정상 일정 날짜 전달을 회귀 대조군으로 유지한다.

## 현재 상태와 실제 결과

구성됨, 실행 전. 위 확인 계획을 수행하거나 제품 코드를 수정한 상태가 아니다. 기존 조사 근거는 위에 연결했으며, 실행할 때 현재 코드·환경과 수정 전 조건을 다시 대조한다.

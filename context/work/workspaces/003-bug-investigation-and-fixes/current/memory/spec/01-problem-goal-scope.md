# 문제·목표·범위

코드베이스 분석 중 기존 설계 기준과 실제 결과가 어긋나는 조건을 발견했다. 트랜잭션과 여행별 미전송 작업 조회는 분리 실험에서 결함을 재현했고, 서버 계약·경로·동기화·초기화 등은 코드에서 확인한 불일치와 실제 재현이 필요한 후보가 섞여 있다.

목표는 발견한 문제를 누락 없이 판별하고, 채택한 결함에서 기대하는 저장·조회·정리·재시도·표시 결과를 구현하고 검증하는 것이다. 실제로 잘못된 결과를 고치는 변경을 가독성 리팩토링에 섞어 범위와 근거를 흐리지 않는다.

[전체 후보](../analysis-items.md)는 기존 분석과 추가 발견·검증을 함께 포함한다. Transaction/queue/cleanup, 동기화 push·pull·retry·복구, 경로 최신성과 좌표 값, 비활성 여행의 데이터 접근, 서버 소유권·삭제·입력/응답 계약, 초기화·폼·실패 화면이 범위다. 아직 기대 UX나 발생 조건이 미정인 관찰은 확인 과제로 남긴다.

사용자는 리팩토링부터 진행하기를 선택했다. 이 Work의 모든 버그를 먼저 고치는 순서를 강제하지 않는다. 리팩토링할 코드의 직접 선행 조건인 결함은 관련 범위만 판단할 수 있다. 각 후보의 우선순위와 첫 실행 Ticket은 아직 정하지 않았다.

이번 요청은 Workspace 두 개 구성이다. 제품 수정·외부 API 재현·실제 DB 변경·새 기능·대규모 구조 개편·README 개선·배포는 이번 생성 범위가 아니다. [사용자 원문](../../../source/user-direction.md)이 범위와 순서 판단의 근거다.

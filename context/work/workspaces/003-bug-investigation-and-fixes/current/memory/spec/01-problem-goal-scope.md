# 문제·목표·범위

코드베이스 분석과 주요 기능의 첫 사용 조사에서 기존 설계 기준과 실제 결과가 어긋나는 조건을 발견했다. 트랜잭션·queue·인증 복구·활성화 정리·지도 준비·여행 수정·경로·날짜 등은 분리 실험 근거가 있고, 서버 및 실제 native 환경은 소스 불일치와 추가 재현 과제가 함께 남아 있다.

목표는 개발자가 앱을 처음 켜서 주요 기능을 시험할 때 발견한 문제를 누락 없이 판별하고, 채택한 결함에서 기대하는 저장·조회·정리·재시도·표시 결과를 구현하고 검증하는 것이다. 실제로 잘못된 결과를 고치는 변경을 가독성 리팩토링에 섞어 범위와 근거를 흐리지 않는다.

범위는 앱 시작·인증, 여행 생성/선택/수정/삭제, 활성화/비활성화/재활성화, 일정·경비와 관계, 지도·검색·경로, 오프라인 입력/재연결, 프로필·계정, 실패 복구·개발자 도구다. 데이터 보존·날짜·소유권·입출력 계약은 이 사용 흐름을 가로지르는 조건으로 함께 본다. 로그인 재시도 안내는 조사 계기이며 범위를 인증에 한정하지 않는다.

[전체 후보](../analysis-items.md)는 원래 관찰과 추가 발견을, [Ticket](../tickets/index.md)은 맡은 결과·미확인의 담당·완료 근거를 연결한다. [카테고리 조사](../../../records/2026-09-13-02-major-feature-category-investigation.md)의 확인 수준을 유지하며, 실제 iOS 전체 시나리오를 통과한 것으로 취급하지 않는다.

사용자의 리팩토링 우선 선택은 유지한다. 이 Work 전체 완료를 다른 Work의 선행 조건으로 강제하지 않으며, 직접 겹치는 결함만 관계를 판단한다. 이번 요청은 조사 결과를 티켓으로 구성하는 것까지다. 제품 수정 착수나 실제 계정·DB·외부 서비스 조작은 포함하지 않는다. 실행 순서 제안과 실제 착수 여부는 [state](../../state/index.md)가 소유한다.

새 기능, 비활성 여행의 오프라인 편집, 대규모 구조 개편·전면 동기화 재설계·배포는 포함하지 않는다. 기대 UX나 충돌 정책이 미정인 조건은 해당 티켓에서 판단 근거와 선택 필요를 먼저 밝힌다. 기존 Work 분리·진행 순서는 [초기 사용자 원문](../../../source/user-direction.md)에 보존한다.

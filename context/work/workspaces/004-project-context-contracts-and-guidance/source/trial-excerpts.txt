# 통화와 금액의 제품 의미

경비 입력·합계·표시를 만들거나 바꿀 때 읽는다. 이 문서는 통화를 분리해 다루는 제품 의미와 현재 확인된 표시 경계를 소유한다. 실제 helper와 화면 구현은 [client source](../../../apps/client/src/shared/lib/currency.ts)가, 반영 배경과 제한된 검증은 [Workspace 002 Ticket 01](../../work/workspaces/002-code-readability-refactoring/current/memory/tickets/01-expense-totals.md)이 소유한다.

## 여러 통화를 환산 없이 보존한다

Trip의 `baseCurrency`는 그 여행에서 새 Expense를 입력할 때 우선하는 기본 통화다. Expense는 자기 `currency`와 금액을 그대로 가지며, 서로 다른 통화의 금액을 하나의 환산 합계로 섞지 않는다. 합계는 통화별로 분리해 보여 준다. 환산 총액을 새로 제공하려면 환율 source, 환율을 확보하지 못한 오프라인 동작과 환산 기준 시점을 먼저 결정해야 한다.

경비 합계 목록은 Trip의 `baseCurrency`가 실제 목록에 있으면 그 그룹을 먼저 둔다. 기본 통화 경비가 없으면 첫 항목은 다른 통화 중 명목 숫자 합계가 큰 그룹이다. 따라서 화면의 첫 항목을 `baseCurrency인가`로 해석하거나 helper의 결과를 “가장 많이 사용된 통화”로 일반화하면 안 된다. 현재 화면은 첫 항목을 강조하고 ‘주 통화’라고 표시하지만, 이 라벨이 기본 통화·사용 빈도·환산 가치 중 무엇을 뜻해야 하는지는 별도 제품 기준으로 확정되지 않았다.

## 현재 표시 규칙과 금액 정밀도는 구별한다

현재 공용 표시 규칙은 KRW·JPY를 소수 0자리, 그 밖의 통화를 2자리로 보여 준다. `getCurrencyFractionDigits`가 이 자릿수를 소유하며 공용 `formatCurrencyDisplay`와 경비 합계 화면이 함께 사용한다. 이 규칙은 표시 자릿수에 관한 현재 답이지, 입력 가능한 금액의 scale이나 저장 정밀도·합산·반올림 시점을 정한 계약은 아니다.

현재 `Expense.amount` schema는 숫자 문자열이라는 형식과 소수 자릿수를 제한하지 않고, client 합계는 문자열을 JavaScript `number`로 바꾸어 계산하며, PostgreSQL은 `decimal(10,2)`로 저장한다. 경비 합계 화면의 `toFixed`와 공용 formatter의 locale formatting은 `1.005 USD` 같은 입력에서 서로 다른 문자열을 만들 수 있다. Workspace 002는 이 차이를 새로 만들지 않고 기존 표시를 보존했을 뿐, 어느 결과가 제품상 옳은지 결정하지 않았다.

금액 처리 작업에서는 입력 검증, client 계산, DB precision, 표시 반올림을 한 계약으로 함께 대조한다. 단순한 formatter 교체로 현재 화면 문자열을 조용히 바꾸거나 Ticket 01의 동작 보존 결과를 Project-wide 금액 정책으로 확대하지 않는다.

## 권위와 다시 확인할 때

이 범위의 현재 제품 의미는 이 문서가 소유한다. [이전 Currency context](../../../.claude/context/currency.md)는 과거 진입 링크를 이 본문으로 연결하고 현재 코드 위치만 안내한다. 화면별 배치와 구현은 code가 소유하며, 본문과 다르면 제품 결정을 자동 변경하지 말고 실제 consumer와 근거를 대조한다.

‘주 통화’의 의미, 허용할 금액 scale, 합산·반올림 시점이나 환산 기능을 정하는 작업에서는 사용자 또는 제품 책임자의 선택이 필요하다. 그 선택이 생기면 이 본문과 관련 schema·저장·표시 가이드를 함께 갱신한다.

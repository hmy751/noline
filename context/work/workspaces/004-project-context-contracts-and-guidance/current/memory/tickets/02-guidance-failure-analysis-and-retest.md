# Project 작성 지침의 실패 분석과 재시험

## 맡은 결과

기존 지침이 실제 갱신 결과의 문제를 걸러내지 못한 이유를 판단하고, 필요한 지침 수정을 수행한 뒤 다른 세션·실행 주체의 결과로 효과를 확인한다. 현재 본문을 Main이 직접 완성하는 것은 이 Ticket의 완료를 대신하지 않는다.

## 실행 맥락

`3baa7b7`은 Project 구조·읽기·REFERENCE를 정비했고 `2937c25`는 원자료 순서의 본문화, 사례 선별, current의 추가 효용·중복, 대표 작업의 읽기 검증을 보강했다. 그 지침으로 다른 세션이 현재 미커밋 초안을 만들었다. 받은 결과는 완료를 보고했지만 Main의 직접 검토에서 다음 문제가 남았다.

- `current/architecture.md`에 테스트 개수, 이번 환경의 EPERM, Docker 미실행 등 실행 이력이 누적됐다. 검사 기반과 증명 범위를 설명하는 의미와 구별해야 한다.
- 이전 currency 정책의 Expense별 통화 선택과 금액·통화 코드/기호 동시 표시가 새 Owner 본문에 명시적으로 이어지지 않았다.
- 날짜 문서는 client local 입력도 date-only를 강제한다고 설명하지만 form·request·local 경계가 서로 다르다.
- 기존 server guide의 API runbook 진입에는 새 API 본문이 연결되지 않았다. 날짜 runbook도 기존 일괄 datetime 문구에서 시작한다.

API 공통 계약과 기능별 적용을 한 흐름으로 구성한 점, 리팩터링을 원칙 중심으로 재구성한 점은 개선됐다. 이 개선은 유지할 후보지만 파일 수가 줄었다는 사실만으로 전체 성공을 판정하지 않는다. [원문 발췌](../../../source/trial-excerpts.txt)는 수정 전 문구를, [생성 기록](../../../records/2026-09-14-01-workspace-setup-and-review-basis.md)은 확인한 근거와 Main의 해석을 구분한다.

## 접근과 열린 판단

[관리 계약](../../../../../../project/MAINTENANCE.md), [구성 기준](../../../../../../project/REFERENCE/composition.md), [읽기 기준](../../../../../../project/REFERENCE/reading.md)과 읽기·갱신 스킬을 직접 대조해 각 문제가 어디에서 발견됐어야 하는지 확인한다. 지침이 없던 것, 표현이나 연결이 불충분한 것, 실제 수행 여부를 확인하지 못한 것을 구별한다. 규칙이 이미 적혀 있다는 이유로 실행자 탓으로 확정하거나, 모든 실패마다 금지문을 추가하지 않는다.

필요한 변경은 해당 기준의 Owner에 통합하고 스킬은 적용 동작이 달라지는 범위에서 맞춘다. 현재 원인은 미확정이며 기존 보고만으로 실제로 읽은 문서나 생략한 판단을 알아냈다고 하지 않는다. 추가 원실행 자료가 없으면 재시험에서 구별할 관찰을 설계한다.

재시험은 현재 지침·입력·산출물의 기준 상태를 보존한 뒤 정한다. 다른 세션에 목표와 범위·권한을 주되 예상 파일명이나 수정 정답을 전달해 지침의 역할을 대신하지 않는다. 기존 산출물을 지우거나 제품 합의가 변경된 입력으로 시험한다면 그 개입과 비교 한계를 남긴다. 원복 대상은 시험 문서의 exact 목록과 기준 commit으로 한정하고 다른 세션 변경과 002/003 작업을 보존한다.

## 완료 확인

실패별 원인 판단에 근거·미확인이 있고, 필요한 지침 변경과 이유가 연결돼야 한다. 새 실행 결과를 Project README와 기존 개발 진입점에서 읽고, 기존 의미의 보존·직접 사실·주제 충분성·현재 맥락의 가치·변경 영향이 개선됐는지 확인한다. 정적 검사 통과와 작성자의 자체 설명은 별도 주체의 적용 결과와 구별한다. 개선이 확인되지 않으면 원인을 다시 판단하며 수동으로 고친 결과를 지침 성공으로 보고하지 않는다.

## 현재 상태

실행 전이다. 지침이 있는데도 실패했다는 관찰은 있으나 원인 분석과 후속 수정·재시험은 아직 하지 않았다. Main의 “기준이 있으니 결과부터 고치자”는 제안은 철회됐고, 이 Work의 목표는 지침을 통한 실제 수행의 개선까지 포함한다.

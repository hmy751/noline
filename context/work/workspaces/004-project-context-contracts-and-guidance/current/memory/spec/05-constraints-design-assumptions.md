# 제약·현재 설계·가정

`common/current/guidance`의 물리 경계와 대문자 `REFERENCE`를 유지한다. Current의 폐기·축소·파일 수를 먼저 결정하지 않는다. Guidance는 순서뿐 아니라 계약·이유·구체 적용·판단·검증을 포함하는 작업 가이드다. 관련 본문이 자기 범위를 충분히 설명하되 모든 구현 세부나 실행 기록을 복제하지 않는 방향은 이미 합의됐다.

제품 미합의 해결과 지침 실패 분석·재시험은 별도 Ticket으로 유지한다. Ticket 01은 제품 계약과 Project 문서의 보완을 맡고, Ticket 02는 기존 의미와 실제 진입점의 연결 누락이 반복된 원인과 최소 개선의 효과를 다시 다룬다. 같은 문서에서 두 문제가 드러났더라도 제품 선택의 정답과 지침 효과를 서로 대신하지 않는다.

지침 시험의 기준 commit은 `2937c252a735ecc6edbe1d3516659fcf459da970`이다. `3baa7b7`에서 Project 구성·읽기 경로를 정비했고 `2937c25`에서 사례 선별·current 중복·읽기 검증을 보강했다. 그 뒤 만든 첫 시험 초안은 Ticket 02의 비교 후 사용자 요청으로 원복했다. 당시 채택한 지침·결정·Workspace 기록은 유지하지만, 후속 별도 세션의 문서 작업에서 연결 누락이 반복됐으므로 격리 재시험의 성공만으로 Ticket 02의 완료를 유지하지 않는다.

002에는 별도 Spec·Ticket·state 수정분이 있고 `.pnpm-store/`도 미추적 상태다. 초안 원복은 이 변경을 대상으로 하지 않았다. 003에는 날짜·폼·서버 경계 관련 Ticket이 있으므로 제품 구현이 필요해지면 담당 범위를 확인한다. 003 README의 오래된 준비 상태 문구만으로 실행 Ticket이 없다고 가정하지 않는다.

선택한 개선은 새 단계·필수 보고 양식·자동 검사를 추가하지 않고, 기존 `update-project-context`의 마지막 확인이 기존 Owner와 기존 작업 진입점에서 시작해 보존할 의미와 변경된 기준·열린 판단으로의 도달성을 대조하도록 한 문장을 명확히 하는 것이다. 이 최소 수정은 현재 문서 보완에 적용했으며, 다른 세션의 실제 지침 적용 과정을 확인하지 않았으므로 다음 독립 갱신의 결과를 보고 추가 장치의 필요성을 다시 판단한다.

# 제약·현재 설계·가정

`common/current/guidance`의 물리 경계와 대문자 `REFERENCE`를 유지한다. Current의 폐기·축소·파일 수를 먼저 결정하지 않는다. Guidance는 순서뿐 아니라 계약·이유·구체 적용·판단·검증을 포함하는 작업 가이드다. 관련 본문이 자기 범위를 충분히 설명하되 모든 구현 세부나 실행 기록을 복제하지 않는 방향은 이미 합의됐다.

현재 설계는 제품 미합의 해결과 지침 실패 분석·재시험을 별도 Ticket으로 나누는 것이다. 제품 선택이 필요한 부분은 사용자와 논의하고, 그 선택에 의존하지 않는 기존 의미 누락·읽기 경로·기록화 문제는 먼저 분석할 수 있다. 두 작업의 수행 순서 자체는 고정하지 않는다.

기준 commit은 `2937c252a735ecc6edbe1d3516659fcf459da970`이다. `3baa7b7`에서 Project 구성·읽기 경로를 정비했고 `2937c25`에서 사례 선별·current 중복·읽기 검증을 보강했다. 현재 Project와 `.claude` 수정분은 그 후 다른 세션이 만든 미커밋 시험 결과다. 해당 diff와 새 파일은 검토 입력으로 보호하며 임의 원복·정리·커밋하지 않는다. 재시험용 원복이나 격리가 필요하면 exact 대상·기준과 다른 세션 변경을 확인하고 복구 가능한 준비를 한다.

002에는 별도 Spec·Ticket·state 수정분이 있고 `.pnpm-store/`도 미추적 상태다. 004 생성에서는 이를 수정하지 않는다. 003에는 날짜·폼·서버 경계 관련 Ticket이 있으므로 제품 구현이 필요해지면 담당 범위를 확인한다. 003 README의 오래된 준비 상태 문구만으로 실행 Ticket이 없다고 가정하지 않는다.

현재 Main의 002 Maintain generation에는 실패 뒤 미반영된 response-end가 남아 있고 해당 generation에서 재시도되지 않는다. 이것은 004 생성의 선행 조건이 아니며 자동 최신화의 근거도 아니다. 다른 세션은 004 파일에서 복구한 뒤 필요한 경우 자기 세션을 명시적으로 연결한다. 이 생성으로 기존 binding·active 기본값·미처리 runtime을 변경하지 않는다.

원인 미확정: 이번 실패가 실행 누락인지, 지침의 표현·연결·확인 방식이 부족한지 아직 판정하지 않았다. “이미 기준이 있으니 결과만 고치자”는 Main 제안은 철회됐다. 실제 재실행 없이 지침이 충분하거나 개선됐다고 결론 내리지 않는다.

# 개념과 계약

Project 본문은 반복해서 사용할 제품 의미·현재 관계·작업 기준의 Owner다. 관리 계약과 REFERENCE는 이를 어떻게 구성·갱신·읽는지 설명하며 스킬은 그 기준을 적용하는 실행 장치다. Workspace 004는 이번 합의·실험의 정의와 상태를 소유한다. 새 제품 기준을 스킬에만 넣거나 이번 실험 이력을 Project의 현재 답으로 누적하지 않는다.

관련 주제의 Owner 이동은 앞선 작업에서 승인됐다. 다만 현재 작업 트리의 새 Project 본문은 검토 중인 결과이고, 그 안의 모든 문장이 채택된 정책은 아니다. 현재 사실의 정정·기존 의미의 복원과 사용자 선택을 요구하는 새로운 계약은 다른 일이다. 이 차이는 제품 논의와 지침 평가 양쪽에서 유지한다.

지침 평가의 입력은 당시 지침, 작업 지시, 실제 산출물과 직접 코드 근거다. 규칙을 읽었는지, 어떤 판단을 했는지 원실행 기록이 없으면 산출물만으로 원인을 단정하지 않는다. 이미 문장이 있다는 사실은 충분한 지침의 증거가 아니고, 한 실행의 실패도 특정 문구가 원인이라는 증거가 아니다. 부족한 근거는 재실행에서 확인한다.

002의 Spec·Ticket·records는 해당 작업의 근거로 단방향 참조한다. 004는 002의 current 전체 복구, 자동 동기화 또는 미처리 Maintain 이벤트의 재적용에 의존하지 않는다. 이번 판단에 필요한 현재 의미는 이 Spec과 두 Ticket에 직접 소유한다.

Machine 계약은 `workspace.json` identity, `recover.json` Project 선택, `verify.json` 제한된 고정 검사, `current/state/status.json` 마지막 Verify 결과로 구분한다. 다음 행동은 사람용 state가 소유하며, 선택된 입력·Recover 성공·Maintain 연결·실제 문서 반영은 서로 다른 사실이다.

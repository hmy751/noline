# 품질과 완료

아래 완료 기준은 생성 때 Main이 쓴 초안이다. 사용자 확인이 남아 있다([state](../../state/index.md)).

## 규칙이 정해졌다고 판단할 근거

- [Spec 02](02-behavior-and-cases.md)의 상황과 Ticket 01에서 찾은 상황 전부에 [Spec 03](03-concepts-and-contracts.md)의 판단이 있다.
- 사용자가 실제 화면을 보고 규칙을 수락했다. 표만 보고 정하지 않는다.
- 이유와 기각한 대안을 기록했다.

## 화면이 맞춰졌다고 판단할 근거

| 확인 | 방법 |
| --- | --- |
| 정한 상황에서 정한 안내만 나오고, 없애기로 한 겹침이 사라짐 | iOS 시뮬레이터에서 상황별 재현과 전후 캡처 |
| 복구 행동이 실제로 동작하고 진행 중·실패가 보임 | 실제 앱 실행 |
| 데이터 삭제 버튼이 정한 조건에서만, 정한 모양으로 나옴 | 데이터 있음·없음, 세션 만료, 복원 실패에서 실행 |
| 안내 변경이 실행 조건을 바꾸지 않음 | 관련 테스트. Policy·Router 변경이 없거나, 있으면 이유 기록 |
| 실제 기기에서도 같음 | 사용자가 확인. 모양 문제는 시뮬레이터만으로 닫지 않는다 |

의미 있는 화면 변경은 구현에 참여하지 않은 별도 검증자가 확인한다. 테스트 통과만으로 완료로 보지 않는다.

## 이 Work의 완료가 아닌 것

- 표시를 추가했다는 사실. 안내가 늘기만 했다면 목표에 못 미친 것이다.
- Project 문서 갱신. 완료 조건이 아니다.
- 출시. 빌드와 제출은 사용자가 정한다.

# 현재 안내와 대표 사례

11월 3~4일 코드와 iOS 화면을 조사하고 11월 10일 빠진 장면을 추가 촬영했다. 아래 표시 형태의 사용처 수는 11월 초 조사값이다. [화면 모음과 촬영 조건](../../../records/2026-11-10-01-notice-screens.md)에서 같은 조건의 실제 화면을 비교할 수 있다.

## 현재 쓰는 표시 형태

| 형태 | 현재 쓰임 | 사용자 행동 |
| --- | --- | --- |
| 전역 배너 | 세션 만료뿐 (`SessionExpiredBanner`, 모든 화면 위) | 재로그인 |
| 헤더 표시 | 네트워크 상태 (`NetworkStatusIndicator`, 10개 화면) | 없음 |
| 작은 안내 | 시간대 확인 필요 (`TripTimeZoneNotice`, 5개 화면) | 일정·경비 화면에서 "여행 시간대 확인" |
| 제자리 안내 | 사용 제한 (`PolicyErrorDisplay`의 `banner`·`inline`·`block`, 13곳) | 있을 때만 연결 재확인 |
| 모달 | 확인 질문, 저장 결과, 누른 순간의 제한, 권한 (`Alert.alert`, 디버그 제외 약 50곳) | 확인·취소 |
| 필드 오류 | 폼 입력 오류 | 고쳐 입력 |
| 토스트 | **앱에 없음.** 개발 빌드의 로그 알림(LogBox)과 혼동하지 않는다 | — |

## 상황별 현재 모습

| 상황 | 지금 보이는 것 | 사용자 판단·관찰 |
| --- | --- | --- |
| 활성 여행, 오프라인·확인 불가 | 헤더 한 단어. 목록은 정상 | 네트워크 표시는 유지 |
| 비활성 여행, 오프라인 | 일정 목록 영역에 제한 아이콘과 문구 "작업을 수행할 수 없습니다 / 인터넷에 연결되어 있지 않아요…" | — |
| 비활성 여행, 확인 불가 | 일정 목록 영역에 제한 아이콘, "인터넷 연결을 확인할 수 없어요." + "다시 확인" | 같은 상태가 활성 여행과 크게 다르다 |
| 오프라인 일정 추가 | 헤더 + 노란 배너 + 빈 상태. 직접 입력을 누르면 같은 문장이 장소 칸에 다시 나옴 | 사용자: 첫 스크린샷 정도는 괜찮다. 안내할 말이 있으니 |
| 오프라인 새 여행 추가 | 모달 "인터넷 연결 필요" | — |
| 경비 삭제 | 이름을 넣은 확인 모달. 삭제가 성공하면 성공 모달, 실패하면 오류 모달 | 시험 서버에서 성공·503 응답 각각 촬영 |
| 일정 저장 (생성) | 성공 표시 없이 목록으로 | 코드상 수정·삭제는 "성공" 모달이 뜬다. 생성과 다르다 |
| 경비 수정 | 성공하면 확인 모달. 실패하면 입력을 유지하고 수정 시트 하단에 오류 표시 | 시험 경비의 제목을 바꾼 뒤 각각 촬영 |
| 홈·경비 조회 실패 | 홈은 여행 정보를 불러올 수 없다는 문구, 경비는 실패 문구와 “다시 불러오기” 버튼 | 홈의 오류 영역에 재시도 버튼은 보이지 않음. 각 조회에 503을 돌려 촬영 |
| 일정 지도 위치 권한 거절 | “권한 필요” 모달과 확인 버튼 | 권한을 거절한 상태에서 현재 위치를 요청 |
| 시간대 없는 여행 | 회색 "시간대 확인 필요 · UTC 기준"이 홈 카드, 일정·경비, 시트에 반복 | 사용자: 뜬금없다 |
| "여행 시간대 확인" | 여행 편집 시트에서 도시 시간대를 확인한 뒤 별도 버튼으로 적용한다. 성공 모달 뒤 홈에서 안내가 사라짐 | 11월 10일 온라인·세션 만료·활성 파리 여행에서 앱 재실행 뒤까지 확인. 기기에 저장됐고 서버 전송은 대기 중. 사용자가 앞서 겪은 문제의 원인은 미확인 |
| 일반 미전송 변경, 평소 | 11월 초 조사에서는 평상시 별도 표시를 찾지 못함 | 007의 구버전 보류 입력에서 나타나는 ‘수정 확인’은 별개 상황. [Ticket 05](../tickets/05-unsent-and-stalled.md) |
| 미전송 있음, 로그아웃 | 모달 "동기화 대기 중 / … 1개 있습니다. 로그아웃하면 이 데이터는 손실됩니다." | 사용자에게 개수를 보여 주는 유일한 곳 |

## 규칙이 구별해야 하는 사례

- **제약과 멈춤:** 오프라인 제한은 사용자의 조건 때문에 지금 못 하는 일이고, 멈춘 동기화는 사용자가 뭘 했든 일어난 문제다. 같은 형태로 보여도 되는지 정해야 한다.
- **사건과 상태:** "방금 실패함"은 지나가도 되지만 "변경 N개가 아직 안 갔다"는 고칠 때까지 계속된다. 토스트 논의의 핵심이다. 토스트는 사건에 맞고, 앱 시작 직후면 지나갈 수 있으며 다시 볼 곳이 없다.
- **할 수 있는 일:** 11월 4일에는 같은 로그인을 다시 시도해도 거절되는 사례가 있었다. 007 Ticket 08에서 원본·검증된 소유자를 찾을 수 없는 옛 요청을 격리하고 같은 계정 로그인을 허용하도록 했다. 당시 거절 화면의 문구를 다시 쓸 때는 현재 어떤 원인이 로그인을 차단하는지 확인한다.
- **데이터가 없을 때와 있을 때:** 처음 쓰는 사람과 데이터가 남은 사람이 같은 로그인 화면을 본다.

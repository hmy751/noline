# 현재 안내와 대표 사례

규칙을 정할 때 출발점이 되는 현재 동작이다. 코드 읽기와 iOS 시뮬레이터 캡처로 모았다(2026-11-03~04). 11-03 캡처의 원본은 Mac 재시작으로 사라졌고 표는 남아 있다.

## 현재 쓰는 표시 형태

| 형태 | 현재 쓰임 | 사용자 행동 |
| --- | --- | --- |
| 전역 배너 | 세션 만료뿐 (`SessionExpiredBanner`, 모든 화면 위) | 재로그인 |
| 헤더 표시 | 네트워크 상태 (`NetworkStatusIndicator`, 10개 화면) | 없음 |
| 작은 안내 | 시간대 확인 필요 (`TripTimeZoneNotice`, 5개 화면) | 일정·경비 화면에서 "여행 시간대 확인" |
| 제자리 안내 | 사용 제한 (`PolicyErrorDisplay`의 `banner`·`inline`·`block`, 13곳) | 있을 때만 연결 재확인 |
| 모달 | 확인 질문, 저장 결과, 누른 순간의 제한, 권한 (`Alert.alert`, 디버그 제외 약 50곳) | 확인·취소 |
| 필드 오류 | 폼 입력 오류 | 고쳐 입력 |
| 토스트 | **앱에 없음.** 개발 빌드의 로그 알림(LogBox)과 혼동하지 않는다 | — |

## 상황별 현재 모습

| 상황 | 지금 보이는 것 | 사용자 판단·관찰 |
| --- | --- | --- |
| 활성 여행, 오프라인·확인 불가 | 헤더 한 단어. 목록은 정상 | 네트워크 표시는 유지 |
| 비활성 여행, 오프라인 | 화면 전체 빨간 블록 "작업을 수행할 수 없습니다 / 인터넷에 연결되어 있지 않아요…" | — |
| 비활성 여행, 확인 불가 | 빨간 블록 "인터넷 연결을 확인할 수 없어요." + "다시 확인" | 같은 상태가 활성 여행과 크게 다르다 |
| 오프라인 일정 추가 | 헤더 + 노란 배너 + 빈 상태. 직접 입력을 누르면 같은 문장이 장소 칸에 다시 나옴 | 사용자: 첫 스크린샷 정도는 괜찮다. 안내할 말이 있으니 |
| 오프라인 새 여행 추가 | 모달 "인터넷 연결 필요" | — |
| 삭제 | 이름을 넣은 확인 모달 | — |
| 일정 저장 (생성) | 성공 표시 없이 목록으로 | 코드상 수정·삭제는 "성공" 모달이 뜬다. 생성과 다르다 |
| 저장 실패, 일부 조회 실패 | "~에 실패했습니다." 모달, 홈은 다시 시도 없음, 경비는 다시 시도 있음 | 화면으로 보지 못함(Ticket 01) |
| 시간대 없는 여행 | 회색 "시간대 확인 필요 · UTC 기준"이 홈 카드, 일정·경비, 시트에 반복 | 사용자: 뜬금없다 |
| "여행 시간대 확인" | 시간대 창이 아니라 "여행 편집" 시트 전체. 오프라인에서는 같은 제약을 세 번 말함 | 사용자: 잘 안 된다. 온라인 동작은 미확인(Ticket 01) |
| 미전송 있음, 평소 | 표시 없음 | — |
| 미전송 있음, 로그아웃 | 모달 "동기화 대기 중 / … 1개 있습니다. 로그아웃하면 이 데이터는 손실됩니다." | 사용자에게 개수를 보여 주는 유일한 곳 |
| 세션 만료 | 주황 배너 + 재로그인. 로그인 화면 위에도 남음 | 이미 로그인 화면인데 재로그인을 다시 권한다 |
| 첫 로그인, 데이터 없음 | 안내 "여행 데이터가 남아 있으면…" + "기기 데이터 정리하고 로그아웃" + Google + Apple | 사용자: 버튼이 이상하다 |
| 복원 실패 | "저장된 로그인 정보를 확인하지 못했어요. 기기의 여행 데이터는 보존되어 있어요." + "복원 다시 시도" + 안내 + 정리 버튼 + Google + Apple. 배너 없음 | 사용자가 실제 기기에서 겪은 화면과 일치 |
| 복원 실패, 로그인 거절 | 빨간 상자 "저장된 변경의 소유자를 확인하지 못했습니다. 데이터는 보존됩니다." 다음 행동 안내 없음 | 다시 시도해도 왜 안 되는지 모른다 |

## 규칙이 구별해야 하는 사례

- **제약과 멈춤:** 오프라인 제한은 사용자의 조건 때문에 지금 못 하는 일이고, 멈춘 동기화는 사용자가 뭘 했든 일어난 문제다. 같은 형태로 보여도 되는지 정해야 한다.
- **사건과 상태:** "방금 실패함"은 지나가도 되지만 "변경 N개가 아직 안 갔다"는 고칠 때까지 계속된다. 토스트 논의의 핵심이다. 토스트는 사건에 맞고, 앱 시작 직후면 지나갈 수 있으며 다시 볼 곳이 없다.
- **할 수 있는 일:** 복원 실패의 원인이 저장 정보 읽기 실패면 로그인으로 풀리지만, 다른 두 원인은 지금 삭제뿐이다. 같은 화면이 다른 행동을 요구한다. 어떻게 풀지는 007 Ticket 08 결과에 달렸다.
- **데이터가 없을 때와 있을 때:** 처음 쓰는 사람과 데이터가 남은 사람이 같은 로그인 화면을 본다.

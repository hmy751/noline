# 문제·목표·범위

## 문제

앱이 예외 상황을 알리는 방식에 전체 규칙이 없다. 각 기능이 자기 안내를 따로 붙여 왔고 2026-11-03~04에 코드와 실제 화면을 모아 보니 다음이 드러났다.

- **같은 사실을 여러 겹으로 말한다.** 오프라인 일정 추가 화면은 헤더, 노란 배너, 빈 상태가 함께 나온다.
- **같은 상태가 화면마다 다르다.** "확인 불가"가 활성 여행에서는 헤더 글자, 비활성 여행에서는 빨간 블록이다.
- **필요한 안내는 없다.** 미전송 변경은 로그아웃 전까지 보이지 않는다.
- **지금 할 일이 흐리다.** 복원 실패 로그인 화면은 데이터 삭제 버튼이 로그인 버튼보다 위에 있고, 처음 쓰는 사람에게도 나온다.
- **맥락 없는 안내가 있다.** 사용자는 시간대 안내가 "뜬금 없다"고 봤다.

표시를 하나씩 더하면 이 문제가 커진다. 사용자도 "예와처리가 너무 많아서 막 제공한다고 좋을것 같진 않아"라고 했다.

## 목표

사용자가 각 상황에서 지금 무슨 일이고 무엇을 할 수 있는지 한 번에 알게 한다. 이를 위해 다음을 만든다.

1. 상황별 안내 규칙: 누가 알아야 하는지, 어떤 형태로, 겹치면 무엇을 먼저, 어떤 말투와 행동으로.
2. 그 규칙에 맞춘 실제 화면.

이번 Work의 결과에는 **안내를 빼거나 합치는 것**이 포함된다.

## 범위

포함한다.

- 아래 상황의 안내: 오프라인과 연결 확인 불가, 비활성 여행, 세션 만료, 복원 실패, 미전송·멈춘 동기화, 시간대 없음, 권한, 저장 결과, 조회 실패
- 로그인 화면의 상태별 구성과 문구
- 시간대 안내의 위치와 확인 흐름
- 토스트 같은 새 표시 형태를 들일지의 판단

포함하지 않는다.

| 항목 | 이유 | 담당 |
| --- | --- | --- |
| 원본 없는 큐 작업으로 복원·로그인이 막히는 원인 | 동기화 큐의 문제다. 여기서는 그 결과의 안내만 맡는다 | 007 Ticket 08 |
| 운영 서버 로그, 동기화 시작·실패 횟수 | 개발자용 기록이다 | 007 Ticket 06 |
| 충돌 규칙, 사용자의 변경 버리기 정책 | 데이터 규칙이 먼저다 | 007 Ticket 07 |
| 규칙 없이도 잘못이 분명한 버그 다섯 가지 | 이 Work를 기다릴 이유가 없다. 목록은 아래에 있다 | Workspace 없이 개별 수정 |
| Project 문서 갱신 | 사용자가 아직 확실하지 않다고 정정했다 | 확정 뒤 사용자 요청 시 별도 판단 |

개별 수정 후보: 경비 화면의 시간대 안내가 헤더 위로 겹침, 오프라인 시간대 시트가 닫기 어렵고 아래가 잘림, 로그인 화면 약관 문구 겹침, 흐리지만 눌리는 로그인 버튼, 세션 만료 배너 아래 빈 공간. 근거는 [007 안내 현황 기록](../../../../007-sync-failure-recovery/records/2026-11-04-01-notice-inventory.md#드러난-문제)에 있다. 이 수정이 먼저 끝나면 해당 화면의 현재 설명을 고친다.

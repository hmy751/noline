# 05. 미전송과 멈춘 동기화 표시

## 맡은 결과와 범위

서버에 아직 안 간 변경이 있다는 것을 사용자가 필요한 때 알 수 있게 한다. 운영 기록과 횟수는 007 Ticket 06, 충돌을 끝내는 규칙은 007 Ticket 07이 맡는다.

## 실행 맥락과 접근

**확인한 사실**
- 오프라인 저장은 조용히 끝나고, 미전송 개수는 로그아웃·계정 삭제 경고에서만 보인다. 다른 곳은 개발 빌드의 디버그 화면뿐이다.
- 화면이 구독하는 동기화 상태는 `isSyncing`과 `lastSyncedAt`뿐이다. 실패는 콘솔에만 남는다.
- 큐에는 상태, `retryCount`, 마지막 시도 시각이 있고 실패 이유는 없다. `getSyncQueueStats`가 개수를 센다.
- 동기화는 앱 시작과 연결·로그인 회복, 수동 실행에서만 시작한다. 실패하면 같은 세션에서 다시 시도할 계기가 없다.
- `triggerManualSync`가 있지만 출시 빌드에서 부르는 화면은 없다. 사용자용 "다시 보내기"는 새 제품 선택이다. 003 Ticket 11의 범위는 개발자용 표시였다.
- 인증 오류로 멈추면 작업이 PENDING으로 돌아간다. 세션 만료 배너와 겹치지 않게 봐야 한다.

**정할 것**
- 오프라인에서 정상으로 기다리는 미전송도 보일지, 실패했을 때만 보일지.
- 형태. 후보는 [Spec 05](../spec/05-constraints-design-assumptions.md#현재-설계)에 있다.
- "다시 보내기"를 줄지. 시작할 수 없는 조건이면 `getSyncBlockReason`으로 판단한다.
- 개수는 로그아웃 경고와 같은 값(PENDING·IN_PROGRESS·FAILED 합계)을 쓸지.
- 변경 버리기는 제공하지 않는 것이 Main 추천이다. 무엇을 버려도 안전한지는 [007 Ticket 07](../../../../007-sync-failure-recovery/current/memory/tickets/07-conflict-rule-and-cleanup.md)이 정한다. 시작할 때 그 Ticket과 [운영 기록을 맡는 007 Ticket 06](../../../../007-sync-failure-recovery/current/memory/tickets/06-stalled-sync-visibility.md)의 현재 상태를 읽는다.

## 완료 조건과 확인 방법

- 정한 조건에서 표시가 나오고, 해결되면 사라진다. 시뮬레이터로 확인한다.
- 정상 오프라인 사용을 경고처럼 만들지 않는다.
- 세션 만료·네트워크 안내와 겹칠 때 정한 우선순위를 따른다.

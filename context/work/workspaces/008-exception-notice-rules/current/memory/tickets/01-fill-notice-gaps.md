# 01. 아직 못 본 안내 화면 채우기

## 맡은 결과와 범위

규칙을 정하는 데 필요한 상황을 실제 화면으로 볼 수 있게 한다. 화면을 고치지는 않는다.

[Spec 02](../spec/02-behavior-and-cases.md)의 표는 일부만 스크린샷이 있고, 일부는 코드로만 봤다.

## 실행 맥락과 접근

**다시 캡처하거나 처음 볼 것**

| 상황 | 왜 |
| --- | --- |
| 오프라인·확인 불가의 활성/비활성 여행, 오프라인 일정 추가, 삭제 확인, 로그아웃 경고 | 11-03 스크린샷 원본이 사라졌다. 규칙을 정할 때 나란히 봐야 한다 |
| 수정·삭제의 "성공" 모달, 저장 실패 모달 | 코드로만 봤다 |
| 홈·경비의 조회 실패 | 코드로만 봤다. 다시 시도 유무가 다르다 |
| 위치 권한 거절 | 코드로만 봤다 |
| 시간대 확인의 **실제 온라인** 흐름 | 사용자가 잘 안 된다고 했는데 재현하지 못했다. 11-03에는 앱이 네트워크를 오프라인으로 읽었다 |
| 데이터가 있는데 세션이 없는 `signed-out` 로그인 | 코드로만 추정했다 |

**이미 있는 화면:** 세션 만료 홈, 세션 만료 로그인, 데이터 삭제 확인, 복원 실패, 로그인 거절은 [artifacts 폴더](../../../../../../../artifacts/2026-11-04-login-screens/)에 있다.

**수행 방법**
- Sonnet medium 담당자가 시뮬레이터에서 캡처하고, Main이 주요 장면을 직접 열어 대조한다.
- 스크린샷은 git에 넣지 않는다. 저장소 root의 `artifacts/` 아래 새 폴더에 두고 `.gitignore`에 그 폴더를 추가한 뒤 records에서 링크로 잇는다. 임시 폴더는 재시작하면 지워지므로 쓰지 않는다.
- 개발 빌드의 로그 알림(LogBox)과 사용자용 표시를 구별한다.
- 로컬 스택이 켜져 있는지 먼저 확인한다. 꺼져 있으면 [start-app](../../../../../../../.agents/skills/start-app/SKILL.md)을 따른다.
- Metro를 `CI=1`로 켜지 않는다. 11-04에 `CI=1`로 켠 Metro가 코드 변경을 반영하지 않아 수정 전 화면이 찍혔다. `CI=1` 없이 `--clear`로 재시작하자 반영됐다. 둘 중 무엇이 해결했는지는 구별하지 않았다. 코드를 고친 뒤 캡처하면 화면이 새 코드인지 먼저 확인한다.
- 시험 데이터를 만들면 무엇을 만들었는지 적고, DB를 바꾸면 먼저 백업한다.

**상황을 만드는 방법**

| 방법 | 근거 | 주의 |
| --- | --- | --- |
| 디버그 화면(프로필 → 디버그 콘솔)의 온라인·오프라인·미확정 강제 설정 | 11-03에 사용함 | 오프라인 강제 설정은 로컬 저장도 막는다. 미전송을 만들려면 실제 오프라인이어야 한다. 끝나면 "실제"로 되돌린다 |
| 시뮬레이터 DB: 앱을 끈 뒤 `xcrun simctl get_app_container <udid> com.noline.dev data` 아래 `Documents/SQLite/noline.db`를 백업·수정, 끝나면 복원 | 11-04에 사용함 | `-wal`·`-shm`도 함께 본다 |
| 복원 실패: 비활성 여행 한 건의 소유자 값 변경, 또는 큐 작업의 원본 행 삭제 | 11-04에 사용함 | 앞과 같이 DB 백업 후 복원 |
| 세션 만료: 로컬 서버 DB에서 해당 사용자의 refresh token 행 삭제 후 앱 재실행 | 11-04에 사용함 | 앱이 기기 토큰도 지우므로 사용자의 재로그인이 필요하다. `.env.production`은 읽지 않고, DB 주소가 localhost인지 먼저 본다 |
| 데이터 없는 첫 화면: 다른 시뮬레이터에 같은 앱 설치 | 11-03에 사용함 | 시뮬레이터 도구는 기기별 접근 허용이 필요하다. 없으면 `simctl` 스크린샷만 된다 |
| 조회·저장 실패: API 서버 중지 | 시도하지 않음 | 서버를 끄는 동안 다른 작업에 영향이 없는지 본다 |
| 위치 권한 거절: `xcrun simctl privacy <udid> revoke location com.noline.dev` | 시도하지 않음 | 안 되면 시뮬레이터 설정에서 바꾼다 |

**사용자가 해야 하는 일:** Google·Apple 로그인과 자격 증명 입력은 담당자가 하지 않는다. 지금 시뮬레이터는 세션 만료 상태라 온라인 흐름을 보려면 사용자의 재로그인이 필요하다. 세션 만료 전에 쓰던 계정으로 로그인해야 한다. 필요해지면 그 지점에서 요청한다.

앱이 네트워크를 오프라인으로 계속 읽으면 앱을 다시 실행해 본다. 11-03에 원인을 찾지 못했고 재시작한 다음 날에는 온라인으로 돌아왔다.

## 완료 조건과 확인 방법

- 위 상황마다 스크린샷이나 볼 수 없는 이유가 있다.
- 시간대 확인이 실제 온라인에서 어떻게 동작하는지 사용자가 말한 문제와 대조해 적었다.
- [Spec 02](../spec/02-behavior-and-cases.md)의 표가 실제 화면과 맞다.

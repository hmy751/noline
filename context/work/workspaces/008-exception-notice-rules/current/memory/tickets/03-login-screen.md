# 03. 로그인 화면 구성

## 맡은 결과와 범위

첫 사용, 세션 만료, 복원 실패에서 사용자가 지금 할 일을 바로 알 수 있게 한다. 원본 없는 큐 작업 자체를 해결하는 일은 007 Ticket 08이 맡는다.

## 실행 맥락과 접근

**확인한 사실** ([재현 기록](../../../../007-sync-failure-recovery/records/2026-11-04-02-restore-failed-dead-end.md))
- [LoginScreen.tsx](../../../../../../../apps/client/src/screens/LoginScreen.tsx)는 데이터 유무와 상관없이 안내문과 "기기 데이터 정리하고 로그아웃"을 항상 Google·Apple 위에 보인다.
- 세션 만료면 "여행으로 돌아가기"가, 복원 실패면 설명과 "복원 다시 시도"가 그 위에 더해진다.
- 세션 만료 배너가 로그인 화면 위에도 남아 "재로그인"을 다시 권한다.
- "복원 다시 시도"는 실패해도 진행 표시나 안내가 없다.
- 로그인 거절 오류가 다음 행동을 말하지 않는다. "데이터는 보존됩니다"만 있어 삭제밖에 없는 상황을 알 수 없다.
- 삭제 버튼은 확인 창에서 몇 개가 사라지는지 알려 주지 않는다.

**정할 것**
- 데이터 삭제 버튼을 언제 보일지, 어디에 어떤 모양으로 둘지. 처음 쓰는 사람에게 보일 이유가 있는지.
- 이 판단에는 기기에 데이터가 있는지 아는 값이 필요하다. 지금 화면에는 없다.
- 세션 만료의 "돌아가기"와 로그인 중 무엇이 먼저인지.
- 복원 실패 문구. 007 Ticket 08이 정해지기 전이면 원인별 경우를 나눠 준비한다.

흐린 버튼과 약관 문구 겹침은 개별 수정 후보다. 같은 파일을 바꾸므로 이 Ticket을 시작할 때 고쳐졌는지 확인하고, 아니면 함께 처리해 중복 수정을 피한다.

시작할 때 [007 Ticket 08](../../../../007-sync-failure-recovery/current/memory/tickets/08-orphaned-queue-task-blocks-login.md)의 현재 상태를 읽는다. 처리 방법이 정해졌으면 복원 실패 문구를 거기에 맞춘다.

## 완료 조건과 확인 방법

- 데이터 없음, 세션 만료, 복원 실패의 원인별로 시뮬레이터에서 화면과 동작을 확인했다.
- 데이터를 지우는 행동이 로그인보다 눈에 띄지 않고, 무엇을 잃는지 알려 준다.
- 사용자가 실제 기기에서 확인했다.

## 현재 상태와 실제 결과

실행 전. Ticket 02를 기다린다.

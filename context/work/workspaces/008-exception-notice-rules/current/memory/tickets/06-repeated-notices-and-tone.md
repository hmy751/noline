# 06. 겹친 안내와 말투 정리

## 맡은 결과와 범위

03~05 밖의 화면을 규칙에 맞춘다. 안내가 늘지 않고 줄어드는 것이 목표다.

## 실행 맥락과 접근

대상 후보는 Ticket 02에서 확정한다. 지금 보이는 것은 다음과 같다.

- 오프라인 일정 추가의 빈 상태와, 직접 입력 뒤 다시 나오는 같은 문장. 노란 배너 자체는 사용자가 괜찮다고 봤다.
- 활성·비활성 여행의 "확인 불가" 차이.
- 생성은 조용하고 수정·삭제는 "성공" 모달을 띄우는 차이. 코드로 확인했고 화면은 Ticket 01에서 본다.
- 다음 행동이 없는 "~에 실패했습니다." 모달.
- "~습니다"와 "~어요"의 혼용.
- 세션 만료 배너 아래 빈 공간. [SessionExpiredBanner.tsx](../../../../../../../apps/client/src/shared/components/SessionExpiredBanner.tsx)와 `MobileHeader`가 상단 안전 영역을 각각 더하는 것으로 코드에서 봤다. 같은 상태의 프로필 화면에서 "계정 삭제"가 탭 바에 잘려 보이는데, 이 여백 때문인지와 스크롤로 볼 수 있는지는 확인하지 않았다. 사용자는 "저 배너는 다른 워크에서 작업하자"고 해 개별 수정으로 먼저 고치지 않았다. 코드상 원인은 `useSafeAreaInsets`가 위에 배너가 있어도 기기의 상단 높이를 그대로 돌려주는 것이고, 로그인 화면의 `SafeAreaView`도 같은 구조다. 고칠 방향의 후보는 배너가 비운 만큼 그 아래 화면에 위쪽 여백을 0으로 알려 주는 것이며 시험하지 않았다. 배너가 위쪽에 남으면 어떤 모양이든 필요하고, 위쪽에서 없애면 필요 없다. 화면은 [홈](../../../../../../../artifacts/2026-11-04-login-screens/session-expired-home.png)에서 볼 수 있다.
- 접근성용 큰 글꼴에서 로그인 버튼 글자가 잘린다. 약관 수정 검증 때 담당자가 보고했고 Main이 화면을 열어 보지는 않았다. 캡처는 [first-use-small-bigtext-top.png](../../../../../../../artifacts/2026-11-04-login-screens/first-use-small-bigtext-top.png)다.

Policy의 `reason`은 여러 화면에 쓰이므로 문구를 바꾸면 소비자를 함께 본다. 안내를 고쳐도 실행 조건은 바꾸지 않는다.

## 완료 조건과 확인 방법

- 정한 화면에서 전후 캡처로 겹침이 줄었음을 확인한다.
- 정책·실행 조건 관련 테스트가 그대로 통과한다.

## 현재 상태와 실제 결과

실행 전. Ticket 02를 기다린다.

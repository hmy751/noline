# 06. 겹친 안내와 말투 정리

## 맡은 결과와 범위

03~05 밖의 화면을 규칙에 맞춘다. 안내가 늘지 않고 줄어드는 것이 목표다.

## 실행 맥락과 접근

대상 후보는 Ticket 02에서 확정한다. 지금 보이는 것은 다음과 같다.

- 오프라인 일정 추가의 빈 상태와, 직접 입력 뒤 다시 나오는 같은 문장. 노란 배너 자체는 사용자가 괜찮다고 봤다.
- 활성·비활성 여행의 "확인 불가" 차이.
- 생성은 조용하고 수정·삭제는 "성공" 모달을 띄우는 차이. 코드로 확인했고 화면은 Ticket 01에서 본다.
- 다음 행동이 없는 "~에 실패했습니다." 모달.
- "~습니다"와 "~어요"의 혼용.

Policy의 `reason`은 여러 화면에 쓰이므로 문구를 바꾸면 소비자를 함께 본다. 안내를 고쳐도 실행 조건은 바꾸지 않는다.

## 완료 조건과 확인 방법

- 정한 화면에서 전후 캡처로 겹침이 줄었음을 확인한다.
- 정책·실행 조건 관련 테스트가 그대로 통과한다.

## 현재 상태와 실제 결과

실행 전. Ticket 02를 기다린다.

1. **Ticket 01:** Sonnet medium 담당자가 빠진 화면을 캡처한다. 화면을 고치지 않는 일이라 아래 초안 확인 전에도 진행할 수 있다. 재로그인이 필요한 지점에서는 사용자에게 요청한다.

## 확인 상태

- **확인한 것:** Spec 02의 현재 동작은 코드 읽기와 시뮬레이터 캡처로 모았다. Sonnet 담당자가 캡처했고 Main이 주요 장면을 대조했다.
- **아직 확인하지 않은 것:** 저장 성공·실패 모달, 조회 실패, 권한, 시간대의 실제 온라인 흐름, 데이터 있는 `signed-out` 로그인을 화면으로 보지 못했다. 사용자 수와 상황별 빈도를 모른다.
- **자료 유실:** Mac 재시작으로 11-03 스크린샷 원본이 사라졌다. Ticket 01에서 다시 캡처한다.
- **제품 Verify:** 실행하지 않았다. `status.json`의 `ready_for_verification`은 생성 때의 초기 값이고 제품이 준비됐다는 뜻이 아니다. 현재 claim은 `recover.json`의 파싱뿐이고 제품 동작을 증명하지 않는다.
- **재진입 확인:** 맥락을 모르는 Sonnet 담당자에게 Recover 결과만 주고 확인했다. 목표·제약·상태·첫 행동을 복원했고 깨진 링크는 없었다. 보완이 필요하다고 판정한 재현 방법, 토스트 관련 기존 선택, 007 Ticket 상태를 읽을 경로, 개별 수정의 경계를 반영했다. 반영 뒤 다시 돌리지는 않았다.
- **커밋:** Workspace 생성은 `661d1c71`, 007의 11-04 기록은 `30fcd7de`로 커밋했다. 약관 겹침 수정 코드는 `46780807`이고, 심사 중인 1.1.0 (13)에는 들어가지 않는다.
- **연결:** active 기본값과 세션 연결은 바꾸지 않았다. 이 세션의 문서 반영은 [Maintain 수동 fallback](../../../../harness/maintain/README.md#session-binding과-lifecycle)으로 Main이 한다.
- **약관 겹침 수정 (11-04, `46780807`, 미배포):** [LoginScreen.tsx](../../../../../../apps/client/src/screens/LoginScreen.tsx)에서 약관의 `absolute`를 없애고 내용 영역과 약관 영역을 위아래로 쌓았으며, 내용이 길면 전체가 스크롤된다. 별도 Sonnet 담당자가 세션 만료, 복원 실패, 데이터 없는 첫 화면을 시뮬레이터로 검증했고 Main이 세 화면을 열어 대조했다. 글꼴을 키워 내용이 넘치게 만든 경우의 스크롤은 담당자가 확인했다. 오류 상자가 붙은 상태, iPhone 16e보다 작은 기기, Google·Apple 버튼 탭은 확인하지 않았다. `pnpm client lint`는 코드 검사 전에 도구가 멈췄다. 타입 검사 오류 8개는 수정 전과 같다고 담당자가 보고했다. 화면은 [artifacts 폴더](../../../../../../artifacts/2026-11-04-login-screens/)의 `-after` 파일이다.
- **로컬 환경 (11-04):** 시뮬레이터 앱은 세션 만료 상태이고, 시험 일정 "표시 확인용" 1건이 미전송이다. 로컬 Postgres, API 서버, Metro가 켜져 있으나 재시작하면 꺼진다.

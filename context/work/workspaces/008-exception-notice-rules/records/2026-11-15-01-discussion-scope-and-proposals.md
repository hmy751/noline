# 전체 정책과 화면을 함께 검토한 이유

008의 논의 범위는 두 번의 정정으로 분명해졌다. 먼저 사용자는 “아니 모든 정책이나 컨텍스트를 비교해보라고”라고 했다. Main이 세션 만료 배너 등 일부 화면부터 제안했던 데 대한 정정이었다. 이어서 작업의 큰 선택만 먼저 묻자 “큰 부분만 집자는게 아니라 전체 아까 화면에서 다 정리를 해보자는거지 어떻게 할지”라고 했다. 두 조건을 함께 적용해 촬영한 각 화면에 대해 사용자가 하려던 일, 이미 정해진 정책, 화면에서 실제로 보인 것, 제안할 안내와 후속 행동을 맞췄다.

원문은 Codex 대화 `01a1c4af-93cd-7ba0-8036-5e1e2d37ea53`의 453·482·575행이다. 532행에서 정책 비교와 촬영되지 않은 상태를 다뤘다. 사용자는 이어서 설명과 사진을 연결하고(635행), 제안하는 모습도 이미지로 보여 달라고 했다(737행). 11월 15일에는 “그럼 지금까지 대화한거랑 기록한거 잘 남겨서 기록하고 커밋해줘”라고 요청했다(1115행).

## 화면을 판단할 때 함께 볼 조건

- 여행 데이터와 외부 서비스는 서로 다른 조건에서 동작한다. 활성 여행에서는 오프라인이어도 일정을 읽고 쓸 수 있고, 장소 검색이 막히면 직접 입력을 제공한다. 비활성 여행에서는 일정 목록 자체의 접근 제한을 알려야 한다. [여행 접근과 조회 복구](../../../../project/guidance/travel-access/INDEX.md)
- 저장과 서버 반영은 시점이 다르다. 세션이 만료된 파리 여행에서 시간대의 기기 저장은 성공했고 전송은 대기했다. 로그아웃 때 손실될 기록은 일반 전송 대기 외에 보류·격리 사례도 있어 사용자가 어떤 행동을 해야 하는지 최신 007과 대조해야 한다. [시간대와 날짜](../../../../project/common/date-and-time.md) · [데이터 저장과 동기화](../../../../project/guidance/data-lifecycle/INDEX.md) · [계정 복원과 종료](../../../../project/current/app-runtime/INDEX.md)
- 같은 오류라도 최초 조회 실패, 이전 자료가 남은 갱신 실패, 입력이 남은 저장 실패는 복구할 위치와 행동이 다르다. 안내가 나오는 영역에서 무엇을 유지하고 어떤 행동을 제공할지 화면별로 제안했다. [오류 처리](../../../../project/guidance/error-handling.md)

기존 내용이 남은 갱신 실패, 지도·경로의 부분 준비 실패, 반복 전송 실패, 격리 기록만 남은 로그아웃, 기기 DB 준비 실패와 계정 종료 도중의 부분 실패는 당시 갤러리에 각각의 차이를 보여주는 장면이 없었다. 이 경우는 촬영 자료가 더 필요한 조건으로 남았다. 11월 4일 로그인 거절과 11월 10일 구버전 수정 보류 사례의 문구·복구 행동 역시 007이 이후에 바꾼 경로와 대조한 뒤 적용한다.

# 흐린 버튼과 넘치는 시트의 개별 수정

11월 4일 008을 만들 때 규칙 없이도 잘못이 분명한 개별 수정 후보로 둔 두 버그, 즉 공용 `Pressable`이 흐린 채 남는 문제와 시간대 확인 뒤 시트의 "취소"가 화면 밖으로 밀려 스크롤되지 않는 문제를 고쳤다. 수정 코드는 11월 4일에 만들어졌지만 검증이 멈춘 채 커밋되지 않았고, 11월 16일 다른 작업 중에 원인이 다시 드러나 비교 실험과 사용처 검증을 거쳐 커밋했다. 두 수정은 안내 규칙과 무관한 공용 UI 수정이며 이 Work의 Ticket 결과가 아니다.

| 커밋 | 내용 | 상태 |
| --- | --- | --- |
| `c9505e41` fix(ui): Pressable이 비활성 해제 뒤에도 흐리게 남지 않게 한다 | `packages/ui/src/components/Pressable.tsx` 기본 클래스에서 `transition-colors` 제거 | 브랜치 `fix/008-pressable-drawer`, main 미병합 |
| `8b95b9ca` fix(ui): 넘치는 Drawer 내용을 끝까지 스크롤할 수 있게 한다 | `packages/ui/src/components/Drawer.tsx`의 바깥 탭 영역을 시트의 조상에서 형제(`absoluteFill`)로 옮기고, 최대 높이를 창 높이의 90%로 두고 `ScrollView`가 남은 공간만 차지하게 하며 패딩을 스크롤 콘텐츠 안으로 옮김 | 같은 브랜치, main 미병합 |

브랜치는 main `4cfaa81e`에서 땄다. 원래 저장소 작업트리에도 같은 두 파일 변경이 미커밋으로 남아 있으며 커밋 내용과 같다.

## 11월 4일: 수정은 만들었지만 검증이 멈췄다

Sonnet 담당자가 원인을 확인한 뒤(state의 11월 4일 확인 메모) Main은 "두 건 다 고쳐야 할 버그"라고 보고했고 사용자가 "둘 다 고쳐"라고 했다. 수정 담당자는 커밋하지 말라는 지시로 두 파일을 고쳤다. `Pressable`은 처음 제안대로 한 단어 제거였지만, `Drawer`는 높이 제약만으로 스크롤이 되지 않아 터치 구조까지 바꾸는 수정이 됐다. Main은 처음 말한 것보다 범위가 커졌다고 알렸다.

별도 검증 담당자는 로그인 화면의 버튼이 진하게 보이고 누르다 취소해도 옅어진 채 남지 않음, 앱 테스트 655개 통과, 타입 오류 8건이 기존과 같음을 확인했다. 그다음 홈으로 돌아가려고 "여행으로 돌아가기"를 탭하자 자동 권한 검사가 거부해 멈췄다. `Drawer` 사용처는 시간대 시트를 수정 담당자만 본 상태였다. Main은 "공용 시트는 터치 구조까지 바뀌어서, 이 검증 없이 커밋하는 것은 추천하지 않습니다"라고 한 뒤 답을 기다렸고, 사용자 응답 없이 세션이 끝났다. 008 state는 수정 지시 전에 쓴 "시작하지 않았다"로 남았다.

원문: Claude 세션 `efdeb864-93a9-429b-b31d-8ba58adb98dd` 4726~4850행(2026-11-04T05:45Z~06:10Z).

## 11월 16일: 다른 작업에서 원인이 다시 드러났다

사용자가 START_GUIDE를 처음 보는 개발자도 따라 할 수 있는지 확인해 달라고 해서, Main이 새로 clone한 저장소와 새 iOS 26.5 simulator로 앱을 띄웠다. 로그인 화면의 Google 버튼과 "기기 데이터 정리하고 로그아웃" 버튼이 계속 비활성처럼 보였다. 사용자가 "원인 확인해봐"라고 해서 진단했다.

- 두 버튼은 Google 인증 요청이 준비되기 전 `disabled=true`로 시작한다. 임시 로그로 요청이 곧 준비되는 것(`request ready: true`)을 확인해 인증 요청 생성은 원인이 아니었다.
- 원래 저장소 작업트리에서는 버튼이 정상으로 보였다. 작업트리에 커밋되지 않은 `Pressable.tsx` 변경이 `transition-colors`를 뺀 것이었다.
- 같은 개발 빌드에서 이 클래스만 넣고 빼며 비교했다. 넣으면 ready 로그 뒤에도 두 버튼이 흐린 채 남고, 같은 버튼을 두 번 눌러도 확인 창이 뜨지 않았다. 빼면 버튼이 진하게 바뀌고 같은 위치 탭에 "이 기기의 데이터 정리" 확인 창이 떴다(취소로 닫음).

11월 4일 기록은 "흐리게 보이지만 눌린다"였다. 눌림 여부는 두 관찰이 다르다. 각각 한 번씩의 관찰이고 iOS 버전 등 차이의 원인은 가리지 않았다. 어느 쪽이든 클래스를 빼면 풀린다는 결과는 같다. 진단용 코드와 임시로 바꾼 `Pressable.tsx`는 원래대로 되돌렸다.

이어 사용자가 "그럼 작업트리의 작업이 버그 해결이었다는거지? … 커밋을 어떻게 할지 다시 생각해봐"라고 했다. Main은 11월 4일 기록과 대조해 두 변경이 버그 수정이며 상태가 다르다고 판단했다. `Pressable`은 11월 4일 검증과 오늘 비교로 확인돼 바로 커밋하고, `Drawer`는 사용처 검증 뒤 따로 커밋하기로 했다. 사용자가 "006 같이 관련 없는건냅두고"라고 해 다른 미커밋 변경은 넣지 않았다. 같은 폴더에서 다른 세션이 작업 중이어서 커밋은 별도 worktree에서 했다.

## Drawer 사용처 검증

새 simulator는 로그인할 수 없어, 사용자가 "내 simulator로 검증"이라고 정했다. Main이 사용자 iPhone 15 Pro simulator에서 서버를 끈 채 저장·삭제 없이 확인했다.

| 시트 | 확인한 것 |
| --- | --- |
| 여행 선택 | 내용 높이로 열림, 시트 안 탭으로 닫히지 않음, 바깥 탭으로 닫힘 |
| 일정 수정 | 저장·취소까지 한 화면에 들어옴 |
| 날짜 선택·시간 선택 | 일정 수정 시트 위에 겹쳐 열림, 바깥 탭으로 그 시트만 닫힘, 시간 휠 스크롤 동작, 확인 없이 닫으면 값 유지 |
| 경비 수정 | 넘치는 내용이 끝까지 스크롤되어 저장·취소까지 닿음 |
| 여행 편집 | 내용 높이로 표시, 바깥 탭으로 닫힘 |

제목·금액은 시트 안 입력 칸이 아니라 입력 창(Alert prompt)으로 바뀐다. 키보드가 올라오면 시트가 위로 밀려 머리글이 화면 밖으로 나간다. 11월 4일 검증 담당자가 코드만 보고 "이전 코드도 같은 구조라 기존 문제로 보인다"고 한 부분이며, 이번에도 수정 전 코드와 비교하지 않아 이 수정 때문에 생긴 문제인지는 모른다.

확인하지 못한 것은 시간대 확인 시트(11월 4일 수정 담당자만 "취소"까지 스크롤되는 것을 봄), 활성화 진행 시트, 11월 13일에 추가된 구버전 충돌 확인 시트(`LegacyUpdateRecovery`), 실기기다. 수정 뒤 `Pressable`이 비활성인 동안 흐리게 보이는지는 화면으로 따로 보지 않았다. 로그인 화면에서는 비활성이 수 ms 만에 풀려 눈으로 볼 틈이 없다.

원문: Claude 세션 `da74d77c-3a97-4f86-9ee3-da972cde564d` 567·606행(관찰), 937~1306행(진단), 1311~1536행(기록 대조와 커밋 계획), 1546~1949행(사용처 검증과 커밋).

## 남은 관련 후보

- `packages/ui`의 `Switch.tsx`에도 `transition-colors`가 있다. 같은 문제가 있는지 확인하지 않았다.
- 이 클래스는 2025-10-21부터 있었고 운영 1.1.2 빌드 16을 준비한 커밋에도 있다. 운영 앱의 Google 로그인 버튼이 같은 상태인지는 확인하지 않았다.
- 키보드가 올라올 때 시트 머리글이 밀리는 문제를 어떻게 다룰지와 브랜치를 main에 넣을 시점은 정하지 않았다.

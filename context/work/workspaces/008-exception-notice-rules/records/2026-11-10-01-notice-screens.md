# 11월 10일 예외 안내 화면 수집

사용자는 007의 다른 티켓을 병렬로 진행하고 있다고 알렸고, 로그인 배너에 대한 제안을 본 뒤 “일단 필요한 화면을 수집하자”고 했다. 상황별 규칙은 실제 화면을 비교한 뒤 논의할 단계다. 원문은 Codex 대화 `01a1c4af-93cd-7ba0-8036-5e1e2d37ea53`의 사용자 발화(원본 17·56행)에 있다.

[예외 안내 갤러리](../../../../../artifacts/2026-11-10-008-notices/index.html)에서 이미지를 누르면 원본을 볼 수 있다. 이미지와 갤러리는 이 체크아웃의 `artifacts/`에 보관한다.

## 11월 10일 새로 찍은 화면

iPhone 16e에서 16장, iPhone 17에서 시간대 흐름 6장을 새로 촬영했다. 007과 다른 시뮬레이터에서 시험 여행을 사용했다. 이전 18장을 합한 갤러리의 원본 40장을 Main이 축소 화면과 대조하고 링크와 이미지 파일을 확인했다. 실제 사용 빈도는 조사하지 않았다.

| 상황 | 관찰 |
| --- | --- |
| 기기에 여행 1개, 로그인 세션 없음 | 기기 데이터 정리와 로그아웃을 먼저 제시하고 그 아래에 Google·Apple 로그인 버튼을 둔다. 11월 4일 데이터가 없는 첫 화면과 구성 순서가 같다. |
| 기기에 미전송 변경 1개 | 프로필에서 로그아웃을 누르면 “동기화 대기 중”과 손실될 변경 개수가 나오고 취소하거나 계속 로그아웃할 수 있다. |
| 경비 조회와 홈 여행 목록 조회 실패 | 시험 HTTP 서버가 각 조회에 503을 응답했다. 경비는 “경비를 불러오지 못했어요.” 아래에 “다시 불러오기”가 있다. 홈은 “여행 정보를 불러올 수 없습니다.” 아래에 “새 여행 추가”가 보이고 오류 영역 안에 재시도 버튼은 보이지 않는다. |
| 경비 수정 | 시험 서버의 PUT 성공에 확인 모달이 떴다. 503 응답 때는 수정 시트가 열린 채로 제목 “점심 식사”가 남고, 아래에 “마지막 저장 실패: 서버 에러가 발생했습니다.”가 나왔다. |
| 경비 삭제 | “점심”이라는 이름을 넣은 확인 모달이 먼저 떴다. 시험 서버의 DELETE 성공과 503 실패는 각각 성공·오류 모달로 알렸다. |
| 위치 권한 거절 | 일정 지도에서 현재 위치를 요청했을 때 “권한 필요” 모달과 확인 버튼이 떴다. |
| 일정 목록과 오프라인 작성 | 개발 앱의 연결 상태를 오프라인·확인 불가로 강제했다. 활성 여행은 두 조건에서 기존 일정이 보인다. 일정 카드의 “좌표 없음”은 시험 일정에 좌표가 빠져서 생긴 별도 안내다. 비활성 여행은 목록이 제한 안내로 바뀌고, 확인 불가에서만 “다시 확인”이 보인다. 오프라인 일정 추가에서는 헤더 표시·장소 검색 제한·빈 상태가 함께 있고, 직접 입력으로 들어가면 장소 입력 영역에 검색 제한이 다시 보인다. |

실제 기기의 통신을 끊는 시험은 하지 않았다. 시험 서버의 503은 조회·저장 실패를 화면에 표시하는 방법을 재현하기 위한 응답이다. [iPhone 16e 화면 원본 16장](../../../../../artifacts/2026-11-10-008-notices/live/)

### 파리 여행의 시간대 확인과 적용

전용 iPhone 17(iOS 26.0)에서 시간대가 비어 있고 세션이 만료된 활성 여행을 준비했다. 온라인에서 홈의 “여행 시간대 확인”을 눌러 여행 편집 시트를 연 다음, “도시 시간대 확인”을 누르니 실제 GeoNames 응답의 `Europe/Paris`가 표시됐다. “시간대 적용”을 누르면 성공 모달이 뜨고 홈의 시간대 안내가 사라졌다. 앱을 종료한 뒤 다시 열어도 이 안내는 돌아오지 않았다.

촬영 담당자는 기기 SQLite에 `Europe/Paris`가 저장됐고 여행 시작·종료 시각의 ISO 값은 그대로였음을 확인했다. 세션이 만료돼 여행 UPDATE 한 건이 전송 대기에 남았다. 서버 반영, 다른 도시·기기·연결 조건에서의 성공 여부, 사용자가 당시 겪은 문제의 원인은 미확인이다. [시간대 화면 원본 6장](../../../../../artifacts/2026-11-10-008-notices/timezone/)

## 이전에 찍은 화면

기존 캡처 18장을 골라 Main이 축소 이미지로 대조했다. 다른 날의 화면으로 사용자에게 보인 차이를 비교할 수 있지만, 그 뒤 바뀐 동작을 판단할 때는 촬영 조건을 확인해야 한다.

| 화면 | 촬영 조건과 읽을 때 주의할 점 |
| --- | --- |
| 연결 제한 5장 | 9~10월 개발 앱에서 연결 상태를 강제했다. 활성 여행의 홈과 비활성 여행의 일정 목록을 오프라인·확인 불가 각각에서 비교한다. 직접 입력은 이전 일정 폼이다. |
| 로그인·기기 데이터 6장 | 11월 4일 첫 사용, 세션 만료 상태의 홈과 로그인, 복원 실패와 이후 로그인 거절, 기기 데이터 정리 확인을 담았다. 로그인 거절은 007의 원본 없는 요청 격리 처리 전 장면이다. |
| 시간대 6장 | 11월 4일 시간대 없는 여행의 홈·일정·경비, 편집 시트, 도시 시간대 확인 결과와 스크롤 수정 후 하단 버튼을 담았다. 이 화면 묶음에서 시간대가 여행에 실제 저장됐는지는 확인할 수 없다. |
| 보류된 경비 수정 1장 | 11월 10일 007에서 경비의 이전 요청과 현재 값을 비교하고 다시 저장할 항목을 고르는 화면을 촬영했다. 일반적인 미전송 알림과는 발생 조건이 다르다. |

# 경비 목록·상세의 온라인 복구

사용자는 2-A 일정 복구와 후속 구조 개선을 커밋한 뒤 다음 작업을 물었고, Main은 Ticket 06의 2-B 경비 목록·상세 연결이라고 답했다. 사용자는 “적용 해줘”라고 실행을 요청했다. 이 기록은 2-B 제품 코드의 판단과 현재 검사 범위를 보존한다.

## 기존 화면에서 확인한 간격

경비 목록과 상세는 이미 `useAppPolicy`로 비활성 여행 offline/unknown 제한 안내를 보여 주었다. 그러나 조회 hook 자체는 제한 중에도 enabled였고, 목록은 `data = []` 기본값으로 미조회·실패·정상 빈 결과를 섞었다. 상세는 첫 조회 실패를 ‘경비를 찾을 수 없음’으로 표현할 수 있었다. 상세에서 연결된 일정 Query도 제한과 대상 경비 존재 여부를 고려하지 않고 구독했다. 성공한 sync push/pull의 공통 갱신은 경비 key를 포함했지만 활성화·비활성화에서 경비 Query는 이전 출처의 진행 중 조회를 취소하지 않았다.

## 적용한 책임과 비용

화면의 표시용 읽기 정책으로 기존 Query 데이터를 소비할지 정하고, 같은 정책의 실제 네트워크 관측 결과가 함께 허용할 때만 목록·상세의 경비 Query를 활성화한다. Query hook은 optional enabled 입력만 받아 Router의 Local/Remote 선택을 계속 사용한다. 별도 복구 상태나 특정 요청 횟수 보장은 만들지 않는다. 유효한 캐시는 복귀 즉시 보여주고 오래되거나 무효화된 캐시는 그 내용을 보인 채 Query 기준으로 갱신한다. 첫 요청 실패에는 전체 오류와 수동 재시도를, 기존 내용이 있는 재조회 실패에는 작은 안내와 재시도를 표시한다. 목록의 합계와 날짜 그룹은 표시 가능한 경비에서만 계산한다. 여행 선택과 수정 Drawer의 mount는 유지한다.

상세는 여행별 경비 캐시에서 route의 대상 ID를 찾는다. 캐시 목록이 있더라도 대상이 없고 최신 조회가 진행 중이거나 실패했다면 ‘찾을 수 없음’을 확정하지 않고 조회 중/오류를 보여 준다. 성공한 빈 결과 또는 갱신 종료 후에도 대상이 없을 때만 부재 안내를 표시한다. 연결된 일정 Query는 현재 경비에 scheduleId가 있고 경비·일정의 표시용 및 실제 읽기 조건이 허용될 때만 활성화한다. 화면에 별도의 데이터 복사나 일정 검색 state를 만들지 않았다.

sync 엔진은 기존처럼 실제 서버 변경 후 trip·schedule·expense key의 진행 중 조회를 취소하고 무효화한다. 활성화·비활성화 callback에서는 일정에 이어 경비 key에도 공통 `cancelAndInvalidateQueries`를 적용했다. 활성 전환 직전의 조회 결과가 새 Local/Remote 출처의 값을 덮지 않게 하기 위한 조치다. 새 GET의 완료는 전환 callback이나 sync 완료 조건에 묶지 않는다.

## 확인과 남은 경계

Main은 관련 경비 화면·sync·활성 전환 검사를 거쳐 전체 client Jest **40개 suite·386개 test 통과**를 확인했다. 화면 검사는 실제 QueryClient·화면·Policy를 사용하며 유효/오래된 캐시, 복귀 조건, 실패·재시도, 상세 대상 부재와 연결 일정, Debug override, 활성 Local, 여행 변경 뒤 늦은 응답을 다룬다. 두 갱신 검사는 변경 전 GET와 push/pull 생략, 활성 출처 전환을 일정·경비 key로 확인한다. 기존 경비 폼 검사는 제목·연결 일정의 제한/재확인 중 입력 보존을 확인하지만 이번 화면 검사는 Drawer를 mock으로 대체했으므로 실제 화면 안의 폼 입력을 새로 입증한 것은 아니다.

repository·HTTP·DB·native 표시 표면은 mock이다. 실제 기기·서버·네트워크 전환 및 native DB 전체를 실행한 결과로 확대하지 않는다. 변경 파일 Prettier와 `git diff --check`는 통과했다. 기존 Prettier plugin 충돌 규칙만 제외한 ESLint는 오류·경고 없이 통과했고, 타입 검사는 기존 Mapbox 좌표 tuple·OfflinePack size/tileCount 오류 3개만 남았다.

2-B 변경과 이 기록은 현재 미커밋이다. 다음은 2-C 토스트의 의미·시점과 중복 방지 기준을 구체화할 일이다. 실패 안내의 최종 UX 확인, foreground 재확인, mutation 오류 전달과 Ticket 전체 완료는 남는다. 현재 결과와 다음 실행은 [Ticket 06](../current/memory/tickets/06-app-startup-lifecycle.md)이 소유한다.

# 지침 보완 범위 정정과 후속 반영

## 정정된 요청 범위

fresh-session Ticket 재구성 보고를 평가한 뒤 Main은 같은 세션에서 구성안을 보완하고 Ticket 07을 실행 가능한 수준으로 작성하는 다음 단계를 권고했다. 사용자는 곧바로 “난 지침 보완이었어”라고 정정했다. 보완 대상은 개별 Ticket 구성안이나 Ticket 문서가 아니라, 이번 검토에서 드러난 간격이 다시 발생하지 않도록 하는 공통 Spec·Ticket 운영 지침이었다.

따라서 앞선 [Ticket 재구성 검토](2026-09-12-06-fresh-session-ticket-recomposition-review.md)의 보고 내용과 세 간격에 대한 평가는 유지하지만, 그 기록 끝의 Ticket 구성안 직접 보완 권고는 현재 다음 행동이 아니다. Ticket 05를 포함한 기존 Ticket 문서와 제품 구현은 이번 단계에서 그대로 둔다.

## 공통 지침에 반영한 의미

Main은 범위를 잘못 이해했다고 인정하고 공통 운영 지침을 보완했다고 보고했다. 제공된 현재 계약에서 다음 변화가 확인된다.

1. 맡은 결과는 살펴볼 파일·상황이나 수행할 조사·수정 활동이 아니라, 실행 뒤 무엇이 가능해지거나 어떤 문제가 해소되고 이전과 무엇이 달라지는지로 정의한다. 기존 작업의 방법을 다른 위치에 적용할 때도 새 범위에 충분한지 판단한다.
2. 조사 자체가 결과인 Ticket은 어떤 판단 근거를 만들고 어떤 미확정을 줄일지가 결과다. 구현 Ticket을 조사 활동만으로 정의하거나 조사 결과를 구현 완료로 보고하지 않는다.
3. 일부 일·결함·관련 기능을 분리할 때는 그것이 남아도 현재 결과가 성립하는지 판단한다. 선행한다면 담당 작업과 해결 전 가능한 진행·완료할 수 없는 결과를 연결하고, 의존 여부가 미정이면 확인할 일과 판단 책임 또는 Main이 배치할 미배정 항목으로 남긴다.
4. 여러 Ticket의 구성안을 제시하거나 재구성할 때부터 Spec의 주요 요구·알려진 문제·기존 결과와 대조해 각 Ticket의 담당, 유지·제외, 미배정·미확인을 설명한다. 마지막 종료 검토는 이 연결의 최종 확인이며 알려진 누락을 처음 배치하는 이유가 되지 않는다.
5. 구성안 단계에는 각 Ticket의 기대 결과·필요 범위·완료 근거의 개요와 주요 의존 관계면 충분하고, 실제 실행할 Ticket은 시작 전 확인 방법까지 구체화한다. 모든 상세 문서나 전수 조사를 미리 끝내도록 요구하지 않는다.

`TICKET.md`에도 코드 개선의 결과를 해소할 이해·수정 부담과 보존할 동작으로 설명하고, 여러 파일을 읽거나 함수·로그를 정리하는 활동만으로 결과를 대신하지 않도록 연결했다. 별도 일을 분리할 때 후속 Ticket 번호만 적지 않고 현재 결과를 막는지와 담당 또는 남은 배치 판단을 적도록 했다. 이 기준은 코드 개선에만 한정하지 않고 기능 구현·결함 수정에도 공통 적용된다.

Main은 선택 이유와 후속 변경을 공통 `HISTORY.md`에도 연결했다고 보고했다. Maintain은 제공되지 않은 HISTORY 본문을 별도로 열거나 그 반영을 독립 확인하지 않았다.

## 확인 범위와 다음 검증

Main은 하네스 직접 검사와 `git diff --check`가 통과했다고 보고했다. Maintain은 검사나 eval을 재실행하지 않았고, 제품 파일·Ticket 본문 변경이나 새 제품 검증·수락은 없다. 후속 변경의 커밋도 보고되지 않았다.

새 지침을 대화 맥락 없는 세션이 실제 Ticket 구성에 독립 적용하는 재검증은 아직 하지 않았다. 다음 판단은 먼저 그 재검증 결과에서 같은 세 간격이 줄었는지 확인하는 것이며, Ticket 구성안이나 Ticket 07 문서를 실제로 고치는 단계는 사용자가 별도로 선택하기 전까지 시작된 것으로 보지 않는다.

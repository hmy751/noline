# Ticket 06 종료 판단과 남겨 둔 범위

Ticket 06은 합의된 앱 준비·인증·네트워크 소비 연결과 그 과정에서 채택한 UX 수정 범위를 마무리한다. Workspace 002 전체와 후속 Ticket은 계속 남는다. 이번 기록·커밋에는 새 제품 수정이나 추가 native 검증이 없다.

## 보고서 대조와 마무리 결정

사용자는 “보고서 보여주고 너도 판단해봐”라고 요청했다. Main은 9월 30일 원래 UX 보고서와 10월 4일 후속 보고서, 후속 구현·검증 기록 및 관련 현재 코드를 대조했다. HTML의 미완료 문구는 당시 상태이며 현재 결함 목록으로 그대로 사용하지 않았다.

| 원래 지적 | 현재 결과와 종료 근거 |
| --- | --- |

이 대조로 Main은 합의된 범위는 종료하고 기본 순서의 07로 넘어가도 된다고 판단했다. 테스트 숫자만으로 판정한 것이 아니라 원래 불편과 원인을 수정했으며, 값·선택 수명·표현 책임을 관련 코드에 모은 결과를 함께 근거로 삼았다. 최신 제품 상태의 client Jest는 앞선 실행에서 60 suites / 650 tests가 통과했고 기존 타입 진단 7개는 남는다. 재대조 중 제품 검사를 새로 실행하지 않았다.

사용자가 남은 항목의 뜻을 물었을 때 Main은 처음에 전체 Ticket 목록으로 답해 범위를 넓혔다. 사용자는 “방금 남은것은 구분이라고 하고 말한것들 더 자세히”라고 정정했다. 아래 네 범주의 구체적인 상황을 설명한 뒤 사용자는 “그래 일단 마무리 하자 기록할거 하고 커밋해”라고 요청했다. 이 맥락에서 Ticket 06의 합의된 범위 마무리와 기록 커밋을 승인한 것으로 반영한다. 미확인까지 검증됐거나 보류 문제가 해결됐다는 수락으로 확대하지 않는다.

## 남은 네 범주의 의미

### 알고 있으며 보류한 두 문제

경비 삭제가 실패했을 때 구체적인 이유가 일반 실패 안내로 뭉개지는 문제가 남는다. 생성·수정 저장 오류 개선은 삭제 오류를 포함하지 않는다. 삭제 자체가 항상 실패한다는 뜻은 아니다.

경비 상세에서 이전 조회 오류가 있고 목록 캐시에 대상이 없으며, Debug 표시만 online이고 실제 연결은 offline인 조합에서는 재시도 버튼이 보이지만 정책의 canFetch가 false라 요청이 시작되지 않는다. 실제 요청 차단은 유지해야 하며, 실행할 수 있는 행동처럼 표시하는 UI와 실행 조건의 불일치가 문제다. 두 건은 기존 사용자 보류를 유지하고 이번 마무리에서 착수하지 않는다.

### 후속 작업이 소유하는 범위

전체 폼의 늦은 편집 데이터·다른 항목 전환·초기화와 입력 보존은 10·11, 여행 기간 밖에 저장된 일정의 표시·접근은 08에서 남은 범위를 판단한다. 이번 날짜 표시 통일과 시간 picker 수명 개선만으로 모두 끝난 것은 아니다.

저장 후 500ms를 기다려 목록과 좌표로 경로를 준비하는 연결, 새 장소 수정 뒤 이전 좌표 소비와 기존 경로 재사용 가능성은 13의 후속이다. 일부 동기화 실패·재시도·결과 전달은 15, 비활성화·정리·로그아웃의 미전송 데이터 보존은 16이 맡는다. 각 Ticket이 가진 앞선 결과를 재사용하며 원래 분석의 모든 가능성을 현재 재현 결함으로 확정하지 않는다.

### 아직 직접 실행하지 않은 검증

새 중앙 휠의 23:59는 자동 검사 근거만 있고 native 마지막 시·분 조작은 미확인이다. 초기 picker 단계의 23:59 native 확인을 새 휠 전체 검증으로 확대하지 않는다. Android의 스크롤·중첩 선택창은 이번에 실행하지 않았다.

Debug offline은 실제 인터넷 단절과 다르다. 실제 단절 중 Local 저장부터 연결 복구·동기화까지, 열린 폼 그대로 실제 연결을 바꾸는 흐름과 새 여행 생성부터 activation까지의 native 전체는 미확인이다. 실패했다고 관찰한 결과가 아니며, 모두를 06 종료의 필수 선행으로 추가하지 않는다.

### 원인을 규명하지 않은 네트워크 오류 관찰

마지막 TimeField native 검증의 Reload 직후 `Full sync failed`, `Pull failed`, `fetchAllTrips` 등의 Network Error가 개발 오류 화면으로 나타났다. 닫은 뒤 picker의 선택·확인·재열기를 검증했다. 개발 서버 연결 문제인지 앱의 요청·오류 처리 문제인지는 이번에 조사하지 않았다. picker 결함이나 무해한 환경 문제 중 하나로 단정하지 않는다.

Main은 추가 확인을 하나 고른다면 이 오류의 발생 조건부터 짧게 확인하겠다고 제안했다. 사용자는 그 뒤 현재 작업 마무리를 요청했으므로 조사에 착수하지 않았다. 다음 앱 실행에서 재발하면 실제 네트워크·API 가용성과 요청 경로를 먼저 확인하고 담당 범위를 정한다. 이 제안을 새로운 확정 구현 Ticket이나 07의 필수 선행으로 만들지 않는다.

## 이후 재진입

다음 기본 후보는 07의 Trip·Schedule client API 경계다. 최초 조사에 남아 있는 PATCH/PUT 불일치는 이미 06 후속에서 수정했으므로 현재 코드·기존 검사에서 출발한다. 07을 이번에 실행하거나 Workspace 전체를 완료한 것은 아니다.

제품 상세와 검증 단계의 차이는 [picker·TimeField 기록](2026-10-06-02-picker-wheel-time-field-and-remaining-scope.md), 앞선 시간대 결과는 [도시 시간대 기록](2026-10-06-01-city-time-zone-commits-and-original-bug-continuity.md)을 따른다. 원래 HTML은 `artifacts/ticket-06-simulator/ux-review-20260930/report.html`과 `remaining-review-20261004/` 아래의 Git 제외 자료이며, 종료 판단에 필요한 내용은 위 표와 기존 Workspace 기록에 보존했다.

자동 Maintain은 unbound이며 사용자의 기록 요청에 따라 수동 guarded apply로 반영한다. 제품 Verify receipt·machine status·active index·session binding은 변경하지 않는다.

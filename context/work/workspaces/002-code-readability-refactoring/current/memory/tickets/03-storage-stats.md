# 03 — 저장 용량의 집계·부분 실패·표시

## 맡은 결과와 범위

`apps/client/src/features/profile/hooks/useStorageStats.ts`와 프로필 표시 연결에서 같은 stats 조립을 두 곳에서 맞춰야 하는 부담을 줄인다. 병렬 조회·새 실패 상태·새 단위 체계는 도입하지 않는다. [Spec 품질·완료 판단](../spec/04-quality-and-completion.md)을 따른다.

## 실행 맥락과 접근

[추가 조사](../additional-research.md)의 Main 보고에서 파일 조회 전체의 실패와 개별 지도 팩 실패는 계속 여부가 다르다. 파일 조회 중 실패하면 이미 집계한 값은 남기고 지도 조회로 진행하지 않는다. 개별 팩 실패는 다음 팩 조회를 계속한다. 현재 코드와 대조해 이 순서를 보존한다. 함수 분리 후 실패 결과를 더 많은 파일에서 찾아야 한다면 개선 여부를 다시 본다.

## 완료 조건과 확인 방법

변경 전 기존 hook을 통해 FileSystem/Mapbox 의존성을 제어하고 빈 디렉터리, 대상 확장자와 무관 파일 혼합, DB 파일 조회 중간 실패, getPacks 실패, 개별 pack.status 실패 후 다음 팩 성공을 확인한다. 0/1,024/소수 단위 표시, 최종 DB·지도·합계와 관련 호출 순서를 수정 후 동일 조건으로 비교한다.

실제 기기 파일 접근·네이티브 지도 팩 확인이 없으면 미확인으로 남긴다. 개선은 성공/실패 표시 조립이 한 의미로 관리되고 부분 결과 보존 위치가 명확한지 비교한다. hook 검사 방법은 실행 때 준비한다.

# 01 — 경비 합계의 강조·소수 자릿수 규칙

## 맡은 결과와 범위

`apps/client/src/screens/ExpensesScreen.tsx`의 통화 합계와 `apps/client/src/shared/lib/currency.ts`의 관련 규칙에서 첫 항목 강조·자릿수 판단을 반복 해석하는 부담을 줄인다. 날짜 그룹·폼·카드 전체·환율 계산은 제외한다. 공통 기준은 [Spec 품질·완료 판단](../spec/04-quality-and-completion.md)을 따른다.

## 실행 맥락과 접근

[추가 조사](../additional-research.md)의 Main 보고를 출발점으로 현재 코드를 대조한다. 기본 통화가 목록에 있으면 우선되지만 없으면 다른 통화가 첫 항목이므로 `isBaseCurrency`로 이름 붙이지 않는다. 화면의 toFixed 표시와 helper의 천 단위 구분자 차이를 보존한다. 내부 변수·함수 배치는 실행 중 정한다. Main의 첫 작업 추천이며 다른 Ticket의 완료를 기술적 선행 조건으로 두지 않는다.

## 완료 조건과 확인 방법

변경 전 `groupExpensesByCurrency`·`formatCurrencyDisplay`의 실제 export와 현재 화면 통화 합계 렌더를 대상으로 필요한 검사를 먼저 실행한다. 빈 경비, 기본 통화 유무, 동일 통화 합산, 동률, KRW/JPY와 EUR/USD, 0·소수·1,000 이상 금액을 다룬다. 변경 후 같은 검사로 계산 순서·정렬·표시 문자열·첫 항목 강조를 비교한다.

화면 자동 검사가 어려우면 고정 fixture의 전후 화면과 관찰 조건을 남긴다. pure helper 검사만으로 UI 표시까지 입증하지 않는다. 개선 효과는 강조 판단의 이름이 정확하고 자릿수 규칙을 여러 곳에서 다시 해석할 필요가 줄었는지 코드로 별도 비교한다. 필요한 최소 검사 실행 방법과 도구는 실행 때 정한다.

## 현재 상태와 실제 결과

2026-09-11 실행 전 초안. Main이 소스·사용처를 확인했다고 보고했으며 제품 코드·테스트 수정과 검사 실행 결과는 없다. 첫 구현 대상으로 사용자 확정되지 않았다.

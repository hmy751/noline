# 제약·현재 접근·열린 판단

채택된 방향은 코드에 집중하고 리팩토링부터 하며 작은 요소에서 시작하는 것이다. 이름·조건·변환·로그·타입을 먼저 보고 작은 함수, 이후 필요한 폼·컴포넌트 내부 흐름으로 범위를 넓히는 접근을 제안한다. 이 세부 순서는 실행 중 근거로 조정할 수 있으며 특정 첫 파일은 확정하지 않았다. 앞서 나온 '일정 생성부터 시작'도 채택된 계획이 아니다.

알려진 경계는 다음과 같다. 트랜잭션과 여행별 미전송 작업 조회는 분리 실험에서 결함이 재현됐다. 큐 상태 보존, 오래된 좌표를 사용하는 경로 계산, 비활성 여행의 로컬 선행 조회, 서버 소유권·응답 계약, 초기화·동기화 실패는 별도의 동작 확인·수정 범위다. 이 부근의 표현을 정리할 때 결함을 더 숨기거나 재현 근거를 없애지 않는다. 버그 전체 완료는 이 Work의 일괄 선행 조건이 아니며 직접 걸리는 부분만 연결한다.

기존 분석의 실행 검증 필요 항목은 장애가 실제 발생했다는 사실로 승격하지 않는다. 폼의 취소·재진입, 활성화 완료·지도 준비·경로 준비, 오류 표시의 기대 UX는 아직 선택이 필요한 부분이 있다. 큰 구조를 먼저 설계하거나 모든 중복을 제거하는 목표를 추가하지 않는다.

구성 기준은 `refactor/codebase`, HEAD `aa2314cd9c1400420ea8d22f5ea39f9d76ceca21`다. 기존 분석 기준은 `b4ed41f6e4bbae26fd45827b3b9063097a2c1ea4`이며 현재 사실은 해당 코드에서 다시 확인한다. 분석 내용은 이 Workspace의 보존본으로 유지한다. 원래 분석 경로의 향후 삭제는 예정됐지만 이번에는 삭제하지 않는다. 기존 미커밋 변경을 보존하고 사용자 요청 없이 stage·commit·push하지 않는다. 다른 작업의 하네스·hook 변경을 이 제품 Work의 결과로 포함하지 않는다.

이번에는 Workspace 문서만 만들며 active 기본값과 session binding을 바꾸지 않는다. 이후 실행·유지 연결은 [Work 지침](../../../../../AGENTS.md)과 [session binding 계약](../../../../../harness/maintain/SESSION-BINDING-AND-LIFECYCLE.md)에 따라 사용자가 선택한 Workspace에만 적용한다.

원래 분석 경로는 과거 출처이며 영구 파일 보존 제약이나 실행 의존성이 아니다. [Workspace 안의 분석 보존본](../../../source/codebase-analysis/README.md)과 [출처·무결성 설명](../../../source/index.md)을 기준으로 읽는다. 원문 사본을 유지하며, 읽기용 문서는 링크 위치와 사용자가 요청한 배경 표현만 다듬었다. 편집 내역은 출처 정보에 남기고 기술 관찰·확인 수준은 유지한다.

# 문제·목표·범위

현재 제품은 일반적인 화면·feature·data·repository 역할 분리를 갖추고 있지만, 작은 처리에도 반복 주석·로그·catch가 붙고 값 변환·조건·타입의 의미를 독자가 다시 추적해야 한다. 폼과 저장 후 처리에도 비슷한 책임이 서로 다른 위치에 놓여 있다. 핵심 기능이 안정적으로 동작하면서 코드의 흐름과 설계 이유가 자연스럽게 읽히게 하는 것이 출발점이다.

사용자가 선택한 방향은 **리팩토링 우선, 큰 구조보다 바텀 요소부터**다. 여기서 바텀은 이름·조건식·기본값·값 변환·작은 함수·타입 등 가까운 코드 요소를 먼저 본다는 해석이다. 특정 디렉터리를 전수 개편하라는 뜻이나 큰 구조 개편으로 반드시 이어져야 한다는 목표를 추가하지 않는다.

포함 범위는 client·server·schema·UI의 코드 표현, 함수 내부 흐름, 기존 계약을 유지하는 타입·검증 정리, 의미가 같은 중복, 폼·컴포넌트·hook의 내부 책임이다. [전체 후보](../analysis-items.md)에 기존 분석과 추가 관찰을 유지한다. 작은 요소를 다듬으며 반복 패턴을 확인한 뒤 더 넓은 책임 정리가 필요한지 판단한다.

README 개선, 신규 기능, 폴더·계층 재편 자체, 버그 수정, 하네스 개편은 이 Work의 목표에 포함하지 않는다. 공개 동작·오류 계약을 바꾸어야 하는 후보는 동작 확인과 수정 범위를 분리한다. 알려진 결함은 잘못된 동작을 영구 보존할 근거가 아니라 이 Work의 선행 조건 또는 제외 경계다.

현재 요청은 두 Workspace 구성이다. 제품 코드 구현·첫 Ticket·세부 순서는 미착수·미확정이며, 이번 생성 요청만으로 제품 수정이나 session activation을 실행하지 않는다. 방향의 원문은 [사용자 발췌](../../../source/user-direction.md)에 있다.

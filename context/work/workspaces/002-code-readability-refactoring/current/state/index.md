## 시뮬레이터와 폼 검증

앞선 시뮬레이터 확인에서는 비활성 여행의 offline·unknown 제한과 온라인 복구, 일정 상세 격리, 경비 폼의 일정 목록 전환, 일정 수정값 유지, API 중단·재시도·복구, 활성 여행의 오프라인 Local 표시를 살폈다. 한 차례 잘못된 offline 판정은 앱 재시작 뒤 해소됐지만 원인은 확인하지 못했다.

추가 검증에서 Main은 다음 전환의 입력값이 복귀 후 유지됐다고 보고했다.

- 경비 생성·수정
- 일정 수정
- 장소 검색 후 일정 생성

검증은 실제 통신 차단이 아니라 디버그 상태 전환으로 수행됐으며, 검증 설정은 원복됐다.

## 새로 확인한 일정 생성 결함

폼 검증 중 기존 일정 생성 화면에서 다음 문제 3건이 확인됐다.

- 수동 작성 중 온라인으로 복귀하면 폼이 사라지고 검색 화면으로 돌아간다. 이후 장소를 선택하면 작성하던 값이 덮어써진다.
- 장소를 선택한 뒤 오프라인으로 전환하면 일반 폼과 수동 폼이 동시에 장착된다.
- 일반 폼에서 취소하면 렌더 중 상태 갱신에 관한 React 경고가 발생한다.

Main은 세 항목 모두 이번 훅 변경 이전부터 존재한 코드 경로라고 보고했다. 이번 확인에서는 수정하지 않았다.

## 2-C 결정과 다음 행동

사용자는 복구 토스트를 현재 추가하지 않고 종합 UX 검토로 진행하기로 했다. 원래 목적은 비활성 여행에서 제한된 내용을 다시 볼 수 있게 됐음을 알리는 것이었다. 현재는 헤더 상태와 내용 복귀가 이미 변화를 전달하며, 온라인이어도 요청이 실패하는 경우는 기존 Query 오류·재시도가 맡는다. 알림을 위해 기존 Store·Policy·Query·Sync의 책임을 중복 구현하지 않는다. [결정 기록](../../records/2026-09-30-02-recovery-toast-and-ux-review.md)에 배경·채택 근거·재검토 조건이 있다.

다음은 홈·목록·상세·폼의 제한·오류·복구 UX 검토다. 기존 스크린샷과 검증 기록으로 후보를 좁히고 필요한 전환만 시뮬레이터에서 확인한다. 안내의 중복, 제한·복귀 때 내용·선택·입력의 유지, 오류·재시도의 자연스러움을 살핀다. 실제로 복귀 인지가 부족한 장면이 확인되면 그때 작은 알림을 재검토한다. 기존 일정 생성 결함 3건의 수정 우선순위도 함께 정한다.

2-C 결정은 구현 완료나 Ticket 06 전체 완료를 뜻하지 않는다. UX 검토·수정과 최종 수락은 아직 남아 있다. 스크린샷·상세 검증·HTML은 로컬 전용 `artifacts/ticket-06-simulator/`에 보관하고 Git에서 제외한다.

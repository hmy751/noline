# 기록

현재 기준은 [Spec](../current/memory/index.md), 남은 일은 [Ticket](../current/memory/tickets/index.md)이 소유한다. 이 색인은 README가 왜 지금 모습이 됐는지 다시 확인할 기록을 묶는다. 02〜04는 기록 담당자가 대화 원문을 직접 읽고 쓴 것이며, 사용자 발화의 원문은 [사용자 방향 원문](../source/user-direction.md)에 따로 있다.

- [2026-11-15 — README 작업을 돌아보며 Work를 만든 경위](2026-11-15-01-work-creation.md): 기록 위치로 Work를 고른 이유, 새 Work로 분리한 이유, 이어받지 않은 것과 인수 확인 범위.
- [2026-11-15 — README의 뼈대와 문장을 정한 과정](2026-11-15-02-structure-and-readability.md): 서술형 보강판과 결정 8개판이 반려된 이유, 2판 뒤의 질문과 답, 설계 절을 4개로 묶은 근거, Authentication·더 읽을 곳을 없앤 과정, 가독성 정리 여섯 가지, 되살리지 않은 옛 수치. 구성이나 절 수를 바꾸려 할 때 읽는다.
- [2026-11-15 — README의 문장을 코드와 배경 문서에 대조한 과정](2026-11-15-03-code-and-background-check.md): 큐 중단 문장에 대한 사용자의 의심과 실제 결과, 고친 여섯 곳의 이전·이후, 배경 문서를 뒤늦게 읽은 경위, Router·Policy 문단을 다시 쓴 이유, 근거를 확인하지 못한 과거 서술. 문장의 사실 여부를 고치려 할 때 읽는다.
- [2026-11-15 — UI State 절이 만들어진 과정](2026-11-15-04-ui-state-section.md): 재료 조사, 독립 리뷰어에게 물은 방식과 답, 5번 절 대신 별도 절이 되고 Architecture 뒤에 놓인 경위, 초안 네 판이 반려된 이유, 최종판에서 다시 빠진 것. 이 절을 고치거나 프론트엔드 쪽 내용을 더하려 할 때 읽는다.

일부러 넣지 않은 것은 주제별로 흩어져 있다. 옛 수치와 이모지 제목은 02의 "되살리지 않은 것", 계층 구조·접근성·테스트 개수는 04의 리뷰어 답, 달라진 항목만 보내는 폼과 연결 미확인의 상세는 04의 "최종판에서 다시 빠진 것"에 있다.

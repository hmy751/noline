# 근거와 인용의 계약

README는 제품 계약의 정본이 아니라 요약이다. 정본은 [Project context](../../../../../../project/README.md)와 실제 코드이며, README 맨 끝 문장이 이 관계를 밝힌다.

**문장의 근거 순서.** 현재 동작에 관한 문장은 실제 코드로 확인한다. Project 본문은 의미와 선택 이유의 출처이고, 각 주제의 `_background`는 그 이유의 형성 과정과 "과거 문서가 지금보다 강하게 말했던 부분"을 알려 준다. 이번 작업에서 Main은 처음에 본문과 코드만 읽었고, 사용자가 `_background`도 확인했느냐고 물은 뒤에야 대조해 두 곳을 더 고쳤다. README 문장을 새로 쓰거나 고칠 때는 세 가지를 모두 본다. 경위는 [코드·배경 문서 대조 기록](../../../records/2026-11-15-03-code-and-background-check.md)에 있다.

**코드 인용.** 인용 블록은 실제 소스와 일치해야 하고 첫 줄 주석에 경로를 적는다. 줄을 뺐으면 "(payload 일부 생략)", "(오류 처리 생략)"처럼 밝힌다. 오른쪽에 붙인 설명 주석은 README가 단 것이다.

**절 형식.** Architecture의 네 절은 제목 → 굵은 결론 한 줄 → 배경 → 표나 코드 → `> **트레이드오프**` → 상세 문서 링크 순이다. UI State 절은 설계 결정이 아니라 화면이 지키는 기준이어서 이 형식을 따르지 않고 도입 문단 → 지키는 것 → 훅 조합 → 늦은 응답 처리로 구성했다.

**공개 문서의 경계.** README는 공개 저장소의 첫 화면이다. `context/personal/`과 `context/work/`의 내용이나 경로를 문안에 끌어오지 않는다. 확인하지 못한 수치와 과거 이력("처음에는 …했다")은 근거가 있을 때만 쓴다. 지금 README의 1번 절에는 과거 서술이 두 문장 있고, 근거의 범위는 [제약·현재 설계·가정](05-constraints-design-assumptions.md#가정과-열린-판단)에 적었다.

**링크.** 목차 앵커는 GitHub의 제목 변환 규칙을 따른다. 제목을 바꾸면 목차와 본문 안의 앵커 링크를 함께 고친다. 링크한 경로가 실제로 있는지는 `pnpm harness:check`와 직접 확인으로 본다.

**커밋.** `docs(readme): …` 형식을 쓰고 README만 스테이징한다. 작업 트리에 다른 수정이 있어도 함께 올리지 않는다.

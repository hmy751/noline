# 02 — 게시 뒤 확인과 보강

## 맡은 결과와 범위

push한 README가 GitHub에서 의도대로 보이는지 확인하고, 반영 과정에서 제안만 해 둔 보강을 사용자와 정한다. 확인에서 문제가 나오면 README를 고친다.

## 실행 맥락과 접근

[Ticket 01](01-readme-restructure-and-verification.md)의 첫 커밋(`707468c4`)만 GitHub 화면에서 확인했고, 그 뒤 세 커밋(`542b3c54`, `bd2be723`, `b418d5cb`)은 보지 않았다. 확인이 필요한 곳은 다음과 같다.

- **목차 앵커.** 새 절 제목 `UI State: 불안정한 연결에서 화면이 지키는 것`은 콜론과 영문이 섞여 있어 변환 결과가 초안과 다를 수 있다. 하위 세 제목과 "현재 한계"에서 `#사용자에게-지키는-세-가지`로 가는 링크도 함께 본다.
- **세로 방향 mermaid 다이어그램.** 가로 방향일 때 글자가 작게 그려져 바꿨다. 바꾼 뒤의 모습은 확인하지 못했다.
- **표.** Preview & Features의 상태별 표, 1번 절의 Router·Policy 역할 표, UI State 절의 훅 표.

제안만 해 둔 보강은 두 가지다. 둘 다 사용자가 결정하지 않았다.

- **실패 상태 스크린샷.** 홈 카드에서 "경비를 불러오지 못했어요"와 정상 "0원"을 나란히 보여 주는 자산이 있으면 UI State 절의 설득력이 오른다는 독립 리뷰어의 제안이다. 지금 Preview 자산은 이전 버전에서 녹화한 것이고 이런 화면이 없다. 누가 어떻게 찍을지는 논의하지 않았다.
- **분량 축약.** README가 383줄이 됐다. 2번 절 트레이드오프의 예외 설명(끝냄·보류·격리)을 한 문장과 링크로 줄이는 안이 있다. 이것도 리뷰어가 범위 밖 제안으로 낸 것이다.

기록 담당자가 대화 원문을 대조하며 찾은 확인 후보가 셋 있다. 사용자에게 아직 묻지 않았거나 답을 받지 못한 것이다. Main은 이 셋을 완료 조건에 넣지 않았다. 사용자의 답이 있어야 다룰 수 있는 항목이므로, 이 Ticket을 실행할 때 먼저 묻고 다루기로 한 것만 범위에 더한다.

- **과거 서술 두 문장.** 1번 절의 "처음에는 모든 여행을 기기에 자동으로 저장했습니다"와 "처음에는 활성 여행이면 … 오프라인 방식으로 동작했습니다"는 당시 코드로 확인한 문장이 아니다. 뒤 문장은 결정 문서와 배경 문서가 근거이고 Main이 기억과 다르면 알려 달라고 했지만 답이 없었다.
- **UI State 절의 문장 강도.** "조회 실패와 0원이 같은 화면이 될 수 없는 이유입니다"가 리뷰어가 일부러 피한 "타입이 강제한다"에 가깝게 읽힐 수 있다.
- **버전 배지 기준.** 저장소 값(1.1.2)과 App Store 공개 버전 가운데 어느 쪽으로 할지 답이 없었다.

각 항목의 경위는 [코드·배경 문서 대조 기록](../../../records/2026-11-15-03-code-and-background-check.md), [UI State 절 기록](../../../records/2026-11-15-04-ui-state-section.md), [뼈대와 문장 기록](../../../records/2026-11-15-02-structure-and-readability.md)에 있다.

브라우저 확인은 공개 저장소 페이지를 여는 것이다. 같은 세션에서 `542b3c54`를 push한 직후 Main이 페이지를 열려던 호출을 사용자가 중단했고, `b418d5cb` push 뒤 Main이 확인을 제안했을 때도 답하지 않았다. 실행 전에 사용자에게 확인한다.

# 01 — README를 다시 구성하고 코드에 맞춘다

## 맡은 결과와 범위

루트 [README](../../../../../../../README.md)를 [목표](../spec/01-problem-goal-scope.md)에 맞게 다시 쓴다. 처음 보는 개발자가 앱이 하는 일, 설계에서 고른 것과 포기한 것, 화면 상태를 다루는 방식을 순서대로 읽을 수 있어야 하고, 모든 문장이 현재 코드와 맞아야 한다. 범위는 README 한 파일이다.

## 실행 맥락과 접근

문장의 근거로 읽은 Project 본문은 [선택한 Project 맥락](../project-context.md)에 있다. 구성은 한 번에 정해지지 않았고 사용자 정정을 따라 네 단계로 바뀌었다. 각 단계에서 무엇이 반려됐고 왜 지금 구성이 됐는지는 단계마다 적은 기록이 맡는다. 사용자 발화는 [사용자 방향 원문](../../../source/user-direction.md)에 있다.

1. **구성 재편.** 서술형 보강 → 문제·선택·트레이드오프 형식의 결정 8개 → 원래 제목과 문단에 목차·이미지 그리드·설계 4개 절. 앞의 두 판은 커밋되지 않았다. 인증과 더 읽을 곳 절은 뺐다. ([기록](../../../records/2026-11-15-02-structure-and-readability.md))
2. **가독성 정리.** 소개 첫 문단, 절마다 굵은 결론 한 줄, 다이어그램을 세로 방향으로 바꾸고 부수 노드 제거, 상태별 표를 Preview & Features로 이동, 용어 통일, 긴 문단 나누기. (같은 기록)
3. **코드·배경 문서 대조.** 사용자가 큐가 막힌다는 문장이 여러 기기 작업 뒤에도 맞는지 의심하며 README 전체를 코드와 대조하라고 했다. 그 문장은 일반 실패에는 여전히 맞았고 예외가 빠져 있었다. 이를 포함해 네 곳을 고쳤고, 사용자가 `_background`도 봤느냐고 물은 뒤 다섯 문서를 읽어 두 곳을 더 고쳤다. Router·Policy 문단은 문제 → 원인 → 역할 표 → 결과로 다시 썼다. ([기록](../../../records/2026-11-15-03-code-and-background-check.md))
4. **UI State 절 추가.** 프론트엔드·사용자 경험 측면의 재료를 context와 코드에서 찾고, 독립 리뷰어에게 반영 방식을 물었다. 리뷰어는 Architecture 5번 절을 추천했지만 사용자가 별도 절을 골랐고, 초안 네 판(세 번의 정정)을 거쳐 Architecture 뒤에 넣었다. ([기록](../../../records/2026-11-15-04-ui-state-section.md))

Main이 확인한 것은 다음과 같다. `542b3c54` 판의 주장과 인용 코드를 해당 소스와 대조했다(소스를 읽은 것이며 실행은 아니다). 링크한 파일과 문서 앵커가 있음을 확인했다. `pnpm harness:check`에서 README 관련 항목은 0건이었다(전체는 과거 Workspace의 끊긴 링크 64건으로 실패하며 이번 변경과 무관하다). 독립 리뷰어가 UI State 절의 근거로 든 파일의 존재와 화면 문구를 검색으로 다시 확인했다. 기록 담당자는 README의 인용 블록 여섯 곳이 현재 소스와 맞는지만 따로 확인했다(`cancelAndInvalidateQueries` 블록은 표기대로 오류 처리와 원래 주석이 빠져 있다).

사용자 수락의 범위는 다음과 같다. 구성은 "얼추 된것 같아 일단 커밋 해보자", UI State 절은 "이정도 방향으로 하자"였다. 가독성 정리와 코드 대조 반영은 결과에 대한 평가 없이 커밋 지시로 이어졌다. README 전체에 대한 최종 수락 발화는 없다.

확인하지 않은 것은 다음과 같다. README가 링크한 테스트를 실행하지 않았다. 실제 앱 화면을 보지 않았다. `707468c4` 시점의 GitHub 렌더링만 한 번 확인했고, 그 뒤 바꾼 세로 다이어그램·새 표·새 목차 앵커는 확인하지 않았다.

코드 대조에서 README 밖으로 이어질 수 있는 사실이 드러났다. 삭제 행을 7일 뒤 실제로 지우는 작업은 여행 정리 예약이 하나 이상 있을 때만 실행된다(`apps/client/src/shared/services/sync/cleanup-job.ts`). README는 "유예 기간"으로 낮춰 썼다. 같은 동작은 Project의 데이터 수명 본문에도 적혀 있으며, 의도한 것인지는 이 Work에서 판단하지 않았다. 서버의 Google 경로 키가 쓰이지 않는다는 보고와 여행 정보 수정의 병합 범위는 [대조 기록의 마지막 절](../../../records/2026-11-15-03-code-and-background-check.md#이-work-밖으로-넘긴-것)에 남겼다.

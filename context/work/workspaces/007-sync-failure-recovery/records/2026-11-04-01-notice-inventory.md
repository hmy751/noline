# 2026-11-04 — 멈춤 표시 논의에서 시작한 앱 안내 현황 수집

Ticket 06의 멈춤 표시를 정하려다, 앱이 지금 예외 상황을 어떻게 보여 주는지부터 모으게 된 기록이다. 논의는 11-03 밤부터 이어졌다. 결론은 "표시 방식을 지금 정하지 않고, 안내 규칙을 따로 정리한다"이다. 복원 실패 화면의 재현은 [별도 기록](2026-11-04-02-restore-failed-dead-end.md)에 있다.

## 표시 방식 논의가 멈춘 이유

Main은 헤더 표시를 먼저 추천했다가, 사용자가 "근데 이건 기존 정책과 현황을 파악하고 생각한거지?"라고 묻자 코드만 봤고 Project 정책 문서와 003 Ticket 11 원문은 읽지 않았다고 답했다. 대조한 뒤 추천을 세션 만료 배너와 같은 구조로 바꿨고, 사용자는 이렇게 답했다.

> "음 그냥 표시가 토스트로는 안되나? 배너 하면 ui 도 꼬일것 같고 해당 상황을 보고 판단해야할것 같은데 일단 좀 더 생각해보자"

> "일단 기존에 배너나 그런 세션 만료 등의 상황등을 일단 수집하자 어떤식으로 실제 제공하는지 그러고 더 고민하자 왜냐면 예와처리가 너무 많아서 막 제공한다고 좋을것 같진 않아"

그래서 표시 방식은 정하지 않았다. 토스트, 배너, 프로필의 상태 줄을 비교한 내용은 아래에 남기되 채택한 안은 없다.

정책 대조에서 얻은 사실은 다음과 같다.

- **003 Ticket 11의 범위:** 원문은 "개발자 수동 동기화 표시"다. 사용자용 "다시 보내기"는 이어받은 약속이 아니라 새 제품 선택이다. 06이 이어받는 것은 "재시도 불가 오류는 무한 반복 대신 식별 가능한 실패와 보존된 입력으로 남는다"는 조건이다.
- **기존 표시의 역할:** `NetworkStatusIndicator`·`PolicyErrorDisplay`는 [UI 기준](../../../../project/guidance/development-boundaries/ui.md)에서 사용 제한 안내에 연결된다. 멈춘 동기화는 사용 제한이 아니다.
- **운영 서버 로그:** 요청 경로 기록은 개발 환경에서만 켜진다([app.ts](../../../../../apps/server/src/app.ts)). Ticket 06의 "모든 요청의 경로가 남는다"는 틀린 문장이었고 이번에 고쳤다.
- **오류 처리 기준:** [오류 처리](../../../../project/guidance/error-handling.md)는 HTTP 응답·화면 문구·진단 로그를 분리하고, 공통 로깅을 도입할 때 범위와 책임을 결정 기록에 남기라고 한다. 운영 로그를 추가하면 이 기준을 따른다.

## 코드에서 모은 표시 방식

Main이 검색과 읽기로 모았다. 이름으로 찾지 못한 표시는 빠졌을 수 있다.

| 형태 | 표시 | 언제 | 사용자가 할 수 있는 일 |
| --- | --- | --- | --- |
| 전역 배너 | `SessionExpiredBanner` (`app/_layout.tsx`, 모든 화면 위) | 세션 만료 | 재로그인 |
| 헤더 | `NetworkStatusIndicator` (`MobileHeader`, 10개 화면) | 항상 | 없음 |
| 작은 안내 | `TripTimeZoneNotice` (5개 화면) | 여행 시간대가 없을 때 | 일정·경비 화면에서 "여행 시간대 확인" |
| 제자리 안내 | `PolicyErrorDisplay` (`banner`·`inline`·`block`, 13곳) | 사용 제한 | `recoveryAction`이 있을 때만 연결 재확인 |
| 조회 실패 | 홈 "여행 정보를 불러올 수 없습니다." / 경비 "경비를 불러오지 못했어요." | 조회 실패 | 경비만 다시 시도 |
| 모달 | `Alert.alert` (디버그 제외 약 50곳) | 확인 질문, 저장 결과, 누른 순간의 제한, 권한 | 확인·취소 |
| 동기화 | 로그아웃·계정 삭제의 "동기화 대기 중", 로그인 화면의 데이터 정리 확인 | 계정을 닫는 순간뿐 | 취소·계속 |

사용자용 토스트는 앱에 없다. 평소 화면에서 미전송이나 동기화 실패를 알리는 표시도 없다.

## 실제 화면에서 본 것

Sonnet 담당자가 iOS 시뮬레이터에서 캡처했고, Main은 주요 장면을 직접 열어 보고와 대조했다. 요청은 로컬 서버로만 갔다.

연결 상태는 디버그의 강제 설정으로 만들었다. 진행 중 앱이 실제 네트워크를 계속 오프라인으로 읽었고, 원인은 확인하지 못했다. Mac은 인터넷이 됐고, 재시작한 다음 날 앱을 다시 켜자 온라인으로 돌아왔다.

| 상황 | 화면 | 형태 |
| --- | --- | --- |
| 활성 여행, 오프라인 또는 확인 불가 | 헤더의 한 단어뿐, 목록은 정상 | 헤더 |
| 비활성 여행, 오프라인 | "작업을 수행할 수 없습니다 / 인터넷에 연결되어 있지 않아요. 오프라인에서는 활성 여행을 선택해주세요." | 화면 전체 블록 |
| 비활성 여행, 확인 불가 | "인터넷 연결을 확인할 수 없어요." + "다시 확인" | 화면 전체 블록 |
| 오프라인 일정 추가 | 헤더 + 노란 배너 "오프라인에서는 장소를 검색할 수 없어요. 직접 입력할 수 있습니다." + 빈 상태 "표시할 장소가 없어요". "장소 직접 입력"을 누르면 같은 문장이 장소 칸에 다시 나옴 | 세 겹 |
| 오프라인 새 여행 추가 | "인터넷 연결 필요 / 여행을 추가하려면 인터넷 연결이 필요합니다." | 모달 |
| 삭제 (여행·일정·경비) | 이름을 넣은 확인 질문 + 취소·삭제 | 모달 |
| 미전송 1개, 평소 | 일정 저장은 조용히 끝나고 홈·목록에 표시 없음 | 없음 |
| 미전송 1개, 로그아웃 | "동기화 대기 중 / 동기화되지 않은 데이터가 1개 있습니다. 로그아웃하면 이 데이터는 손실됩니다." | 모달 |

처음 받은 보고에는 "토스트가 탭 바를 덮는다"는 항목이 있었다. Main이 화면을 보니 개발 빌드에서만 뜨는 로그 알림(LogBox)이어서 사용자 문제에서 뺐다. 첨부한 스크린샷의 아래쪽 어두운 막대도 같은 것이다.

### 시간대 확인

"여행 시간대 확인"을 누르면 시간대 창이 아니라 "여행 편집" 시트 전체가 열린다. 비활성 여행을 오프라인에서 열면 다음 문제가 있었다.

- 같은 제약을 세 번 말한다: "여행지는 수정할 수 없습니다…", 노란 배너 "오프라인에서는 활성화된 여행만 수정할 수 있어요.", "시간대 확인에는 인터넷 연결이 필요합니다."
- 취소 버튼이 보이지 않고, 삭제 버튼이 화면 아래에서 잘리며, 스크롤이 되지 않는다. 담당자는 아래로 쓸어내려도 닫히지 않았다고 보고했다.
- 화면의 버튼은 "여행 시간대 확인", 시트 안 버튼은 "도시 시간대 확인"으로 이름이 다르다.

**온라인 동작은 미확인이다.** 디버그의 "온라인" 강제 설정에서도 "도시 시간대 확인"이 꺼져 있었고 비활성 여행은 오프라인 블록을 보였다. 앱이 실제 네트워크를 오프라인으로 읽던 때라 테스트 환경 탓일 수 있다. 실제 온라인 상태에서 다시 봐야 한다. 사용자가 말한 "시간대 확인도 잘 안되고"는 아직 재현하지 못했다.

### 사용자 판단

> "생각보다 할게 많아 보이네 시간대 확인도 잘 안되고 보니까 로그인 처음에 할때 데이터 잇을때도 버튼이 이상하거든 … 정책 별로 예외 상황을 알리는걸 좀 뭔 가 정리가 필요해보이네 뭐 첫번째 스크린샷 정도는 괜찬ㅇ하 보이긴해 오른쪽 네트워크 상황 표시는 그렇다치고 안내를 말해야되니까 근데 음 시간대 확인도 뜬금 없기도 하고 … 그리고 마지막 저 버그는 심해보이고"

- 오른쪽 네트워크 표시는 유지한다. 오프라인 일정 추가의 노란 배너는 괜찮은 쪽이다.
- 시간대 안내는 뜬금없으니 다시 본다.
- "마지막 저 버그"는 아래 경비 화면 겹침이다. 심각하다고 봤다.

## 드러난 문제

**같은 상황이 일관되지 않게 나온다**
- 한 사실을 여러 겹으로 말한다. 오프라인 일정 추가와 시간대 시트가 대표적이다.
- 같은 "확인 불가"가 활성 여행에서는 헤더 글자, 비활성 여행에서는 빨간 블록이다.
- 말투가 "~습니다"와 "~어요"로 섞이고, 세션 만료 배너는 한 안에 둘이 있다.
- 복원 행동이 있는 안내는 재로그인, 연결 재확인, 경비 다시 불러오기, 복원 다시 시도 정도로 드물다.

**규칙을 정하지 않아도 잘못된 것 (개별 수정 후보)**

| 버그 | 근거 |
| --- | --- |
| 경비 화면에서 비활성 여행을 고르면 시간대 안내와 버튼이 헤더 위로 올라가 상태 표시줄과 시계를 덮음 | Main이 화면으로 확인. 일정 화면은 정상. 별도 작업 카드로 제안했고 시작하지 않음 |
| 오프라인 시간대 시트가 닫기 어렵고 아래가 잘림 | Main이 화면으로 잘림 확인. 닫기 실패는 담당자 보고 |
| 로그인 화면의 버튼이 늘어나면 약관 문구가 Apple 버튼과 겹침 | Main이 화면으로 확인 |
| "기기 데이터 정리하고 로그아웃"과 "Google로 계속하기"가 흐린데 실제로 눌림 | 시뮬레이터에서 담당자가 확인. 사용자: "실제 기기에서도 흐리지만 눌렸어" |
| 세션 만료 배너 아래에 빈 공간이 크게 생기고, 프로필의 "계정 삭제"가 탭 바에 가림 | 빈 공간은 Main이 화면으로 확인. 가림은 담당자 보고 |

흐린 버튼의 원인은 미확인이다. 두 버튼은 `isGoogleLoading`(Google 준비 전 참) 등으로 `disabled`가 되어 `opacity-50`이 붙는다. 켜진 뒤에도 흐림이 남는 것으로 추정하지만 확인하지 않았다. Main이 처음에 "실제로 꺼져 있다"고 설명한 것은 틀렸다.

## 표시 방식 비교 (채택 없음, 008의 입력)

| 방식 | 놓치지 않음 | UI 부담 | 다시 보기 |
| --- | --- | --- | --- |
| 토스트만 | △ 앱 시작 직후면 지나갈 수 있음 | 작음. 다만 토스트 장치가 앱에 없어 새로 들여야 함 | ✕ |
| 배너 (세션 만료와 같은 구조) | ○ | 큼. 사용자가 UI가 꼬일 것을 우려했고, 전역 배너 둘이 겹치는 경우를 처음 다뤄야 함 | ○ |
| 프로필 등의 상태 줄 | ✕ 찾아가야 보임 | 작음 | ○ |
| 토스트 + 상태 줄 | ○ | 중간 | ○ |

표시할 시점으로는 "마지막 동기화 실패"를 추천했다. 같은 세션에서 다시 시도할 계기가 없고, 오프라인 대기는 동기화가 시작되지 않아 이 기준에 걸리지 않기 때문이다. 인증 오류로 멈추면 작업이 PENDING으로 돌아가 이 기준에 걸리지 않으며 세션 만료 배너가 맡는다. 사용자 결정은 아니다.

## 자료

첨부 없이 표로만 남긴 화면은 11-03에 캡처한 것이다. Mac 재시작으로 임시 폴더가 지워져 원본 스크린샷이 없고, 필요하면 다시 캡처할 수 있다. 같은 일로 Ticket 03의 임시 원자료(`t03/`)와 막힌 DB 백업도 사라졌다. 앞으로 스크린샷은 사용자 지시로 git에 넣지 않고 저장소 root의 `artifacts/`에 두어 링크로 잇는다. 판단에 필요한 발췌는 [실제 앱 확인 기록](2026-11-03-05-stage-one-real-app-verification.md)에 남아 있다.

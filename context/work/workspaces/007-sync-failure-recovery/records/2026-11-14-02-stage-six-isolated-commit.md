# 6단계 호환·삭제 변경의 분리 커밋

2026-11-14. Main은 6단계 설명 뒤 사용자가 관련 변경을 커밋하고 7단계를 설명하도록 요청했다고 전달했다. HEAD 기반 후보에 필수 진단 연결을 보완한 **36파일을 d45ee70a로 분리 커밋**했다. 7단계는 설명 요청이며 커밋 승인으로 확대하지 않는다.

>

두 인용은 Main이 기록 담당자에게 전달한 사용자 발화다. 이번 후속 대화의 전체 원문이나 6단계 설명 전문을 기록 담당자가 직접 읽은 것으로 표시하지 않는다. 사용자는 확인을 필요한 범위로 제한하고 커밋을 마무리하도록 지시했다. 이 요청을 테스트 금지나 확인하지 않은 결과의 통과 처리로 해석하지 않는다.

## 선별한 책임과 제외한 변경

초기 후보 목록 `/tmp/noline-stage6-commit/paths.json`의 33파일을 직접 확인했다. 이후 독립 범위 감사에서 발견한 필수 진단 연결 3파일을 더해 최종 commit의 **36파일·2,465줄 추가/62줄 제거**를 직접 확인했다. 관련 기능이 단독으로 연결되도록 다음 범위를 함께 선별했다.

- 서버의 보류 입력 GET·ACK와 공유 응답 schema: 구버전 입력 원문을 다시 읽고 사용자의 처리 완료를 서버에 전달한다.
- 클라이언트의 409·410 처리와 직접 수정·삭제 경로: 검증된 보류·삭제 증거를 처리하고, 근거 없는 거절로 입력을 폐기하지 않는 경계를 연결한다.
- 보류 입력 저장·수신·복구 UI 및 화면 연결: 사용자 선택으로 새 수정 또는 현재 값 유지에 이어지고, 보류와 아직 전송하지 못한 ACK를 구별한다.
- 계정·로그아웃 보호: 보류 및 미완료 ACK가 있는 상태를 계정 전환·기기 정리 판단에 포함한다.
- 위 경로의 관련 테스트와 서버 안내.

6단계가 보류·삭제를 해결한 뒤 보내는 `resolved` 신호에 필요한 Signal union·info 수준과 최종 필터의 허용 어휘, 해당 `beforeSend` 검사를 최소 범위로 포함했다. 독립 감사가 발견한 호출과 진단 계약의 연결 누락을 닫기 위한 의존성이다. 단계 이름만으로 진단 파일 전체를 제외하지 않았다.

7단계의 fingerprint 소유권 정리·engine 진단 stage 위치·console 정리, 일반 가독성 정리와 여행 목록의 별도 후속은 제외했다. 같은 파일에 섞인 변경도 해당 기능의 필수 연결만 선별하며 다른 작업 트리 변경을 되돌리지 않는다. 이전 5단계 코드 **a8f57bc8**·기록 **af76cf11**은 유지한다.

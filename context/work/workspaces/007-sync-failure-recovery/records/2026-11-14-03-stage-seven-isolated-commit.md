# 7단계 진단 변경의 분리 커밋

2026-11-14. Main은 7단계 설명 뒤 사용자가 “7단계 그래 커밋 하자”라고 요청했다고 전달했다. 진단 처리와 관련 검사 **5파일을 ef3772df로 분리 커밋**했다. 직전 “그냥 적당히 확인하고 커밋해”라는 범위 지시를 유지하며 전체 테스트·실환경 확인으로 확대하지 않는다.

## 선별 범위와 책임

Main이 선별하고 실제 commit에서 기록 담당자가 확인한 범위는 진단 생산자 `sentry.ts`, 최종 필터 `sanitize-sentry-event.ts`, 동기화 `engine.ts`, 진단 검사 `sentry.test.ts`, 재시도 검사 `retry.test.ts`의 5파일이다.

최종 허용값을 확정한 필터가 fingerprint를 만드는 책임을 맡도록 중복 계산을 정리한다. engine은 작업별 전송 전 stage를 초기화하고, 전체 sync의 중복 로그·catch를 줄이며 실패 분류 helper의 배치를 정리한다. 관련 검사는 같은 실행·진단 계약을 따라 연결한다. 앞선 6단계에 포함한 resolved 신호의 최소 계약은 유지한다.

`engine.isSyncTable`의 own-property 변경은 별도 전송 검증 책임이므로 이번 진단 커밋에서 제외한다. 다른 가독성 잔여분·여행 목록 후속·다른 작업 변경도 일괄 포함하지 않는다. 7단계를 커밋했다고 모든 미커밋 작업이 완료되거나 Work007 전체가 끝난 것으로 표시하지 않는다.

## 확인과 현재 상태

Main은 HEAD 기반 격리 후보에서 진단·재시도·로그아웃 동기화의 **3묶음 23개 통과**를 확인했다. 기록 담당자는 `/tmp/noline-stage7-commit/tests.log`의 실제 선택 경로와 통과 결과를 대조했다. Main은 staging 및 실제 commit 내용과 검사 후보의 바이트 일치, diff check 통과도 확인했다. 작업 시작 hash와 대조한 결과 Work007 기록 외 원본 파일 내용 변경은 없었다.

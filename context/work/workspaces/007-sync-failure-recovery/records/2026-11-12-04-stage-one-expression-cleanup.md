# 1단계의 불필요한 초기화 함수·별칭·조건 정리

[React 공식 문서 기반 UI 정리](2026-11-12-03-react-official-save-ui.md) 뒤 사용자는 단순 초기값을 `useState(() => currentExpense)`로 감싸는 것은 입력 기준 보호에 필수가 아니라고 지적했다. Main은 이를 받아들였고 사용자는 “그 부분 수정하고, 1단계 코드에 이런 불필요한 표현이 더 있는지도 같이 봐줘. 기존 동작은 유지하고 검증도 해줘”라고 요청했다.

입력 기준이 유지되는 이유는 state의 수명이며 initializer 함수의 존재가 아니다. 조건부 내부 폼·기록 key가 새 편집의 시작을 나누는 기존 설계는 유지한다. 계산 없이 변수를 반환하는 경비 초기값과 작은 일정 기준 객체는 직접 인자로 전달하도록 바꿨다. 일정 공개 wrapper의 단순 전달용 `suppliedTimeZone` 별칭과 내부 non-null 타입으로 존재가 보장된 `scheduleData` 중복 조건도 제거했다. 실제 제품 변경은 두 Drawer 파일에 한정한다. Main은 변경 계산·저장 훅·mutation·표식 발급·Repository 수정 경로도 읽었지만, 불필요한 표현으로 판단해 추가 수정한 곳은 없었다.

반면 저장 잠금·이전 폼의 늦은 검증/결과 보호·성공 뒤 비교 기준 reset은 유지했다. 경비의 `setSubmitError(() => error)`도 유지한다. 오류의 타입은 unknown이고 함수 값일 수 있으므로, 이 wrapper는 React가 오류 값을 상태 갱신 함수로 실행하지 않고 값으로 보관하게 하는 역할이 있다. 초기 상태에 단순 값을 넣는 이번 제거 대상과 같은 표현으로 취급하지 않는다.

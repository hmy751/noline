## DB를 먼저 반영하고 서버를 교체했다

현황 확인 당시 운영 DB에는 일정·경비 `field_edits`와 `legacy_update_holds`가 없었다. 부팅 health는 새 계약의 준비를 증명하지 못하므로 [배포 SQL](../../../../../apps/server/sql/20261110-field-edits.sql)의 열·테이블·인덱스를 push 전에 준비했다. 별도 임시 DB에서 SQL 적용·재실행·기존 값 보존과 통합 5파일50개 검사가 통과했다. 운영 DB에서 통합 검사를 돌리거나 로컬 `noline_test` 제한을 풀지 않았다.

운영 적용 후 새 구조 존재와 기존 **일정10개·경비1개 원래 값 보존**을 확인했다. 보존 대조의 원본에는 실제 사용자 데이터가 있으므로 이 기록에는 복사하지 않는다. Main은 Render 실제 자동 배포 설정을 확인한 뒤 push했고, **dep-dbrjh0142hec73bp4gq0**에서 새 서버 기동과 운영 응답을 확인했다. [Render 배포](https://dashboard.render.com/web/srv-d5v1siggjchc7390ietg/deploys/dep-dbrjh0142hec73bp4gq0)의 소스는 ef6838f2다.

전용 임시 계정으로 인증, 여행·일정·경비 생성, 일정·경비 표식 수정, 구버전 경비409, 보류 조회·확인 처리·재조회까지 **10개 운영 API**를 확인했다. DB의 경비 값·편집 표식과 보류 payload도 대조했다. 첫 두 시도는 HTTP10개를 마친 뒤 검사용 script가 DB 표식 표현을 읽는 assertion에서 실패했다. ## 사용자 영상과 운영 조회 — 수정값 오프라인 조회·서버 반영 확인(원문1807행까지)

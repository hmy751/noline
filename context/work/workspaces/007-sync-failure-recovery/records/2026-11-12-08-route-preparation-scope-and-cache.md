# 1단계 일정 후처리의 경로 범위와 캐시 교체

사용자가 일정 폼의 저장 후 처리가 전체 일정 정렬·좌표 변환·다운로드까지 맡고, 제목 수정에도 전체 경로를 새 행으로 추가하는 문제를 지적했다. Main의 코드 확인에서도 실제 요청·중복 저장·오래된 선 선택의 위험이 확인됐다. 사용자는 “제목만 바꾸면 경로 요청 안 하고, 시각이나 장소가 바뀔 때 필요한 경로만 갱신”하고 기존 유틸·중복·오래된 표시까지 검증하도록 승인했다. 단순 함수 이동으로 끝낼 요청이 아니라 실행 범위와 캐시 유효성을 함께 고치는 작업이다.

**이번 경로 후처리 범위의 구현·high 검토·자동/독립 검증을 마쳤다.** 기존 FIFO·편집 표식·사용자 원본·sync queue 정책은 유지하며 별도 경로 준비의 서비스 캐시를 정리한다. 사용자 수락·커밋·push·배포와 실제 네이티브 실행 확인은 별개다.

## 폼의 후처리 책임을 실제 경로 영향으로 좁힌다

일정 Drawer는 저장한 patch에 scheduledAt 또는 좌표가 있을 때만 경로 준비를 호출한다. 제목만 변경하면 호출하지 않는다. 기존 폼의 경로용 목록 조회·정렬·좌표 변환은 제거하고 여행 ID만 넘긴다. 시각 변경도 즉시 전체 Directions 재요청을 뜻하지 않는다. 후속 준비가 현재 구간과 캐시를 비교해 같은 순서·좌표라면 재사용한다.

`useAutoDownloadRoutes`의 별도 구현은 공통 downloader 위임으로 바꿨다. 생성 화면의 500ms timer와 캡처한 목록 전달도 제거하고, 활성화 호출도 여행 ID만 넘긴다. 저장 성공/화면 닫기는 경로 네트워크 준비 완료와 묶지 않는다.

## 현재 Local 일정으로 구간을 만들고 같은 입력만 재사용

공통 downloader는 로그인 사용자 소유의 활성 여행과 현재 Local 일정을 읽는다. 폼·활성화 응답이 들고 온 옛 목록을 기준으로 저장하지 않는다. 기존 날짜 유틸로 여행 현지 날짜를 나눠 **각 날짜 안에서 시간순 인접 구간**을 만든다. 지도와 downloader는 공유 구간 계산·좌표 판독·캐시 matcher를 사용한다.

캐시는 출발/도착 일정 ID 쌍뿐 아니라 **계산 당시 좌표와 이동 profile까지 일치**할 때 재사용한다. 누락된 profile만 요청하고 같은 구간의 유효 캐시는 유지한다. 좌표 0은 유효하게 읽고 빈 문자열·범위를 벗어난 좌표는 사용하지 않는다. 공통 유틸로 묶은 이유는 기존 두 downloader와 지도에서 일치 조건이 달라 생긴 오래된 선·중복 요청을 함께 막기 위해서다.

기존 rows에는 계산 당시 좌표를 알 수 없으므로 nullable `coordinates_key`와 반복 실행 가능한 Local migration을 추가했다. 구버전 geometry에 현재 좌표를 사후 추정해 신뢰하지 않는다. 지도는 현재 입력과 맞지 않거나 확인할 수 없는 geometry를 실선으로 고르지 않고 현재 좌표 사이 점선으로 표시하며 다음 준비에서 교체한다.

## 중복·늦은 응답이 현재 캐시를 되돌리지 않게 한다

같은 사용자·여행의 경로 준비 작업은 직렬화한다. 캐시 정리와 최종 삽입은 트랜잭션에서 처리하지만 Directions 네트워크 대기 전체를 DB lock 안에 두지 않는다. 같은 입력의 중복 rows는 안정적인 최신 row 하나로 정리하고 현재 구간에 없는 오래된 캐시는 정리한다.

요청 전과 저장 전에는 현재 세션과 실제 DB 구간을 다시 대조한다. 다운로드 중 일정이 이동·삭제되거나 여행이 비활성화되면 옛 응답을 현재 구간의 캐시로 쓰지 않는다. high 검토는 필수 결함 없음으로 반환했고, Main은 재사용 가능한 캐시를 먼저 확인한 뒤 필요한 경우에만 live DB를 다시 읽는 순서 개선을 채택했다. 값·좌표·상태의 의미를 바꾼 선택은 아니다. 좌표의 엄격한 파싱은 이번 공통 구간 유틸의 계약이며, 기존 상위 container의 parseFloat 등 좌표 처리 전체를 같은 수준으로 정리했다는 주장은 하지 않는다.

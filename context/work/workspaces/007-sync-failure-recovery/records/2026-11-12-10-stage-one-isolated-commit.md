# 1단계 클라이언트 저장 코드의 분리 커밋

사용자는 현재 1단계 설명·정리를 검토한 뒤 “그래 그럼 1단계 코드 커밋 하자 기록 할거 하고”라고 요청했다. 기존 HEAD `a527e977`의 경로 변경 위에 **클라이언트의 입력·저장 1단계와 필요한 공유 입력/기기 저장 계약만** 분리한다. 이 기록을 포함한 1단계 커밋의 **제품/검사 51경로 분리판은 검증을 마쳤고, 커밋 실행 전 상태**다. 자기 자신을 포함할 커밋의 해시를 미리 본문에 쓰지 않는다.

## 포함하는 기능과 선택

- 수정창은 열린 대상의 ID에 맞춰 내부 폼을 만들고 처음 받은 기록·일정 시간대를 편집 기준으로 고정한다. 배경 조회가 초안을 바꾸지 않는다.
- RHF isSubmitting으로 제출 상태를 관리하고 저장 중 닫기 시도에는 안내한다. 제출한 값의 저장 성공 후 닫으며, 대기 중 추가 입력은 별도 보존·자동 저장하지 않는 사용자 선택을 유지한다. 별도 초안 저장소·공통 저장 잠금은 추가하지 않는다.
- isMounted는 해제된 폼의 늦은 검증·성공·실패가 새 화면의 입력·알림·닫기를 건드리지 못하게 한다. 같은 폼의 추가 입력 동등성을 검사하는 값은 아니다.
- 실제 변경 항목만 계산하고 지출액의 금액·통화와 장소의 이름·주소·좌표를 같은 그룹으로 보낸다. 같은 금액의 문자열 표현 차이는 새 수정으로 보내지 않는다.
- Repository가 요청을 검증하고 표식을 준비한다. `PreparedEdit` 내부 입력은 edit을 필수로 하며 하위 Local/API의 중복 발급은 제거한다. API의 전송·응답 검증과 서버 표식 관찰은 유지한다.
- Router는 준비 완료를 기다리기 전에 여행별 작업을 등록한 뒤 현재 활성 상태로 Local/API를 선택한다. 활성 여행은 온라인이어도 Local을 사용한다. 오버로드는 두 호출 형식의 타입 관계이며 실행 순서를 만드는 장치는 아니다. 이번에 오버로드 코드를 바꾸지는 않는다.
- Local 행 변경·큐 추가·반환 변환은 같은 트랜잭션에서 확정하거나 함께 되돌린다. 같은 요청 재전송에 표식을 다시 발급하지 않으며 기존 FIFO를 유지한다.
- 생성·수정·삭제 data 훅은 기존 취소·조회 갱신 유틸로 늦은 첫 조회를 버린다. 새 조회의 성공을 데이터 저장 성공 조건으로 묶지 않는다.
- 위 클라이언트 입력에 필요한 shared fieldEdits schema와 SQLite 항목 표식 열·migration을 포함한다. wire 구버전 edit optional 호환과 앱 내부 준비된 입력의 edit 필수 계약을 구별한다.

## 이번 커밋에 넣지 않는 책임

Repository의 직접 수정 실패 조합과 구버전 보류·확정 삭제 처리는 후속 6단계이므로 이번 분리판에서 제외한다. 서버 항목별 승자 판정, 전송 응답 반영/ACK, pull·cursor·미전송 입력 재투영, 구버전 복구·삭제 증거 종결과 관련 전체 구현도 이번 1단계 커밋의 기능이 아니다. 따라서 **이 커밋을 배포 가능한 전체 동기화 기능 완성본으로 해석하지 않는다.**

다른 2〜7단계 제품·Project·Personal·기존 Work 문서 변경은 현재 작업 폴더에 보존한다. 이번 기록은 후속 미커밋 문서를 읽어야만 경계를 이해하는 방식으로 구성하지 않는다. 기록 파일 하나와 records 색인의 해당 항목만 커밋 문서 후보이며 나머지 현재 문서 전체를 묶지 않는다. 작업 폴더의 전체 판본과 이 분리 커밋 판본의 검사 결과를 구별해야 한다.

## 분리 검증과 현재 상태

기존 HEAD `a527e977` 위에 제품/검사 **51경로**를 골랐다. 30개는 파일 전체, 21개는 여러 단계가 섞인 파일에서 1단계 차이만 분리했다. `apps/client`의 일정·경비 저장 계층/폼·공유 편집 표식/Router·DB/큐의 필요한 부분과 대응 검사, `packages/schema`의 entity/request/field-edits·export가 포함된다. 경로는 이전 커밋에서 이미 구현돼 있으며 이번 수정 폼도 그 호출 경계를 유지한다. 전체 Project·다른 Work·Personal·다른 단계 문서를 함께 넣지 않는다.

`/tmp/noline-stage1-only-commit`의 독립 분리판에서 검사했고, 최종 검증자는 후속 단계 코드가 의존성으로 끌려오지 않았는지도 확인해 필수 수정 없음으로 반환했다. 실제 파일 목록은 `/tmp/noline-stage1-commit-files.txt`다. 기록 파일과 records 색인의 해당 항목은 이 51개 제품/검사 경로와 별도다.

이전 전체 작업 폴더의 892개·독립36개와 경로 분리판726개는 이번 판본 통과 수치로 사용하지 않았다. **분리 범위의 구현과 검증은 완료했고 이 기록을 포함한 커밋 실행은 Main이 이어갈 단계**다. 아직 커밋 수행 완료·push·배포를 기록하지 않는다. 네이티브 수정창·Keychain·실서버·Mapbox/live Directions는 이번 자동 검사로 확인됐다고 확대하지 않는다.

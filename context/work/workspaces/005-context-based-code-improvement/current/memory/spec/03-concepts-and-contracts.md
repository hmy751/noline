# 핵심 개념과 판단의 계약

**당시 기록**은 그때의 요청·조건·선택·관찰 근거다. 정확한 정정 범위나 판단 이유가 중요하면 기록의 원문 발췌와 해당 커밋을 확인한다. 기록 요약을 대화 전체 검토로 확대하지 않는다.

**현재 코드**는 지금 구현한 동작의 근거다. 제품 요구를 대체하지 않으며, 오래된 경로가 사라졌다면 실제 소비자부터 다시 찾는다. **Personal**은 판단 관점과 조건, **Project**는 제품 의미·계약·현재 지원을 제공한다. 경험 모음의 미채택 후보를 실행 규칙으로 올리지 않는다.

**Ticket 단위**는 당시 문제·설계 선택·실제 코드 결과를 함께 판단할 수 있는 범위다. 현재 분야별 목록은 검토할 대상을 찾는 지도이며 필요한 수정 수를 뜻하지 않는다.

**검토 결과**는 관찰 사실·적용 조건·현행과 대안의 차이·선택 이유·미확인을 연결한다. 별도 고정 보고 양식은 만들지 않는다. **채택한 개선**은 보존할 계약과 의도한 변화, 구현 책임·확인 방법을 가진다.

당시 테스트 통과, 이번 코드 열람, 이번 재실행과 사용자 수락은 서로 다른 근거다. 제품 Verify의 기계 pass는 Workspace 완료가 아니다.

002는 단방향 근거 참조 대상이다. 과거 current를 수정하거나 두 Workspace 사이에 자동 동기화를 만들지 않는다. 동일 범위의 작업이 별도로 진행 중이면 실행 책임을 먼저 맞춘다.

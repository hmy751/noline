# 제약·현재 구성·확인할 전제

## 보존할 경계

활성 여행의 Local 데이터와 queue, 비활성 여행의 Remote, 인증·사용자 소유권, 시간·통화·삭제의 제품 약속을 유지한다. 002의 경비 삭제 오류·특정 상세 재시도 보류와 미확인 native 범위를 새 문서의 보장으로 바꾸지 않는다. 조회 feature 재사용의 Project-wide 예외 채택은 당시 보류 범위를 보존하며 현재 소비 구조의 설명과 구별한다.

## 현재 작업 구성

먼저 04에서 앱 준비·인증·DB 작업과 종료 조율을 복원한다. 이는 로그인 하나의 설명이 아니라 앱이 사용할 준비가 됐다는 뜻과 데이터 보존을 함께 이해할 기반이다. 05는 그 기반을 참조해 네트워크 관측·Query·화면 복구의 관계를 맡고, 06은 이를 이용하는 작성·장소·선택창·날짜 입력의 관계를 맡는다. 05/06의 기존 본문 대조는 04의 모든 문장이 완성되기 전에도 가능하며 관련 계약이 확정돼야 최종 연결을 닫는다.

각 Ticket 안에서 조사·본문 수정·읽기 경로·검증을 이어 수행한다. 별도 조사·검증 Ticket을 늘리지 않는다. 이미 반영된 API·날짜 등은 관련 작업에 연결해 충분성과 충돌을 확인하며, 전체 대응은 review-scope가 맡는다.

## 확인할 전제

002의 최종 기록 뒤 구현과 Context가 바뀌었을 수 있으므로 실제 편집 시 현재판을 확인한다. 원문 기록의 초기 정책·후속 변경·사용자 보류를 구별한다. 필요 파일과 배치는 Ticket에 현재 접근으로 제시하며 실제 내용 충분성에 따라 조정한다. 제품 정책 변경·개인 기준 채택은 이번 편집으로 정하지 않는다.

01의 승인된 코드 보완·검증은 기존 결과로 유지한다. 이전 02·03의 코드 구조 재검토는 새 Context 작업으로 대체했고, 이후 코드 개선이 필요하면 그때 확인한 문제와 권한으로 판단한다.

# 요구 결과와 대표 사용 장면

각 Ticket은 관련 기록·채택 결정·현재 코드·검사를 대조하고, 기존 Context의 유효한 의미를 보존하면서 빠진 관계와 낡은 설명을 고친다. 본문 구성·읽기 경로·직접 확인까지 같은 Ticket에서 마친다. 코드와 기록의 차이를 문서 편집만으로 제품에서 해결했다고 주장하지 않는다.

- 앱 준비나 로그아웃을 바꾸는 개발자는 DB 준비·인증 복원·화면 진입과 실행 중 sync/cleanup/저장의 종료 관계를 설명할 수 있어야 한다. 재로그인 필요와 로컬 작업 불가, 작업 호출 완료와 전송 성공을 구별한다.
- 연결 복귀 화면을 바꾸는 개발자는 실제 관측과 화면 표시, 조회 허용과 데이터 표시, 최초 실패와 갱신 실패를 구별하고 기존 데이터·선택을 보존하는 경로를 찾을 수 있어야 한다.
- 일정·경비 폼을 바꾸는 개발자는 저장값·폼 초안·선택창 임시값의 수명, 장소 검색 결과와 호환 처리, 날짜/시간의 입력·전송·저장 관계를 이해할 수 있어야 한다. 단일 폼 유지라는 문장만으로 전체 책임 설명을 대신하지 않는다.

대표 장면은 내용 충분성을 확인할 출발점이다. 기존 본문에서 유효한 다른 조건·예외를 이 사례에 맞춰 삭제하지 않는다. 충분한 본문은 유지하고, 보완했으면 독자가 그 본문에서 답을 얻은 다음 실제 코드로 내려갈 수 있는지 확인한다.

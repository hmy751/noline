# 002의 실제 결과와 Context 보완 배치

이 표는 구현할 기능 목록이 아니라 현재 Context에서 맡을 의미와 이미 반영된 결과의 대응이다. 상세 조사 근거는 [전체 대응 기록](../../records/2026-10-30-08-context-coverage-reassessment.md)에 있다.

| 실제 결과 | 이번 처리와 책임 |
| --- | --- |
| 앱 준비·인증 복원·Local 이용·세션 변경 | 04의 [app-runtime 본문](../../../../../project/current/app-runtime/INDEX.md)에 현재 관계·이유·조건과 읽기 경로를 복원했다. |
| DB 비동기 transaction·직렬 실행·sync/cleanup 종료 조율 | 04의 app-runtime 본문에 원자성 원칙과 실제 실행·중단·완료의 의미 및 보호 한계를 연결했다. |
| 네트워크 관측·unknown·Debug 표시·foreground | 05의 기존 Policy 본문에 관측·표시 강제값·감지 수명·재확인의 관계를 보완했다. |
| 일정·경비 조회·홈 요약·복구 표시 | 05의 Policy·오류 본문에 Query·접근·실행·표시와 부분 데이터 보존을 연결했다. 일반 FSD 예외 채택의 보류를 유지했다. |
| 여행 생성·목록 사본·선택 보존·갱신 | 05에서 기존 selective-activation 본문을 재사용하고 선택 정리 조건·실제 조회 설명과 연결했다. |
| 일정·경비 초안·검색·저장 실패·일정 연결 | 06의 form 본문에 초안·작성 단계·일정 연결·제출과 실패 수명을 연결하고 기존 policy/manual-input 계약을 유지했다. |
| Places 공통 결과와 수정 화면 호환 | 06의 form 본문에 정상 상세·부분 실패·수정의 0/0 호환과 지도 표시/채택 차이를 복원했다. |
| picker·TimeField·날짜 입력 | 06에서 TimeField 구독·picker 확인/취소/재열기·다른 항목 전환을 설명하고 form/components의 낡은 예시·책임을 정정했다. |
| 도시 시간대·Expense date-only·API·직렬화·ownership | 기존 구체 본문을 유지했다. 04의 보존·접근, 05의 읽기, 06의 도시 시간대·date-only·미변경 값·입력/응답 경계를 연결했다. 날짜 본문에는 picker 수명의 역방향 진입만 보완했다. |
| 경비 합계·도시 검색·저장 용량·초기 리팩터링 | 앞선 조사에서 확인한 충분한 Project 본문과 005-01 완료를 유지했다. 06은 통화의 기본값/정밀도·도시 검색과 시간대 확인을 연결했고, 저장 용량·리팩터링은 기존 전용 진입과 결과를 재사용했다. 새 코드 감사로 확장하지 않았다. |
| 경로 준비·활성화·sync/cleanup 등의 미완료 전체 | 현재 보장·열린 한계를 설명하는 근거로 사용한다. 002/003의 미완료 제품 구현은 인수하지 않는다. |
| 개인 판단·협업 경험·스킬 개선 | 사용자 선택으로 후순위. 현재 세 Ticket의 실행·완료 조건에 넣지 않는다. |

한 문장이 여러 영역을 다루면 주 책임 Ticket이 실제 Owner에 반영하고 다른 Ticket은 그 본문을 참조한다. 실제 내용 대조에서 필요한 공백이 더 드러나면 해당 결과의 범위를 보완한다. 알려진 공백을 전체 종료 시점까지 미배정으로 남기지 않는다.

04–06의 맡은 본문·진입·대표 읽기를 마쳤다. 구체적인 근거·미확인은 각 Ticket과 실행 기록이 소유한다. 남은 제품 구현과 개인 판단 개선은 위 명시된 별도 범위이며 문서 개수로 완료를 대신하지 않는다.

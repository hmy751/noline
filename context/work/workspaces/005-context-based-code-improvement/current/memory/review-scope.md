# 002의 실제 결과와 Context 보완 배치

이 표는 구현할 기능 목록이 아니라 현재 Context에서 맡을 의미와 이미 반영된 결과의 대응이다. 상세 조사 근거는 [전체 대응 기록](../../records/2026-10-30-08-context-coverage-reassessment.md)에 있다.

| 실제 결과 | 이번 처리와 책임 |
| --- | --- |
| 앱 준비·인증 복원·Local 이용·세션 변경 | 04에서 현재 관계·이유·조건과 읽기 경로를 복원한다. |
| DB 비동기 transaction·직렬 실행·sync/cleanup 종료 조율 | 04에서 원자성 원칙과 실제 실행·중단·완료의 의미를 연결한다. |
| 네트워크 관측·unknown·Debug 표시·foreground | 05에서 정책과 감지 수명·재확인의 관계를 보완한다. |
| 일정·경비 조회·홈 요약·복구 표시 | 05에서 Query·접근·실행·표시와 부분 데이터 보존을 설명한다. 일반 FSD 예외 채택의 보류를 유지한다. |
| 여행 생성·목록 사본·선택 보존·갱신 | 기존 selective-activation 본문을 05에서 재사용하고 실제 조회 설명과 연결한다. |
| 일정·경비 초안·검색·저장 실패·일정 연결 | 06에서 기존 policy/manual-input과 form·실제 서비스의 관계를 보완한다. |
| Places 공통 결과와 수정 화면 호환 | 06에서 서비스 보장과 legacy 처리의 현재 범위를 복원한다. |
| picker·TimeField·날짜 입력 | 06에서 낡은 form/components 설명을 고치고 입력 수명을 연결한다. |
| 도시 시간대·Expense date-only·API·직렬화·ownership | 이미 구체 본문이 있다. 04의 보존·접근, 05의 읽기, 06의 입력 경계에서 필요한 조건·충돌을 확인하며 상세 계약을 중복 작성하지 않는다. |
| 경비 합계·도시 검색·저장 용량·초기 리팩터링 | 해당 Project 본문의 실질 반영을 앞선 조사에서 확인했다. 기존 결과를 유지한다. 관련 본문 연결은 06과 마무리 대조에서 확인하며 새 코드 검토로 확장하지 않는다. 005-01의 완료는 보존한다. |
| 경로 준비·활성화·sync/cleanup 등의 미완료 전체 | 현재 보장·열린 한계를 설명하는 근거로 사용한다. 002/003의 미완료 제품 구현은 인수하지 않는다. |
| 개인 판단·협업 경험·스킬 개선 | 사용자 선택으로 후순위. 현재 세 Ticket의 실행·완료 조건에 넣지 않는다. |

한 문장이 여러 영역을 다루면 주 책임 Ticket이 실제 Owner에 반영하고 다른 Ticket은 그 본문을 참조한다. 실제 내용 대조에서 필요한 공백이 더 드러나면 해당 결과의 범위를 보완한다. 알려진 공백을 전체 종료 시점까지 미배정으로 남기지 않는다.

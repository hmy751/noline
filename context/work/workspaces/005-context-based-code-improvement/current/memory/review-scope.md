# 실제 결과와 다음 검토 범위

02의 결과를 빠뜨리지 않고 다음 검토를 고르는 지도다. 각 범주는 구현 요구나 확정된 Ticket 수가 아니다. 검토 단위는 당시 문제·설계 선택·최종 코드 결과의 관계에서 정한다.

| 실제 결과·관련 근거 | 배치와 남은 확인 |
| --- | --- |
| 저장 용량 집계·실패 정책·React 연결, 기존 03 | 새 Ticket 01. 초기·최종 선택과 현재 코드의 일부를 읽었으며 개선 판단·검증은 남아 있다. |
| 일정·경비 조회 복구와 공통 조합, 기존 06 | 새 Ticket 02. 기록과 공개 조합 일부를 읽었으며 실제 소비자 전반의 대조는 남아 있다. |
| 인증·세션과 Local 이용 책임 재배치, 기존 06 | 새 Ticket 03. 기록에 따른 초기 범위이며 현재 코드 검토·필요한 분할은 착수 시 확인한다. |
| 경비 합계·도시 검색·API·서버 직렬화, 기존 01·02·04·05와 17 선행 결과 | 미검토. 실제 선택·변경 경계를 복원해 다음 단위를 고른다. |
| 네트워크 관측·앱 초기화·sync 연결·여행 생성과 목록 갱신, 기존 06 | 초기 세 Ticket과 겹치는 소비자는 그 범위에서 확인한다. 나머지 결과는 미검토다. |
| 일정·경비 작성 수명, 도시 시간대·홈 표시·선택창, 기존 06과 후속 선행 조각 | TimeField 일부를 읽었으며 결과 전체는 미검토다. 실제 선택과 연결 단위로 후속 검토를 구성한다. |
| 일정 저장 후 경로 준비, 기존 13의 남은 책임 | 후속 후보. 기존 결과와 미완료의 관계를 확인한 뒤 우선순위·실행 책임을 정한다. |
| 활성화·sync·cleanup 등의 나머지 미완료, 기존 09·14–18 | 기존 결과의 보장을 판단할 때 관련 의존을 확인한다. 미완료 전체의 구현을 인수한 것은 아니다. |

범위 지도는 [02 산출물 지도](../../../002-code-readability-refactoring/output/index.md)와 [02 Ticket 색인](../../../002-code-readability-refactoring/current/memory/tickets/index.md)을 단방향 근거로 사용한다. 세 Ticket을 끝낸 뒤에도 미검토 범위를 확인해 다음 결과를 선택한다. 전체 완료는 각 범주의 검토·근거 있는 제외/보류와 채택한 개선의 완료를 종합해 판단한다.

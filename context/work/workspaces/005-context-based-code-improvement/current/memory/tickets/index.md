# 실행 Ticket

당시 설계 선택과 실제 결과를 한 단위로 검토한다. 각 Ticket은 기록·코드 대조, 대안 판단, 채택한 수정과 검증까지 맡으며 근거 있는 유지로 끝날 수도 있다.

- [01 — 저장 용량 Hook의 책임 분리 재검토](01-storage-stats-responsibilities.md): 초기 정리와 최종 책임 분리를 현재 집계·부분 실패·React 수명에 대조한다.
- [02 — 일정·경비 조회 조합의 공통화 재검토](02-policy-query-composition.md): 공통 접근·실행·표시 계약이 실제 소비자의 차이를 표현하는지 판단하고 필요한 개선을 잇는다.
- [03 — 인증·세션 책임 재배치 재검토](03-auth-session-responsibilities.md): 복잡도 재검토·원복·재배치의 이유와 현재 구조·보존 동작을 대조한다.

진행과 실제 결과는 각 Ticket이, 전체 다음 행동은 state가 소유한다. [나머지 검토 범위](../review-scope.md)는 실제 결과가 드러날 때 다음 Ticket으로 구체화한다. 번호는 기본 진행 순서이며 앞 Ticket의 코드 변경이 뒤 Ticket의 필수 선행은 아니다.

# 앱 실행 Context의 보기 개선과 저장

사용자는 04 결과의 보기가 아쉽다고 점검을 요청한 뒤 “그 방향으로 내용이랑 근거는 유지하면서 보기 좋게 정리해봐”라고 요청했다. 이어 “좋아 기록할거 했으면 커밋하고”라고 저장을 지시했다. 앞선 [본문 보완 기록](2026-10-30-11-app-runtime-context.md)의 제품 의미와 검증 범위를 유지하며 표현 정리와 최종 확인을 덧붙인다.

[현재 본문](../../../../project/current/app-runtime/INDEX.md)의 첫머리에 시작·재인증·종료의 요약과 해당 절 이동을 넣었다. 긴 문단은 동작·조건·책임별로 나누고, 표는 준비 결과·화면·보존 조건 또는 실패 지점·남는 데이터·후속 상태를 비교하도록 바꿨다. 확인 근거는 별도 절에서 찾도록 했다. 새 제품 정책·코드 변경이나 형성 자료의 해석 변경은 없다.

Main은 수정 전 본문과 대조해 데이터 보존 조건, 예외, 완료의 범위, 담당 위치를 유지했는지 확인했다. 기존 근거 링크의 목적지는 모두 남아 있다. 형식 검사에서 본문의 링크·절 이동·표 열 수·공백을 확인했다. 실제 화면 렌더링이나 다른 독자의 이해를 검증했다고 주장하지 않는다.

저장 직전, 이 기록 추가 전의 변경·신규 Markdown 17개와 상대 링크 209개 및 참조 anchor 검사를 통과했다. 명시적 005 Recover의 JSON 생성·파싱과 git diff --check도 통과했다. 기록 추가·Ticket 갱신은 Maintain guarded apply에서 링크·형식·현재판을 다시 확인한다.

제품 코드와 테스트가 달라지지 않아 기존 14개 suite·146개 test 통과 근거를 재사용했다. 전체 harness 검사의 기존 002·003 끊어진 링크 8건과 실기기 미확인 경계는 앞선 기록대로 남는다. 문서 정돈 때문에 제품 전체 검사를 반복하지 않았다.

저장 범위는 04의 Project 본문·형성 자료, architecture·Project/client/rule의 읽기 경로, 005의 Ticket·상태·산출물·기록이다. 기존 `.pnpm-store/`는 제외한다. 다음 작업은 05이며 Personal·스킬 개선의 후순위와 미완료 제품 범위를 유지한다. 커밋은 이 문서들과 함께 만들고 push는 수행하지 않는다.

# 05 저장과 06 작성 Context 사전 대조

사용자는 “좋아 기록 정리됐으면 커밋하고 06도 보자”라고 요청했다. 05의 변경 범위와 diff 형식을 확인하고 본문·진입·Work 기록 15개 파일을 `ca3882a` (`docs(context): 네트워크·조회·화면 복구 맥락 보완`)로 커밋했다. 기존 `.pnpm-store/`는 포함하지 않았다. push는 하지 않았다. 기존 13개 suite·199개 test와 링크·재진입 확인 근거는 [05 기록](2026-10-30-13-network-read-context.md)을 재사용했고 제품 검사를 반복하지 않았다.

## 06에서 확인한 공백

[form 가이드](../../../../../.claude/context/form.md)는 RHF·Controller와 일반 계층 표는 설명하지만 검색/작성 화면 전환 위에서 유지되는 초안, 제목·장소 채택, 저장 실패와 종료, picker의 별도 선택 수명을 설명하지 못한다. picker state를 일괄 feature hook 책임으로 둔 표는 현재 TimeField와 맞지 않는다. [components](../../../../../.claude/context/components.md)에는 제거된 ManualExpenseForm 예시도 남는다. manual-input의 단일 폼·기능별 제한 계약은 유효하므로 유지한다.

현재 CreateScheduleScreen과 useCreateScheduleForm에서 검색·작성 단계를 오가도 초안이 유지되고 여행 ID 변경에서 새 수명을 갖는 것을 확인했다. 선택 장소는 좌표와 연결되고 사용자 수정 제목은 보존하며 직접 장소 편집은 좌표 연결을 해제한다. useSubmitSchedule과 경비 useCreateExpenseForm·ExpenseScheduleField는 초안·조회·실행·표시 책임을 나누고 있어 하나의 범용 폼 구조로 합쳐 설명하지 않는다.

Places의 공통 서비스는 resolved와 unresolved-detail을 구별한다. 생성은 상세 검증을 통과한 결과만 받고 상세 하나의 실패도 검색 실패로 처리한다. 지도용 결과와 현재 채택 가능한 결과도 다르다. 수정 feature의 compatibility adapter는 상세 실패를 0/0으로 바꾸는 기존 동작을 유지하고 있으므로 정상 좌표의 공통 보장으로 올리지 않는다.

TimeField는 useController로 폼 값을 구독하고 열기·닫기·확인 시 반영을 맡으며, TimePicker는 RHF를 모르는 내부 임시 선택을 소유한다. DatePicker는 날짜를 누를 때 반영하고 하단 확인은 닫기다. 시간은 확인해야 폼 값이 바뀌며, 다시 열 때 현재 폼 값으로 시작한다. 수정 화면의 항목 ID·닫힘 key와 원래 날짜·시간·시간대 기준도 확인했다.

[날짜와 시각](../../../../project/common/date-and-time.md)은 도시 시간대, 미확정 상태, DST, 변경하지 않거나 되돌린 날짜·시간의 원본 보존을 이미 설명한다. 10월 2일 기록의 당시 설명만 옮기면 후속 도시 시간대 변경을 놓칠 수 있으므로 현재 본문을 재사용한다.

## 구성과 다음 실행

[06 Ticket](../current/memory/tickets/06-draft-input-context.md)에 초안과 제출, 장소 후보와 채택, 선택창과 입력값, 저장 요청의 네 관계를 구체화했다. Ticket을 더 나누지 않고 기존 form을 중심 본문으로 보완하며 components·manual-input·기존 제품 계약과 읽기 경로를 맞추는 접근이다. 예를 들어 저장 10:00에서 시간 선택창으로 11:00을 확인했어도 폼 자체를 취소하면 저장값은 10:00인 장면으로 세 수명을 구별할 수 있어야 한다.

근거는 002의 [일정·Places 기록](../../002-code-readability-refactoring/records/2026-10-02-01-schedule-create-boundaries-and-verification.md), [경비·날짜 기록](../../002-code-readability-refactoring/records/2026-10-02-03-expense-time-decisions-and-verification.md), [picker·TimeField 기록](../../002-code-readability-refactoring/records/2026-10-06-02-picker-wheel-time-field-and-remaining-scope.md), [최종 종료 기록](../../002-code-readability-refactoring/records/2026-10-06-03-ticket-06-closure-and-followups.md)과 현재 소스다. 002의 Ticket 06 합의 범위는 종료됐지만 전체 폼 수명·경로 준비·좌표 후속과 native 미확인은 별도로 남았다. 이를 현재 결함 목록이나 이번 005-06의 필수 구현으로 자동 전환하지 않는다.

이번은 사전 대조와 실행 내용의 구체화다. Project 본문·제품 코드·테스트는 수정하지 않았고 제품 검사를 새로 실행하지 않았다. 본문 편집·대표 읽기·필요한 검증은 다음 실행에 남는다. 기존 보류·개인 판단 개선 후순위·session binding·Verify 경계는 유지한다.

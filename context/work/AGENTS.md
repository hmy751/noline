# Work를 이어 가는 방법

## 요청에 맞춰 재개한다

다른 세션에서도 현재 목표·판단의 이유·조건·남은 일을 이어받도록 한다. Main의 일반 재개에서는 사용자가 지정한 Workspace를 우선하고, 지정이 없으면 [Workspace 색인](workspaces/README.md)의 기본 선택을 따른다. 해당 README에서 `recover.md`를 찾아 기본 자료를 읽고, 이번 요청에 해당하는 조건부 자료로 확장한다. 이번 요청이 배경 설명인지 수행인지 판단하고, 과거에 적힌 다음 행동으로 현재 요청을 덮어쓰지 않는다.

범위를 정해 위임받은 담당자는 지정된 작업·판본과 관련 Spec/Ticket·원문에서 시작하고, `recover.md`의 해당 조건과 필요한 공통 맥락을 추가로 확인한다. 한정 과업에 일반 재개의 전체 읽기를 강제하지 않는다. 적용되는 상위 지침과 맡은 계약의 필수 읽기는 유지한다.

맡은 범위에서 무엇을 왜 하는지, 지켜야 할 조건, 확정과 미정, 다음 행동과 이유를 복원하면 현재 과업으로 돌아간다. 중요한 공백·충돌이 있으면 관련 본문·원문·실물로 범위를 넓힌다. 안내는 탐색의 출발점이며 추가 확인의 상한이 아니다. 안내가 없거나 경로가 끊겼으면 기존 README·current·output에서 필요한 의미를 확인하고 발견한 공백을 반환한다. 읽지 못한 근거를 추정하거나 Workspace 전체 열람으로 누락을 가리지 않는다.

[공통 읽기 방법](../USAGE.md)으로 관련 Personal·Project 본문과 필요한 source를 골라 이번 판단에 적용한다. 개발 수행의 역할·시점·반환은 [개발 절차](../../.agents/skills/development/SKILL.md)가 연결한다. 한정 설명이나 읽기 요청 때문에 개발 전체를 시작하지 않는다. 개인 기준을 읽었다는 이유로 제품 약속을 바꾸지 않는다.

## 재개 안내를 구성하고 갱신한다

각 Workspace 루트의 `recover.md`는 현재 재개의 초점을 이해할 짧은 설명과 읽을 대상·이유·조건을 소유한다. README는 정체성·구성과 이 안내의 위치를 설명하고, current의 색인은 본문 탐색을 맡는다. 같은 재개 순서를 여러 입구에서 따로 관리하지 않는다.

| 구분 | 선택 기준 |
| --- | --- |
| 기본 읽기 | 빠지면 현재 목표·범위·선택 이유·다음 행동을 잘못 이해할 자료 |
| 조건부 읽기 | 특정 판단·수정·검증에서 필요한 상세. 읽을 조건과 필요한 절·구간을 함께 적는다. |
| 과거 근거 | 선택·정정의 뜻을 다시 확인할 자료. 현재 판단에 필요한 의미는 current에 직접 남기고 상세 과정·원문을 연결한다. |

기본 자료의 수나 고정 분량을 강제하지 않는다. Spec 다섯 관점과 Ticket·state·output 가운데 현재 과업에 필요한 계약을 빠뜨리지 않도록 선택한다. 이미 Project·Personal 선택 문서가 있으면 그 문서를 통해 필요한 본문을 찾게 하고, 같은 목록을 재개 안내에 복제하지 않는다.

현재 본문에는 선택 이유·적용 조건과 확정·잠정·미정의 구별을 남긴다. 표현의 강도나 정정 범위가 판단을 바꾸면 [작성 기준](workspaces/DOCUMENT-WRITING.md)에 따라 최소 원문과 정확한 접근점을 보존하고 필요한 때 읽게 한다. `recover.md`에는 자료를 고르는 데 필요한 짧은 의미를 두며 상세 상태·검사 수치·선택 과정은 해당 Owner에서 유지한다.

생성 담당자가 초기 안내를 구성한다. 기록 담당자는 방향·단계·중심 과제·자료 위치가 바뀌어 읽을 대상이나 이유가 달라졌을 때 안내도 갱신한다. 문서를 전달하기 전에 필요한 반영을 확인하되, 안내가 유효하면 호출마다 다시 쓰거나 호출 이력을 쌓지 않는다. 갱신 뒤에는 안내에서 필요한 의미와 원문을 찾을 수 있는지 대조한다. 링크 확인과 실제 새 세션의 재개 성공은 구별한다.

## 작업 판단과 기록을 잇는다

Main은 이 지침과 실제 Workspace·Project·Personal의 관리 계약을 이해한다. Work 기록은 [record-work](../../.agents/skills/record-work/SKILL.md)의 담당자에게 맡기고, 다음 작업이 문서에 의존하면 실제 반영을 확인한다. 사람용 문서는 [작성 기준](workspaces/DOCUMENT-WRITING.md)과 [갱신 기준](workspaces/spec-and-tickets/MAINTENANCE.md)을 따른다. 담당자의 결과·제안을 검토해 현재 선택과 남은 일을 연결하며, 반영을 제안했다는 사실로 공유 current의 수정 권한이 생기지는 않는다. 별도로 배정한 기록 담당이 있으면 그 범위에서 수행한다.

목표·계약·가정은 memory, 전체 상황·다음 행동은 state, 실행 단위의 결과는 Ticket에 맞춘다. 입력은 source, 결과 위치는 output, 선택·시행착오·검사 이력은 records가 맡는다. 원자료와 과거 기록을 새 결론에 맞춰 덮어쓰지 않는다.

중요한 제안·근거와 채택·조정·미채택의 이유, 실제 반영·확인 결과는 기존 Ticket·records에서 다시 찾을 수 있게 한다. current에는 지금 유효한 의미와 남은 검토·반영·확인만 유지한다. 반영 도중 중단되면 이미 맞춘 곳과 남은 판단·담당·다음 행동을 구별해 이어갈 수 있게 남긴다. 모든 제안·읽기·발화를 기록하거나 새 제안함·필수 상태값을 만들지 않는다. 이 자료는 이후 경험 개선에도 사용할 수 있지만, 일상 유지가 그 단계를 기다리지는 않는다.

결과를 반환할 때는 해당 current·Ticket·output이 실제 최신 결과와 같은 완료 범위를 가리키는지 확인한다. 한정 요청 완료, Work 목표 완료, 대화 중단을 구별하고 핵심 미확인은 남은 수행으로 잇는다. 같은 목표는 같은 Work에서 이어가며 세션 교체만으로 새 Work를 만들지 않는다. 독립 목표 생성·전환이 요청되면 [해당 계약](workspaces/CREATE-AND-TRANSITION.md)을 따른다.

검사는 [실행 안내](../../CLAUDE.md#코드-영역과-경로별-가이드)를 사용하고, 근거의 충분성·재사용은 [검증 기준](../../.agents/skills/development/references/verification/INDEX.md)을 따른다. 필요한 결과와 한계는 Work에 연결하며 별도 Verify 단계를 요구하지 않는다. 검사 통과·문서 반영·사람 수락·Work 완료를 구별한다. 자동 Maintain이나 session activation은 연결하지 않는다. 이전 Verify의 snapshot·receipt·freshness 계산과 프로세스 종료 보장을 직접 읽기나 모든 검사 도구가 제공한다고 가정하지 않는다. 실제 실행 도구의 제한을 확인하고 필요한 근거와 한계를 남긴다.

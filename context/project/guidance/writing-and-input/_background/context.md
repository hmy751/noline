# 값의 위치보다 수명을 먼저 구분한 이유

[작성 기준](../INDEX.md)을 이해하고 변경할 때 필요한 형성 맥락이다. 일정·경비·picker의 기존 설명과 2026-10-01~06 구현 기록, 현재 호출부·검사를 대조해 구성했다. 당시 검증 수치를 현재 전체 앱의 보장으로 이어받지 않는다.

## 하나의 초안과 기능별 제한을 유지했다

일정 생성의 이전 문제는 네트워크 정책에 따라 수동/일반 폼과 전체 차단 화면이 달라지고, 장소 변경의 reset과 감시 effect가 제목·입력을 덮는 것이었다. 값 자체가 이미 화면의 hook에 있었다는 점만으로 문제를 설명할 수 없었다. 사용자 작성 단계, 초안과 채택 장소, 검색·지도·저장 가용성을 구분해 네트워크가 작성 수명을 지배하지 않게 했다.

초안·검색·제출 hook을 조건부 패널보다 위에서 유지한 것은 검색을 오갈 때 작성 상태를 보존하기 위해서다. 코드 길이를 줄이려고 hook을 폼 내부로 옮기거나 총괄 workflow hook을 추가하는 안은 필수 개선으로 채택하지 않았다. 수명을 확인하는 소비 경로가 늘어나는 비용을 받아들였고, 현재 변경도 부모 key·장착·대상값을 함께 보게 했다.

경비는 날짜와 일정 연결을 독립된 입력으로 정했다. 활성 여행의 일정은 Local에 있는데 오프라인이라는 이유로 연결을 숨기거나 경비와 같은 날짜로 후보를 제한할 이유가 없었다. 같은 여행 전체 후보와 명시적 해제를 사용하며, 비활성 여행이 제한되면 전체 후보 대신 이미 선택한 일정 설명만 보존한다. 이 선택의 제품 의미와 발췌는 [여행 접근 근거](../../travel-access/_background/evidence.md#경비-초안과-일정-연결)가 소유한다. 날짜를 결제일/사용일로 부르는 의미나 일정 삭제·접근권 변경 뒤 연결 정책까지 결정한 것은 아니다.

## Places는 결과 보장과 소비자 호환을 분리했다

생성과 수정이 공유하는 것은 검색·상세 검증·query·정책이며, 후보를 초안에 채택하는 행위는 feature가 맡는다. 생성은 상세 확인된 결과만 받으므로 한 건의 상세 실패가 전체 검색 실패가 되는 비용이 있다. 부분 성공 UX로 바꾸려면 결과와 오류 표현의 계약을 함께 판단해야 한다.

수정은 이전 상세 실패의 0/0 동작을 adapter에 격리했다. 정상 장소 타입의 보장을 낮추지 않고 기존 동작을 유지하기 위한 한정 선택이며, 그 값이 실제 장소를 가리킨다는 뜻은 아니다. 정상 0 좌표와 실패 대체값을 구분해야 한다. 지도에서 B를 보여도 초안 A를 유지하고 명시적으로 선택할 때만 바꾸는 이유도 표시와 채택의 보장이 다르기 때문이다.

## Picker의 임시 선택과 폼 연결을 나눴다

폼 날짜와 다른 달로 열리고 폼 시각과 다른 행부터 보이는 문제는 저장 시간대 변환과 별개였다. DatePicker는 현재 폼 날짜의 달·강조를 받고 재열기 때 새 Calendar를 만든다. 시간은 중앙 고정 줄에서 값을 읽는 유한 휠을 채택했다. 무한 순환·native picker·입체 효과까지 요청한 결과로 확장하지 않았다.

TimePicker는 원래도 RHF를 몰랐다. 실제 분산은 Controller의 표시·오류, 화면의 watch, 여러 위치의 열기·닫기·setValue였다. TimeField가 이를 구독·선택창 수명·확정 반영으로 묶고 trigger 모양은 호출자가 정하게 했다. 기존 setValue 검증·dirty/touched 의미는 보존했다. public API 이름을 바꾸거나 TimeWheel 파일을 추가하는 것을 자동 필수 작업으로 만들지 않았다.

## 기존 설명의 현재성은 부모까지 다시 판단했다

이관 전 폼 본문은 책임·조건·실패를 이미 구체적으로 설명해 유효한 문단·비교표·Controller 예시를 유지했다. 초안·장소·picker는 별도로 바꿀 질문이어서 상세를 나눴고, 제출과 공통 책임은 시작 본문에 두었다. 수동 입력만 별도 폼인 것처럼 보이게 하는 문서는 통합했다.

경비 Drawer 내부의 ID effect만 보면 같은 ID의 isOpen 토글은 reset하지 않는다. 그러나 실제 부모는 닫을 때 선택 대상을 비운다. 이관 시 부모까지 대조해 현재 재열기는 원본으로 reset한다고 바로잡았다. 수정 장소 검색도 닫힌 채 장착된 경우와 실제 부모의 조건부 해제를 구별했다. 일정 정책 제한은 입력 표시 계약을 어기지만 RHF 상태는 유지하고 TimeField 임시 선택은 해제한다. 이 차이를 제품 계약 축소나 모든 초안 소실 주장으로 바꾸지 않았다.

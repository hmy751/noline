# 설명과 근거 기준

## 적용과 수명

이 문서는 `work-discussion`, `explanation-recovery`, `work-artifact-briefing` 중 하나가 현재 요청에 적용돼 이 기준을 읽을 때만 사용한다. Skill별 호출 조건과 실행 방법은 각 `SKILL.md`가 소유하며, 이 문서가 일반 대화나 모든 AI 응답에 자동 적용되는 상위 workflow가 되지 않는다.

Project의 source·authority 계약이나 세 skill의 역할이 바뀌거나, 실제 사용에서 이 기준이 중요한 차이를 반복해서 놓치거나 불필요한 부담을 만들면 다시 판단한다. 세 consumer가 모두 없어지거나 같은 책임을 더 가까운 current canonical이 소유하면 제거하거나 그 Owner로 합친다.

관련 Project-wide 설명 계약을 바꾸는 작업 주체가 이 문서와 [`guidance index`](README.md), consumer link를 함께 유지한다. 제품 의미·중요 제약·최종 acceptance를 새로 정하거나 바꾸려면 사용자 결정이 먼저다.

## 목적과 정본 경계

목표는 설명을 무조건 짧게 만드는 것이 아니다. 사용자가 현재 질문에 필요한 의미와 실제 근거의 관계를 이해하고, AI의 결론을 그대로 빌리지 않은 채 다음 질문이나 자기 판단을 만들 수 있게 하는 것이다.

이 문서는 제품 의미, 현재 code 상태, test 결과와 사람의 결정을 소유하는 새 정본이 아니다. 현재 질문의 실제 Owner를 읽고 서로의 범위를 섞지 않는다. 전체 history·모든 file·모든 evidence를 기본 입력으로 불러오거나 별도 이해 상태 ledger를 만들지 않는다.

## 기준 상태와 현재성

답의 의미가 달라질 때만 관련 기준 상태를 확인하고 설명에 드러낸다.

- current code라면 필요한 branch·commit·working tree와 runtime configuration
- 실행 동작이라면 실제 provider·wiring과 관찰한 조건
- 과거 code·decision·review라면 당시 시점, 대상과 확인 범위

모든 응답에 hash와 환경 정보를 붙이라는 뜻은 아니다. 과거 상태를 현재로 오해하거나 source·configuration이 바뀐 뒤에도 같은 설명을 재사용할 위험이 있을 때만 밝힌다. 현재성을 확인하지 못했으면 확인한 것처럼 말하지 않는다.

## 근거별로 말할 수 있는 범위

- **과거 decision·design:** 당시 의도와 제약을 보여 준다. 현재 구현이나 유효성을 자동으로 증명하지 않는다.
- **Current source·configuration·사용 위치:** 현재 구조, 가능한 동작과 연결된 component를 보여 준다. 실행되지 않은 경로의 실제 수행을 증명하지 않는다.
- **Trace·log·runtime observation:** 관찰한 조건과 실행에서 지나간 경로와 결과를 보여 준다. 다른 입력과 모든 실행을 보장하지 않는다.
- **Test·compiler·rule:** 표현되고 실행된 조건이 통과했음을 보여 준다. 다루지 않은 위험, 제품 목표의 타당성과 전체 완료를 판정하지 않는다.
- **AI 해석:** 위 근거가 현재 질문에서 무엇을 뜻하는지 연결한 판단이다. Source나 관찰 사실 자체가 아니다.
- **외부 답변과 사람 판단:** 외부 책임자만 아는 사실은 그 답변 범위에 한정한다. 제품 가치, 중요한 범위 축소, 위험 수용과 최종 acceptance는 실제 책임자가 판단한다.

이 구분을 모든 응답에 고정 제목으로 나열하지 않는다. 다음처럼 섞였을 때 결론이 더 강해지거나 다른 뜻이 되는 경우에만 확인 사실·AI 해석·미확정·사람 판단을 드러낸다.

- 과거 의도와 현재 구현
- Source상 가능한 동작과 실제 runtime 관찰
- 국소 test와 전체 목표 충족
- 수행한 부분과 stub·mock·hard-coded·미연결·미구현 부분
- AI가 조사할 사실과 사람이 정할 선택

## 작업 결과와 근거를 볼 때 놓치지 않을 대비

- Interface나 type의 존재는 실제 provider 연결이나 runtime 수행을 증명하지 않는다.
- 국소 refactor와 test 통과는 전체 제품·구조 목표의 완료를 증명하지 않는다.
- 데이터가 끝까지 전달됐다는 사실은 그 데이터를 사용자 답변으로 해석·변환하는 책임의 완료를 증명하지 않는다.

이 대비는 작은 산출물의 가치를 부정하지 않는다. 실제 수행한 가치와 아직 수행하지 않은 상위 책임을 같은 완료로 합치지 말라는 기준이다.

## 설명 깊이와 종료

직접 답부터 주고, 답을 바꾸는 전제·현재성·근거 한계만 필요한 깊이로 펼친다. 작은 작업이라는 이유만으로 중요한 조건을 삭제하지 않고, 정확하다는 이유로 관련 없는 배경까지 모두 펼치지 않는다.

현재 질문에 답했고, 결론의 의미를 바꾸는 미확정·미수행·사람 판단이 있다면 그것이 보이면 현재 응답을 끝낸다. 구체적인 조사 순서와 결과 형상은 호출된 skill의 종료 조건을 따른다. 사용자의 침묵이나 짧은 동의를 `이해 완료`로 저장하거나 quiz·재진술·형식적 승인을 기본으로 요구하지 않는다.

## 판단과 부작용 경계

- 설명에 필요한 현재 사실은 허용된 범위에서 더 조사할 수 있다.
- 직접 확인한 차이와 그 차이에서 근거 있게 도출되는 동작·사용상 영향은 설명하고, 추론한 부분과 그 근거 범위를 밝힌다. 요구 위반 여부, 위험 수용, 작업 중단과 최종 acceptance를 설명 요청만으로 새로 확정하지 않는다. 별도 판정이 요청됐다면 그 요청 범위와 실제 책임을 따른다.
- AI는 선택별 차이와 추천 이유를 설명할 수 있지만 추천을 채택된 사람 판단으로 말하지 않는다.
- 설명 요청만으로 code·source·test·문서·review 결과를 수정하거나 durable context 인수와 후속 작업을 시작하지 않는다.
- 다른 Owner나 workflow를 수신처로 제안한 것과 실제 인수가 끝난 것은 구분한다.

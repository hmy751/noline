# 데이터 저장·동기화·정리

활성 여행의 Local 저장부터 서버 반영, 비활성화·정리와 계정 종료까지 데이터가 남거나 제거되는 조건을 관리한다. [본문](INDEX.md)은 관련 개발의 계약·현재 구현 차이·확인할 경계를 함께 설명한다. Router·목록은 [여행 접근](../travel-access/INDEX.md), 인증 상태와 종료 절차의 상세는 [앱 실행](../../current/app-runtime/INDEX.md)이 맡는다.

현재 적용에는 본문의 작업별 진입을 사용한다. 비활성화와 실제 삭제를 나눈 이유, 받아들인 저장 비용과 과거 설명을 수정한 근거, queue 실패 횟수 한도를 없애고 간격 재시도를 보류한 이유가 필요하면 [형성 자료](_background/README.md)를 읽는다. 이 자료는 현재 본문을 설명하는 맥락·선택 근거이며 과거 구현의 완료 주장을 현재 보장으로 사용하지 않는다.

이 주제의 현재 의미는 Project가 소유한다. 저장·queue·push/pull·활성화·cleanup의 동작이나 보존 계약이 바뀌면 변경 책임자가 해당 절과 앱 실행·여행 접근의 관련 설명을 함께 대조한다. 작업 진행과 실행 수치는 Work가 소유한다.

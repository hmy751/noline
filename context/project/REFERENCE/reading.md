# Project context 읽기와 적용

관련 작업에 어떤 Project 본문이 필요하고 그 내용을 어떻게 적용할지 판단할 때 읽는다. 목표는 많은 문서를 읽는 것이 아니라, 이번 작업의 의미·계약·현재 제약을 이해하고 필요한 구현 확인으로 이어가는 것이다. 문서를 읽는다는 이유로 제품 변경이나 문서 갱신 권한을 새로 얻지는 않는다.

## 작업·주제에서 본문을 선택한다

[Project README](../README.md)의 주제별 진입점에서 이번 작업과 관련된 본문을 찾는다. 독자가 먼저 common/current/guidance 중 하나를 정해야만 진입할 수 있게 하지 않는다. 이미 읽은 본문이 현재 질문을 충분히 다루고 달라졌다는 신호가 없다면 같은 문서를 다시 읽는 절차를 반복하지 않는다.

읽을 문서에서는 그 문서가 맡은 범위와 적용 조건을 확인한다. 이름이 같거나 링크로 연결됐다는 이유만으로 모두 읽지 않고, 현재 판단을 바꾸는 추가 자료를 선택한다. 필요한 주제가 Project에 아직 없다면 README가 연결한 기존 상세 Owner에서 읽는다. 없다는 이유로 계약을 추정하거나 다른 주제의 문서를 억지로 적용하지 않는다.

Owner나 읽기 경로를 바꾼 결과를 확인할 때에는 Project README에서만 시작하지 않는다. 실제 작업자가 계속 사용할 active runbook·workspace guide·호환 문서·skill 가운데 대표 진입점을 골라 새 Owner까지 따라간다. Project README 경로의 성공은 다른 진입점의 연결을 증명하지 않으며, 모든 링크를 일괄 순회하는 것으로 이 판단을 대신하지 않는다.

## 계약과 이번 작업의 관계를 이해한다

선택한 본문에서 이번 작업이 보존하거나 바꾸려는 의미, 적용할 계약과 예외, 판단을 바꾸는 현재 차이와 열린 선택을 파악한다. 문서의 규칙을 인용하는 데 그치지 않고 이번 변경 대상과 어떤 관계인지 연결한다.

예를 들어 API 응답을 수정한다면 공통 변환·검증 계약과 해당 기능의 적용을 함께 읽는다. 제품 날짜 의미를 바꾸는 작업으로 범위가 달라지면 관련 domain 본문을 추가한다. 일부 응답 경로만 기준이 적용된 상태라면 그 차이를 설명하는 현재 자료가 필요한지 본다. 이 예시는 읽기를 확장하는 조건이지 매번 세 층을 모두 읽으라는 순서가 아니다.

코드·설정·테스트는 구현과 증거의 확인을 맡는다. 문서에서 의미를 이해했다고 실제 구현이 그 계약을 충족한다고 단정하지 않는다. 바꾸거나 설명할 대상의 실제 경로를 대조하고, 문서가 소유한 현재 기준과 구현 사실을 구별한다. 한 문장이 여러 구현 경계의 공통 동작을 주장하면 실제로 포함된 경계를 각각 확인하거나 문장의 범위를 확인한 경로로 좁힌다. 반대로 코드를 읽을 예정이라는 이유로 여러 경로의 관계와 선택 이유를 담은 본문을 생략하지 않는다.

충돌을 발견하면 단순히 최근 문서나 코드를 승자로 삼지 않는다. 해당 본문이 명시한 권위와 직접 근거를 대조해 이번 작업에서 확정할 수 있는 범위를 좁힌다. 사용자의 결정이 필요한 제품 선택은 질문으로 남기며, 영향받지 않는 부분은 계속 진행한다. 문서 갱신이 요청되었거나 갱신 조건이 충족되면 [관리 계약](../MAINTENANCE.md)으로 연결한다. 읽기 동작 자체는 파일을 수정하지 않는다.

## 필요한 이해가 확보되면 본래 작업으로 돌아간다

이번 작업의 기준과 중요한 예외, 추가로 확인할 코드·근거, 결과를 바꾸는 미정 사항을 설명할 수 있으면 읽기를 마친다. 이는 고정 보고 양식이 아니다. 실제 작업의 판단과 검증에 적용하고, 사용자에게는 접근이나 결론을 바꾸는 내용만 필요한 만큼 설명한다. 단순 선택을 매번 별도 보고서나 영구 기록으로 만들지 않는다.

선택한 본문을 읽어도 자기 범위의 뜻을 조립하기 위해 여러 상세 Owner를 새로 찾아야 한다면 본문의 부족함을 드러낸다. 읽기 스킬이 빠진 계약을 대신 발명하거나 전체 자료 탐색을 기본값으로 삼아 숨기지 않는다.

## Recover와 읽기 스킬의 관계

Workspace의 `recover.json`은 그 작업에 선택된 Project 문서와 이유를 보존하고, Recover는 그 선택으로 제한된 재진입 자료를 만든다. 작업 중 질문이 달라졌을 때 필요한 추가 읽기를 금지하거나, 선택 문서를 실제로 이해·적용했음을 보장하는 장치는 아니다.

[read-project-context](../../../.claude/skills/read-project-context/SKILL.md)는 적용할 본문이 아직 잡히지 않았거나 기존 선택만으로 새 질문을 다루기 어려울 때 이 기준을 실행한다. 이미 확보된 Recover 자료와 현재 읽은 내용을 재사용하며 Recover·Workspace 연결을 자동 재실행하지 않는다. 지속 문서 선택의 변경이 필요하다면 Work의 기존 Owner와 [관리 계약](../MAINTENANCE.md)으로 연결한다.

읽기 스킬의 자동 선택 가능성, 실제 호출, 실제 본문 읽기와 작업 적용은 서로 다른 사실이다. 설치·링크 검사는 선택 경로만 확인한다. 효과는 관련 요청에서 선택한 본문과 그 내용이 실제 판단에 사용됐는지로 확인한다.

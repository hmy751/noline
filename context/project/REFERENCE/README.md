# Project context 구성과 사용 기준

이 reference는 다음 관련 작업이 필요한 의미를 찾고 이해하며 적용할 수 있도록 Project 본문을 구성하고 읽는 판단 기준을 소유한다. 제품 정책이나 Workspace의 작업 상태를 담는 네 번째 내용 층은 아니다.

Project 전체의 정체성·물리 층·권위 관계는 [Project README](../README.md)가, 실제 제품 의미와 작업 계약은 각 주제 본문이 소유한다. 이 reference는 그 내용을 고르고 연결하는 기준이며, 별도의 제품 정본을 만들지 않는다.

## 필요한 기준에서 시작한다

- 본문을 새로 쓰거나 복원·통합·분리할 때는 [내용 선별과 주제 구성](composition.md)을 읽는다. 남길 가치, 함께 이해할 범위, 근거와 열린 판단을 다룬다.
- 관련 작업에서 어떤 본문을 읽고 어떻게 적용할지 판단할 때는 [읽기와 적용](reading.md)을 읽는다. 주제별 진입, 추가 자료를 읽을 조건, 코드 대조와 읽기의 종료를 다룬다.
- 실제 갱신 시점·변경 권한·영향 범위·Owner 이동·완료 확인은 [MAINTENANCE.md](../MAINTENANCE.md)가 소유한다. 쓰기 기준을 이 폴더에 다시 정의하지 않는다.

사람은 이 문서들에서 직접 기준을 적용할 수 있다. [읽기 스킬](../../../.claude/skills/read-project-context/SKILL.md)과 [갱신 스킬](../../../.claude/skills/update-project-context/SKILL.md)은 각각 필요한 기준을 읽고 적용하는 교체 가능한 실행 장치다. Skill을 제거해도 문서의 읽기 조건·권위·갱신 책임은 남는다.

## 이 기준을 바꿀 때

새 문제를 기존 기준과 대조하고, 영향을 받는 기준 본문과 실제 소비 경로를 맞춘다. 각 실패를 금지문으로 덧붙이거나 모든 주제를 같은 양식으로 고정하지 않는다. 구성 기준의 소비자는 작성·갱신 주체이고, 읽기 기준의 소비자는 관련 작업을 수행하는 주체다. 한쪽 기준의 변경만으로 모든 제품 문서나 스킬을 일괄 수정하지 않는다.

선택 배경과 보류한 판단은 [구성·읽기 기준 결정](../../../.claude/decisions/2026-09-14-project-context-authoring-and-reading.md)에 있다. 세부 기준을 크게 바꿀 때 확인하되 일반 제품 작업의 필수 읽기로 추가하지 않는다. 특히 `current`의 독립적인 효용은 재구성 결과로 확인할 대상이며, 이 reference는 제거·축소나 문서 수를 미리 정하지 않는다.

책임과 관리 장치의 관계에 `ai-system_context-ownership-boundary.md: 적용`, `ai-system_responsibility-cohesion.md: 적용`, `ai-system_harness-rippability.md: 적용`.

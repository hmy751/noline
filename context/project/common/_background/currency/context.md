# 환산 없이 기록하고 정밀도 선택을 분리한 이유

[통화와 금액](../../currency.md)의 선택 이유를 설명한다. 초기 통화 설명은 여러 국가의 경비를 네트워크나 환율 API에 의존하지 않고 기록하려는 목적에서 시작했다. 서로 다른 통화를 각자의 원금액으로 저장하고 통화별 합계를 표시하면 환율의 시점·출처가 없어도 기록의 단위를 잃지 않는다. 대신 여행 전체를 하나의 환산 총액으로 비교할 수 없다.

옛 문서의 “가장 많이 사용된 통화”와 첫 그룹 강조는 현재의 대표 의미를 충분히 설명하지 못한다. 현재는 baseCurrency가 있으면 우선하고 그렇지 않으면 단위가 서로 다른 숫자 합계를 비교한다. 사용 빈도도 환산 가치도 아니다. 홈의 첫 그룹과 추가 통화 개수는 제한된 공간에서 모든 합계를 나열하지 않는 표현이며, 경비 화면은 각 통화를 따로 보여 준다. 대표 라벨을 정하는 일은 단순 코드 정리보다 큰 제품 선택이어서 열린 채로 유지했다.

2026-09의 합계 리팩터링은 KRW·JPY 0자리와 나머지 2자리라는 판단만 공용 helper로 모았다. `toFixed`와 formatter의 차이를 동작 보존의 관찰로 남겼고, 올바른 반올림의 기대값으로 고정하지 않았다. 금액 입력·Local 문자열·서버 decimal·합산을 함께 정해야 해서 formatter 하나의 교체로 문제를 닫지 않은 것이다.

후속 코드 대조에서 홈 요약의 고정 두 자리, 개별 카드의 원문 표시, 숫자 형식을 검사하지 않는 입력과 늦은 여행 통화의 미반영도 확인했다. 본문은 이 차이를 직접 설명하지만 제품 정책으로 승인하지 않는다. 표시를 통일하면 일관성을 얻는 대신 원문 표시·반올림 결과가 바뀌고, 저장 정밀도를 바꾸면 기존 데이터와 동기화의 수용 범위까지 바뀐다. 각각의 영향과 기대값을 정한 뒤 구현해야 한다.

옛 긴 문서의 web markup, EUR fallback, 통화 코드가 검증된다는 설명과 개선 후보는 현재 구현의 지시로 가져오지 않았다. 환율 참고·최근 통화·심볼 확장은 당시 후보일 뿐 채택된 계획이 아니며, 현재 본문을 이해하는 데 필요한 기록 목적과 비용은 이 설명과 [근거](evidence.md)에서 복원할 수 있다.

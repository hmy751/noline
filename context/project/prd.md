# Noline 제품 기준

## 목적

Noline은 여행 중에도 네트워크 상태 때문에 일정 확인·기록과 경비 관리가 중단되지 않게 한다. 사용자는 필요한 여행 하나를 활성화해 오프라인에서도 핵심 데이터를 사용하고, 네트워크가 돌아오면 누적한 변경을 서버와 동기화한다.

## 현재 문서가 지지하는 성공 기준

- 활성화한 여행은 로컬 데이터와 필요한 오프라인 리소스로 핵심 일정·경비 흐름을 이어 갈 수 있다.
- 비활성 여행의 데이터 Owner를 Server API로 유지해 로컬 저장공간과 동기화 복잡도를 제한한다.
- 오프라인 변경은 local write와 sync queue 기록을 함께 남겨 이후 동기화 가능성을 보존한다.
- 데이터·서비스·정책 UI의 권한을 섞지 않고, 네트워크·활성 상태에 맞는 제한을 사용자에게 설명한다.
- client/server 계약은 `@repo/schema`에서 함께 관리하고 서버는 인증·사용자 소유권을 검증한다.

## 범위 밖과 acceptance 경계

이 문서는 현재 제품 설명과 공통 판단 기준을 재서술한 것이며, 특정 릴리스의 완성·App Store 동작·지도와 OAuth 공급자·운영 데이터베이스·실제 동기화 성공을 보장하지 않는다. 그 검증과 사람 acceptance는 관련 앱·서비스 Owner와 실제 환경에서 별도로 수행한다.

제품 구조와 실행 경로는 [`architecture.md`](architecture.md), 계속 적용되는 선택은 [`decisions/`](decisions/)에서 찾는다.

# Read Project Context

이 skill은 [Project 읽기 기준](../../../context/project/REFERENCE/reading.md)을 실행한다. 문서별 적용 조건과 제품 계약은 해당 본문이 소유하며, 이 skill에 별도 목록으로 복제하지 않는다. 기본 동작은 읽기 전용이다.

## 필요한 본문을 선택한다

1. Root [AGENTS.md](../../../AGENTS.md), [Project README](../../../context/project/README.md)와 읽기 기준을 확인한다. 현재 요청의 주제와 필요한 판단, 이미 읽은 내용과 Recover가 제공한 자료를 함께 본다. 같은 세션에서 확보한 유효한 내용까지 다시 읽지는 않는다.
2. 주제별 진입점에서 관련 본문을 선택하고 실제 내용을 읽는다. 작업을 먼저 세 층으로 분류하거나 모든 층을 일괄 탐색하지 않는다. Project에 아직 없는 상세 주제는 README가 연결한 기존 Owner로 내려간다.
3. 본문 범위와 이번 작업의 관계를 확인하고 필요한 자료만 추가한다. 코드 경로·검증 근거가 결론에 영향을 주면 해당 app/package guide와 실제 Owner를 대조한다. Workspace 자료가 필요하면 [Work 지침](../../../context/work/AGENTS.md)을 따른다.

## 이해를 작업에 연결한다

읽기 기준에 따라 이번 작업이 보존·변경하려는 의미, 적용할 계약·예외, 현재 차이와 열린 판단을 작업 대상에 연결한다. 문서만으로 구현 준수를 단정하거나 코드만으로 제품 결정을 대체하지 않는다. 충돌을 확인하면 직접 근거와 권위를 대조하고, 확정할 수 없는 선택만 사용자에게 남긴다.

필요한 이해가 확보되면 읽기를 마치고 사용자의 원래 작업으로 돌아간다. 읽기 결과 설명이 요청된 경우에는 적용할 핵심 내용과 남은 확인을 설명한다. 다른 작업의 준비로 호출됐다면 접근이나 결론을 바꾸는 사항만 필요한 만큼 드러내고 별도 보고서·영구 기록을 기본 생성하지 않는다.

본문이 맡은 의미가 빠져 있으면 그 부족함을 밝힌다. 읽기 skill이 임의의 계약을 만들거나 문서 전체를 탐색해 빈칸을 감추지 않는다. 갱신 조건이 충족되면 [Project 관리 계약](../../../context/project/MAINTENANCE.md)과 [update-project-context](../update-project-context/SKILL.md)로 연결한다. 이 읽기 동작 자체로 문서를 수정하지 않는다.

## 다른 실행 경계

Recover 자료는 재사용하되 이 skill을 호출했다는 이유로 Recover·Maintain 연결을 다시 실행하지 않는다. 지속 문서 선택의 변경은 Work의 기존 책임에 연결하며 `recover.json`·machine 상태·제품 코드를 이 skill의 부작용으로 수정하지 않는다. 읽기 뒤 본래 요청이 허용한 실행은 그 작업의 계약을 따른다.

정적 설치·bridge의 존재는 실제 호출·본문 읽기·작업 적용을 증명하지 않는다. 사용자가 요청한 이해나 작업에 실제로 사용한 내용과 확인 한계만 보고한다.

# 기존 Work 계약을 유지한 development 적용

2026-10-30 사용자는06-01·06-02의 실제 남은 작업을 보완하고 Maintain과 분리 가능한 부분부터 반영하도록 요청했다. 전체 실행 본문을02까지 대기시킨 안내를 정정한 후속이다.

prototype의 판단·호출 조건·완료 강도를 유지하고 대상 경로에 연결했다. development의 구현·검토·검증 역할, improvement-loop의 사용자 요청 실행·한정 시도 종료, work-discussion의 충분성 판단, create의 의미 구성·인수가 적용 대상이다. 이 스킬과 관련 없는 역할의 기준을 새로 정의한 것은 아니다.

준비된 Work의 실제 갱신은 [현재 관리 계약](../../../../../context/work/workspaces/spec-and-tickets/MAINTENANCE.md)을, 생성·전환은 [현재 생성 계약](../../../../../context/work/workspaces/CREATE-AND-TRANSITION.md)을 따른다. 자동 Maintain·hook·session binding·Workspace schema를 교체하지 않는다. prototype의 직접 기록·수동 demo 계약을 설치 대상에 덮어쓰지 않았다. 기존 생성 스킬의 기계 계약·Recover·activation은 보존했다.

02에서 기록·전환 계약을 채택하면 본체의 해당 연결을 다시 대조한다. 이 적응을 영구적인 이중 정책이나 새 기록 담당으로 만들지 않는다. 형성 자료는 당시 이유를 보존하고, 현재 지시는 SKILL.md와 대상 Work 계약이 소유한다. 파일·링크·호출 설정 확인과 실제 host의 발견·호출·수행 효과는 구별하며 통합 테스트는02에서 잇는다.

# 기존 두 본문 재검토와 설명 수행의 구체화

사용자는 두 모델 설정의 응답 비교와 본문 대조 뒤 “이 방향으로 수정뿐만 아니라 기존 스킬 다시 꼼꼼히봐서 더 검토해봐”라고 요청했다. 앞선 네 보완 후보만 적용하지 않고 삭제 직전 두 본문 전체, 형성 맥락·관련 근거, 현재 본체·두 상세·공통 기준을 다시 대조했다. Main의 재검토이며 새 독립 리뷰나 응답 생성 시험은 아니다.

## 무엇을 바꾸고 어디에 두었나

| 재검토한 책임 | 대조 판단과 이번 반영 |
| --- | --- |
| 변경 전후 조사 | 기존 브리핑은 diff·변경 후 source·실제 사용처를 명시했다. 통합본의 비교 기준 선택을 구체화해 본체에서 비교 주장의 근거 대조를 요구하고, 작성 상세에서 기존 기반·이번 변화·결과를 구별한다. 전후 모든 파일을 읽게 하지는 않는다. |
| 구현과 설명의 대응 | 기존에는 실제 코드와 의미를 함께 보여 주도록 했으나 통합본에서는 표현 수단 선택처럼 읽힐 여지가 있었다. 본체가 응답 안의 실제 처리·의미 대응을 맡고 상세가 조건·위임·반환·값의 소비를 골라 잇는다. 코드 블록 수나 모든 줄의 해설은 기준이 아니다. |
| 목표에 대한 설명 | 국소 검사와 전체 목표의 구별은 공통 기준에 남아 있었다. 그러나 한계 표시만으로 목표를 얼마나 이루었는지 답할 수는 없다. 본체는 실제 목표·범위·완료 기준과 결과의 연결을, 상세는 개선하려던 부담에 맞는 비교 방법을 맡는다. |
| 목적별 충분성 | 공통 종료 문구를 구체화했다. 뜻·구조/동작·변경·진행 질문 각각에 필요한 연결이 있는지 작성자가 판단한다. 배타적 모드나 출력 점검표를 만들지 않는다. |
| 전체와 부분의 연결 | 추가 검토에서, 통합본의 한 대목 작성 예시만으로 전체 구조의 자료 선정까지 충분히 안내되는지 다시 보았다. 본체는 전체 역할에서 대표 사건으로, 상세는 진입부터 결과·외부 효과까지 따라가며 부분을 선택하도록 보완했다. 기존 시험에서도 전체 역할 설명은 있었으므로 이를 관찰된 실패의 원인으로 확정하지 않는다. |
| 구조의 이득과 남은 부담 | 기존 배경의 다음 변경 예시는 무엇을 함께 읽지 않아도 되는지와 여전히 함수 내부에 남은 기준을 구별했다. 현재 상세의 일반적인 효과·비용 비교를 읽기·수정 작업에서의 책임·사용처 대조로 구체화했다. 구조에서 도출한 이득과 실제 비용 감소 관찰은 구별한다. 과거 개선 주장일 때만 전후 자료를 요구한다. |
| 여러 차례 이어진 복구 | 원래 복구에는 이미 바꾼 설명과 새 질문, 현재 유효한 용어를 확인하는 요구가 있었다. 통합본에도 공유 맥락은 있으나 이 두 선택이 덜 직접적이었다. 앞선 발화 상세에 보완했다. 이것이 현재 시험의 열세 원인이라는 증거는 없다. |

첫 전달에서는 코드 품질 개선과 함께 실제 동작이 바뀌었다면 그 영향도 설명하게 했다. source06의 과거 철회를 정답으로 삼거나 가독성 작업의 동작 변경을 일괄 금지하는 조건이 아니다. 사용자 인터뷰와 당시 허용 범위를 함께 고려한 선택이다.

## 재검토했지만 추가하지 않은 것

- **실제 연결·현재성·미완성:** 선언과 실제 provider 연결, 과거와 현재, 가능한 동작과 실행, stub·미연결 등은 작성 상세와 공통 기준에 이미 있다. 모든 설명에 상태·환경 목록을 붙이지 않고 현재 조건부 연결을 유지했다.
- **이유와 판정:** 당시 의도와 현재 효과, 질문과 수정 권한, 근거와 최종 수락의 구별은 유지돼 있다. 모든 설명을 설계 리뷰로 넓히거나 독립 검토자를 자동 호출하지 않는다.
- **복구의 핵심:** 실제 발화의 뜻, 뜻 질문과 이의, 유지·정정·철회, 새 의미의 소급 금지는 이미 두 예시와 함께 있다. 복구 상세를 전면 재작성하지 않았다. 옛 복구 본문이 보류 후보였다는 지위도 유지한다.
- **분량과 표현:** 대표 값·조건 비교, 실제 관찰과 설명용 예시, 도식의 근거·생략 범위, 불필요한 문법 해설 방지는 유지돼 있다. 모든 답에 코드·그림·표·다음 행동을 요구하지 않는다.
- **운영 연결:** 옛 고정 Main/Maintain 연결과 기본 제목은 복원하지 않았다. 실제 대상의 관리 규칙과 현재 작업 담당자가 소유한다. 첫 결과의 조사·구현 책임도 설명 스킬로 옮기지 않았다.

기존 조항을 모두 되살리는 대신 현재 설명 행동의 선택 조건과 결과를 분명히 했다. `skill-creator`의 조건부 상세·의사결정 중심 원칙과 로컬 스킬 본문 관리 정책을 적용했으며, 이 prototype이 명시적으로 관리하는 `_background`는 계속 유지한다. `ai-system_instruction-clarity.md`에 따라 조사할 자료와 응답에 보여 줄 관계를 구별하고 기존 절을 수정했다.

## 근거와 확인 한계

삭제 직전 본문은 [브리핑](../legacy/work-artifact-briefing/records/2026-10-23-before-explain.txt)과 [복구](../legacy/explanation-recovery/records/2026-10-23-before-explain.txt)에 그대로 있다. 전체·부분과 구조의 이득 판단에는 [브리핑 형성 맥락](../legacy/work-artifact-briefing/context.md), 작은 복구와 원뜻·현재 타당성 구별에는 [복구 형성 맥락](../legacy/explanation-recovery/context.md)을 대조했다. 형성 예시는 실제 장기 효과의 증거가 아니다.

06 비교에서는6.0-sol medium의 새 스킬 이점이 뚜렷하지 않았고6.1-sol high에서는 기존판의 실제 전후 구현·이유 연결이 더 나았다. 새 스킬 실행은 두 번 모두 작성 상세를 읽었다. 이 관찰은 재검토의 계기이며 문구 약화가 결과 차이의 원인이라는 증명은 아니다. 최소 발췌·입력 조건·원자료 식별자는 [근거](../evidence.md)에 있다.

이번에는 대표 요청에 대한 읽기·자료 선정·출력 책임의 연결을 Main이 정적으로 확인했다. 새 모델 응답이나 사용자 이해 효과는 검증하지 않았다. source06의 정답 해설·코드를 실행 예시로 넣지 않았으며, 수정했다는 사실만으로 개선 성공이나04-02 완료를 선언하지 않는다.

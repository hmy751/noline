# 본체 구조 정리와 기존 인증 예시 분리

2026-10-25. 본문 구조를 다시 보고 배경의 맥락을 지키라는 사용자 요청에서 시작했다. 긴 인증 예시를 별도 파일로 나누는 Main 제안은 처음에 보류됐다. 본체 정리 중 사용자는 새 예시 작성이 아니라 기존 예시의 분리라는 뜻을 확인하고 분리를 요청했다. [발화 근거](../evidence.md#본체-정리-승인과-예시-분리-보류--2026-10-25)를 함께 본다.

본체를 질문 범위, 자료 확인과 판단, 설명 구성, 충분성, 권한으로 정리했다. 설명 구성 안에서는 전체 연결로 순서 잡기, 실제 대상과 해설 연결, 읽을 수 있게 배치를 구별했다. 반복된 짧은 질문·정정·대표 경로 조건을 해당 행동 가까이 모았다. 동작과 선택 이유를 별도 상세로 다시 나누거나 설명 유형·시점별 모드를 만들지 않았다.

실제 코드 동반, 첫 결과의 목표 연결, 전체와 국소 범위, 등록/현재 실행·관측/선택 작업·독립 경로, 실제 조건·오류 의미, 선택의 근거, 앞선 말의 정정과 권한 경계를 수정 전 본체와 대조했다. 앞선 발화 상세와 공통 근거 기준·development 연결은 바이트 그대로 유지한다. 작성 상세의 인증 전체·후속 구간은 설명·코드·조건을 그대로 `references/examples/auth-flow.md`에 함께 옮기고 제목 단계와 진입·복귀·출처 링크만 맞췄다. 작성 상세의 다른 예시·방법은 유지했다. 본체와 작성 상세 모두 전체 설명에서 분리한 대비 예시를 읽도록 연결해 기존 읽기 책임을 유지한다. 기존 상세가 가리키는 마무리 앵커도 유지하고 분리한 권한 절로 연결했다.

스킬 관리 정책의 ‘분량 축소 자체를 목표로 삼지 않기’와 본체가 직접 실행 기준을 맡는 경계를 적용했다. 지침 명확성·사람용 구조 기준은 조건과 행동을 가까이 두고 책임을 찾기 쉽게 하는 데 적용했다. 다른 문서의 목차나 파일 수를 고정 양식으로 가져오지 않았다.

정리의 목적은 적용할 조건과 책임 위치를 찾기 쉽게 하는 것이다. 새 응답 비교나 모델 성능 시험은 수행하지 않았다. 의미 대응·보호 파일 대조·표시 사본 검증의 상세는 Workspace014 `records/2026-10-25-ticket04-02-body-organization-adoption.md`가 소유한다. 기존 비교 결과와 첫 전달 등 남은 검토는 그대로 유효하다.

# Explain의 형성 자료

Reference의 현재 배치와 프로토타입 당시 기록의 차이는 [2026-10-29 부분 적용 기록](/Users/hammyeong-yeon/Desktop/ai-workspace/reference-project/context/_background/records/2026-10-29-reference-partial-application.md)에서 확인한다. 현재 Work 기록 계약을 유지한 대상 적응이며, 아래 과거 기록이 새 실행 담당이나 미설치 스킬을 활성화하지 않는다.

현재 실행은 [본체](../SKILL.md)와 [작성 상세](../references/constructing-explanations.md), [앞선 발화 상세](../references/prior-explanation.md)가 맡는다. 작성 상세의 긴 [인증 전체·후속 예시](../references/examples/auth-flow.md)는 실행 예시로 별도 배치했다. 이 묶음은 왜 기존 두 스킬을 하나의 설명 진입점으로 바꾸었고 무엇을 달리 구성했는지 보존한다. 일상 설명마다 읽을 자료가 아니다.

| 수정할 때의 질문 | 읽을 자료 |
| --- | --- |
| 어떤 문제를 해결하려 하고 기존 분리를 왜 바꾸었나 | [현재 형성 맥락](context.md) |
| 사용자가 요구한 것과 Main·리뷰어의 판단을 어떻게 구별하나 | [발화·관찰 근거](evidence.md) |
| 이번 생성에서 무엇을 채택하고 무엇을 옮기거나 남겼나 | [통합·연결 변경 기록](records/2026-10-23-unification.md) |
| 응답 비교 뒤 기존 두 스킬을 다시 보아 무엇을 보완하고 유지했나 | [설명 수행 재검토·반영](records/2026-10-24-explanation-revision.md) |
| 반복 비교 뒤 목적·사용 경험·외부 자료를 어떻게 선별해 실제 본문을 바꿨나 | [선별한 개선안의 실행 반영](records/2026-10-24-selective-improvement-adoption.md) |
| 코드 동반·가독성 요구를 실제 본체·예시에 어떻게 다시 연결했나 | [코드·표현 보완](records/2026-10-25-code-presentation-adoption.md) |
| 전체 설명과 국소 해설 사이의 공백을 어떻게 보완했나 | [전체 구성과 인증 예시 반영](records/2026-10-25-composition-adoption.md) |
| 도입 흐름과 본문의 가독성을 어떻게 함께 다듬었나 | [흐름·문단 배치 반영](records/2026-10-25-flow-readability-adoption.md) |
| 기존 예시를 분리하고 본체의 책임과 조건을 어떻게 정리했나 | [본체 구조 정리](records/2026-10-25-body-organization.md) |
| 이전 두 스킬은 어떤 이유로 만들어졌나 | [브리핑의 이전 형성 자료](legacy/work-artifact-briefing/README.md), [복구의 이전 형성 자료](legacy/explanation-recovery/README.md) |
| 선택 질문에서 지원 목표와 실제 사용처를 어떻게 함께 비교하게 했나 | [선택 판단 보완](records/2026-10-26-choice-judgment-adoption.md) |

이전 형성 자료는 과거 선택의 근거다. 현재 설명 스킬을 사용하려고 이전 두 본문을 함께 읽거나, 그 조항 전부를 새 본문의 필수 조건으로 취하지 않는다. 새 스킬은 기존 두 실행 본문을 제거하는 전제로 작성했으며, 필요한 설명 행동을 현재 목표·source·사용자 논의로 다시 구성했다.

설명 방법의 의미·구성을 바꾸는 주체는 [스킬 본문 관리 정책](../../SKILLS-CONTENT-POLICY.md)을 적용하고 이 맥락·근거·변경 기록을 함께 맞춘다. 장문의 Workspace 분석·시험 원자료는 원래 보존 위치에 두고, 여기서는 본문의 선택을 재검토하는 데 필요한 발췌와 식별자를 유지한다.

# 판단에 필요한 최소 근거와 provenance

이 파일은 [work-discussion](../SKILL.md)의 현재 선택을 검토할 수 있도록 필요한 발화·관찰·판본을 가까이 보존한다. 아래 `W`는 `context/workspaces/014-ai-development-workflow-design`다. 바깥 원자료는 추가 조사 때 찾는 식별자이며 현재 실행의 필독 경로가 아니다. 실제 외부 저장소 경로로 다시 접근하지 않고 W의 보존 사본을 확인했다. `source_line`은 corpus JSONL의 물리행 번호와 다르다.

## 기존 책임의 근거

**보존 기준판**: `W/source/noline-baseline/.claude/skills/work-discussion/SKILL.md`.04-01 DB·인증 대조 기록은 문서 blob `ff2ba390217e8823810cb85422b42d030460b993`와 기준판의 일치를 확인했다고 보고한다. 이번 적용에서도 기준판을 직접 읽었다. 기준판은 이미 다음을 말한다.

> 사용자가 필요하다고 판단해 직접 호출하는 예방적 보강이며, 일반 작업 대화에서 자동으로 끼어들거나 사용자가 이미 하던 인터뷰와 구체화를 대체하지 않는다.

> 작업 이해안은 현재 대화의 이해·선택 산출물이며, 반환했다는 사실만으로 Spec·Ticket의 실제 반영까지 끝난 것은 아니다.

**당시 AI의 연구 요약**: `W/source/discussion/conversation.jsonl`, `source_line`155, 2026-10-11. 이 요약은 작업 전 논의를 사람이 결과·근거·한계를 이해하도록 하는 지원에 배치했고 다음과 같이 책임을 구별했다.

> 좋은 설명, 제품·코드의 충분성 검토, 실제 수정, 지속 문서 반영은 각각의 책임

같은 발화는 Spec을 전체 결과·공통 기준, Ticket을 확인 가능한 실행 결과·진행, state를 현재 상황·다음 행동에 배치하며 Main 판단·Maintain 문서 갱신과 실제 반영 확인을 설명했다. 이 원문은 AI의 당시 해석이다. 스킬 최초 작성 전체 대화나 사용자의 각 조항 채택 발화까지 확보한 것은 아니므로, 이 요약을 모든 문장의 직접 형성 원인으로 삼지 않는다.

## 기존 정의와 새 관찰의 구별

**직접 원문**: `W/source/noline-evaluation/corpus/01a08e27-753f-76f0-95fa-32e1c324561f/messages.jsonl`, 물리행4~10, `source_line`67~132. 사용자 호출(74)은 다음과 같다. 링크 표기는 생략했다.

> 더 구체화 할거 있나? 티켓에 대해?

AI는105에서 구조 개선·정렬과 빈 목록·반올림 보존·동작과 가독성 검사 네 묶음을 새 보강처럼 제시했다. 사용자가120에서 물었다.

> 이게 상위에 없어?

AI의125 응답 중 직접 발췌:

> 대부분은 이미 상위 Spec에 있습니다. 내가 방금 티켓에 보강할 내용처럼 길게 제시한 건 중복이었습니다.

> 새로 확인된 것은 `1.005`에서 화면은 `1.00`, helper는 `1.01`이 되는 **반올림 방식 차이**뿐입니다.

**실행 전 Ticket 판본**: `W/source/noline-evaluation/documents/blobs/d5ed37a2cc24b3b91496699e88a408662cf8fb08.md`. 표시 차이 보존, 기본 통화가 없어도 첫 항목 강조, 빈 목록·동률·통화별 검사, helper와 UI 확인 구별, 구조 개선의 별도 비교가 이미 있었다. 예를 들어 완료 확인은 다음과 같다.

> pure helper 검사만으로 UI 표시까지 입증하지 않는다.

따라서 단순히 사용자가 불만을 보였다는 사실만으로 중복이라고 판단한 것이 아니다. 다만 해당 판본이 응답 순간 실제 읽힌 미커밋 본문과 바이트 단위로 같은지는 미입증이다. 반올림 값도 당시 AI가 보고한 계산식의 제한된 관찰이며 실제 화면 검증 결과가 아니다.

## 비교에서 관찰한 차이

**큰 안 비교**: `W/records/experiments/work-decision-skills-2026-10-20/`. `protocol.md`, `versions/current/work-discussion/SKILL.md`, `versions/proposed/work-discussion/SKILL.md`, `case-inputs/D1/`·`D2/`, `results/run-11.md`·`run-14.md`를 직접 대조했다. 전체16회와 독립 검토의 종합 판정은 `W/records/2026-10-20-ticket04-01-blind-skill-comparison.md`를 확인했다.

- D1은 기존 정의가 충분하고 계산식의 반올림 관찰이 추가된 조건이다. 기존판 run-11은 “조금 더 구체화할 부분은 있습니다”라며 반올림 외 강조 의미·가독성 기준도 더 명시하자고 제안했다. 이미 정한 요구라고 밝혔고 새 제품 선택은 없다고 판단했다.
- 같은 D1의 보완판 run-14는 “지금 티켓은 구현에 들어갈 만큼 구체적입니다”로 시작하고 새 반올림 경계만 기존 보존 검사에 연결했다.
- D2는 금액 표시 통일로 범위를 바꾸고 최종 표시 기준을 미선택으로 남긴 가상 반대 조건이다. 두 판본 모두 필요한 선택을 제안했다는 종합 결과를 확인했다.

이 차이는 충분성 요청의 재서술 제안 감소다. 독립 검토가 모두 충분으로 판정했으므로 기존판 오답을 고쳤거나 정확도를 높였다고 해석하지 않는다.16회는 두 스킬·네 조건을 합친 수이며 work-discussion에16회를 수행한 뜻이 아니다.

**최소안 확인**: `W/records/experiments/work-discussion-minimal-2026-10-21/`의 `protocol.md`, `change.patch`, `SKILL.md`, `results/run-a.md`·`run-b.md`. 최소안은 큰 안의 단순 복사가 아니라 기존 정의 대조·새 관찰 연결·요청별 반환을 기존 문장에 통합했다. 각 입력은1회만 실행했다.

run-a의 첫 판단:

> 티켓은 이미 실행 범위와 완료 판단을 잡을 만큼 구체적입니다.

뒤에서 반올림 사례를 기존 완료 조건에 붙이고 실제 코드에서 먼저 관찰을 확인하도록 했다. run-b는 표시 통일 조건에서 천 단위 구분자와 반올림을 선택으로 제시하고, 합산·자릿수·정렬·강조는 다시 선택하지 않았다. 두 응답 모두 제안과 실제 문서 수정·구현을 구별했다.

사용자 승인은 `W/records/2026-10-21-ticket04-01-minimal-update-and-two-checks.md`에 다음처럼 보존돼 있다.

> 이 최소 수정안으로 반영하고, 기존 정의가 충분한 경우랑 실제로 구체화가 필요한 경우 둘 다 제대로 판단하는지 확인

입력은 필요한 사실을 미리 선별한 조건이다. 전체 Spec·제품 코드·긴 작업 이력을 재현하지 않았다. 두 확인은 역사적 실패 재현, 새 Work 전체 수행, 기존판 대비 향상·반복 안정성의 증명이 아니다. 반올림 제안도 채택·구현 시 일반 규칙과 실제 데이터 계약을 더 확정해야 한다.

# 작업 이해를 실행 가능한 정의로 잇기

[work-discussion](../SKILL.md)은 구현 전에 사용자가 받을 결과와 보존할 의미를 맞추고, AI가 확인할 사실과 사람이 정할 선택을 구별하도록 돕는다. 사용자가 필요할 때 직접 호출하는 보강이다. 이 자료를 구성하면서 현재 본문을 새로 설계한 것이 아니라, 보존 기준판·사용 장면·04-01의 비교와 채택을 대조해 기존 책임과 이번 최소 보완의 이유를 구별했다.

## 기존 책임이 남은 배경

보존된 설계 요약은 사람이 결과의 뜻·근거·한계를 충분히 이해하지 못하면 나중에 재질문·재조사·재작업이 생긴다는 문제를 설명하고, 구현 전 논의·실제 결과 재판단·작업물 설명·설명 복구를 서로 다른 책임으로 두었다. 이 요약은 당시 AI의 연구 해석이며 사용자 원요구 전체나 최초 작성 과정을 대신하지 않는다. 보존 work-discussion 기준판은 이미 직접 호출, 사실 조사, 필요한 선택, 부족한 대체 결과와의 대비, Spec/Ticket 연결을 포함했다. 따라서 이번에 새로 만든 책임으로 기록하지 않는다. [근거 A](evidence.md#기존-책임의-근거)

직접 호출과 사람의 선택을 유지한 이유는 질문 자체를 비용으로 제거하려는 설계가 아니기 때문이다. DB·인증 사례에서 AI는 두 실패 모두 안내·재시도를 추천했지만, 사용자는 설명을 들은 뒤 DB 실패 재시도만 채택하고 인증 복원 실패의 기존 로그인 이동을 유지했다. 회고에서도 중요한 선택과 이해 보충이었다고 평가했다. AI가 자료로 답할 사실을 조사하면서 결과를 바꾸는 선택은 사람에게 남기는 책임이 실제로 쓰인 장면이다. 이는 질문 수 감소나 모든 작업의 자동 인터뷰를 정당화하지 않는다. [근거 B](evidence.md#선택을-없애지-않은-이유)

Spec에는 Work 전체 결과와 공통 기준을, Ticket에는 확인 가능한 실행 결과와 진행을 둔다는 책임도 기준판에서 이어받았다. 당시 AI 요약은 내부 데이터 연결이나 테스트 통과가 사용자가 받을 핵심 결과를 대신하는 문제를 배경으로 설명했다. 현재 본문의 대표 장면 대비·핵심 수행을 미루지 않는 Ticket·동작 보존과 구조 개선의 별도 확인은 이 경계를 구체화한다. 다만 각 문장의 최초 채택 대화까지 이번 조사에서 확인하지 못했으므로, 특정 역사적 사건 하나가 모든 조항의 직접 원인이라고 말하지 않는다.

Main이 이해·선택을 반환한 것과 지속 문서가 실제로 준비된 것을 구별하는 Main·Maintain 문구 역시 기준판의 기존 계약이다. 이번04-01은 이를 유지했으며 새 Maintain 운영을 채택·설치하지 않았다. 실제 운영 책임을 바꾸는 작업은 별도 후속이다. 현재 본문의 운영 지시와 이 유지 사실을 혼동해, 이 형성 자료만으로 Maintain을 활성화할 수는 없다.

## 왜 충분성 판단과 반환을 최소 보완했는가

경비 합계 장면의 사용자는 새 Work 전체를 처음 정의해 달라고 한 것이 아니라 기존 Ticket에 더 구체화할 것이 있는지 물었다. AI는 이미 있는 구조·정렬·검사 기준을 새 보강사항처럼 제시했고 사용자 정정 뒤 중복을 인정했다. 새로 찾은 `1.005`의 화면·helper 반올림 차이는 유효한 관찰이었지만, 기존 표시 보존 요구를 다시 선택할 사안이 아니라 그 요구를 확인하는 검사 사례였다. 실행 전 Ticket에도 강조 의미·표시 차이 보존·빈 목록과 통화별 검사·구조 개선 확인이 있었다. [근거 C](evidence.md#기존-정의와-새-관찰의-구별)

기준판에도 이미 정한 것을 다시 열지 말고 유지·새 구체화·변경을 구별하라는 요구가 있었다. 먼저 드러난 것은 원칙 부재가 아니라 적용 부족이다. 사용자는 기준이나 사례를 더 붙이는 것 이상으로 실제 판단을 바꾸는 구체안을 요청했다. AI의 큰 교체안은 보완 후보와 기존 정의를 대조하고, 충분성 질문에는 실행 가능 여부와 실제 부족분부터 답하도록 제안했다. 이는 당시 실패의 단일 원인을 입증한 분석이 아니라 비교 가능한 설계 가설이었다.

기존판·큰 보완판을 비교하자, 충분한 Ticket에서 보완판은 재서술 제안을 줄였지만 기존판도 새 제품 선택을 잘못 열거나 착수를 막지는 않았다. 표시 통일이 새로 요청된 반대 조건에서는 두 판본 모두 필요한 선택을 남겼다. 복구 알림을 다룬 reconsider-work도 기존판이 이미 필요성 확인을 제안했으므로 그 본문 교체의 이득은 입증되지 않았다. 이에 전체 큰 안을 가져오지 않고, work-discussion의 기존 정의 대조·새 관찰 연결·요청별 반환을 통합한 최소안만 선택했다. [비교와 한계](evidence.md#비교에서-관찰한-차이)

사용자가 최소안 반영과 두 조건 확인을 승인한 뒤, 충분한 정의에는 기존 요구를 재보강하지 않고 경계 검사만 연결했고, 표시 기준이 미선택인 가상 조건에서는 필요한 선택을 제안했다. 각 입력 한 번의 관찰이며 기존판 대비 우월성이나 새 Work 전체 구체화·장기 안정성을 증명하지 않는다. 필요한 사실을 선별해 제공했으므로 긴 이력에서 AI가 문서를 스스로 찾는 능력도 검증하지 않았다.

## 현재 선택과 열린 책임

04-01은 최소 보완 채택·prototype 반영과 reconsider-work 유지의 설계 결과로 완료됐다. DB·인증의 구조 목표가 구현·검토·완료 판단까지 이어지지 않은 문제는 이미 기준이 있던 수행·책임 문제를 스킬 사례 추가로 해결할 근거가 부족해, 사용자 결정으로 워크플로 후속01-01·01-02에 남겼다. 호출·실행 연결은01-01·04-03, Maintain 제거 뒤 기록 책임은02·06, 실제 이식·통합은06·07의 별도 범위다. 실제 Reference·외부 프로젝트 설치와 제품 검사는 하지 않았다.

이번 형성 자료 구성은 [SKILLS-CONTENT-POLICY](../../SKILLS-CONTENT-POLICY.md)의 실행 본문·형성 맥락·기록·최소 근거 구별과 선택적 읽기 안내를 적용했다. 긴 실행 본문을 쪼개거나 기존 절차를 background로 옮길 필요는 없어 본문에 안내만 더했다. 외부014 전체 기록은 복제하지 않고 이해·수정에 필요한 핵심만 이곳에 보존했다. 최초 작성 의도를 확인하지 못한 부분을 새 역사로 채우지 않는다.

## 실행 연결 후속 반영

2026-10-23에는 명시 호출 조건을 유지하면서 development의 자동 호출 문구를 제거했다. 사용자 합의에 따라 현재 기록 담당은 대상 root·Work·Project 지침을 따르는 Main으로 맞췄다. 앞선 Maintain 전제는 형성 이력이며 현재 실행 의무가 아니다. [통합 근거](../../development/_background/records/2026-10-23-execution-integration.md)에 직접 요청과 반영 범위를 남겼다.

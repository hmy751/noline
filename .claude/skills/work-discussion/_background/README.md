# work-discussion 형성 자료

이 자료는 prototype의 형성 맥락·당시 선택을 보존한다. 설치 대상의 현재 Work 갱신·생성·전환은 기존 계약을 유지하도록 적응했다. [이번 적응과 남은 연결](records/2026-10-30-existing-work-contract-adaptation.md)을 먼저 구별하며, 아래 당시 Main 직접 기록·수동 demo 설명으로 현재 운영 계약을 바꾸지 않는다.

이 자료는 [현재 실행 본문](../SKILL.md)의 목적·책임이 어떤 배경에서 남았고, 기존 정의의 충분성 확인을 왜 최소 보완했는지 복원하기 위한 것이다. 현재 요청에 스킬을 적용할 때 필요한 호출·조사·선택·Spec/Ticket·반영 책임은 계속 SKILL.md가 소유한다. 형성 자료는 실행 지침이나 새 승인 절차를 대신하지 않는다.

| 수정자가 가진 질문 | 읽을 자료 |
| --- | --- |
| 이 스킬이 이루려는 결과와 기존 책임을 왜 유지했는가 | [기존 책임과 유지 이유](context.md#기존-책임이-남은-배경) |
| 충분성 판단의 최소 보완은 왜 필요했고 큰 교체안은 어떻게 좁혔는가 | [최소 보완을 선택한 이유](context.md#왜-충분성-판단과-반환을-최소-보완했는가), [선택 기록](records/2026-10-21-selection-and-policy-application.md) |
| 사용자 발화·실행 전 정의·비교 응답은 실제로 무엇이었는가 | [최소 근거와 provenance](evidence.md) |
| 목적·호출·선택·운영 책임의 의미를 바꾸려는가 | 위 관련 맥락·선택·근거와 현재 본문을 대조하고, [스킬 관리 원칙](../../SKILLS-CONTENT-POLICY.md)의 변경 범위를 적용한다 |

현재 선택은 work-discussion 최소 보완의 prototype 반영이다. 최초 작성 전체 대화, 실제 제품 효과와 장기 안정성까지 복원·입증한 자료는 아니다. 바깥 Workspace 기록을 필독 경로로 만들지 않으며, 상세 원자료 위치는 evidence의 코드 경로와 source_line·판본으로 식별한다.

현재 실행의 Main 갱신 책임과 명시 호출 연결은 [후속 맥락](context.md#실행-연결-후속-반영)에서 찾는다.

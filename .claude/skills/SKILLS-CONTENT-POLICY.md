# 스킬 본문과 형성 자료의 관리 원칙

스킬을 현재 요청에 충분히 적용할 수 있게 설명하면서, 이후 수정자가 그 목적·배경·선택 이유를 복원할 수 있도록 본문과 형성 자료를 함께 관리한다. **이 문서는 Noline의 `.claude/skills/`에서 스킬과 공통 실행 기준을 작성·구성·변경하는 주체가 적용할 지침**이다. 스킬을 새로 만들거나 의미·구성을 바꿀 때 읽으며, 개별 스킬을 사용하는 매 요청의 필독 문서는 아니다.

각 `SKILL.md`는 해당 스킬의 호출 조건·판단·행동·결과를 소유한다. 이 정책은 그 내용을 어떻게 구성하고 형성 근거와 함께 유지할지를 맡는다. 호출 조건·실행 권한·프로젝트 운영 책임을 새로 정하거나 스킬 설치를 지시하지 않는다. 기존 스킬의 적용 현황과 읽기 경로는 [스킬 안내](README.md)에서 확인한다.

[context의 본문 관리 원칙](../../context/CONTENT-POLICY.md)의 본문·형성 자료 구분을 스킬에 맞게 구체화했다. 그 정책의 context 적용 범위를 확장하거나 Work의 적용 보류를 바꾸지는 않는다. [체계 지침의 역할과 구성](../../context/SYSTEM-GUIDANCE.md)에 따라 현재 파일이 실질적인 진입 본문을 맡는다. 이 정책의 목적·선택 이유를 재검토할 때는 [형성 자료 안내](_background/skills-content-policy/README.md)를 읽는다.

## 현재 실행할 내용과 형성 이유를 구별한다

| 역할 | 담을 내용과 위치 | 읽을 때 |
| --- | --- | --- |
| 실행 본문 | `SKILL.md`의 목적·호출 조건·핵심 판단·행동·제약·종료와 필요한 자료의 읽기 조건 | 현재 요청에 스킬을 적용한다 |
| 나누어 둔 실행 상세 | 조건별 절차·현재 사용하는 사례·자료 계약 등. 필요에 따라 `references/`나 기존 보조 문서에 둔다 | 해당 조건의 실행 판단에 필요하다 |
| 공통 실행 기준 | 여러 스킬이 공유하는 현재 기준. 실제 소유 위치 한 곳에서 관리하고 사용하는 스킬을 연결한다 | 각 스킬이 정한 적용 조건에 해당한다 |
| 형성 자료 | `_background/`의 현재 형성 맥락·당시 기록·원문과 관찰 근거 | 목적을 더 정확히 이해하거나 의미·과거 선택을 재검토한다 |
| 실행 도구·출력 재료 | 기존 `scripts/`, `assets/` 등의 실제 실행 보조와 산출물 재료 | 해당 작업에서 사용하거나 고친다 |

일상 실행에 필요한 이유·조건·예외는 본문과 필요한 실행 상세에 남긴다. 형성 자료를 읽어야만 현재 행동을 결정할 수 있도록 중요한 조건을 옮기지 않는다. 가끔 읽는 자료라고 모두 형성 자료가 되는 것은 아니다. 현재 기준을 적용하는 사례는 실행 상세이고, 과거 선택을 설명하는 사례·실험 결과는 형성 근거다.

본문의 분량을 줄이는 것 자체를 목표로 하지 않는다. 사용자가 받을 결과와 판단이 달라지는 조건을 충분히 설명하고, 반복이나 특정 상황에만 필요한 긴 상세는 읽기·수정에 도움이 될 때 나눈다. 짧고 충분한 스킬에 분할 파일을 억지로 만들지 않는다.

## 스킬의 진입과 관리 단위를 유지한다

`SKILL.md`는 실제 실행 지침을 계속 소유한다. 이를 `INDEX.md`로 바꾸거나 파일 목록만 남기고 본문 전체를 다른 곳으로 보내지 않는다. 이름·description·도구별 메타데이터가 맡는 발견·호출 관계도 유지한다. 파일명의 대소문자나 폴더 위치가 호출 권한을 대신하지 않는다.

실행 본문을 내용별로 나누는 것과 수정 전후의 판본을 보존하는 것을 구별한다. 분할한 실행 상세는 현재 본문과 함께 사용하는 내용이며, 수정 후보·비교판·과거 판본은 변경을 검토하는 자료다. 본문 분할의 이름 규칙을 수정 상태나 판본 표시로 확장하지 않는다.

수정안을 별도로 보존해야 하면 해당 작업의 기록·실험 영역에서 관리하고 현재 실행 본문과의 관계를 밝힌다. 채택할 때는 현재 본문과 읽기 경로를 갱신하고, 임시 후보 파일의 남은 역할을 확인한다. 동일 판본이 실험 입력이나 변경 기록에 이미 보존돼 있다면 중복 후보는 정리한다. 별도로 남길 필요가 있으면 그 이유와 지위를 명시한다.

하나의 스킬을 독립적으로 이해하고 수정하는 단위로 삼되, 여러 스킬이 공유하는 기준은 별도 책임을 유지한다. 공유 기준의 형성 자료도 그 기준 가까이에 한 번만 두고 관련 스킬에서 연결한다. 같은 근거를 사용한다는 이유만으로 스킬들을 하나의 관리 단위로 합치지 않는다.

개별 스킬의 형성 자료는 보통 해당 폴더의 `_background/`에 둔다. 이 정책처럼 기존 진입 파일을 유지하는 공통 지침은 `_background/skills-content-policy/`처럼 대상을 구별해 연결할 수 있다. `SKILL.md` 또는 기존 본문 진입점에서 형성 자료의 역할을 짧게 설명하고, 의미 변경·의도 확인·과거 선택 재검토에 필요한 읽기 경로를 안내한다. 파일 구조를 맞추기 위한 별도 스킬 README나 빈 자료는 만들지 않는다.

스킬을 작성·수정하는 주체가 들어오는 `skills/README.md`에서는 이 정책을 연결한다. 실제 설치·이식 때는 대상의 작성·수정 진입 경로와 필요한 자료의 동반 배치도 확인한다. prototype의 경로를 연결했다는 사실만으로 외부 환경에서도 같은 관계가 유지된다고 보지 않는다.

## 형성 맥락을 실제 근거에서 구성한다

새 스킬에는 이후 수정에도 필요한 목적·조건·선택 이유를 남긴다. 기존 스킬은 본문·관련 자료와 접근 가능한 작성 대화·조사·비교·실험에서 현재 내용이 남은 이유를 확인한다. 가까운 배경 파일이 없다는 이유로 조사를 생략하거나 기존 본문을 요약해 형성 맥락으로 대신하지 않는다.

형성 자료 안에서는 다음 책임을 처음부터 구별한다. 자료의 양에 맞춰 실제 필요한 내용을 쓰며 빈 양식을 채우지 않는다.

- `_background/README.md`: 대상 본문과 형성 자료의 역할을 설명하고, 수정자가 가진 질문에 맞춰 아래 자료의 필요한 부분으로 안내한다.
- `context.md`: 이루려는 결과, 필요해진 배경, 현재 선택이 남은 이유와 열린 판단을 연결해 설명한다. 기록 목록이나 현재 규칙의 재서술로 대신하지 않는다.
- `records/`: 중요한 논의·선택·정정·유보와 당시 조건·이유·확인 범위를 보존한다. 현재 결론이 바뀌어도 과거 판단을 새 결론으로 덮어쓰지 않는다.
- `evidence.md`: 판단에 필요한 실제 발화·관찰·비교 결과와 출처·당시 조건·한계를 보존한다. 정확한 문구가 중요한 근거는 링크와 함께 최소 발췌를 둔다.

사용자의 요구, 당시 AI의 제안, 채택된 선택, 실제 수행에서 확인한 결과를 구별한다. 기준 미수행·기준의 부족·입력이나 책임 배치의 문제를 증거 없이 같은 스킬 결함으로 묶지 않는다. 미채택 대안과 작은 비교 실험도 중요한 선택 이유가 될 수 있지만, 이를 실제 운영 실패나 일반 성능 향상으로 확대하지 않는다.

이 정책이나 다른 작성 지침을 참고했다면 무엇을 가져오고 무엇을 스킬에 맞춰 달리 정했는지 남긴다. 현재 선택에 영향을 주지 않은 자료를 사후에 형성 근거로 붙이지 않는다. 확인하지 못한 과거 의도는 만들어 채우지 않고, 조사 범위와 남은 공백이 어떤 판단을 제한하는지 밝힌다.

전체 작업 기록과 긴 실험 원자료는 기존 보존 위치를 유지한다. 스킬 가까이에는 해당 본문의 이해·수정에 필요한 맥락과 최소 근거를 선별해 두고 상세 원자료로 연결한다. 바깥 Workspace의 전체 진행을 읽어야만 현재 선택을 이해하게 하거나 같은 기록 전체를 여러 정본으로 복제하지 않는다. 스킬의 사용 결과로 생긴 제품 Spec·Ticket·작업 기록은 해당 작업의 기존 소유 영역에 둔다.

## 변경한 책임과 근거를 함께 맞춘다

| 하려는 일 | 확인하고 갱신할 범위 |
| --- | --- |
| 스킬을 현재 요청에 사용한다 | `SKILL.md`와 해당 조건에 필요한 실행 자료. 형성 자료 전체를 기본 입력으로 만들지 않는다 |
| 목적·호출·우선순위·판단·결과·책임 경계를 바꾼다 | 관련 형성 맥락·기록·근거와 영향을 받는 실행 본문·공유 기준을 확인한다. 현재 맥락을 맞추고 이후 재검토에 필요한 전환 이유를 남긴다 |
| 새로운 관찰이나 비교 결과가 생긴다 | 기존 선택에 실제로 어떤 영향을 주는지 판단한다. 관찰만으로 본문을 자동 수정하지 않으며, 채택·유보와 확인 한계를 구별해 남긴다 |
| 오탈자·링크·의미가 같은 표현을 고친다 | 해당 부분과 직접 연결을 확인한다. 과거 입력 전체 재조사·별도 변경 기록·행동 실험을 매번 요구하지 않는다 |
| 자료를 나누거나 이동·개명한다 | 기존 진입 책임과 호출 관계를 유지하고 들어오는 링크의 목적에 맞게 연결한다. 현재 본문·안내·표시 사본을 갱신하되 보존 원문과 당시 판본을 바꾸지 않는다. 수정안 채택에 따른 정리에서는 현재 본문·임시 후보·보존 판본의 위치와 연결도 함께 확인한다 |

공유 기준을 바꾸는 주체는 실제로 사용하는 스킬에 미치는 영향을 함께 확인한다. 이 정책을 편집한 사실이나 형성 자료를 읽은 사실이 실행·배포·제품 선택의 권한을 넓히지는 않는다. 이미 승인된 범위의 변경에 형식적인 재승인 단계를 추가하지 않는다.

## 적용 결과를 확인한다

적용한 본문·다른 구성을 유지한 대상·남은 공백을 구별한다. 폴더와 링크를 만들었다는 사실로 형성 맥락을 보완했다고 판단하지 않는다. 현재 실행 조건을 본문에서 찾을 수 있는지, 수정자가 가까운 자료에서 선택 이유와 중요한 근거를 이해할 수 있는지, 설명한 이유가 현재 행동과 맞는지 확인한다.

새 정책의 작성과 개별 스킬에 대한 실제 적용은 별개다. 개별 스킬의 기존 본문·자료를 대조하지 않았다면 적용 완료로 표시하지 않는다. 중요한 행동을 바꿨다면 그 차이가 드러날 대표 조건에서 확인하고, 사용 장면과 지침 수정 장면의 검증 범위를 구별한다. 링크 검사나 한 번의 성공을 모든 사용·수정의 신뢰성으로 확대하지 않는다.

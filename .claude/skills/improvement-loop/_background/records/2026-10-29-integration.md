# 스킬의 적용 설명과 Personal의 근거를 같은 책임 안에 둔다

2026-10-29. 사용자는 루프가 스킬에 할당됐는데 루트 문서가 별도로 필요한지, development에도 같은 기준이 적용되는지, 대문자·CONTENT-POLICY와의 일관성이 맞는지 재검토를 요청했다. 독립 감사와 수정 범위 추가 점검 뒤 루트 문서 통합·Personal 근거 분리·발견한 오류 정정을 요청했다.

## 루트 유지 판단을 바꾼 이유

이전에는 여러 구성요소를 함께 설명한다는 이유로 루트 안내를 유지했다. 그러나 development도 Personal·Project·Work와 실제 수행을 연결한다. 설명에 여러 영역이 등장한다는 사실은 별도 관리 단위의 근거가 아니며, 루트 안내에 스킬과 다른 공통 기준은 없었다. Personal을 사용하는 설명을 스킬 아래에 두더라도 Personal의 내용·관리 책임이 스킬로 옮겨가는 것은 아니다.

일반 진입은 prototype와 skills의 기존 README, 호출·공통 수행·완료는 [SKILL](../../SKILL.md), 현재 규칙을 적용하는 사례는 [application](../../references/application.md)에 통합했다. 원문 확인과 효과 판단 상세는 기존 references에 둔다. 옛 루트 파일은 연결 안내로 남기지 않고 제거했다. 이전 루트 안내의 원문은 Workspace014의 `records/reviews/improvement-loop-2026-10-29/input/improvement-loop-before-integration.txt`에 보존했다. 이 파일 없이도 현재 스킬과 적용 사례를 읽을 수 있다.

대표 공통 체계 지침이면 대문자 이름을 쓸 수 있지만, 독립 책임이 없는 안내를 대문자로 바꾸는 것은 이번 문제를 해결하지 못한다. 스킬 상세의 소문자 application은 현재 스킬 관리 정책과 맞는다. 모든 스킬에 대응 루트 문서나 같은 수의 references를 만드는 변경은 하지 않았다.

## Personal과 수행 순서의 관계

Personal의 범위 선택 근거는 Personal이 유지하며, 그 안에서도 맥락 설명과 직접 발췌를 구별한다. 짧다는 이유로 context에 합친 두 발췌를 [Personal evidence](../../../../../context/personal/_background/experience-collection/evidence.md)로 분리했다. Personal의 [정정 기록](../../../../../context/personal/_background/experience-collection/records/2026-10-29-ownership.md)이 이 경과를 맡는다.

전체 대화를 훑고 관련 경험을 고르는 루프 수행 순서는 SKILL이 소유한다. 공통 USAGE는 루프로의 연결과 평소 읽기를, Personal의 MAINTENANCE는 경험의 조회·보존·갱신을 설명한다. 본체가 Personal 계약을 사용하는 관계를 유지하고 서로 전체 수행 순서를 반복하지 않게 했다. 대화 전체 검토·관련 본문 전체 검토·사용자 선택·즉시 반영·다음 관련 사용 확인의 합의는 유지했다.

## 내용 정정과 확인의 의미

설명 효과 주제에서 사용자 반응으로 묶였던 Main의 우열·국소 이득 판단을 원 비교 기록과 대조해 나눴다. 사용자 원문·AI 해석·현재판 유지 선택의 지위를 구별하며 새로운 효과 관찰을 만들어내지 않았다. Workspace의 오래된 파일 구성 미정·검토판 유지 문구와 인접 형성 맥락도 현재 결과에 맞췄다.

확인은 현재 규칙의 담당, 진입·적용 사례·형성 자료의 읽기 경로, 근거 대조, 과거 판본 보존과 viewer의 원문·링크를 대상으로 한다. 실제 루프 수행·운영 설치·장기 효과는 별도다. 앞선 실행 개선 두 제안의 채택·완료나 05 전체 마감으로 확대하지 않는다.

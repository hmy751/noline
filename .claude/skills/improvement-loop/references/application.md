# 실제 경험에서 개선 선택과 반영 대상을 구별한다

[improvement-loop](../SKILL.md)의 판단을 구체적인 적용 장면에서 이해할 때 읽는다. 보존 경험과 현재 해석을 바탕으로 가능한 다음 선택을 설명하는 사례이며, 해당 후보를 이미 채택하거나 이 루프를 실제 운영한 결과가 아니다.

호출·검토 범위·선택·반영·종료는 스킬 본체가 맡는다. 사례에서 사용하는 경험과 원문은 Personal이 보존하고, 경험의 지위·저장·갱신은 [Personal 관리 계약](../../../../context/personal/experience/MAINTENANCE.md)을 따른다. 이 문서가 그 계약이나 제품·스킬의 현재 내용을 대신 소유하지 않는다. 아래 장면은 고정 분류나 모든 요청에 적용할 출력 양식이 아니다.

## 여러 자료가 좋지만 무엇을 가져올지 고르기 어렵다

[설계 논의 주제](../../../../context/personal/experience/topics/design-conversation.md)에는 실제 사용자 발화와 당시 진행을 보존했다. 현재 해석은 자료를 더 모으는 것에 더해 대안의 실제 차이와 남은 질문을 연결할 필요가 있다는 것이다. ‘비교 후 질문하기’는 열린 후보이며 매번 도식·인터뷰를 요구하는 기준은 아니다.

다음 대화에서도 선택 기준이 불분명했다면 Main은 새 대화의 실제 비교·질문·사용자 선택, 기존 주제, work-discussion 전체를 대조한다. ‘인터뷰’라는 단어가 같은지만 찾지 않고 같은 어려움을 만든 조건과 실제 수행을 살핀다. 아래는 그 대조에 따라 가능한 다음 선택이며 현재 채택 결과가 아니다.

| 확인한 조건 | 가능한 선택 | 실제로 달라지는 곳 |
| --- | --- | --- |
| 기존 스킬의 비교·질문 방식이 충분하고 실제로도 도움이 됐다 | 현행 유지, 필요하면 경험만 보존 | Personal 주제의 경험·해석 |
| 기존 지침은 충분하지만 이번에 읽거나 적용하지 못했다 | 찾는 경로·적용 조건·실제 수행을 보완 | 확인된 원인에 해당하는 진입 또는 수행 |
| 특정 열린 설계에서는 유망하지만 일반 적용 근거가 부족하다 | 사용자 선택에 따른 한정 시도 | 해당 작업에서 언제 어떤 비교·질문을 할지와 Personal의 시도 범위·기대 변화·반영 대상 |
| 기존 스킬의 조건에 구체적인 부족이 확인됐다 | 사용자 선택에 따른 본문 보완 | 실제 스킬과 필요한 연결·직접 확인, Personal의 반영 결과 |

기존 스킬로 충분한데 인터뷰 단계만 늘리는 안은 제외할 수 있다. 추천할 때 실제 바꿀 문장이나 수행 장면을 보여준다. 한정 시도는 일반 채택과 구별하고, 기준 전문은 경험 주제에 복제하지 않는다. 아무것도 고르지 않거나 미결 이유가 같으면 후보를 유지하며 자동 재권고하지 않는다.

### 다음 설계 한 번에 시도하기로 선택했다면

다음은 위 열린 후보를 사용자가 한정 시도로 골랐다고 가정한 적용 예다. 이 사례를 작성한 사실이 실제 후보의 채택이나 실행을 뜻하지 않는다.

| 시점 | 기존 구조에서 연결하고 정리할 내용 |
| --- | --- |
| 선택 | Personal의 같은 설계 논의 주제에 이번 시도의 이유·범위·기대 변화와 실제 수행 위치를 남긴다. 길잡이에 실행 전문을 복제하지 않는다. |
| 특정 다음 작업으로 연결 | 그 작업이 원래 읽는 재개 본문에 ‘이번 설계 논의 한 번에서 대안 차이를 비교한 뒤 남은 질문을 묻는다. 끝나면 이 임시 지시를 정리하고 사용 경험을 해당 Personal 주제에 잇는다’는 뜻을 둔다. 기존 Work라면 `current/state/index.md`의 이어갈 내용에 둘 수 있다. 상세한 수행 조건을 Ticket이 소유한다면 상태에는 그 연결만 둔다. |
| 실행·종료 | 정한 논의가 끝나면 임시 지시를 제거하거나 종료로 갱신한다. Personal에는 실제 비교·질문을 했는지, 선택에 도움이 됐는지 또는 부담·미확인이 있었는지를 구별해 잇는다. 작업 결과는 원래 Work에 남길 필요가 있는 경우 그 계약을 따른다. |
| 이후 판단 | 다음 요청 루프에서 실제 경험을 근거로 유지·조정·접기·지속 채택을 제안한다. 한 번 수행했다는 이유로 스킬을 자동 수정하지 않는다. |

현재 대화에서 바로 할 수 있으면 별도 재개 문서를 만들지 않고 수행한다. 어느 작업에서 할지 미정이면 Personal에 남기되 연결 완료라고 하지 않는다. 적용 기회 없이 범위가 끝나면 미사용으로 남기고 다음 작업에 자동 연장하지 않는다. 이 예를 인증 demo의 실제 Ticket에 넣거나 모든 작업의 필수 단계로 만들지 않는다.

## 좋은 편집 경험으로 관련 본문 전체를 살핀다

[문서 품질 주제](../../../../context/personal/experience/topics/document-quality.md)는 첫 11편 편집의 긍정 반응과 조건·순서·예외를 보존한 방식을 담는다. 다음 문서 반영에서는 새 정보 한 줄뿐 아니라 해당 주제 전체와 내용 지침을 대조한다. 같은 설명이 충분하면 무수정 유지, 부족한 적용 조건이 확인되면 기존 본문 통합, 다른 문서에서도 유용한 판단이면 Personal 사례 보완을 추천할 수 있다.

이 좋은 경험에서 모든 문서를 표로 바꾸는 기준이 나오는 것은 아니다. 실제 보완이 선택되면 대상 본문과 들어오는 참조를 함께 맞추고 목적·조건·예외가 복원되는지 확인한다.

## 대화 전체 확인이라는 같은 목적에서 수행 수단을 고른다

대화 전체를 훑는 합의와 [원문 확인 절차](conversation.md)는 이미 있다. 여기서는 원문을 찾고 순서대로 읽는 준비를 어떻게 개선할지 비교한다. 당시 확인한 로컬 세션 구조가 모든 host에 적용되거나 실제 반복 비용·누락이 확인됐다는 뜻은 아니다. 아래 조건은 실제 사용에서 대조할 가정이다.

| 실제 확인한 조건 | 가능한 선택과 달라지는 수행 | 이득과 부담을 판단할 근거 |
| --- | --- | --- |
| 원문에 접근할 수 있고 직접 준비·읽는 부담이 크지 않다 | 현행 유지: 기존 절차로 원문을 직접 읽는다. | 현재 목적을 충족하면 새 설명·도구의 관리 비용을 더하지 않는다. |
| 시작·끝 범위나 중복 메시지·요약의 구별을 이해하지 못했다 | 설명·사례 보완: 해당 원문 확인 지침에서 혼동한 조건을 분명하게 한다. | 이해 문제에는 직접적이다. 반복적인 파일 탐색·정리 작업 자체를 줄이지는 않는다. |
| 범위는 이해하지만 세션 식별·순서 정리·중복 구별을 반복하며 누락이나 부담이 생겼다 | 읽기 전용 추출 도구의 한정 시도: 필요한 원문과 위치를 준비하고 Main은 그 원문에서 판단한다. | 실제 준비 부담·누락과 기존 도구의 재사용 가능성을 먼저 확인한다. host 변화·fork·압축 경계를 처리하고 유지할 비용도 비교한다. |

설명 부족이면 설명을, 수행 준비의 반복이 문제이면 기존 도구 연결이나 도구 시도를 비교한다. 근거가 없으면 도구가 필요하다고 결론 내리지 않는다. 세 대안 전부를 매번 제시하거나 새 도구 후보를 의무적으로 만드는 표가 아니다.

도구 시도를 사용자가 실제로 선택하면 처리 범위·원문 순서/위치·중복/압축 구별을 해당 도구의 직접 확인 대상으로 삼고, 정한 작업과 종료 범위는 스킬 본체의 한정 시도 연결을 따른다. 준비 결과를 만든 사실이 전체 대화를 읽고 해석했다는 증거는 아니다. 원문 읽기·개선 판단은 Main이 맡는다. 이 사례의 채택은 추출 도구의 제작·설치·실행 승인이나 효과 확인이 아니다.

## 이전 보완을 썼는데 이득이 애매하다

[설명 방식의 효과 주제](../../../../context/personal/experience/topics/explanation-effects.md)에 보존한 비교에서는 일부 근거가 좋아졌지만 전체 이득이 제한적이었고, 문구를 더하지 않고 현행을 유지한 판단이 있었다. 이것을 이번 루프 스킬의 사용 효과로 옮기지 않는다.

다음 관련 사용에서는 이전 변경의 목적과 실제 사용을 대조한다. 읽지 않은 장면이면 접근·적용 문제를, 사용했지만 효과가 불분명하면 조건과 부담을 살핀다. 작은 이득이 있어도 불필요한 절차가 커졌다면 범위 축소·간소화를 권할 수 있다. 선택을 바꿀 가치가 있을 때만 관련 요청에서 한정 비교한다. 이 판단의 상세는 [effects](effects.md)가 맡는다.

## 📝 구현 시 참고사항

### 핵심 파일 구조 (CRUD-Centric)

```
apps/client/src/
  shared/
    policy/
      types.ts           # CRUDPermission, AppPolicyContext, CRUD-Centric 타입
      constants.ts       # TRIP/SCHEDULE/EXPENSE_POLICIES (CRUD-Centric)
      useAppPolicy.ts    # 단일 Hook (PolicyKey 계산 포함)
      errors.ts          # PolicyError 클래스
      index.ts           # Clean exports

  entities/
    schedule/
      ui/
        ManualScheduleForm.tsx  # Phase 3
    expense/
      ui/
        ManualExpenseForm.tsx   # Phase 3

  screens/
    CreateScheduleScreen.tsx   # ✅ Policy 적용 완료
```

### 구현 순서 권장사항

1. **먼저 Phase 1 완료** → useAppPolicy() 작동 확인
2. **Phase 2 중 SmartMapView 우선** → 가장 영향 큰 기능
3. **Phase 3 Schedule Manual Input 우선** → Expense보다 복잡
4. **Phase 4는 점진적으로** → 한 번에 하지 말고 하나씩
5. **Phase 5는 마지막** → 모든 구현 완료 후

### 주의사항

- `useAppPolicy()`는 항상 현재 상태 기반으로 실시간 정책 반환
- Policy 변경 시 UI가 자동으로 업데이트되도록 설계
- Manual Input은 "기본 모드"가 아닌 "Fallback"으로 구현
- 네트워크 복구 시 데이터 보강은 백그라운드에서 조용히 수행

### CRUD-Centric 구조의 장점

- **직관성**: 각 동작이 4가지 상태에서 어떻게 동작하는지 한눈에 파악
- **유지보수성**: 정책 변경 시 해당 operation의 4가지 상태만 수정
- **확장성**: 새 Entity 추가 시 CRUDOperationPolicies 인터페이스 활용
- **단순성**: 단일 Hook으로 모든 정책 제공, 불필요한 중간 레이어 없음

### 테스트 시나리오 예시

```typescript
// Scenario 1: 온라인 + 활성화
describe('online_active', () => {
  it('should allow all features', () => {
    const policy = useAppPolicy();
    expect(policy.createTrip.allowed).toBe(true);
    expect(policy.mapProvider).toBe('google');
    expect(policy.searchMode).toBe('api');
  });
});

// Scenario 2: 오프라인 + 활성화
describe('offline_active', () => {
  it('should block trip creation but allow schedule manual input', () => {
    const policy = useAppPolicy();
    expect(policy.createTrip.allowed).toBe(false);
    expect(policy.createSchedule.allowed).toBe(true);
    expect(policy.searchMode).toBe('manual');
  });
});
```

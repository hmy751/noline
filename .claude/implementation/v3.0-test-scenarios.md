## ✅ 검증 포인트

### 1. Policy 객체 구조

```typescript
const policy = useAppPolicy(tripId);

// CRUD-Centric 접근
policy.trip.create.allowed; // boolean
policy.schedule.create.mode; // 'full' | 'manual-only' | 'disabled'
policy.expense.read.reason; // string

// Service Layer
policy.service.mapProvider; // 'google' | 'mapbox' | 'none'
policy.service.searchMode; // 'api' | 'manual'
```

### 2. 4가지 상태 매트릭스

| 상태             | Trip 생성 | Schedule 생성 | Map    | Search |
| ---------------- | --------- | ------------- | ------ | ------ |
| online_active    | ✅        | ✅ full       | Mapbox | API    |
| online_inactive  | ✅        | ✅ full       | Google | API    |
| offline_active   | ❌        | ✅ manual     | Mapbox | Manual |
| offline_inactive | ❌        | ❌            | None   | Manual |

### 3. PolicyErrorDisplay 스타일

- **banner**: 노란색, 경고 (상단 배너)
- **block**: 빨간색, 화면 차단 (전체 화면)
- **inline**: 노란색, 인라인 (폼 내부)

## 🐛 Known Issues & Edge Cases

### 1. Policy 전환 딜레이

- useAppPolicy는 async 상태 조회
- 초기 렌더링 시 잠깐 loading 상태 가능
- → useMemo로 최적화 완료

### 2. Manual Input 좌표 보강

- 자동 보강 없음 (의도적 설계)
- 사용자가 온라인에서 직접 재검색
- → 더 정확한 좌표 확보 가능

### 3. Service Layer Router 미사용

- Map, Search는 Router 사용 안 함
- Component-Level에서 Policy 체크
- → 순수 함수 유지, 의존성 최소화

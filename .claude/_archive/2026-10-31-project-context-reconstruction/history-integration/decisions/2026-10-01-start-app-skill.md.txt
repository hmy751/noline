# Decision: start-app 로컬 skill

> Date: 2026-10-01
> Status: Accepted

## 배경과 결정

개발 DB와 API 서버, Expo 클라이언트를 실제로 연결해야 하는 작업이 있다. 사용자가 수동으로 앱 실행을 시키거나, 현재 작업을 마치려면 실제 앱 실행이 반드시 필요한 경우에 `start-app`을 사용한다. 정적 코드 조사와 검사만으로 끝나는 작업에는 자동 적용하지 않는다.

`.claude/skills/start-app`을 Claude/Codex 공통 원본으로 두고 `.agents/skills/start-app`을 Codex 상대 symlink로 연결한다. 스킬은 기존 실행 상태를 확인하고 필요한 구성요소만 시작한 뒤, 서버 건강 상태와 클라이언트의 실제 API 요청을 구분해 확인한다. 실행 시점의 주소·명령·기기 상태는 현재 설정과 환경에서 확인한다.

## 영향 범위

이 스킬은 개발 환경 실행 절차만 안내한다. 제품 정책, 서버·클라이언트 설정의 정본, Context Harness의 Workspace·Maintain 계약을 옮기지 않는다. 하네스 검사는 새 원본과 bridge의 존재를 확인한다.

## 같은 날 실행 시험과 문서 보완

Luna 서브에이전트의 실행 시험에서는 Docker 시작 권한 검토와 `pnpm`의 재설치 제안에서 막혔다. 사용자 재시작 승인 뒤 설치된 실행 파일로 DB·서버·앱 초기화와 API 요청을 확인했다는 보고를 받았다. 보고에는 실제 앱 화면 확인 근거가 없었다.

사용자가 “시뮬레이터 접근해서 잘 돌아가는지 확인부터 해야 되는거 아니야?”라고 정정하고 `recall-document-guidance`로 추가 내용을 재검토하도록 요청했다. 초기 접근은 재사용·복구·시작을 결정하는 상태 확인으로, 완료 시 화면 확인은 정상 실행 판단으로 명확히 했다. 끝에 덧붙였던 일반 장애 처리 문단은 이번 실행에 필요한 의존성 실행 경로와 사용자 승인 근거 전달로 정리했다. 이 문서 보완 뒤 실제 앱을 다시 실행해 검증한 것은 아니다.

사용자는 이어 “다음 세션에서도 실행할때 난 스무스하게 되길 원했다”고 명확히 했다. 일회성 시험 방식이었던 서브에이전트 사용 안내는 스킬에서 제거하고, 설치된 실행 파일을 먼저 사용하는 기준과 요청 범위 안의 실행에 재확인을 반복하지 않는 기준으로 두 문단을 수정했다.
